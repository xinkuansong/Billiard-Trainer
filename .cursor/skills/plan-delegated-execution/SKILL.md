# 方案全程委派执行（主控验收 + 子智能体执行）

输入是一份声明为真源的方案文件（含批次表、依赖图、逐批完成标准、锚点索引）。本技能定义主控如何**把每个批次委派给执行子智能体、独立验收、驱动返工、串行推完所有批次**。主控自己不写业务代码，专注：读方案、发任务、验结果、判达标、回写状态。

## 角色分工

| 角色 | 承担者 | 职责 |
|---|---|---|
| 主控 | 当前会话（本技能执行者） | 锁真源、拆派任务、独立验收、驱动返工、状态回写、向用户汇报 |
| 执行者 | Task 子智能体（模型按批次风险路由，默认 `claude-opus-4-8-thinking-medium`） | 在独立上下文中完成一个批次的全部实现与自测 |

每个批次默认新开一个执行子智能体（fresh context）；同一批次的返工用 `resume` 复用该子智能体（保留其已有上下文，修改成本最低）。

## 主循环

对批次表按依赖序逐批执行，每批走完以下闭环再进入下一批：

1. **锁真源 + 选批**：重读方案文件本批相关章节（范围、完成标准、红线、锚点），确认前置批次已实证完成（看代码/测试，不信文档自述）。前置未就绪则停下报告。
2. **组装委派提示词**：子智能体看不到本会话历史，提示词必须自包含（模板见下）。
3. **派发**：用 Task 工具启动执行子智能体，`subagent_type: generalPurpose`（或方案指定的项目专项角色），显式指定路由确定的模型（见红线「模型路由」）。
4. **独立验收**（子智能体返回后，主控亲自做；子智能体的「通过/达标」判断只作参考，最终判断由主控基于一手证据做出）：
   - 读子智能体改动的关键文件，核对是否符合方案语义、未越界改相邻批次内容；
   - **测试验收：不重复跑，但必须亲读原始产物**。全量测试成本高（动辄十几分钟），主控默认不复跑；取而代之，子智能体必须把测试原始产物**落盘**（完整 build/test 日志文件、xcresult 路径、截图/录屏目录）并在汇报中列出产物清单。主控**亲自打开这些原始文件**核验：日志尾部的 `TEST SUCCEEDED/FAILED` 与失败计数、实际跑了哪些 suite/case（覆盖面是否对准本批完成标准）、有没有跳过/删改断言（新增/修改的测试读 diff，确认没有硬塞期望值）、截图内容是否支持对应标准。汇报中贴的摘要不作为判据——摘要是二手信息，判据只认落盘的原始输出；
   - **复跑仅在存疑时**：原始产物缺失或不完整、日志与代码现实对不上、测试方法/覆盖面不对、或主控读代码后对某条标准仍有疑点——此时主控亲自复跑该疑点对应的最小测试面（而非全量）；
   - 主控必须亲自跑的最小集：合并/落地后主树 build（归因合并本身，成本低且子智能体无法替代）；
   - 逐条对照该批完成标准打勾，任何一条不满足即判「未达标」。
5. **返工循环**：未达标时，用 `resume` 向同一子智能体发返工指令——逐条列出「哪条标准没过 + 主控看到的实际证据（报错输出 / 代码位置）+ 期望行为」，禁止只说「不对，再改改」。返工后回到第 4 步重新验收。
   - **熔断**：同一批次返工满 3 轮仍未达标，停止循环，向用户汇报卡点（哪条标准、尝试过什么、当前判断），等待裁决；禁止为了推进而放宽标准。
6. **回写与检查点**：达标后更新真源文件批次状态（✅ + 日期）、项目进度台账（如 `tasks/PROGRESS.md`）、命中项（ADR / FAILURE-LOG）；输出一行检查点：
   ```
   [检查点] 批次 Wn 完成（返工 x 轮）| 变更文件：<列表> | 下一批：Wm
   ```
7. **推进判断**：下一批依赖已就绪则继续第 1 步；全部批次完成后做总结（各批状态、总返工轮数、遗留项），并同步 Project Hub 状态卡（若项目有此约定）。

## 委派提示词模板

```
你是本项目的执行智能体，负责实现以下批次，完成后如实汇报。

【真源文件】<方案文件绝对路径>——先完整阅读其中批次 Wn 的章节再动手。
【本批范围】<逐条列出本批条目>
【明确不做】<相邻批次内容点名排除，防越界>
【关键锚点】<文件/组件/行号；提醒：行号可能漂移，动手前重读代码确认>
【红线约束】<本批命中的项目红线：几何契约、ADR 触发、回归面等>
【完成标准】<逐条列出，含可验证项及验证命令>
【测试产物要求】build/test 完整日志、xcresult、截图/录屏必须落盘保留
（如 build/wN-logs/、build/wN-screenshots/），不得只在汇报里贴摘要后丢弃。
【汇报要求】返回：改动文件清单、每条完成标准的自测结果、**测试产物清单**
（每个日志/xcresult/截图的绝对路径 + 一句话说明它证明哪条标准）、
未完成或存疑的点。禁止宣称未验证的事项为「已完成」。
```

返工时的 resume 提示词只需：未通过的标准编号 + 主控实测证据 + 期望行为，不必重复全量上下文。

## 会话与上下文管理

- 子智能体承担了实现的上下文消耗，主控上下文主要花在验收上，通常可在一次会话内推完多个批次。
- 主控自身上下文变长或经历压缩后，继续任何动作前**重读真源文件**相关章节，禁止凭记忆验收。
- 若用户中途打断，先把当前批次状态（🔄 + 已过/未过的标准）写回台账再停。

## 红线

- **主控不代写**：验收发现问题一律回给子智能体改，主控不顺手修业务代码（避免验收者与实现者混同、责任不清）。唯一例外：纯状态回写类文件（PROGRESS、真源批次状态）。
- **不改需求语义**：主控与子智能体都无权增删、弱化方案条目；执行中发现方案与代码现实冲突，小偏差如实记录，大偏差停下等用户裁决，拍板后写回真源并升版本号。
- **诚实验收**：判「达标」必须以主控**亲自读过的落盘原始产物**（日志文件 / xcresult / 截图）或主控亲自复跑的输出为据；**不允许**以子智能体的结论性自述或汇报里的摘要转述作为判据。复跑只在存疑时对最小测试面进行（见主循环第 4 步），不作为每批默认动作——省的是重复执行，不省的是证据审读。
- **不跳依赖、不放宽熔断**：前置未实证完成不开工；3 轮返工未过必须上报，不得自行降低标准。
- **模型路由由主控确定**：默认 `claude-opus-4-8-thinking-medium`；主控可按批次风险改派（判断密集批用强推理模型，条目明确的机械批可用快速模型并升级验收强度——路由准则见 `plan-parallel-delegated-execution` § 模型路由）。用户显式指定时以用户为准。
- 正文用简体中文；代码标识符英文。
