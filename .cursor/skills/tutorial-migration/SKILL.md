# 精讲迁移：保留有效教学信息，修正旧结构与旧事实

## 入口与职责

使用本技能前，完整读取 [billiard-copy-editing](../billiard-copy-editing/SKILL.md) 和[动作库内容重写统一规范](../../../docs/research/20261015-动作库内容重写统一规范.md)。教学判断、材料读取、逐杆讲解、术语、数量和验收口径由这两个入口统一管理；本技能只补充迁移中的路由、旧材料取舍和结构保护。

当前用户要求优先于历史文案与旧模板。实际授权范围从用户请求和当前任务方案读取，不因调用本技能自动获得全库改写、正式资源回填、代码修改或发布权限。只审查时不执行迁移；已授权迁移也只在指定文件和字段内工作。

迁移通常处理 `tutorial` 字段。若用户另行授权完整动作重写，按该任务字段白名单执行；本技能不自行扩展到课名、介绍、训练要求或训练配置。直接编辑正文，脚本只负责盘点、提取、检查和呈现，不生成或批量回灌教学正文。

## 什么算完成迁移

分别检查三件事，不能混为一个“新版”标签：

| 维度 | 核对对象 | 判断边界 |
|---|---|---|
| 身份与结构 | `tutorial.sections` 或 `tutorial.formations`、球形ID、逐杆关联、`tutorialKind` | 单球形与多球形都可能需要迁移；不能为套版改变球形数量和身份 |
| 证据与内容 | 当前意图、素材、每个保留的教学断言 | 有图片或参数不代表意图正确；旧正文不能证明最新击球事实 |
| 学员能否理解 | 任务、适用打法、选择原因、进球与走位目的、必要观察与纠错 | `content` 可自然成段，`items` 可用于并列信息；二者有无不判定质量或版本 |

四段纯文本只是识别旧材料的线索，不是必须改成列表的理由。把原文按句号切进 `items`，没有重新审查依据与教学任务，不算完成迁移。反过来，语义完整且结构可解码的自然段不因缺少 `items` 被退回。

## 1. 冻结输入，建立动作专属材料包

1. 备份当前实际文件并记录SHA，不用 Git HEAD 代替用户当前内容。列清目标路径、字段范围及所有受保护对象。
2. 在仓库根目录运行只读上下文清单，参数换成目标动作：

   ```bash
   python3 .cursor/skills/billiard-copy-editing/scripts/collect_drill_copy_context.py drill_c065
   ```

3. 读取当前完整 Drill JSON、用户原始训练意图和最新纠正、所有相关球形与序列、相关图片、同主题相邻动作和必要的理论资料。具体读取要求按统一入口执行，不把脚本列出的路径当成已读证明。
4. 为每个球形记录来源、缺口、版本及映射：drill ID → formation token → 序列文件 → step ID／杆序 → section → image。单球形与多球形均逐项覆盖；不只处理第一个球形。
5. 实际查看所有相关开局图和逐杆图。图、序列与渲染输入不一致时先定位，不用旧文字解释掉矛盾，也不自行重出图片。

主输入路径按当前[内容数据契约](../../../.kiro/steering/content-data-contract.md)确认。`content/position_play/sequences/` 是源序列入口；Bundle 派生资源不能冒充独立事实源。历史文件数量、课名、退役profile和旧示例只作追溯线索，不直接决定当前路由。

## 2. 按素材与教学任务路由

对每个动作及其球形判定，不凭名字、分类、`items` 或序列条数拍板。

| 当前材料与教学任务 | 处理路径 | 本技能交接内容 |
|---|---|---|
| 有可映射的当前录制序列 | 转 [tutorial-authoring](../tutorial-authoring/SKILL.md) 的当前流程 | 完整材料包、旧要点取舍表、已读图记录、冲突与缺口；不能只转交主控或旧稿的结论 |
| 无对应序列，任务确为身体动作／器材操作 | 无序列技术课 | 依据用户意图、可核实的动作资料与实际素材说明怎么做；不伪造击球参数、轨迹或停位 |
| 任务确为规则、计分、失败条件或开放式挑战 | 规则流程课 | 读取规则真源及产品现行行为；区分练习规则、训练剂量和技术成功条件 |
| 教学需要具体击球示范，但缺录制、缺图或映射不明 | 材料缺口 | 列出缺什么、影响哪一段；暂停依赖该材料的写作，不以无图技术课掩盖缺失 |

有序列不等于连续击球，也不等于必须套同一多杆排版。有序列的规则课仍可能以规则为主，序列仅作案例；先确认它与当前球形的关系，再决定如何使用。分类、标准要求和旧文可提供线索，不能用“满足两项”代替教学判断。

分别写清**录制组织**（独立重摆／连续接打）和**教学关系**（并列情况／递进／对照／连续衔接）。只录首杆也可能要走下一颗；没有录下后续击球，不是把后续目标改称参照球的依据。下一条step是另一开局时，又不能把它冒充当前after的真实接续。

缺素材时可以继续已授权且证据充分的部分；需要改变交付形式或训练目标，先明确缺口与可选处理，不静默降低完成标准。

## 3. 审查旧材料，逐项记录去向

逐段提取旧文中的教学要点，先判定依据与有效性，再决定保留、修正、合并、删除或待核。不要求保留错误句子，也不因重写而丢掉有价值的意图。

| 旧材料 | 需要核对 | 处理原则 |
|---|---|---|
| 训练目的、球形设计说明 | 用户原始意图、最新反馈、当前球形 | 保留有效意图；旧解释冲突则记录并纠正，不让润色覆盖原意 |
| 身体／器材经验和具体数值 | 可核实资料、适用条件、与本动作的关系 | 不因属于“经验值”就自动照抄；无依据的间隙、距离等数值待核或删去 |
| 操作与观察步骤 | 现行规则、实际行为、技术原理 | 组织成可执行说明；不用通用试错替代示范方案 |
| 球位、角度、路线、停位和杆法效果 | 当前序列、经核验分析、图片对应关系 | 旧文、旧digest和目测不能证明；先核事实再决定怎样写 |
| 次数、时长、换位或失败后重试指令 | 训练设置、规则与原技术成功条件 | 去除重复剂量与无依据门槛；真实计分或成功判定保留，不能随删数字取消 |
| 跨动作引用 | 当前索引、实际ID和名称、课程关系 | 引用存在且确有教学关系才保留，不按旧课名恢复退役内容 |
| 空泛、重复或无依据的解释 | 是否帮助决定怎么打、为什么、怎样观察 | 删除或改写，并在取舍表说明；不另凑一条提醒填空 |

去向表至少包含：旧段落／原句、旧要点、证据路径与定位、处理结论、新版落点或不采用理由。每个有实际教学意义的旧要点都要有去向；保留原句不等于已核真，删除空话也不需要虚构替代事实。

## 4. 无序列场景的事实边界

- 无录制不能编造“这杆实际发生了什么”。存量 `shotIntent`、历史animation、旧参数、旧profile都不能代替当前录制证据。元数据用于理解产品定位，不自动证明几何和物理结论。
- 未证实的角度或距离，不能仅删去数字就变成确定的“很薄”“中等距离”等断言。定性说法同样需要依据；没有依据就省略该断言或列为待核。
- 图片用于确认对象、对应关系与画面，不用于目测角度、球距或计算停位。只有完成有效映射和事实核对，才能把路线与教学目的连起来。
- `params` 只填有对应当前shot证据的值，不给无序列技术课或规则课凑参数。教学角度按统一规范使用有效瞄准角；缺失时不以0、袋心夹角或实际接触切角补位。
- `image` 只引用实际存在、已查看且关联正确的素材。身体动作缺手型照片就如实记录，不能拿无关球台图替代；不因迁移擅自启动拍摄或生成图片。
- 规则文本区分官方规则、产品行为和教学建议。有冲突先报告；不借迁移改变计分、结束条件、训练剂量或设置。

证据卡分列“录制／现行行为事实”“用户教学意图”“候选解释”。几何有路可打不证明课程希望打这个袋，更不证明后续走位成功；候选需要什么验证要明确，不能让它悄悄进入确定性正文。

## 5. 按内容选择结构，不固定标签和篇幅

先确认现行模型、schema和渲染器支持的结构。以下是信息覆盖提示，不要求固定节数、标题顺序、条数或三标签：

| 路由 | 应覆盖的信息 | 组织方式 |
|---|---|---|
| 无序列技术课 | 做什么、适用条件、关键动作及原因、怎样观察、必要的纠错 | 连贯段落或少量步骤列表；有实际训练价值才写进阶建议 |
| 有序列教学 | 按当前authoring流程覆盖所有球形和逐杆信息 | 章节与图、参数正确关联；是否精简依据教学信息是否重复，而非“中间杆可一律留空” |
| 规则流程课 | 怎样开始、如何进行、计分／记录、结束或失败条件、必要变体 | 按学员执行顺序组织；没有固定击球案例时不编“第N杆”与参数 |

不用 `为什么／怎么打／自检` 固定三标签裁定通过，也不要求强行指定“胜负手”。可以解释图中路线怎样服务下一颗，不受“图已画出就不得写”的绝对禁令限制；避免的是无意义描图。重点、原理和纠错多少由真实教学任务决定，不机械配齐加难／降难各一条。

新增节标题前读当前渲染代码，不沿用历史行号或假定图标映射。通用回退样式是否足够，应按实际界面与授权范围判断；本技能不要求为每个新标题修改SwiftUI。确需代码、schema或布局变化时单列依赖，未经授权不顺带修改。

`tutorialKind` 及其值必须核对当前模型和解析器。不把“未知JSON键必然解码失败”等历史说法当事实；既有类型与迁移目标冲突时先定位依据。类型修正若属本次明确授权，记录前后值与原因；否则保持并报告。

## 6. 写回保护与验收

动笔前确定字段白名单。默认只改目标文件 `tutorial` 内已授权内容；保护 drill ID、球形token与顺序、原序列step ID及关联、图片对应、训练配置、计分语义、animation、shotIntent、序列、物理、瞄准和回放。迁移需要补齐逐杆节或修正结构时，依据当前模型和唯一映射进行，不借迁移删杆、合并球形、重编号或修改原击球数据。

多球形保持每个球形身份与覆盖；顶层 `sections` 和 `formations` 按现行契约使用，不为套模板同时填两份。用户当前素材发生变化时，重新核对受影响证据，不用旧备份整文件覆盖。

交付前逐项检查：

1. 路由有当前素材和教学任务依据，缺口明确；不是照历史动作清单或父任务结论执行。
2. 已实际读取动作专属材料并完成逐杆／逐规则判断，读取记录与判断依据分别列出；作者报告不代替原始证据。
3. 旧要点取舍表完成：保留项有依据，删除项有理由，训练意图和真实成功条件未丢失。
4. 事实、意图与候选解释分开；独立首杆的后续目标未被误降为参照；未把当前示范写成无条件正确答案。
5. 全文可执行且连贯，图文关联正确；无固定标签、固定重点或 `items` 数量门槛，没有为凑结构制造教学内容。
6. 全部球形和已授权内容均覆盖；参数、瞄准角、图引用与当前事实匹配，未增加训练数量和换位门槛。
7. JSON可解码，身份、结构、字段范围和受保护对象检查通过。运行当前项目文案及内容专用门禁，记录真实命令、退出码和原有失败；不能通过删除素材或放宽门禁变绿。
8. 由审稿者独立读取意图与相关素材，再对照最终候选全文；不能只复述作者结论。审稿绑定最终SHA，材料或正文变化后重审受影响项。
9. 按任务授权验证实际页面；纯技能维护不启动App构建。未做的UI、回放、真机或发布检查明确标为未验证。

## 交付

报告实际迁移范围、采用路径及依据、材料读取和缺口、教学判断、旧要点去向、允许字段差异、校验结果、最终文件SHA及仍未验证事项。数据门禁通过、教学审稿通过、用户认可、正式集成、安装和发布分别报告，不合并成“已完成迁移上线”。

本技能不固定某次样稿的数量或动作ID；每次从当前请求与任务方案确认范围。历史迁移记录只作追溯，不作为当前素材清单或授权。
