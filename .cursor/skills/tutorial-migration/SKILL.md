# Tutorial Migration Skill — 旧版精讲 → 新版精讲

## 你要做的事（一句话）

拿一条 legacy drill（`tutorial` 只有四段纯 `content`，无 `items`），判定它该走哪类模板，把旧文本里**站得住的**教学信息提炼出来、按新版结构重写，写回 drill JSON。**格式统一只是及格线，内容规范达标才算迁移完成。**

## 「新版」的判据（⛔ 别跟多球形搞混）

两个**互相独立**的维度，最容易在这里翻车：

| 维度 | 载体 | 与本技能的关系 |
|---|---|---|
| **① 一个 drill 有几个球形** | `tutorial.formations[]` vs `tutorial.sections`（ADR-P12-02），顶部分段控件切换 | **迁移不改变它**。c053 迁完还是 8 个球形，只是 8 套内容都变新 |
| **② 精讲内容是纯文本还是结构化图文** | section 里有没有 `items`（为什么/怎么打/自检）+ `params` + `image` | **这才是新旧版的唯一判据** |

四种组合库里全都存在：

| | 四段纯文本（旧版） | 结构化图文（新版） |
|---|---|---|
| 单球形 | `c032` 中台角度球 | `c001` 半台直线球 |
| 多球形 | `c053` 中袋角度精准（8 球形 × 4 段墙文） | `c030` 分离角走位应用（5 球形 × 逐杆图文） |

判定用 `items` 有无，**不是**用 `formations` 有无。`c053` 有 8 个球形、切换体验完整，但点进任一球形仍是四段墙文——没有逐杆图、没有打点参数、没有可证伪自检，读者拿到的东西与 `c032` 无异，是**旧版**。2026-08-03 用户确认口径。

## 与 tutorial-authoring 的分工（先读这一节，决定要不要用本技能）

| | `tutorial-authoring` | 本技能 `tutorial-migration` |
|---|---|---|
| 输入 | 走位序列 JSON（编排台录制） | legacy drill JSON 的旧四段文本 + 元数据 |
| 几何事实来源 | `tutorial_digest.py` 事实清单 | **无几何事实源**（这正是它难的地方） |
| 产出 | 多杆应用课 | 单杆技术课 / 规则流程课 |
| 关系 | 写作规范真源 | 复用其规范，只补「旧内容怎么处理」与另两类模板 |

⛔ **有序列的 drill 不归本技能。** 判定为多杆应用课的，本技能的职责到「路由判定 + 旧文本资产化」为止，之后转 `tutorial-authoring` 正常流程执行。全库实测（2026-08-03）52 条 legacy 里 **42 条有序列**，绝大多数走那条路。

以下规范以 `tutorial-authoring/SKILL.md` 为真源，本技能**不重复定义、原样适用**：

- **§为何而写**（总原则：文字的价值＝提供图/动画/试打看不出来的东西；三条推论）——**这是判断一切取舍的依据**
- **§第0步 意图锚定 + 读图**（意图卡四问 + 四条意图红线 + 读图三目的 + 看图边界 + 图健康检查）——迁移同样适用，差异见下节
- **§不重复原则**（跨媒介 / 跨杆次 / 跨 drill 三个方向）——**迁移场景下跨 drill 重复风险最高**：legacy 多为同类技术训练，`c032`/`c033`/`c052`/`c062`/`c072` 全是角度或直线准度，极易写成同一段。批量迁移时每写完一条，与同 `subcategory` 已迁移条目对读一遍。
- **§参数递进型序列的写法**（首档写透、后续只写差异、差异自带参照）——11 条 `formations` 型 legacy 基本都是递进型（`c053` 切角阶梯、`c075` 塞量阶梯、`c078` 远台带塞），**这是它们的主要写法**
- **§重点指认**（全组一个胜负手，客观依据）
- 理论引用三层渐进式披露（⛔ 正文禁出现定理编号 / 「法则告诉我们」句式）
- `items` 三标签 `为什么`/`怎么打`/`自检` 的写作公式与可证伪自检要求
- 打点用身体语言、力度用档位语言，⛔ 禁 spin 数值上屏
- 写回目标只改 `tutorial` 字段，写回后校验 JSON 可解码

### 意图锚定在迁移场景的差异

照 `tutorial-authoring` §第0步 读元数据与 profile、答意图卡四问，但有两处变化：

**问 3 换问法**（本技能两类模板没有「逐杆」）：

| 模板 | 问 3 改为 |
|---|---|
| 单杆技术课 | **这个动作的关键控制点是什么？** 做对与做错的分野在哪一个具体环节（不是「多练」，是「食指环留 1 毫米间隙让杆滑顺」这种）|
| 规则流程课 | **这套规则为什么这样设计？** 它逼迫用户练什么——Ghost Game 的「一次失误就输一局」不是记分方式，是**把实战压力人为造出来** |

**旧文本里已有的意图要提炼，不要丢**：legacy 的「技术原理」段常已含真意图，`c065` 的「引入心理压力——每一杆都有代价，接近实战中的紧张感」就是很好的训练意图陈述，`c008` 的「手架相当于球杆的前导轨」是很好的原理类比。这类内容**优先保留并强化**。但同样在旧文本里的「全面覆盖各种常见角度」「保持每一杆的专注度」属空泛意图，按红线 2 删除。

**没有事实清单兜底时，意图更要克制**：无序列的 drill 拿不到实测参数，问 3 的答案只能来自元数据与身体动作经验，⛔ 不得借意图之名重新引入几何断言（「这个角度最能体现…」——你并不知道那是什么角度）。

**读图在迁移场景的两点差异**：

1. **无序列的两类模板往往无图可看**（10 条零素材 drill 全部无图）。此时 §不重复原则的「跨媒介」方向不适用——**但另两个方向（跨杆次、跨 drill）照旧**，且因为没有图分担信息，文字要把「怎么摆、怎么做」交代得比应用课更完整。
2. **有序列的 42 条转 `tutorial-authoring` 前，读图仍是你的职责**：路由判定时顺手做图健康检查，把坏图清单交给下游，别让下游重蹈 E7。

### 决策树（自上而下，命中即停）

1. **`seq > 0`** → **多杆应用课**。转 `tutorial-authoring`，本技能只交付「旧文本资产化清单」（第1步）给它当补充素材。
2. **开放式挑战**——每局开局不同、以规则/计分/胜负为核心，写「第 N 杆」在教学上就是错的。判据（需同时满足两条以上）：`category == combined`；`standardCriteria` 是胜率/局数/清台数而非进球数；旧文本「动作要领」讲的是流程与记录而非某一杆的打法 → **规则流程课**。
3. **纯身体动作 / 器材操作**——训练对象是手架、握杆、站位、出杆本身，球台渲染帮不上忙 → **单杆技术课（无球台图）**。
4. **其余**（单一击球的技术训练，本可出图但尚未录序列）→ **缺素材，不是缺模板**。⛔ 不要为了完工硬套单杆技术课，正确处理是列为「待补录序列」并上报，或经用户同意后先出无图版单杆技术课并在交付说明标注为临时态。

## 第1步：旧文本资产化（提炼，不是切块）

⛔ **最容易犯的错：把旧四段按句号切开塞进 `items`，改完格式像新版、内容还是旧墙文。这算伪迁移，不予验收。**

先把旧四段拆成一张**信息清单**，每条标注去向。逐条判定，不判定不准动笔：

| 类别 | 例（来自 `drill_c008`/`drill_c032`） | 处理 |
|---|---|---|
| 身体/器材经验值 | 「手架距母球 15–20 厘米」「食指环留约 1 毫米间隙」 | ✅ 保留，可直接进 `怎么打` |
| 可操作流程 | 「先从袋口方向确认接触点，回到击球位后用假想球法瞄准」 | ✅ 保留，重写为动作步骤 |
| 球台几何断言 | 「形成约 30–45 度入袋角度」「母球置于台面中心区域」 | ⚠️ **无事实清单支撑一律不得原样搬**。见下方红线 |
| 心理/习惯建议 | 「连输三局后暂停 30 秒」 | ✅ 保留（规则流程课的核心素材） |
| 跨 drill 引用 | 「可挑战『远台斜线入角袋』」 | ✅ 保留，但必须校验名称存在（命令见下） |
| 空话 | 「只关注进球不关注方法」「保持专注度」 | ❌ 删除或改写成可证伪的动作 |

跨 drill 引用校验：

```bash
python3 -c "
import json,glob
names={json.load(open(f))['nameZh'] for f in glob.glob('QiuJi/Resources/Drills/*/drill_*.json')}
for n in ['远台斜线入角袋','三分点角度入袋']:   # 换成正文里实际引用的名字
    print(('✅' if n in names else '❌ 不存在'), n)
"
```

## 内容红线（本技能特有，因为没有事实清单兜底）

1. **几何断言必须降级或删除。** 旧文本里的角度、距离、母球落点是历史文案，无出处、未经引擎实测。允许的处理只有三种：① 改成不含具体数值的定性描述（「中等距离的角度球」）；② 若该 drill 有配图且图上可直接看出，改成对图的描述并配 `caption`；③ 删除。⛔ 绝对禁止照抄旧数值，更禁止把旧数值改写得更精确——那是凭空造数，属 FL-027 同类。
2. **⛔ 禁止从存量 `shotIntent` 反推几何事实。** 2026-06-13 用户拍板：示范击球以编排台人工录制为准，存量 `shotIntent` 精度不可靠。所有 legacy 都有 `shotIntent`，但它**不是**可用的事实来源。
3. **`params` 只在有实测来源时才写。** 单杆技术课与规则流程课默认**不写** `params`。
4. **配图不虚构。** `image` 只填 `ls QiuJi/Resources/DrillTutorials/` 确认存在的文件名。身体动作类需要手型照片，当前**无此素材管线**——如实列为待办，不用球台渲染图凑数。

## 第2步：模板骨架

### A. 单杆技术课（`tutorialKind: singleShot`）

| # | title | 容器 | 配图 |
|---|---|---|---|
| 1 | `技术原理` | `content` 1–2 段 | 无 |
| 2 | `动作要领` | `items` 3–5 条，label = 步骤名（`架杆`/`瞄准`/`出杆`/`收势`），**中性色渲染** | 可选，有确认存在的图才填 |
| 3 | `常见错误与纠正` | `items` 2–4 条，label = 错误名，text = 现象 + 后果 + 纠正 | 可选 |
| 4 | `进阶练习` | `content`，降阶 + 升阶各至少一个方向 | 无 |

- `动作要领` 每条必须是**可执行动作**，不是心法。判据：读完能立刻照做。
- 至少有一条给出**可证伪的自检征兆**（可并入 `动作要领` 末条或单列一条 label 为 `自检`，后者有橙色配色）。

### B. 多杆应用课（`tutorialKind: multiShot`）

⛔ 不在本技能定义。骨架见 `tutorial-authoring/SKILL.md` §模板，样板 `QiuJi/Resources/Drills/positioning/drill_c042.json`。

### C. 规则流程课（`tutorialKind: ruleset`）

| # | title | 容器 | 配图 |
|---|---|---|---|
| 1 | `技术原理` | `content`，讲**这个练习在练什么能力**、为什么这样设计规则 | 无 |
| 2 | `怎么摆` | `content` + `image`（开局示意）| 有图才填 |
| 3 | `怎么计分` | `items`，label = `一局怎么算`/`记什么`/`怎么算进步` | 可选计分示意 |
| 4 | `失败判定` | `items` 2–4 条，label = 判定项（`犯规`/`未清台`/`超时`） | 无 |
| 5 | `常见错误与纠正` | `items`，label = 错误名 | 无 |
| 6 | `进阶变体` | `content`，给出加难与降难各一 | 无 |

- 计分节必须给出**具体可记录的量**（如「平均清台球数」而非「进步幅度」），这是开放式挑战唯一可证伪的抓手。
- ⛔ 不得出现「第 N 杆」节——开局每次都不同，写具体某一杆就是错的。

### 渲染层实情（如实告知，别以为改完就完美）

`DrillTutorialView.swift:138-157` 的图标与配色映射表**只有 4 个标准标题**（`技术原理`/`动作要领`/`常见错误与纠正`/`进阶练习`）和 3 个标签（`为什么`/`怎么打`/`自检`）。上表新增的 `怎么摆`/`怎么计分`/`失败判定`/`进阶变体` 能正常渲染，但会 fallback 到 `doc.text.fill` + `.btPrimary`，视觉上与其他节无区分。

因此：新增标题时**必须同步**在 `DrillTutorialView.swift` 的 `sectionIcons` / `sectionColors` 补映射，并在 `QiuJi/Resources/Drills/schema.md:66` 的 Standard section titles 补登记。不做这一步就说「渲染层无需改动」是不实陈述。

### `tutorialKind` 字段

值域 `singleShot` / `multiShot` / `ruleset`，写在 `tutorial` 对象下。该字段属 `问题集合_v25.md` E21，若 `DrillContent` 尚未落地此字段，**先不要写进 JSON**（会解码失败），改在交付说明中声明本条判定为哪一类，待字段落地后回填。写之前先确认：

```bash
rg -n "tutorialKind" QiuJi --glob '*.swift'
```

写完后，对旧四段逐段做去向对照，输出成表：

| 旧段落 | 旧要点 | 新版落点 | 判定 |
|---|---|---|---|

## 自查清单（写完逐条回显 ✅/❌，有 ❌ 先修复）

0. 意图卡四问已回显（问 3 按模板换过问法）；`coachingPoints` 逐条有落点；无空泛意图；旧文本里已有的真意图已保留强化而非丢弃。
0b. 有图的条目：图已实际看过 + 图健康检查过，坏图已上报；无图条目已说明。
0c. 不重复三方向自查，其中**跨 drill** 必须与同 `subcategory` 已迁移条目对读；递进型的差异描述自带参照；全组已指认胜负手（多杆/多档条目适用）。
1. 路由判定有盘点脚本输出支撑，不是凭 drill 名猜的。
2. section 顺序与所选模板骨架完全一致，标题一字不差。
3. `items` 每条是重写的，不是旧 `content` 的切片——抽查任一条，能说出它比旧文本多了什么（结构 / 可执行性 / 可证伪性）。
4. 正文无未经实测的几何数值；保留的每个数值都能说出出处（身体经验值 / 图上可见 / drill 元数据）。
5. 未使用存量 `shotIntent` 推导任何几何断言。
6. 正文无定理编号、无「法则/原理告诉我们」句式（`tutorial-authoring` §理论引用）。
7. `image` 指向 `ls` 确认存在的文件；缺图已列待办而非虚构文件名。
8. 跨 drill 引用的名称已用脚本校验存在。
9. 保真核对表完成，旧要点无无声丢失。
10. 新增 section 标题已同步 `sectionIcons`/`sectionColors`/`schema.md`，或已明确列为待办。
11. 写回后 JSON 语法有效：`python3 -c "import json; json.load(open('<file>'))"`。
12. 多球形 legacy：`formations` 内**每个球形**都已迁移，不能只改第一个。
