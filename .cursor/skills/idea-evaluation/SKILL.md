# Idea Evaluation Skill — 批判与证伪的通用能力

赋予使用者一套**与议题无关**的评估方法论：把任何想法 / 方案放在证据下严格检验，区分真问题与伪命题，并把"还不知道的"转成可执行的验证。具体辩题 / 证据源由当前议题文件提供。

## 触发场景

- 在结构性辩论中需要评判对方提出的任何想法 / 方案时。
- 任何"需要冷静、用证据判断一个主张是否成立"的场合。

## 方法库

### 1. 依目标搭 rubric

不要用通用清单空评。先从**议题目标**反推"成立必须满足哪些条件"，把这些条件列成评估维度，逐维判断。常见维度（按议题裁剪）：真实需求、可行性、规模 / 盘子、差异化与可复制性、单位经济、获客 / 触达、留存、风险 / 合规、护城河。

### 2. Steelman（先建最强版再批）

评判前先把对方想法**补成最强形态**再批，避免打稻草人。然后问："即使是最强版，它最可能怎么死？"

### 3. 杀手测试（kill-tests）+ A/B 分类

对每个想法写出**会让它死的可证伪条件**，并分两类：

- **A 类·当场可查**：靠代码 / 文档 / 公开资料现在就能定论。**必须当场读真实材料解决，禁止写成"待测"推给未来。**
- **B 类·须实测**：需实验 / 上线才有结果。配**门槛值**与验证方式，转成"验证计划"。

（本议题的 A/B 具体例子见议题文件。）

### 4. 伪需求 / 伪共识识别

- 对象嘴上要 ≠ 会用 ≠ 会付费 / 会传播。区分"表面诉求"与"底层 job"。
- 警惕"自我认同"：方案若来自同体系，更要往死里挑；"达成共识"若靠互相礼貌，判未达成。

### 5. 基准率与外部对照

用同类案例的真实基准（留存 / 转化 / 复制速度等）校准乐观估计，别拿孤例当规律。

### 6. 联网核验（按需）

对事实性主张、基准率、竞品客观事实、合规 / 政策规定**主动联网核验**，别只信对方自述。可联网查到的公开事实属 **A 类**（当场可查），须**附来源链接 + 日期**、优先权威来源；不可用网络替代对内部证据源（代码 / docs）的阅读。

## 共识门槛与枪毙权（你是闸门）

见 `.cursor/rules/70-debate-protocol.mdc` § 共识门槛。要点：

- 收敛前议题文件的全部议程维度必须处理过，漏维即不达成——主动点名被漏的。
- A 类必须当场用真实证据解决；B 类转验证计划即可，不作前置闸门。
- 共识 = 不确定性下的决策 + 验证计划，不是"已证明成功"。
- **枪毙权只针对"想法 / 方案本身不成立"**，不能枪毙"作决定"这个动作。
- 无理由点头 = 失职；宁可枪毙。
