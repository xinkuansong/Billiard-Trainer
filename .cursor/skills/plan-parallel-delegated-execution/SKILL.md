# 方案并行委派执行（波次 + worktree 隔离 + 主控串行合并）

前置：先掌握 `plan-delegated-execution`（串行版）的主循环、委派提示词模板、返工熔断与诚实验收——本技能只定义**并行差异部分**，其余全部沿用串行版。

## 何时并行、何时不并行

| 批次性质 | 执行方式 |
|---|---|
| **横切批**：产出被其它批引用的真源（组件/常量/token），或改动面跨多个页面域 | 串行（走 `plan-delegated-execution`），且必须先于依赖它的页面批 |
| **页面域批**：条目集中在互不相交的文件集合 | 并行（本技能），同波 ≤3 个 |
| **收口批**：又是横切、但依赖页面批先落定 | 串行，放最后一波 |

## 波次规划（动手前一次性做完）

1. 重读真源方案，按上表给每个批次定性。
2. **文件集合实证**：对同波候选批次，用 `rg`/`Glob` 列出各批实际要动的文件集合，两两求交。**有交集就拆波，不凭批次描述认定不相交**。共享构建配置文件（如 `project.pbxproj`）的交集可接受（合并时主控解），业务代码交集不可接受。
3. 输出波次表（波 → 批次 → 执行方式 → 推荐模型）给用户过目，模型确认后**写入真源方案文件的批次表**（后续会话据此视为已指定，不再重复询问），再开工。

## 波内并行执行

1. **派发**：同波每个批次用 `best-of-n-runner` 子智能体（独立 worktree + 独立分支）派发，提示词沿用串行版模板，额外加两条：
   - 「你在独立 worktree 中工作，构建/测试/截图全部在自己的树内完成」；
   - 「禁止改动本批范围外的文件；共享真源（组件/常量）只允许引用，不允许修改」。
2. **等待（成本纪律）**：并行子智能体全部返回后再进入合并；单个失败不阻塞其余批次的合并。整波派发完后主控**直接结束回合**，靠完成通知回来（只付一次缓存未命中）；禁止等待期间反复轮询——一个波动辄数十分钟，远超缓存 TTL，每次轮询都是按主控全量上下文计费的一次未命中。
3. **串行合并（主控亲自做）**：按风险从低到高逐个合并回主分支；**每合并一个批次，立即在主树重跑 build（及该批验收项），绿了才合下一个**。冲突由主控解：构建配置类冲突直接手解；业务代码冲突说明波次规划失误——停下，把后合并的批次退回子智能体基于最新主分支重做（记 FAILURE-LOG）。
4. **验收与返工**：沿用串行版第 4–5 步（主控独立验收、resume 返工、3 轮熔断）。返工在该批原 worktree 进行，重走合并。
5. **波收尾**：整波全部合并且主树全绿后，回写真源批次状态与进度台账，输出检查点。**一波一会话**：收尾后建议用户开新会话跑下一波（状态全在真源与台账中，新会话冷启动成本远低于长会话后期的缓存未命中代价；成本模型见串行版 § 会话与上下文管理）。

## 模型路由（主控给推荐，最终按 `01-subagent-model-selection` 规则与用户确认）

技能不写死模型；默认 `cursor-grok-4.5-high-fast`，已写入真源批次表的模型视为已指定。主控在波次表中按以下准则给出**推荐路由**供用户确认：

- **横切批 / 收口批**：判断密集、一处错全库错——建议强推理模型（如 `claude-opus-4-8-thinking-medium`）或主控亲自做（此时豁免串行版「主控不代写」红线，但验收标准不降）。
- **页面域批**：条目明确、机械性强——可用快速模型（如默认的 `cursor-grok-4.5-high-fast`），配套两条纪律：提示词把红线/禁令**前置**（快速模型易掉尾部约束）；主控验收从「抽查」升为「逐文件读 diff」。
- 用户显式指定模型时以用户为准，但主控应说明风险权衡。

## 验收分层

- **每批**：子智能体自证（build/test 完整日志、xcresult、改前/改后截图**全部落盘**并在汇报中列产物清单——路径 + 证明哪条标准）→ 主控独立复核（读 diff 查范围蔓延与禁令、**亲自打开落盘的日志/xcresult/截图核验**：结果行与失败计数、suite 覆盖面是否对准完成标准、断言有无删改；子智能体的「通过」判断只作参考，判据只认原始产物）。**默认不重跑测试**——省的是重复执行，不省的是证据审读；复跑触发条件见串行版主循环第 4 步，且只跑疑点对应的最小测试面。
- **每波**：合并后主树全量 build（主控必跑，归因合并本身）；单测/UI 测以各批子智能体在 worktree 内落盘的原始产物为准，仅当合并产生冲突解、或跨批共享真源被多批触碰时，主控在主树补跑受影响测试面。
- **全程收官**：可与用户约定「最终统一人工验收」——主控汇总一份人工冒烟清单（按波列交互点），用户一次性在模拟器/真机过完；发现的问题按批归属 resume 返工。

## 红线（在串行版红线之上追加）

- **同波并行度 ≤3**：构建资源与主控验收带宽的上限，不为赶进度加宽。
- **业务代码冲突零容忍**：出现即视为波次规划失误，退回重做并记录，禁止主控「顺手改一改」把两份实现缝合。
- **合并顺序即验收顺序**：禁止一次性合并整波再统一 build——必须逐批合并逐批验证，保证失败可归因。
- **worktree 清理**：每波收尾删除已合并的 worktree 与分支，防止陈旧树被误用。
