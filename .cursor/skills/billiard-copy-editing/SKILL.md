# 台球学员文案编辑

目标是让文字像一位懂球、会教的教练：术语准确，动作明确，读完能执行；不把理论名词的数量当作专业度。

## 核心工作流

修改 Drill 学员文案时，必须执行 [训练意图 × 逐杆图片 × 事实流程](references/intent-image-workflow.md)。先运行上下文清单脚本，再逐张查看它列出的开局图和逐杆图：

```bash
python3 .cursor/skills/billiard-copy-editing/scripts/collect_drill_copy_context.py drill_c001
```

脚本只负责找齐证据，不等于完成读图。只列文件、没实际查看图片，不得开始改写。

训练意图、图片和序列是三条并行约束：训练意图回答“为什么练”，图片回答“用户已经看到了什么、画面是否健康”，序列/digest 回答“实际发生了什么”。三者不可互相替代；发生冲突时停止写作并报告。

## 真源优先级

低层资料不得覆盖高层事实，也不得为了文案顺畅补造缺失信息。

1. **实际事实**：代码、`content/position_play/sequences/*.json`、`tutorial_digest.py` 输出、当前 UI 行为。
2. **几何与物理**：`.kiro/steering/table-geometry.md`、`.cursor/rules/45-aiming-principles.mdc`、相关代码与实测理论文档。
3. **训练与课程语义**：用户在训练意图表写下的原文、完善列、概念所有权表、课程地图。用户原文不可改写；完善列只能辅助理解，不得覆盖原意。
4. **标准术语**：`voice-billiard-terms/glossary.md`。它只裁定名称，不得改写物理含义。
5. **表达方式**：`docs/research/20260818-v40-精讲内容规范.md`。
6. **界面容量**：目标 View、共享卡片组件与 `swiftui-design-system`。

出现冲突先报告并修正真源，不在冲突上继续批量改文案。

## 每次必读

1. 目标文件、目标字段以及同组相邻文案；不要脱离页面单改一句。
2. `docs/research/20260818-v40-精讲内容规范.md`，重点遵循教练话、诊断句、图文分工和防模板腔。
3. `.cursor/skills/voice-billiard-terms/glossary.md` 中与本次主题相关的词条。
4. 修改任一 Drill 学员字段时，读取 `references/intent-image-workflow.md`，运行上下文清单脚本，并实际查看该 Drill 的全部相关图片。

## 按字段加载

| 修改对象 | 额外读取与动作 |
|---|---|
| `nameZh` | 动作库分类、课程地图、现网相邻课名；名称只标识主训练对象，不塞入全部变量。 |
| `description` | `formation-training-intent` + 对应意图行 + 各球形开局图；写清固定项、变化项、目标与主练，不写剂量或几何明细。 |
| `coachingPoints` | 逐杆图、当前 JSON、序列/digest 可证实的动作与观察信号；每条只承担一个动作或判断，不复述 HUD 和轨迹。 |
| `standardCriteria` | 内容数据契约、真实剂量与可观察结果；写自然语言通过条件，不写泛泛目标。 |
| `tutorial` | 完整执行 `tutorial-authoring`；读取概念所有权表、digest，并逐张查看开局图和每杆图。 |
| Drill 练习卡标题/副标题 | 对应训练意图、卡面/封面、目标详情页和实际卡片组件；检查双列卡宽度、行数与相邻卡平行性。 |
| 功能/理论卡标题/副标题 | 目标页面、卡面/封面、对应功能/理论页和实际卡片组件；不套用 Drill 逐杆流程。 |

以下主题命中时再加载，禁止无差别把所有理论灌入上下文：

- 角度、距离、方位、袋口、路线、落点：`geometry-spatial-reasoning` + `table-geometry.md`，几何事实必须来自计算或 digest。
- 瞄准、挤偏、弧线、投掷、高低杆有效厚度：`45-aiming-principles.mdc`、`docs/research/20260804-瞄准理论总纲.md` 与相关理论页。
- 30°/90°/切线、最少加塞、反向规划、关键球等：只读相关 theorem/module/flow 条目，不全文灌入。
- SwiftUI 文案容量或组件行为变化：`swiftui-design-system` 与 UI 规格；纯 JSON 文案修改不加载整套视觉规范。
- 疑似口述或 ASR 错词：执行 `voice-billiard-terms`；书面文案只使用其 glossary，不套用语音纠错流程。

## 字段职责

- **标题**：这是什么训练。
- **卡片副标题**：用户会学到什么或解决什么问题；不写公式摘要。
- **description**：固定什么、改变什么、主要练什么。
- **coachingPoints**：站到球台边立刻能做的动作或观察。
- **standardCriteria**：打完以后怎样判断通过。
- **tutorial**：为什么这样打、错在哪里、下一步怎样调整。

同一事实只在最合适的字段出现一次。标题和副标题不复述；description 不承担精讲；精讲不抄图和参数栏。

## 第一性原理压缩门禁

证据不是要全部写进正文，而是用来找出这项训练不可替代的价值。动笔前先写一句内部“最小训练命题”：**改变了什么、隔离或检验什么能力、学员要得到什么可观察结果**。这句话不直接交付给学员，但后续所有字段都必须服务于它。

- **相邻项互换测试**：遮住标题后，如果这段话也能放到同组另一项训练里，说明主练对象还不够具体，必须重写。
- **注意力预算**：`description` 只保留“任务 + 主练”；剂量、杆法和次要限制只有在区分训练时才进入。`coachingPoints` 每条只给一个当下动作或一个失误判断。`standardCriteria` 只写结果门槛，不重复动作说明。
- **证据做减法**：图片已经清楚呈现的球位、路线和 HUD，不再用正文复述；序列和理论用于约束断言，不自动获得正文席位。
- **隔离机制优先**：若练习通过锁定变量或拿掉某个变量来单独检验能力，应把“为什么这样设计”说清，但不要展开成理论课。
- **口头教练测试**：把文案读出声。若学员听完仍不知道下一球先做什么，或句子像规格说明、验收记录，应继续删改。

### 自然度去 AI 腔门禁

- 学员正文优先用球桌边会说的动词：站线、找点、打厚、打薄、擦袋口、贴库、送杆。能用这些词说清时，不换成“变量、容差、机制、基准、结果主要反映”等分析词。
- 默认删除“本组用于……”“这样设计是为了……”“最后一杆用来检验……”这类替课程设计辩解的句子。只有这段原因会改变学员下一杆的做法时，才保留一句。
- 先写动作，再写失误信号和修正；不要先铺背景、理论和证据。例：把“结果主要反映瞄准点和出杆方向”改成“打偏了先改厚薄，别拿力气补”。
- 朗读时一口气说不完就拆句；连续两句都以“这组/每次/用来”开头，或同一意思换词重复，继续压缩。
- 自然不等于口水话。不要添加“其实、简单来说、你只需要”等填充词，也不要为了亲切使用不准确的俚语。

专业不等于信息密度高。这里的专业度来自因果准确、动作可执行、反馈可观察，以及与相邻训练有清楚差别。

## 专业表达

- 第一次出现专业概念时，可用“术语 + 一句台上含义”；后文只用术语。例如：“挤偏，也就是母球出发时偏向塞的反侧”。
- 优先写动作、结果、诊断：`看到 X，通常说明偏 Y，下一球往 Z 调`。
- 一句话只承载一个动作或判断。能删去而不损失训练价值的理论名词就删。
- 禁止教材腔、验收腔、内部工作流词和机械复读；连看三条同组文案，句式同构即返工。
- 台面距离、力度、杆法与厚薄话术遵循 `tutorial-authoring` 和 v40 规范；不要自造“半档力度”等计量。

## 当前标准术语

- `cut angle`：**切球角**；短文可用“切角”，不用“切入角”。
- `squirt`：**挤偏**，指母球出发方向受侧塞影响而偏向塞的反侧。
- `swerve`：**弧线**，指母球行进中的弯曲。
- `throw`：**投掷**，指球球碰撞时接触摩擦使目标球偏离理想进球线。
- **让点**：为抵消挤偏等偏差而主动调整瞄准点；不是挤偏或投掷的同义词。

## 修改与验收

1. 先列出目标字段、学员任务和能引用的事实；事实不足就保留原文并上报。
2. Drill 文案先为每条生成证据卡和一句最小训练命题；意图、图片、序列任一缺失或冲突时按流程降级/停止，不凭语感补齐。
3. 先改一个同质小组，执行相邻项互换测试、口头教练测试和自然度去 AI 腔门禁，确认信息层级与语感，再扩大范围。
4. 运行 `make -f scripts/Makefile verify-copy`；改精讲再运行其专用门禁。
5. 卡片文案改动须检查实际 View 或 Preview；JSON 文案至少验证可解码。
6. 最后报告修改范围、意图覆盖、读图结果、事实依据、自动检查结果及仍需 H-11 人工判断的内容。
