# 训练意图 × 逐杆图片 × 事实的文案流程

本流程用于修改动作库 Drill 的 `nameZh`、`description`、`coachingPoints`、`standardCriteria`、`tutorial`，以及直接指向 Drill 的练习卡标题/副标题。功能卡、理论卡只执行入口技能中的页面流程，不套逐杆步骤。

## 三条证据各管一件事

| 证据 | 回答 | 不能替代 |
|---|---|---|
| 用户训练意图 | 为什么这样摆、主要练什么、各球形差在哪 | 不能证明实际球路或参数 |
| 开局图与逐杆图 | 用户看到了什么、图是否健康、文字边界在哪里 | 不能用目测得出角度、距离、厚薄或袋口结论 |
| 序列 + digest + 当前 JSON | 实际怎么打、参数/袋口/落点/剂量是什么 | 不能凭数据代写用户的训练目的 |

基本原则：**训练意图定方向，图片定图文分工，事实定技术断言。**

## 第 0 步：确定修改对象

记录：

- Drill ID、球形数、目标字段。
- 文案出现在哪个页面、允许几行、相邻条目是谁。
- 本次是课级概括、球形级说明，还是逐杆说明。

禁止一边浏览全库一边随手改句子。先确定一个同质小组，再逐条完成闭环。

## 第 1 步：生成上下文清单

在仓库根目录运行：

```bash
python3 .cursor/skills/billiard-copy-editing/scripts/collect_drill_copy_context.py drill_c001
```

清单必须列出：

- 当前学员字段与剂量。
- `docs/research/20260819-动作库球形训练意图.md` 中该课的全部球形行。
- profile 和序列文件。
- JSON 实际引用的开局图、逐杆图，以及 PNG 母版/HEIC 发布图是否存在。

清单只完成“找齐”，不代表图片已看过。

## 第 2 步：读训练意图

逐球形读取两列：

1. **训练意图**：用户原文，语义优先且禁止修改。
2. **完善**：AI 的五槽收口；非空时可辅助拆解，但不得覆盖用户原意。

为每个球形提取五槽：

- 固定什么。
- 改变什么。
- 打进哪类袋或把母球送到哪类区域。
- 主要练哪 1–2 项可验证能力。
- 相对同课其他球形，本形新增了什么难点。

若原文为空且完善列为“跳过（待素材）”，标记为**意图降级**：只能使用已有元数据/profile 可证实的内容，不得编造设计者意图。

## 第 3 步：逐张看图

按球形依次查看：

1. `initial` 开局图。
2. 每一张被 tutorial 引用的 `sNN` 逐杆图。
3. 若正文涉及完整路线、吃库数、弧线或动态过程，再看对应 `sNN_still.png` / `sNN.mp4` 出片。

优先查看 `QiuJi/Resources/DrillTutorials/<image>.png` 母版，同时确认用户实际加载的 `QiuJi/Resources/TutorialFigures/<image>.heic` 发布图存在。不得只看文件名或缩略图列表。

### 每张图记录四项

- **对象**：球数、目标球、母球、球杆、轨迹线、HUD 是否存在。
- **一致性**：开局图与第一杆、前一杆落点与后一杆起点是否连贯。
- **意图可见性**：训练意图所说的固定项/变化项，在各球形和逐杆图中是否看得出来。
- **文字边界**：哪些信息图上一眼可见，正文不再重复；哪些“为什么、怎么判断、错了怎么调”必须由文字补充。

### 读图边界

图片用于**证伪和划分信息边界**，不用于几何取值。禁止从图上目测并写入：

- 具体角度、距离、球厚。
- 绝对方位或袋口名称。
- 塞量、力度或打点数值。
- “一定会”发生的物理结果。

这些内容必须回到 digest、序列、参数或几何真源。

## 第 4 步：取得事实清单

对清单列出的每条序列运行 `scripts/tutorial_digest.py`。使用第一杆 `before` 与开局图交叉验证开局母球，不直接采信可能为占位值的序列 `initial`。

额外核对：

- `sets` 与 `standardCriteria` 的剂量、次数、母球留台要求。
- profile 的固定变量、目标变量和球形差异。
- 概念所有权：本课是引入、后续还是合成。
- 相关理论条目和标准术语；正文只写教练话，不写编号或公式。

## 第 5 步：填写证据卡

动笔前为每个 Drill 写一张内部证据卡：

```text
Drill：
球形：
用户意图：
固定 / 改变：
目标 / 主练：
最小训练命题：
图片已经表达：
文字必须补充：
事实依据：
冲突或缺口：
```

证据卡不写入学员字段，但交付时要概括回显。

## 第 6 步：冲突红灯

任一命中即停止相关字段写作并报告：

- 训练意图所说的球形、目标袋、杆法或主练对象与图片/序列相反。
- 开局图与第一杆不连续，或逐杆图片相互错位。
- JSON 引用了不存在的图片，或发布图与母版不是同一内容。
- digest 出现母球落袋、目标球未进等示范缺陷，而文案要把它写成标准答案。
- 关键几何/轨迹结论只有目测，没有事实来源。

缺训练意图时可按“意图降级”继续保守编辑；缺对应图片时，涉及球形与逐杆表现的字段不得标为完成。不要用现有旧文案反过来证明自己。

## 第 7 步：提炼最小训练命题

先不写正式文案，用一句内部工作句回答：

```text
改变：……；隔离或检验：……；学员结果：……。
```

只允许一个主训练命题。剂量、图中球位、全部技术参数和次要收益先留在证据卡，不默认进入这句话。

然后做两次反证：

1. **相邻项互换**：遮住标题后，这句话能否原样放到同组另一项训练？能就说明差异没有提炼出来。
2. **删词保真**：删掉某个术语或事实，是否仍不影响学员理解这项训练为什么存在？不影响就删。

只有最小训练命题通过后，才按字段分配信息。

## 第 8 步：按字段写

| 字段 | 主要来源 | 写什么 |
|---|---|---|
| `nameZh` | 用户意图 + 课程地图 | 主训练对象；不塞全部变量 |
| Drill 卡片副标题 | 用户意图 + 详情页 + 卡面 | 学员会练到什么；一眼能懂，不复述标题 |
| `description` | 五槽意图 + 开局图 + 球形差异 | 固定项、变化项、目标、主练；不写剂量 |
| `coachingPoints` | 逐杆图边界 + digest + 理论 | 台边能做的动作、观察信号和下一球调整；不抄 HUD/轨迹 |
| `standardCriteria` | `sets` + 真实结果约束 | 可观察的通过条件；不写空泛能力目标 |
| `tutorial` | 完整 tutorial-authoring 流程 | 为什么练、为什么这样打、错了如何判断和调整 |

每条训练意图至少在一个合适字段落地，但同一信息不要在标题、副标题、简介和要点里反复出现。

## 第 9 步：四向验收

### 意图覆盖

- 用户原意有没有被遗漏、弱化或擅自改成另一种训练。
- 多球形的差异是否分别落地，段落能否互换；能互换就是没写出差异。

### 图文分工

- 每张相关图片都实际看过。
- 文字没有重复球位、轨迹和 HUD；新增的是原因、判据和调整方法。
- 图片异常已列出，没有靠文字遮盖。

### 事实追踪

- 每个角度、距离、袋口、杆法、力度和物理方向都能指回事实源。
- `standardCriteria` 没有改变原剂量和过关数字。
- 卡片在实际 View/Preview 中检查行数与截断。

### 信息压缩

- `description` 是否只承担任务和主练，没有把剂量、步骤和次要限制一起塞入。
- `coachingPoints` 是否每条只包含一个动作或判断，学员能据此打下一球。
- 遮住标题后，文案是否仍能与相邻训练区分；不能区分即返工。
- 朗读时是否像教练在台边说话，而不是规格说明或验收记录。

最后运行 `make -f scripts/Makefile verify-copy`；改 Drill JSON 时验证可解码，改 tutorial 时再跑完整精讲门禁。每个同质小组进入 H-11 人工复核，通过后再扩下一组。
