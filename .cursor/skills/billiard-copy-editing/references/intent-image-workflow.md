适用于主控、作者与审稿者。路径未特别注明时相对**主控声明的事实源仓库根**，不能自动相对作者工作树解析。教学要求由[统一规范](../../../../docs/research/20261015-动作库内容重写统一规范.md)维护；本文件负责把要求加载、执行和核验，不另设教学模板。

## 2. 每个动作的专属材料包

先运行：


该命令只寻找材料，不完成阅读。主控把下面的路径全部解析为实际绝对路径，传给作者和审稿者：

1. 当前`QiuJi/Resources/Drills/<category>/<id>.json`完整内容、当前候选及原文备份。区分事实源与候选写回路径，不能把worktree旧副本当最新生产输入。
2. `docs/research/20260819-动作库球形训练意图.md`中该动作**所有球形的用户原文**和完善列。二者分开；后者不能覆盖前者。读`.cursor/skills/formation-training-intent/SKILL.md`以理解两列职责，不因此获得改表授权。
3. `docs/research/20260818-v40-概念所有权表.md`中该动作、相关引入课和相邻课条目；相关相邻课当前内容与意图。历史“轻改即可”等建议不能覆盖本轮重写要求。

无序列规则课使用规则实现和用户训练意图，不补造序列、参数或角度。profile存在则核其适用性；profile缺失但已有用户意图，不得宣布“无意图”。

## 3. 怎样才算进入上下文

- 将`已定位`、`已读取`、`已理解并落实`分开。读取记录包括绝对路径、版本/哈希、实际读取章节或行段、用途、剩余缺口；图片记录实际查看对象与待核疑点。
- `cat`命令成功但返回被截断，不等于全文读取。分段补齐缺口；不能仅统计行数或查看目录后勾选。不要求把无关大文件全文灌入上下文。
- 主控在派发中指定规范源根和事实源根。独立worktree只作为候选输出位置，规范和事实不能静默落回该树旧版本。
- 文件哈希相同但正文只剩“已读”摘要时，不能认为其内容仍在可用上下文。压缩/换会话/换审稿角色后，重读共同规范、流程、任务当前状态及将使用的原始依据；稳定且仍完整可见的资料无需机械重复读取。
- 用户追加要求后主控先更新约定与派发；作者/审稿补读变更及受影响上下文，受影响判断和旧审稿标为待复核。不是所有资料无条件重读，也不能继续沿用旧结论。
- 读取记录不等于理解证明。下面的判断审核才决定能否动笔。

## 4. 理解审核：先判断，后写作

每个球形形成一份内部证据卡，不写成学员正文：

| 项目 | 必须回答 |
|---|---|
| 训练目的 | 用户原意是什么，与同课其他球形、相邻动作有什么区别？ |
| 两种分类 | 录制是独立重摆还是连续？教学是并列、递进、对照、衔接或其组合？ |
| 固定/变化 | 哪些条件真的固定？多个参数同时变化不能写成单变量因果；有顺序才讨论递进。 |
| 球的角色 | 当前目标、下一目标、后续衔接、障碍还是纯标记？每种角色依据是什么？ |
| 逐杆方案 | 本杆球/袋、杆法/力度、实际路线/停位；为什么该方案服务于本形目标？ |
| 走位目的 | 下一球/预期袋、所需位置和角度；进一步衔接是否影响选择？不能因只录首杆而省略。 |
| 难度依据 | 角度、球距、入袋方向、遮挡、靠库及后续走位，哪些真正影响这杆判断？ |
| 证据层次 | 用户明确意图、已录/实测事实、几何支持的候选、尚未验证的原因或后续打法分别列出。 |
| 正文取舍 | 学员必须知道什么，图/参数已经说明什么，analysis有哪些只作内部核对？ |

下一颗袋口不在shot字段里时，先查意图与after，再计算候选；不得把下一条独立step当作接续，也不能直接将“最小角/最近袋”认作预期袋。明确结论依据和剩余不确定性，缺口局部处理，继续不依赖它的已授权工作。

作者和主控先分别形成教学判断并比对。审稿者从原始依据独立复核；主控派发中的无来源结论只能当待核假设。出现“独立所以没有下一颗”“球图正确所以意图正确”等推断即退回判断阶段，不靠润色掩盖。

## 5. 写作与自查

理解审核通过后，按统一规范直接编辑获授权候选；不新增训练数量、成功率或容限，不改受保护数据。结构保留当前消费者要求的球形、杆序、图片与params关联；语言不强制三标签或每杆等长。

逐杆先教具体方案和理由，再按需要补错误判断。去掉无用重复，保留理解走位所必要的路线说明。理论因果要有适用条件，不从一次示范推出唯一原因，不从打点/速度反推出未记录的人体出杆动作。

样稿修改后同时交出：候选diff/SHA、读取记录、证据卡、各要求在正文的具体落点、未解决问题和技术校验日志。不能只回“所有检查通过”。

## 6. 分层验收与退回条件

| 层 | 审什么 | 不通过时 |
|---|---|---|
| A 资料 | 来源/版本/范围、实际读图、缺失和截断 | 补读，相关段不进入写作 |
| B 教学判断 | 用户目的、逐杆用途、下一球与袋、并列/递进/对照、证据层次 | 回判断阶段；不要只换词 |
| C 技术事实 | 参数、有效瞄准角、球号/袋口、路线和因果限制 | 回原始资料或必要计算，禁止改序列凑文字 |
| D 教学表达 | 自然具体、主次、术语、剂量、analysis克制；相邻项互换和朗读 | 作者逐句修订，不套统一句式 |
| E 结构/保护 | JSON、字段白名单、ID/step/image/params、保护对象、对应门禁 | 修候选或工具缺陷，不放宽检查 |
| F 用户审阅 | 三稿整体语感、训练理解与关键教学判断 | 按用户反馈修订；不自动扩库/集成 |

作者自查、交叉审稿、主控独立验收均覆盖本批完整字段/球形/杆；不能以通用QA抽样取代。参数检查和语义判断分别报告。对应层可使用同一证据，但不能用一个通过结论覆盖其他层。

审查绑定最终候选SHA和源版本；后续改动重验受影响项目。机器扫描只找疑点，主控亲读证据和全文；不能把检查器复述了错误前提当第二份独立证明。界面/构建/安装只在对应授权阶段执行，文档整理不声称已经验证App。

## 7. 派发必须自包含

派发消息至少包含以下实际内容，而不是“按之前的要求做”：

- 本轮动作、球形、字段、输出路径、保护对象、当前阶段与禁止动作。
- 当前用户关键要求和上轮失败点的原意；共同规范的绝对路径、版本与SHA。
- 事实源根、候选工作树；共同必读清单及专属材料的实际路径、应读章节/图集。
- 需要启用的技能与角色文件；已确认模型（本轮全部继承当前模型）。
- 先读取与形成判断、再写作的顺序；验证层次、交付位置、缺口处理。
- 哪些是已证事实、哪些只是主控待核假设；不得下发预制教学答案要求照写。

作者先回报实际读取范围和缺口，再完成理解核验。审稿派发不预设“本稿已正确”，也不省略原始材料。

## 8. 续接与当前状态

交接保留版本、输入/候选SHA、已验/未验层、用户反馈与下一步；重启时读取当前真源，不复述旧“已读”代替内容。文件清单和SHA用于发现漂移，不是自动将文件注入模型上下文的机制。

2026-10-16用户已认可R5三稿标准，授权按此修改全部动作和球形。当前按任务方案推进全库批次，作者写隔离候选，交叉审及主控全文验收后串行集成；录制、物理、瞄准、图片与配置受保护。原样稿阶段限制不再阻止此次全库授权，新稿的用户复阅状态仍独立记录。
