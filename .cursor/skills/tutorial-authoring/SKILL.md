# Tutorial Authoring Skill — 序列 → 图文精讲

## 你要做的事（一句话）

读一条走位序列 JSON，跑事实提取脚本，把脚本输出的事实**组织成中文教练话**，填进固定模板，写回 drill JSON 的 `tutorial` 字段。你只做语言组织，**不做任何几何计算**。

## 路径地图（先记住，最容易搞混的地方）

以下均为**仓库根目录**（`/Users/song/projects/13.billiard_trainer/`）下的相对路径。三个长得像的目录职责完全不同，⛔ 禁止混用：

| 路径 | 是什么 | 你怎么用 |
|------|--------|----------|
| `content/position_play/sequences/*.json` | **走位序列 JSON（真相源，编排台录制）**。文件名以 drill id 开头，如 `drill_c042__…-初级蛇彩走位 · 球形1-5杆.json` | **唯一输入**。喂给 digest 脚本 |
| `QiuJi/Resources/Drills/<category>/drill_xxx.json` | **drill 内容 JSON（App Bundle）** | **唯一写回目标**（只改其中 `tutorial` 字段） |
| `QiuJi/Resources/DrillTutorials/*.png` | 精讲配图（出片产物落位后） | 只确认存在 + 引用文件名，不生成 |
| `QiuJi/Resources/Videos/<drillId>/*.mp4` | 详情页示范视频 | 不归你管，缺了列待办 |
| `build/position_play_export/seq_<id8>/` | 出片管线原始产物（未落位） | 只在缺图时告知用户来源；核对轨迹表述时看这里的 `sNN_still.png`/`sNN.mp4` |
| `build/position_play_sequences/` | 出片收件箱（临时） | ⛔ 不读不写 |

⛔ **序列 JSON 只在 `content/position_play/sequences/`，不在任何 `Resources/` 目录下**。`QiuJi/Resources/` 下没有序列文件；如果在那里找序列，说明你走错了。找不到序列文件时用：

```bash
ls content/position_play/sequences/ | grep <drillId>
```

## 总流程（严格按顺序，禁止跳步）

```
第1步  跑脚本拿事实清单（唯一几何事实来源）
第2步  检查事实清单里的红灯（有红灯 → 停下报告，不写精讲）
第3步  确认配图/视频资产存在
第4步  按模板逐节填写（本文件 §模板 + §写作公式）
第5步  跑自查清单（本文件 §自查），逐条回显结果
第6步  写回 drill JSON（QiuJi/Resources/Drills/<category>/drill_xxx.json，只改 tutorial 字段），验证 JSON 可解码
```

## 第1步：跑脚本

在仓库根目录执行（序列文件在 `content/position_play/sequences/`，见§路径地图；文件名含空格和中点号，**必须加引号**）：

```bash
cd /Users/song/projects/13.billiard_trainer
ls content/position_play/sequences/ | grep <drillId>   # 先列出该 drill 的序列（多球形会有多条）
python3 scripts/tutorial_digest.py "content/position_play/sequences/<完整文件名>.json"
```

输出是「事实清单」：开局布局、逐杆 params/打点读数/力度/相对方位/切球角/落点/与下一杆的衔接/理论参考、终局。

⛔ **铁律：精讲里所有几何事实（方位、距离、角度、落点区域）只准抄事实清单，禁止自己看坐标心算，禁止看渲染图目测。** 这是本项目 `geometry-spatial-reasoning` 技能的核心铁律在内容写作上的落地。清单里没有的几何事实 = 不准写。

清单**不含轨迹细节**（吃几库、路径形状、是否走弧线）。要写「一库走位」「贴库滚动」这类表述，必须先看对应出片（`build/position_play_export/seq_<id8>/sNN.mp4` 或 `sNN_still.png` 预告线）确认，看不到就不写。

## 第2步：红灯检查（任一命中 → 停止写作，如实报告）

| 红灯 | 处理 |
|------|------|
| 清单出现「含母球 scratch ⚠️」 | 序列本身有缺陷（示范杆母球进袋），报告用户重录，不写精讲 |
| 某杆目标球未进袋（无「本杆进袋」行且非自由球） | 同上，报告用户 |
| 序列文件不存在 / 解码失败 | 报告，不要试图手动解析 JSON |
| 用户要求「从 drill 的 shotIntent 反推序列再写精讲」 | 拒绝并说明：红线规定示范击球以编排台人工录制为准（2026-06-13 用户拍板），存量 shotIntent 精度不可靠 |

## 第3步：资产确认

精讲配图约定（真源：content-engineering SKILL §媒体配套）：

| section | image 字段值 | 文件应在 |
|---------|--------------|----------|
| 开局与击球顺序 | `<drillId>_initial` | `QiuJi/Resources/DrillTutorials/<drillId>_initial.png` |
| 第N杆 | `<drillId>_sNN`（NN 两位数：s01, s02…） | `QiuJi/Resources/DrillTutorials/<drillId>_sNN.png` |

多球形 drill（一个 drill 多条序列）图名带球形序号，以目录中实际文件为准。用 `ls` 确认存在；**缺图不虚构文件名**——在交付说明中列出缺哪些图、对应出片产物路径（`build/position_play_export/seq_<id8>/initial.png`、`sNN_still.png`），提醒用户先跑 `make position-export` 落位。图缺但事实清单齐全时，可以先写文字、image 字段留待补图（在交付说明中明确标注）。

## 模板：应用课 Section 骨架（固定顺序，不增不减不换名）

真源：ADR-P11-14 / content-engineering SKILL；样板：`QiuJi/Resources/Drills/positioning/drill_c042.json`（写之前先读一遍对齐语感）。

| # | title（一字不差） | 用什么容器 | 配图 |
|---|------------------|-----------|------|
| 1 | `技术原理` | `content`（1–2 段） | 无 |
| 2 | `开局与击球顺序` | `content` | `<id>_initial` + caption |
| 3..N | `第N杆：X号球 · 袋口`（袋口用中文名：左上袋/右上袋/左下袋/右下袋/上中袋/下中袋） | `items` 3条 + `params`，`content` 填 `""` | `<id>_sNN` + caption |
| N+1 | `常见错误与纠正` | `items`（label=错误名，2–4条） | 可选 |
| N+2 | `进阶练习` | `content`（降阶 + 升阶各至少一个方向） | 无 |

- 数字标题用中文：第一杆、第二杆…（对齐 drill_c042 样板）。
- `content` 支持 `\n\n` 分段和 `**加粗**`；每张图配一句话 `caption`。
- `params` = `{"spinX": …, "spinY": …, "velocity": …}`，**从事实清单「params（照抄进 JSON）」行原样抄**，不四舍五入不改写。
- 多球形 drill：`tutorial.formations: [{id:"f1", title:"球形 A：…", sections:[…]}]`，每球形一套完整骨架；单球形用 `tutorial.sections` 平铺。二选一，不能同时存在。

## 写作公式：逐杆节 items 三条

label 固定为 `为什么` / `怎么打` / `自检`（App 渲染有专属配色，一字不差）。

### `为什么`（填空模板）

> 母球在{目标球}的{方位}，向{袋口}{切角描述}；用{杆法}让母球{接触后的走向}，停到{落点区域}——{这为下一杆创造了什么 / 收尾杆则写“干净完成”}。

- {方位}{切角描述}{落点区域} 抄事实清单；「为下一杆创造什么」抄清单的【为下一杆创造的局面】【为下一杆留出的切球角】两行。
- 非最后一杆**必须**写出下一杆需要什么（反向规划的落地）；最后一杆写不需要再留位置。

### `怎么打`（要领，不重复数字）

- 打点用身体语言：「中上约一个皮头」「低杆加足」「中心击球」——**禁止**出现 spinX/spinY 数值或百分比读数（params 行已经展示了）。
- 力度用档位语言（轻推/轻/中/中大/大力）+ 节奏描述（「轻推出杆、送透不急收」）。
- 事实清单「理论参考」提示了反直觉物理时（如短距高杆更贴切线），在这条里用教练话点破。

### `自检`（可证伪）

> 母球应停在{参照球/库边}的{方位}约{N颗球}距离，{与下一杆袋口的角度关系}；若停在{错误位置}，说明{力度/打点}偏了。

- 落点全部抄事实清单的 after 落点行和【为下一杆…】行。
- 必须给出至少一个「若…则说明…」的失败征兆。
- 最后一杆的自检写整组完成判据（对齐 drill 的 `standardCriteria`）。

## 理论引用：三层渐进式披露（SOP-A，⛔ 禁教材腔）

事实清单每杆给出「理论参考」（T 编号 + 一句话）。你的职责是把它**翻译成教练话**放进正文：

- ⛔ **正文绝对禁止出现定理编号或术语引用**。禁写：「根据 T03 切线法则」「依据 30° 法则」「切线法则告诉我们」。
- ✅ 把原理说成「就是这样」的常识。对照表：

| 清单里的提示 | 正文教练话写法（示例，可改写） |
|--------------|------------------------------|
| T03 切线法则 | 「母球吃球后总是先沿垂直于两球连线的方向走，之后才被旋转拉弯」 |
| T01 30°法则（自然滚动） | 「中杆滚动球吃半颗球厚度时，母球大致偏开 30° 左右」 |
| T02 90°法则（stun） | 「定杆吃球，母球沿切线直角分开」 |
| 短距高杆贴切线 | 「母球到目标球距离短，高杆来不及转成滚动，分离会比想象中更贴切线——这是正常物理，照参数打即可」 |
| 直线球无切角 | 「直线球没有切角，母球只能沿击球线前后走，走位全靠跟进量/缩杆量」 |
| T05 反向规划 | 「顺序和袋口是一起规划出来的，不是逐杆临时决定」「这一杆的落点是从下一杆倒推出来的」 |
| T06 关键球 | 「这是全局真正的胜负手——它决定收尾那杆好不好打」 |
| T09 最少加塞 | 「能用中杆走到的位置绝不加塞；这里不得不用塞，是因为…（写出具体原因）」 |

- 深挖原文（可选）：`/Users/song/projects/16.billiard_theory/contracts/theorem-tags.json` 的 `statement_one_liner` / `common_errors` 字段；`common_errors` 是「常见错误与纠正」节的优质素材来源（挑与本序列杆法相关的 2–4 条，改写成本局面的说法）。
- `theoremIds`/`moduleIds` 数据字段目前**未进** drill schema，不要往 JSON 里加。

## 「常见错误与纠正」与「进阶练习」

- 常见错误：label 用错误名（如「走成直线球」「力度过大」），text = 现象 + 后果 + 纠正方法。优先从本序列的具体风险出发（哪杆最容易失误、失误后局面如何），再用 theorem-tags 的 `common_errors` 补充通用项。
- 进阶练习：至少一个降阶（简化：减球数/放宽落点）+ 一个升阶（加难：加球/换袋口规划/在编排台自摆对比）方向。

## 自查清单（写完必须逐条回显 ✅/❌，有 ❌ 先修复）

1. section 顺序与命名和骨架表完全一致；逐杆节 `content == ""`。
2. 每杆 `params` 与事实清单原始数值逐字符一致（抄的是原始 spinX/spinY/velocity，不是百分比读数）。
3. 正文中每个几何断言（方位/距离/角度/落点/是否过中线）都能在事实清单中找到对应行——逐杆列出「断言 → 清单行」对照。
4. `怎么打` 条目不含任何 spin 数值/百分比。
5. 非收尾杆的 `为什么` 都写了对下一杆的意义；`自检` 都有失败征兆。
6. 正文无定理编号、无「法则/定理/原理告诉我们」句式。
7. 涉及吃库/路径形状的表述已核对出片（未核对则不出现此类表述）。
8. `image` 字段指向已确认存在的文件（或已在交付说明中列为待补）。
9. 写回后 JSON 语法有效（`python3 -c "import json; json.load(open('<file>'))"`）。
10. 文案与示范一致性复核：把每杆 `为什么/自检` 重读一遍，对照清单确认没有「文案说留角度、数据是直线球」这类矛盾。

## 交付说明格式（最后回复用户时）

- 写了哪个 drill / 哪些球形、各几杆。
- 自查清单 10 条的逐条结果。
- 未验证/待办事项如实列出（缺图、待跑出片、待人工审核 H-11 等）。
- 事实清单中值得注意的点（如某杆理论参考提示了加塞但正文难以自圆其说 → 如实上报，不硬编理由）。
