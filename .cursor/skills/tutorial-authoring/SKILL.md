# 序列与图片 → 精讲

本技能负责有序列精讲的专项步骤。先完整读取[billiard-copy-editing](../billiard-copy-editing/SKILL.md)、其[执行流程](../billiard-copy-editing/references/intent-image-workflow.md)和[统一规范](../../../docs/research/20261015-动作库内容重写统一规范.md)。所有角色执行同一资料与理解审核，不能直接从JSON参数开始写正文。

## 输入与授权

从主控指定事实源根读取当前动作完整JSON、所有对应序列、用户原始意图、全部开局/逐杆图、相关相邻课、理论和调研。先核版本及drill/token/step/image映射，再进入判断。相关路径和读取范围按执行流程解析，不依赖旧工作树或历史文件名示例。

| 资产 | 职责 |
|---|---|
| `content/position_play/sequences/` | 人工录制源序列；当前before/after、方向、shot和analysis |
| `QiuJi/Resources/DrillBoards/` | App消费的序列副本；核同步关系，非文案编辑目标 |
| `QiuJi/Resources/Drills/` | 正式动作内容；只有获授权时才写入 |
| 明确指定的候选路径 | 隔离样稿写回位置；本轮不回填生产 |
| `QiuJi/Resources/DrillTutorials/` | 配图母版；实际逐张查看 |
| `QiuJi/Resources/TutorialFigures/` | 发布图片；核对应版本，不在文案任务重出 |
| 本任务映射确认的出片/回放目录 | 需要时核动态过程；不存在即报告，不猜历史目录 |

本技能通常处理tutorial；完整动作任务可同时授权description、coachingPoints、standardCriteria。以本轮字段白名单为准，不扩改name、sets、计分、序列、图片、animation或shotIntent。

## 1. 取得事实，不让提取器代替判断

运行上下文清单，并对每条关联序列运行：

```bash
python3 scripts/tutorial_digest.py "content/position_play/sequences/<已核实的完整文件名>.json"
```

- digest是读取辅助，不是教学意图真源。核其输出字段实际含义，不照抄旧理论提示、形态分类或角度标签。
- 开局优先核首杆before与开局图，不盲信initial占位值。freeAim或独立序列的顺序/袋口派生提示可能不适用，回查原始数据。
- 展示本杆角度只取有效`analysis.aim.aimAngleDegrees`，显式称瞄准角。缺值不能用旧球心夹角、实际接触切角或0兜底。
- params取对应shot的spinX/spinY/velocity原精度。recordedDirection用于核示范输入，不把出杆方向角与瞄准角混为一谈。
- 几何断言必须有当前契约下的计算证据，禁止脑算和看图目测取值。现有事实包缺项时可按几何技能补只读计算，记录输入、方法和限制，不改录制。
- 轨迹、吃库顺序、球是否进袋须有当前图/事件/必要回放互证，不能只看after推完整过程。analysis只作所需核对，不把指标堆给学员。

## 2. 实际看图，核清训练目的

逐张看全部开局图和逐杆图；既核球、线、HUD与身份，也核用户意图中的固定项、变化项、各球角色和走位用途。文件存在与哈希一致不等于完成看图。

将录制组织（独立重摆/连续接打）和教学关系（并列/递进/对照/衔接）分开。只有连续接打才检查前杆after能否接后杆before；独立首杆仍可为图中下一颗走位。

每杆内部回答：本杆球/袋、适用杆法力度、实际结果、选择理由、下一颗与预期袋口、需要的角度/位置、证据及不确定性。与统一规范§6及流程的理解审核一致。

下一杆未录制时，从意图、当前after与合理候选核后续目标；不使用下一条独立step伪造接续。几何候选不能冒充已验证进球和后续走位，也不能因缺nextPocket字段把目标球降为纯标记。

## 3. 把已理解的方案写成教学

- 先讲当前条件下怎样打、为何这样打及进球/走位目的。排查和调整作为补充，不能取代示范方案。
- 图片已经展示的参数不用反复播报；为理解下一颗所需的母球路线、停位关系和打法理由仍要讲清。
- 并列情况分别解释适用打法；真实单变量才讲递进；多项变化的对照不强归因于一种打点。重点按教学判断安排，不强指定“全组最难/胜负手”。
- 中间杆确无新增教学信息可简写；独立首杆有不同走位任务时不能按“独立”自动留空。篇幅由信息需要决定。
- 保留当前消费者所需的球形、逐杆节、图片和参数关联；自然段或items按当前模型支持使用，不强制“为什么/怎么打/自检”三标签、固定错误条数或升降阶段落。
- 概念首次引入时讲清当前所需机制；后续或综合课补新判断，不机械套五问或重复基础课。不把课程所有权表当当前球路事实。
- 术语、发力与物理状态的区分、analysis克制、训练数量和姿势用语统一执行规范§4–9。不能从杆速推断真人一定用了推/点/打，也不把中杆自动解释成斯登。
- 理论从相关一手资料与实测条件取证，转成自然解释；不把旧示例（如“短距高杆来不及滚动”“碰袋唇就是厚”）当普遍规律。

内部计算使用准确单位；确需学员距离描述时采用易读的约数，≤50公分可取5公分倍数，更远可用约X.X米。不得为凑教学新增精确停点容限。球厚“半颗球”与台面距离不是同一单位。

## 4. 缺口与冲突

源文件/图片缺失、版本不匹配、示范未进目标球或母球落袋、意图与实测冲突时，停止对应确定性表述并记录范围。已授权且不依赖该缺口的工作可继续。不得用改序列、重出图片、降低训练标准或虚构解释消除冲突，也不擅自要求用户重录。

原文可以是待核资产，不能证明自己正确。没有profile但有用户原意时继续依据原意；用户意图缺失时说明缺口，不用旧元数据或模型猜测冒充用户设计目的。

## 5. 验收与交付

按共同流程A–F逐层检查；重点：

- 每球形目的与所有有走位任务的杆均有依据，独立首杆未漏掉下一颗；合理候选与已验证方案分开。
- 正文具体自然，打点/发力/碰球状态/结果不混同；纠错不挤掉主体教学。
- 所有params、有效瞄准角、图片与step对齐；字段白名单及受保护数据不变。
- JSON解码、适用文案/精讲门禁、原文与候选diff均有实际结果。不能以脚本通过替代教学语义验收。
- 交付完整候选、读取范围、逐杆证据与未决项、校验日志、最终SHA；交叉审稿与主控验收覆盖全文。

禁止任何生成或批量回写tutorial正文的脚本。允许脚本提取事实、计算、备份、校验和将已人工编辑的候选呈现为预览；展示转换不是新增教学正文。
