# Geometry & Spatial Reasoning Skill

## 触发场景

涉及以下任一时，先读取并逐条执行本技能（不可跳过）：
- 计算/修改 角度、方向、叉积、反射、投影、最近点、相交判定
- 坐标系之间的转换（归一化 ↔ SceneKit ↔ 物理）
- 球位 / 进球线 / ghost ball / jaw / 袋口 等相对位置推理
- 任何会写出 `atan2`、`sin/cos`、`.x/.y/.z` 取轴、符号判定的代码

## 核心铁律

**禁止用脑内想象直接给出几何结论。凡几何/相对关系，先算或先画，验证通过再下结论。**
违反即按 `00-orchestrator.mdc` 第 3 条「假装完成」处理，记 FL-NNN。

## 强制流程（每次几何任务）

### 1. 钉死坐标契约（动代码前回显）
显式写出并与真源对齐后再写一行代码：
- 在哪套系：归一化 2D / SceneKit 世界系 / 物理系
- 水平面是哪两个轴、哪个轴朝上、各轴正方向、单位
- 真源：`.kiro/steering/table-geometry.md` + `BTPhysicsConstants` + `AngleSceneCalculator`
- **交叉核对**：若文档与代码数值不一致（已知 D-A4/D-B2 双真源，如角袋 X = ±1.312 文档 vs ±1.300 代码、检测半径 42mm 文档 vs 落袋半径 70mm 代码），先停下指出，不在矛盾上继续脑补。

本项目速查（来自 table-geometry.md，以代码为准时须注明）：
- SceneKit：水平面 = **X–Z**，**Y 朝上**；+X=右端；台面中心 (0, 0.80, 0)。
- 归一化（代码真源 `AngleSceneCalculator.sceneToNormalized`，DR-063 实锤）：原点 = SceneKit (−1.270, **−0.635**)；X 右增 [0,1]，Y 增 [0,0.5]。
- `canvasX = (sceneKitX + 1.270)/2.540`，`canvasY = (sceneKitZ + 0.635)/2.540`——**canvasY 增 = Z 增（同向）**。旧文档/旧版本技能写的 `(0.635 − Z)/2.540` 是**错的**（DR-063 纠错），发现残留即改。
- 屏幕系两套（用户可见方位词必须按渲染面选对）：
  - landscape（`applyTopDown2D`）：屏幕右 = +X，屏幕上 = −Z（= canvasY 小）。
  - portrait（`applyTopDown2DRotated`，全部 drill 用户面）：屏幕上 = +X（= canvasX 大），屏幕右 = +Z（= canvasY 大）。
  - ⇒ portrait 屏幕系袋口名：topLeft=左下角袋、topRight=左上角袋、bottomLeft=右下角袋、bottomRight=右上角袋、topCenter=左侧中袋、bottomCenter=右侧中袋。

### 2. 禁止脑算清单（命中任一 → 必须落到数值草稿或图）
- 角度的 `atan2` 参数顺序与象限（SceneKit 水平角恒为 `atan2(z, x)`，勿写成 `atan2(x, z)`）
- 叉积/`orient` 的正负与手性、CW/CCW
- 库边反射法向方向（见真源「法线」列）
- ghost ball：`target − 2R·normalize(pocket − target)`（朝袋反向退 2R，符号别反）
- off-by-2R / off-by-R（ghost 用 2R，接触点用 R）
- 度 ↔ 弧度

### 3. 用一次性数值草稿验证（不靠脑算）
- 写最小可运行片段（Swift REPL 或 Python），代入**手算已知答案**的标准样例，跑出对上了再写进生产。
- 标准样例库（金标准回归）：
  - 45° 切角直球：cue/target/pocket 偏 45°，`cutAngle` 应 ≈ 45。
  - 正对直球：cue、target、pocket 共线，`cutAngle` ≈ 0、ghost 在 target 正后方 2R。
  - 中袋对穿：target (0, ±0.3)、上中袋 (0, +0.688)，进球线应平行 Z 轴。
  - 贴库平行：target 距长边 < R 余量时，进球点沿库平行（不扎库）。

### 4. 可视化义务
- 几何改动须出图自检（复用 `ShotScenarioRenderTests` 的 PNG 出图，或临时画散点）。
- 肉眼核对方向 / 象限后，把判据**量化为断言**（方向误差、是否出界、对称性），别停在「看着对」。

### 5. 不变量优先于事后诊断（最高杠杆，源自 FL-020）
几何/物理结论尽量表达成可随机批量断言的不变量：守恒、不出界、不重叠、对称、确定性。
新增几何逻辑 → 优先进 `PhysicsInvariantTests` / `PhysicsMatrixTests` 而非只 print/出图。

### 6. 诚实交付钩子
- 几何结论若未经数值/图验证，**必须如实标「未验证」**，列出未验证点。
- 翻车后按 `00-orchestrator.mdc` 写 FL-NNN，并把教训回写本技能「经验教训」区——把每次翻车转成硬约束。

## 经验教训

（按 FL-NNN 逐条追加，格式：场景 + 强制检查点）

### ⛔ FL-030 — 教学示意角的「基准」跨页盲借 ⇒ 把特例硬编成通用公式
**场景**：把 A 页的角度/方向函数复用到 B 页配图（本仓：「旋转与加塞」页相对**进球方向 n**
固定 60° 的教学折线，被 T01「30° 法则」页直接当成滚动线用；而 T01 的命题基准是**原瞄准线**）。
表现：拖参数滑杆时该线纹丝不动，且只在某一档（半球 θ=30°）正确——因为 60° = θ + 30° 只在 θ=30 成立。
**强制检查点**：
1. ⛔ 复用任何角度函数前，先写一行「它相对**谁**测量」并与本页命题的基准逐字比对；
   基准不同即**不是同一条线**，必须另立入口，禁止直接调用。
2. ⛔ 角度公式里出现常数（60/90/30…）时，先验它是不变量还是某一档的值：
   用参数扫描（不是单点）确认，扫描断言进测试；单点绿 = 零覆盖。
3. ⛔ 注释/文档承诺「随 X 变化」或「与 X 无关」，必须有对应的扫描断言，否则删掉该承诺。
4. ⛔ 可交互图上的角度读数一律由几何实测格式化（本例 `rollingDeflectionDegrees`），
   禁止写死字符串；写死的标签会在滑杆一动时说谎，并与同页表格互相矛盾。
5. 教学图连线要连到所属实体（瞄准线画 母球→假想球，不要只在假想球附近留一小截）；
   台呢底图上 `opacity < 0.5` + hint 线宽的白线实机近乎不可见，主体线用主线宽。
6. 优先找**权威公式真源**再动手：本例 `Theory/contracts/theorem-tags.json` T01 的
   `key_formula`（`tan δ = sinφcosφ/(sin²φ+2/5)`）与 `alternative_method`（5/7 切线 + 2/7 瞄准线）
   互为独立推导，可直接做对拍单测——比自拟近似值可靠得多。

### ⛔ DR-027 — 球杆遮挡/碰撞：分离闩锁；仰角整杆冻结；遮挡跨最大回杆
**场景**：渲染层球杆抬杆与收杆守卫（`CueStick` / `CueClearance` / `CueStroke`）。
**强制检查点**：
1. **坐标契约**：SceneKit X–Z 水平、Y 上；杆局部 +z = back = −aim；枢轴 = 击球点；仰角 `euler(−elev, yaw, 0)`。手工 `worldPoint` 必须用真实 `SCNNode.convertPosition` 交叉验证。
2. **遮挡 s 区间**必须覆盖 `maxPullBack`（本仓 0.15m ≈ v=2.9m/s），否则「瞄准不穿、回杆穿」。
3. **分离闩锁（禁止时间窗/调 margin 喂绿）**：`tipOffset=R+1mm` 已小于阈值 `R+tipR+margin`，软杆触球后若干帧仍贴杆。每颗球必须**曾经出过阈值**后才成为碰撞候选；探针按球 id 传递。禁止「跳过前 N 帧」或按速度特例。
4. **仰角整杆冻结**：导出跟杆循环用 `elevationOverride`，禁止随球运动重算仰角。
5. **跟杆钳制与导出同源**：`clampedFollowThroughPull` / `firstCollisionTime` 实时与导出器共用。
6. **`.blocked` 合法盘面不可达**（球遮挡峰值≈32°@s=2R；库边≈23°因 dist 地板）——保留为防御分支，禁止为可达而放大仰角。
7. **已知不自洽**：大仰角渲染 ≠ 引擎平杆物理；禁止特例分支「喂绿」。

### ⛔ FL-022 — 安全网边界与合法接触位置零余量重合 ⇒ 浮点竞态
**场景**：数值安全网（硬钳/出界判定）的边界恰好等于物理事件的合法接触位置（如 `safeMaxZ == 库线 − R`），CCD 把球精确演进到接触点时浮点噪声落在边界外，安全网抢在已排定的物理事件前改写状态。表现为**偶发**、同场景微扰即不复现。
**强制检查点**：
1. 设计/审查任何「出界→钳制」逻辑时，先问：合法物理状态能否恰好落在边界上？能 ⇒ 必须留明显大于浮点噪声、明显小于真实越界位移的触发余量。
2. 方向自适应的碰撞解析器（按速度符号翻转接触系）必须配「只推不拉」护栏（v·n < 0 才施加冲量），防止过时事件把退离球反射回障碍物内。
3. 验证修复必须复刻**用户真实调用路径**（含求解器补偿瞄向等中间层）；同参数简化路径不复现 ≠ 修好。把可疑测量归为「误报」前，须逐帧 dump + 同输入手动复算解析器双向确证。

### ⛔ FL-024 — 浮点增量推进的 while 循环必然存在下溢死循环参数组合
**场景**：沿弧长/时间铺设周期性几何（虚线、刻度、网格、采样）时用 `while t < len { step = f(取余/减法); t += step }` 推进。Float32 精度下 `step` 可下溢到小于 `t` 的 ULP ⇒ `t += step` 不变 ⇒ 主线程死循环；触发依赖具体弧长与周期组合，表现为「某个场景必现、其他场景全好」。UI 测试症状：「Timed out while evaluating UI query」+ 页面冻结但 spinner 仍转（CAAnimation 由渲染服务器驱动）。
**强制检查点**：
1. 周期性铺设一律用**整数索引**推导第 k 个 on 段区间 `[k·period, k·period+dash)` 再与目标段求交；禁止浮点相位累积推进。
2. 任何 `t += step` 型循环若 `step` 由减法/取余导出，必须证明 `step` 有正下界，否则改整数计数。
3. 主线程疑似挂死时用 `sample <pid>` 直取调用栈定位，禁止在渲染/状态层猜测。
**场景**：收紧几何/物理判据（如落袋从大捕获圆+速度阈值改为纯「球心入孔圈」）后出现新失败；或自适应子步把球逼近到碰撞前 ~1e-5s 量级时球穿透几何体。源自 ADR-P10-09（QuarticSolver 近双二次塌缩 + 弧 CCD `epsilon=1e-4` 拒真根，被旧大捕获圆掩盖多年）。
**强制检查点**：
1. 收紧宽容判据前，预期它掩盖了存量求解器缺陷；收紧后的新失败**先按被掩盖旧 bug 排查**，禁止直接回退判据或改断言。
2. CCD「拒绝过小碰撞时间」的 epsilon 下限必须远小于自适应子步的最小剩余时间（本仓统一 1e-6）；防重复检出靠逼近方向检查（v·n），不靠放大时间下限。
3. 解析求根器（Ferrari 等）在退化邻域（近双二次、大项浮点抵消）会漏根，必须有退化形式播种 + Newton 抛光兜底，并与外部权威求根器全范围比对。
4. 判据变更后的测试失败必须三分归因：被掩盖旧 bug（修引擎）/ 合法新物理结局（轨迹诊断确证后改断言口径）/ 混沌区容差放大（加敏感度自测门）；禁止不归因就动断言。

### FL-050 — SceneKit 离屏投影必须验证视口及相机同步
- 离屏SCNView以非零frame初始化并显式layout；不能假定snapshot就能修正1×1默认投影视口。
- 每次相机姿态/anchor平移后同步SceneKit事务；用当前相机局部(0,0,-1)转世界再projectPoint，断言落在实际viewport中心。
- 未通过单位和姿态同步断言的包围体/可行性统计全部无效；0用例/中断日志不得作为通过。
- 预设安全区是诊断假设，真实UI验收必须测量HUD；完整入镜也要核验球的屏幕可读尺寸。

### FL-051 — 自动取景不得替换已有手势语义
- 改拟合姿态后，横向与纵向输入分别验证实际yaw、height、pitch及松手后的状态；只验zoom或横向环绕不能作为相机交互通过。
- 自动取景的高度下限复用相机姿态配置；新题取景和持续渲染须分开验证，持续帧不能抢回手动姿态。

### DR-278 — 内部接触分配与可观测运动精度
surface-moment严格迭代未达到roundoff时，可用可行力矩凸优化gap提供整体角加速度误差界sqrt(2g)，按R*dt²转换为现有空间容差验收。滚阻圆盘/自旋区间容量须保持可行，gap负值超过舍入界或非有限值必须失败。不得直接把内部残差阈值调大；验证坡面静止/加速、滚阻不反转与不增能，且比较实际滑动初态而不只看自然滚动样本。
Changelog：2026-09-13 / DR-278 / 接触力矩误差界，八项回归通过。


### DR-279 — 有限步摩擦的浮点尺度

### DR-285 — 局部接管须覆盖球体前缘（2026-09-13）
袋口窗口的中心域使用窗口半宽+球半径的保守包络，不能等球心越界才接管已触及边缘的球体。必须核对完整接触网格覆盖扩大域及其邻球范围；保留原穿透预算，检查进入状态与实体的最小间距。记录球心位置、球半径、窗口几何和交接时钟，不能靠放宽修正量处理毫米级初始重叠。
Changelog：2026-09-13 / DR-285 / FL-071球体接管边界。

### DR-287 — 恒定球心边界查询省算（2026-09-13）
EventDrivenEngine静态直库/圆弧/袋口查询仅在v与a全部分量严格为零时跳过。不可改为速度阈值或只看运动状态；v=0但旋转摩擦使a非零仍能运动。球球检测与状态转换保留，受撞后重新查询。验证同时保留多球开球、完整搜索与展示一致性，耗时只按实际设备/构建报告。

### DR-288 — 圆弧保守可达范围（2026-09-13）
圆弧外侧点仅在初距超过接触半径与本时间窗速度/加速度位移上界之和时拒绝求根；必须包含原根检测允许的时间尾差。保留原求根对照入口，覆盖加速/转向/短窗接触。避免以跨步无碰撞缓存代替当前状态判定；少量终局一致不得宣称所有候选轨迹一致。

### DR-294 — `TrajectoryPlayback.surfaceY` 是球心平面，不是台呢面（2026-09-14）
所有 `TrajectoryPlayback(recorder:surfaceY:)` 调用点传的是 `yLevel = surfaceY + R`（球心绘制平面）。任何从回放层派生的高度几何（袋内落位、下落起点）若拿它当台呢面就差整一个 R（本例 y 0.7259 vs 0.6973，端到端断言抓出）。台呢面真源取 `PocketEntrySnapshot.geometry.pockets[].center.y` 或 `AngleTrainingScene.surfaceY`；写高度几何前先回显「这个 Y 是球心还是台面」。网兜剖面等从资产实测的常量必须配一条对资产的门禁测试（`testProfileMatchesBundledBagEnvelope`），不能只靠注释注明来源。
DR-279 补注（DR-295）：含 v/dt 操作数的**每个**残差都要有 `velocityRoundoff/dt` 的舍入下界，不只是 motion 残差；dt≈1e-15 的时钟碎片步上，漏设下界的残差会以数 m/s² 的伪值报不收敛。


### DR-297 — 平面袋心 ≠ 袋壁轴心；「吃水平速度」在斜壁上要先分解切平面（2026-09-14）
①`TableGeometry.pockets[].center/radius` 是**平面判据**的落袋圆，不是 USDZ 皮革杯的几何：角袋皮革在台呢高度的球心自由区半径 ≈18 mm、轴心在平面袋心**内侧 24 mm**，平面袋心本身已在皮革里；把落袋圆当袋口壁建漏斗 = 球在皮革里 48 mm。任何「袋内」几何都要对资产做**球体-网格**探测（球心自由区，不是网格顶点统计），并用极坐标环（轴 + 各向可达）而非单一半径描述非圆袋口。②深度约定要显式写清是「球底低于台呢」还是「球心低于台呢」（本文件 DR-294 已警告 `surfaceY` 是球心平面）。③「吃掉水平速度、垂直按重力」在**斜壁**上不是良定义：持续接触时先去法向分量，再把切平面分成沿坡向（重力驱动）与环向（可阻尼）；对整个切向或对 `v.y` 每步乘保留系数都会把下落变成蠕动（DR-294 版 0.07 m/s）。到达冲击（前一步未接触）才整体 ×retention。④门禁写「球体侵入网格 ≤ x mm」+「离壁步 dvy 恰为 −g」这类可证伪量，不写「看起来对」。

### DR-296 — 「台呢是一个平面」是假设，不是事实；先探针再定容差（2026-09-14）
内置 USDZ 的头半台（+X）长库旁床面 quad 有一个顶点抬到物理面（+5.3 mm，帐篷面），−X 同位置却是平面多边形。以 `|y − bedY| < ε` 判「床面」时，ε 无论取 1e-5 还是 1 mm 都会把帐篷面整块丢掉，footprint 出 13 cm 宽空洞，所有投影线在此被裁光。教训：①「同一形态只在一侧出现」是**资产缺陷**的强信号，先怀疑模型再怀疑浮点；②诊断要用 `hitTestWithSegment(.all)` + 逐面 dump 世界坐标看**真实顶点高度**，不要只看被过滤前后的统计（我据 12 个 1.2e-5 抖动面误判了根因，后被 dump 推翻）；③门禁测试必须真正跑到——本次新测试写进了同文件另一个 class，`-only-testing:` 指错类名执行了 0 条却被当作通过，务必看 `Executed N tests` 的 N。屏幕轴映射同理：rotated 顶视 screen-right=+Z / screen-up=+X，landscape screen-right=+X / screen-down=+Z，任何屏幕手势→世界平移都要按模式分支并用不动点测试钉死（本次修掉 rotated 平移轴对调的旧 bug）。
