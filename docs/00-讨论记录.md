### 2026-03-23 — 新增角度感知训练模块，确认交互细节

- **本轮确认信息**：
  - 训练记录进球数：**数字键盘输入**（精确）

- **新增功能：角度感知训练（独立第5个Tab）**
  - 设计理由：角度瞄准法是最准确的瞄准系统，该模块专门训练玩家的角度视觉感知能力，是市场上所有台球App都没有的独创功能
  - 子功能一：**角度测试**（随机出题，用户目测切入角并数字输入，动画揭示答案+接触点位置）
  - 子功能二：**进球点对照表**（交互式滑块实时更新接触点，完整角度对照表）
  - 核心公式：偏移量 = sin(α) × R，纯本地计算，零网络依赖
  - 信息架构：从4 Tab 升级为5 Tab（训练/动作库/角度/历史/我的）

- **仍待确认**：
  - 角度测试出题策略：纯随机 vs 自适应（根据历史误差重点出薄弱角度）？
  - 难度分级容差：宽松±10° / 标准±5° / 严格±2°？

### 2026-03-23 — 多源训练计划调研整合 + 角度测试设计定稿

- **本轮确认信息**：
  - 角度测试出题：**随机 + 自适应权重**（按误差率加权，角袋和中袋分开统计）
  - 难度容差：**专业级 ±3°**（唯一难度）
  - 训练计划：**多源调研整合**，不仅限新锐台球学院

- **多源调研结论**（6个来源）：
  - **国内**：新锐台球学院六级认证体系 + 伟林培训三阶段 + 王桁教练三步递进
  - **国际**：Billiard University (Dr. Dave) BU考试体系（Exam I/II/IV）+ BIZU Billiards 单次会话结构 + Billiard & Pool Center 四阶段
  - 整合后形成 **L0–L4 五级体系**，与中国六级认证 + BU考试体系双向对应
  - 设计 **6套官方训练计划**（入门8周/基础杆法6周/走位8周/中级10周/高级8周/全能持续）

- **角度测试自适应算法定稿**：
  - 出题权重 = 基础权重(30%) + 误差权重(70%)
  - 以5°为单位分18个区间，各区间独立记录最近10次误差
  - 角袋(0–75°, 60%比例) vs 中袋(15–60°, 40%比例) 分开统计和出题
  - 每次建议20题，历史以5题为组追踪进步趋势

### 2026-03-23 — 登录方式调整：增加微信 + 手机验证码

- **背景**：中国市场用户普遍习惯微信登录，Sign in with Apple 单一方式门槛偏高
- **决策**：
  - 原方案：仅 Sign in with Apple + CloudKit
  - **新方案：微信登录 + 手机验证码 + Sign in with Apple 三种并存**
  - 用户数据层从 CloudKit 私有库改为 **LeanCloud**（原生支持三种登录，数据在中国大陆）
  - CloudKit 公开库保留，继续用于 Drill 内容热更新
- **架构变更原因**：微信 OAuth 和短信验证码均需后端服务，LeanCloud 是无需自建服务器的最简方案
- **匿名使用**：未登录用户可浏览动作库、使用角度训练，训练记录仅本地存储
- **微信开放平台**：需提前申请，审核约 1–3 天，是上线前需完成的前置事项

#### 二、Drill 教程图文化路径

**问题**：当前 `tutorial.sections` 是 4 段纯字符串（技术原理 / 动作要领 / 常见错误与纠正 / 进阶练习）。台球教学本质是空间几何，纯文字信息密度太低——例如 drill_c024 第 3 节"接触角"概念纯文字读完用户大概率不懂，画一张图两秒钟懂。Dr. Dave / Jewett BD / DrillRoom 等国际标杆几乎所有概念都配图。

**结论**：值得做、应该做，但**不能做成"给每段文字配几张静态图"**——粗算 72 drill × 4 节 × 1-3 图 ≈ 600+ 张静态图，OTA 包体积爆炸 + 维护噩梦（drill 文本一改图就要重画）。

**四类图分级处理**：

| 类别 | 例子 | 生产成本 | 复用率 | 路径 |
|---|---|---|---|---|
| **A 球台俯视含标注**（占 90% 信息量）| CB/OB/袋口 + 路径 + 90° 分离线 + 落位区 + 箭头 + 文字 | 已有 `BTMiniTable` Canvas 组件，零增量 | 100% | **代码生成（动态）** |
| **B 击球点示意** | 母球正视图 + 9 个固定击点（中/高/低/左/右/中上/中下/左下/右下）| 一次画 9 张 SVG | 高（杆法/分离角/控力 大量复用）| **静态共用素材**（≤ 9 张）|
| **C 姿势/动作实拍** | 握杆/站位/手架/出杆 | 真人拍照或专业插画 | 仅基础功 7 个 drill（c006-c009/c022/c023/c043）| **限定范围实拍**（≤ 30 张）|
| **D 理论原理图** | T01 5/7+2/7 几何、T02 90° 推导、T09 squirt+swerve+throw | 专业制图 | 跨 drill 共享 | **16 项目侧产出**（≤ 12 张）|

**关键洞察**：A 类是最大头但成本几乎为零——已有 `BTMiniTable`，缺的不是"图"而是"标注能力"。

**总资产量**：A 类 0（动态）+ B 类 9 + C 类 30 + D 类 12 = **约 50 张静态图 + 一个标注引擎**——比"全配图"少一个量级，信息密度反而更高（A 类支持多分镜）。

### 2026-06-18 — 商业价值评估 + 产品定位收敛（练脑型交互式训练）+ 用户教育增长策略

**背景**：用户提出严肃的商业问题，要求结合中国台球市场、相关产品与教学形态，公正客观评估本产品商业价值；随后逐轮收敛产品定位与增长策略。本节记录战略层判断与定位决策（不含代码改动），供后续规划与排期参照。所有判断标注性质：〔事实〕据本仓库文档/代码进度，〔推断〕为分析判断，〔假设〕为待验证项。

#### 一、商业价值评估（公正客观）

- **工程含金量〔事实〕**：产品已远超"训练记录 App"——含完整移植自 pooltool 的事件驱动物理引擎 + 走位反解器 + 斯诺克安全球反解 + 球形生成器 + 拍照建球形 + 教学视频离线渲染管线（2D/3D/HUD/出杆动画）。在国内 C 端台球 App 里属断层式领先。
- **市场现实〔事实+推断〕**："台球+训练/AI"赛道真正在收钱的是 To B 硬件（小铁/谈小娱/客满台/易付乐，顶置摄像头+投影，加盟+SaaS）；C 端教学被抖音/B站近免费占满，C 端娱乐被游戏占满。本产品卡在"严肃训练工具"——中国 C 端付费意愿最薄的一类。
- **核心风险〔推断，按重要性〕**：①付费意愿是命门且大概率偏低（用户研究已亮红灯：Persona A 偏好 30–50 元买断、对订阅敏感；订阅主要只能打小众的 Persona B）；②"记录+计划"Keep 式逻辑在台球（多为社交娱乐）场景留存存疑；③技术含量最高的物理/反解功能商业确定性最低（仍是 2D 平面物理、手机→真台迁移有限、有"极客玩具"风险，存在过度工程迹象）；④内容才是真护城河却最薄弱（真人示范视频仍占位、理论↔drill 仍两座孤岛）；⑤内容权威/教练 IP 缺位；⑥降维打击风险真实（DrillRoom 中文化 / 抖音站内工具 / 硬件厂商反向做 C 端）。
- **量化判断〔推断，需打折〕**：按现状"独立 C 端订阅 App"路线，无强运营/内容/投放下年收入很可能仅几千~十几万人民币量级，非可养团队的独立生意；乐观情形需叠加可信教练 IP + 持续内容 + 投放方可到几十万级。**结论：作为独立 App 直接卖订阅，投入产出比偏低。**
- **被掩盖的价值岔路〔推断〕**：真正值钱的是"引擎+内容渲染管线"本身，可①反向供给硬件/门店赛道当"算+教"软件层；②当内容生产工厂（给短视频/课程供片）；③绑可信教练 IP 转技术优势为内容权威；④用"诚实几何教学"（理想线 vs 带塞修正）做差异化。

#### 二、产品定位收敛（用户拍板）

- **用户决定**：App 定位为 C 端"**学练记**"闭环产品——系统教学（学）+ 交互式练习（练）+ 训练记录（记）；**不追内容工厂/B 端那条主线**（可作远期可选上行）。
- **柱子主次〔决策〕**：交互式练习=主角/英雄功能（唯一护城河+差异化+内容产能）；系统教学=权威层/承重墙（用户正在补充）；训练记录=习惯黏合剂（非卖点）。定位一句话建议："看得懂、练得到的台球训练 App"。
- **关键设计原则（用户确认）— "交互式练习 = 练脑，不是练手"**：手机练不了真实出杆手感，只能且正好能练**线路判断 / 几何角度直觉 / 战术决策（做杆·解球·走位规划）**；定位为真实球台练习的"课前预习+课后复盘"，不做替代品。现有反解器/编排台/角度训练/斯诺克战术正好落在这一层。
- **目标用户（用户给出，判断最准的一刀）**：中间层爱好者——有兴趣、常打、卡在瓶颈期，**刷短视频拼不出体系、又没时间/条件请教练**的人。职业玩家太少、休闲玩家无提升意愿，均非主力。

#### 三、增长 = 用户教育（与定位自洽，非二选一）

- **核心判断〔推断〕**：目标用户的需求是**潜在而非显性**——他们痛感是"老是清不了台/走死"，但不会翻译成"我缺走位思路训练"，故不会主动搜索、却会被戳痛点的内容吸引。因此**用户教育的真正作用是"创造需求"**（先帮用户命名痛点、揭示盲区，产品才是答案），对这个产品教育是最优且几乎唯一可行的获客方式。
- **能成的硬前提〔推断〕**：必须配一个**有台球可信度的真人 IP/面孔**（纯引擎动画立不住权威，台球是强 KOL 领域）。这同时解决"内容权威缺位"风险。
- **三件事分清〔推断〕**：产品是什么（学练记 App，已定）／怎么被知道（教育内容引流，引擎能近零成本量产讲解片是独特优势）／怎么赚钱（订阅为主+课程/社群为辅，B 端授权为远期可选）——三者不矛盾、互为一体。
- **产品侧死命令〔推断〕**：新用户进来还不知道自己缺思路，App 必须在前几分钟制造"啊哈时刻"——用用户自己的球（拍照建球形→让他先决策→引擎正解对比揭示盲区→第一个小胜），否则会被当成"画线工具"流失。

#### 四、结论与决策

- ✅ 产品定位收敛为：**面向"中间层瓶颈期爱好者"的"练脑型"系统化台球训练 App（学练记闭环）**。
- ✅ 增长策略方向：**教育驱动（创造需求）**，引擎量产讲解内容引流；需补"可信教练 IP"这块非代码短板。
- ✅ 工程纪律：**停止继续加物理新功能**（2D 物理已够用），重心转向①把学练记连成环（练习结果回灌记录、记录驱动教学推荐）②补"系统教学"承重墙③重排交互式练习信息架构为"练脑"梯度④"啊哈时刻"首启路径。
- ⚠️ 商业天花板未因定位变好而改变；建议尽早用最小成本做**真实付费意愿验证**（用户研究列为高优先级但至今未被真实数据回答）。

#### 仍待确认

- 可信教练 IP 的获取方式（合伙人 / 现成教练分成）。
- 首启"啊哈时刻"的具体落地形态（拍照建球形 vs 示例球；放哪个页面）。
- "系统教学"补充的排序原则（建议按"中间层认知缺口/获得感"排，而非按难度从头堆）。
- 是否、何时启动最小付费意愿验证（落地页/问卷/课程预售）。
- B 端授权 / 内容工厂是否纳入远期路线（当前定位为可选上行，不影响把 App 做好）。

### 2026-05-14 — 物理引擎介入路径与 17 号项目立项判断

**背景**：在跨项目讨论中追问 2026-05-07 那一节"Drill 教程图文化路径"——质疑"BTMiniTable + 手画 path JSON"的方案，提出能否引入物理引擎自动生成轨迹。讨论过程中先后澄清了三个被低估的现状，最终落到"是否新建 17 号项目"的决策。本节记录决策留痕，避免日后重提。

#### 一、被澄清的三个现状（修正 2026-05-07 那节的判断盲区）

1. **13 早已不只有 BTMiniTable**——`QiuJi/Core/Scene/AngleTrainingScene.swift`（1324 行）已经在 P5 角度训练 Tab 跑真 3D SceneKit 场景：USDZ 球桌（`TaiQiuZhuo.usdz`，沿袭自 `01.billiard_app`）+ 16 颗 USDZ 球节点 + USDZ 球杆（`QiuGan`）+ studio/plain 双套灯光 + 顶视 2D / 顶视 2D 旋转 / 透视 3D 三种相机模式 + 平滑过渡 + ghost ball / 瞄准线 / 进球线 / cut-angle arc / flat text 标注。**2026-05-07 节里说"A 类靠 BTMiniTable 零增量"是 v1.0 早期事实，已落后于现状**。
2. **现有 3D 场景 ≠ 物理引擎**——`TableModelLoader.disablePhysics(in:)` 把 USDZ 自带的 `SCNPhysicsBody` 全剥光了。当前是"3D 渲染 + 解析几何工具"，不是动力学仿真。能演示"接触前的几何"（瞄准线、ghost ball、cut angle、击球点），**做不了**"接触后的动力学"（30° 法则、squirt/swerve/throw、cushion COR、cluster 散开）。drill_c001~c023 类靠现有几何工具够用，drill_c024~c072 的杆法/走位/控力/特殊球路类不够。
3. **`pooltool.PocketTableSpecs` 是参数化的**——中式八球桌不需要"塞进 pooltool"，是直接实例化一个新 specs 对象（约 30 行 Python）。13 这边的"中式八球真值"已经全在 `AngleSceneCalculator` + `BTTablePhysics` + `.kiro/steering/table-geometry.md` 里，平移过去即可。`model_descr=TableModelDescr.null()` 告诉 pooltool 不加载它自带 GLB → 渲染层走 SceneKit + USDZ，物理层 build-time 走 pooltool，两边各管一摊。

#### 二、推荐的整体架构（三层职责严格分离）

```
┌──────────────────────────────────────────────────────────┐
数据层  scenarios/*.py（球初始位 + 击球参数 + 教学标注语义）
        — source of truth，渲染无关
┌──────────────────────────────────────────────────────────┐
物理层  ┌──── 接触前几何 ─── 现有 AngleSceneCalculator
        ├──── 动力学 ────── pooltool（build-time，输出 keyframes JSON）
        └──── 粗略碰撞 ──── SceneKit Physics（目前未启用，不推荐启用）
┌──────────────────────────────────────────────────────────┐
渲染层  ┌── ① BTMiniTable          → 列表/缩略图（保持）
        ├── ② AngleTrainingScene   → 抽出 DemoScene 通用类，详情页/教学
        ├── ③ ShootersPool         → 视频生产（15 项目）
```

**关键设计原则**：
- **iOS 端永远不跑 pooltool**——它是 build-time 工具，输出制品才上设备

#### 七、风险点（需要在阶段 1 验证）

1. **中式八球袋口几何与 pooltool 默认的"7ft showood"袋口设计不完全一样**——pooltool 的 `corner_pocket_width / angle / depth / jaw_radius` 是按美式 7ft 建模的。中式八球角袋（杏色皮革 + 较小袋口 + 较深袋）需要独立校准。**这是阶段 1 的核心验证任务**。
2. **物理参数（球-台呢摩擦、COR）**——pooltool 默认是美式九球。中式八球台呢更短毛、球更光滑，COR 略不同。先用默认跑，校准时如果误差 > 5% 再调。
3. **作者门槛升高**——写 scenario 比"在 BTMiniTable 上画两条虚线"难。立项时配模板（直线、cut shot、cushion 反弹、走位四种基础类型），作者改参数即可。
4. **build-time 工具链**——13 的 CI 要新增 Python + pooltool 环境（pip install 即可，pooltool-billiards 在 PyPI）。CI 跑 ~72 scenario × 50ms < 5 秒，可以接受。
