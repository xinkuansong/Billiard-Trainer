# UI 打磨审阅：状态呈现横切（空态 / 加载 / 错误 / 锁定 / 明暗）

> 范围缩写 **ST**。对照 `00-打磨基准.md`。已避开第一轮单页条目（如 F-HI-03、F-PF-01、F-HI-04、F-TR-13、F-PF-02 等），本文件只收**跨页横向**问题。

## 概述（五类状态全库盘点）

| 类别 | 组件 / 形态 | 主要出现点 | 横向结论 |
|---|---|---|---|
| **空态** | `BTEmptyState`（约 10 处） | 收藏、统计、计划列表、动作库/角度搜索、训练会话、角度历史等 | 组件已收敛，但**行动建议接入方式与文案语气未统一**；历史日历故意手写紧凑空态（见 07 存疑，不重复开 finding） |
| **空态（手写）** | 本地 `VStack` + 小图标 | `HistoryCalendarView` 日历下；`BTSetInputGrid`「还没有组数」 | 紧凑场景合理，与整屏 `BTEmptyState` 权重差大 |
| **加载** | 裸 `ProgressView` | 训练首页、计划列表/详情、收藏、历史、统计、订阅商品、登录中、求解顶栏 mini | **列表类加载几乎全是转圈** |
| **加载** | `BTDrillListSkeleton` + `BTShimmer` | **仅** `DrillListView` | 骨架能力已有，未横向复用 |
| **加载** | 按钮内 `ProgressView` | 订阅购买/恢复、Apple 登录 | 进行时反馈到位（购买失败静默见 F-PF-01，不重复） |
| **错误** | inline `Text` | Login / PhoneLogin；订阅商品加载失败 | 可见 |
| **错误** | `.alert` | 训练保存、自定义计划保存、注销、恢复购买 | 可见 |
| **错误** | 写入但不展示 / 吞掉 | `AuthState.errorMessage` 同步失败；`StatisticsViewModel` catch 后 `sessions = []` | **本轮重点**（与 F-HI-03 / F-PF-01 并列的第三类静默） |
| **Freemium** | `BTPremiumLock` | 统计 fullMask；计划详情 / 动作详情 progressive | 组件化，但文案/CTA 形态分叉 |
| **Freemium** | 手写限免卡 / 行锁定 / PRO 角标 | 角度训练 4 页限免；历史锁定行；计划/动作卡片徽章 | **三套视觉语言并存** |
| **明暗** | `colorScheme ==` 分支 | 阴影清零（多数）；芯片/底栏/图表色/登录按钮等 | 阴影清零属 C5 合理；**改布局/换语义色**的分支需收编 |

## Findings

### F-ST-01 错误态通道分裂：同步失败写了不展示，统计失败被吞成空态
- **类别**：B微交互
- **位置**：
  - `QiuJi/App/QiuJiApp.swift:87-88`（写入 `authState.errorMessage = "数据同步失败，稍后会自动重试"`）
  - `QiuJi/Features/Profile/Views/SettingsView.swift:46-53`（`errorMessage` **仅**在 `isDeletingAccount` 时弹「注销失败」）
  - `QiuJi/Features/History/ViewModels/StatisticsViewModel.swift:400-404`（`catch { sessions = [] }`，无 error 字段）
  - 对照已展示路径：`LoginView.swift:38` / `PhoneLoginView.swift:90-91`（inline）；`ActiveTrainingView.swift:119-125` / `CustomPlanBuilderView.swift:67-73`（alert）
- **现状**：全库错误反馈至少四种——inline、alert、写了不读、吞成空列表。登录后迁移失败时用户无任何提示；统计加载失败时用户看到的是「还没有训练数据」空态（`StatisticsView.swift:86-93`），与真失败不可区分。
- **问题**：对照 **B3**（失败要有诚实反馈）。本条不重复 F-HI-03（历史 `errorMessage` 未绑视图）与 F-PF-01（购买失败静默）；补的是**同 App 内其余静默通道**。
- **建议**：① 同步失败在 Profile 根或全局 toast/横幅读 `authState.errorMessage`（与注销 alert 解耦）；② `StatisticsViewModel` 增加 `errorMessage` 并在 `StatisticsView` 与空态分流展示「加载失败 + 重试」（形态可与历史修复方案对齐）。
- **语义影响**：无（只把已有失败信息露出，不改同步/查询逻辑）
- **严重度**：P2

### F-ST-02 同类列表加载：仅动作库用骨架，其余一律裸 ProgressView
- **类别**：D一致性
- **位置**：
  - 骨架：`DrillListView.swift:158-160` → `BTDrillListSkeleton()`；实现于 `BTShimmer.swift:103`（`BTDrillListSkeleton`）
  - 裸转圈：`TrainingHomeView.swift:19-21`、`PlanListView.swift:34-36`、`PlanDetailView.swift:27-28`、`FavoriteDrillsView.swift:14-16`、`HistoryCalendarView.swift:37-38`、`StatisticsView.swift:17-19`
- **现状**：内容列表的「首次/刷新加载」至少两种形态——动作库卡片骨架 vs 其它页居中 `ProgressView`。`BTShimmer` / `BTDrillCardSkeleton` 已在组件库，Features 几乎不用。
- **问题**：对照 **D2 / D4**——同类交互同形态；页面手写了组件库已有能力的替身（此处是「不用已有骨架」）。
- **建议**：计划网格 / 收藏列表 / 训练首页计划区优先复用 `BTDrillListSkeleton` 或抽出通用 `BTListSkeleton`；历史/统计可保留轻量 `ProgressView`（数据区非卡片网格），但同一「卡片网格加载」族内统一骨架。
- **语义影响**：无（只换加载占位视觉，不改数据获取或空态分支）
- **严重度**：P2

### F-ST-03 列表加载 → 内容切换普遍硬切，无过渡
- **类别**：A动效
- **位置**：
  - `TrainingHomeView.swift:19-26`（`isLoading` ↔ 内容，无 `animation`/`transition`）
  - `PlanListView.swift:34-37`、`FavoriteDrillsView.swift:14-27`、`StatisticsView.swift:17-20`（同上）
  - 对照：`DrillListView.swift:160` 声明了 `.transition(.opacity)`，但 `DrillListViewModel` 切换 `isLoading` 未见配套 `withAnimation`（与 02 笔记一致）——过渡形同虚设
- **现状**：用户感知为转圈突然消失、内容突然出现；动作库本应有淡入但动画未接通。
- **问题**：对照 **A6**（突现突消 = P2）。
- **建议**：加载布尔翻转外包 `withAnimation(.easeOut(duration: 0.2))` 或基准面板 spring；内容侧统一 `.transition(.opacity)`。勿对数据拉取本身加长动画。
- **语义影响**：无（仅 chrome 过渡，不改加载时机或结果）
- **严重度**：P2

### F-ST-04 Freemium 锁定视觉语言分裂为三套
- **类别**：D一致性
- **位置**（横向对比）：
  1. **组件遮罩**：`BTPremiumLock.swift:64-83`（fullMask 模糊 +「解锁 Pro」实心金钮）；`StatisticsView.swift:36-37`；progressive：`PlanDetailView.swift:253`、`DrillDetailView.swift:52-53`
  2. **角度限免手写卡**：`GeometricAngleQuizView.swift:203-220` / `AimPointTrainingView.swift:282-295` / `AimPointSceneTrainingView.swift:621-638`（皇冠 +「今日免费次数已用完」+ **「解锁全部内容」**）；`SceneAimingView.swift:416-424`（同文案但 `BTButtonStyle.primary`）
  3. **列表行/角标**：`HistoryCalendarView.swift:327-345`（`lock` + 文案「Pro」+ opacity 0.7）；计划卡 `PlanListView.swift:353-367` / `TrainingHomeView.swift:399-406`（黑字金底 Capsule「PRO」）；动作网格 `BTDrillCard.swift:192-203`（`lock`+「PRO」白字金底）；动作列表行 `BTDrillCard.swift:58-61`（仅 `lock.fill` 三级色，无 PRO 字）
- **现状**：解锁动词「解锁 Pro」vs「解锁全部内容」；徽章「PRO」胶囊至少三种（组件内描边小标 / 计划黑字金底 / 网格白字金底）；历史锁定行无皇冠、无统一 CTA 样式。
- **问题**：对照 **D2 / C6**——同类锁定应同形态、同一叫法。用户难以建立「这是 Pro 门槛」的稳定心智。
- **建议**（不改门槛规则）：① 内容遮罩继续用 `BTPremiumLock`，把 fullMask 标题/副文案参数化（见 F-ST-07）；② 日限场景抽出共享 `BTDailyLimitGate`（皇冠 + 统一 CTA 文案，建议与 Pro 解锁动词对齐为「解锁 Pro」或全库统一「解锁全部内容」二选一）；③ 列表角标统一一种 PRO/lock 组合（网格与计划对齐即可，列表行补同一徽章）。
- **语义影响**：无（不改免费次数、可预览周数或付费墙入口，只统一视觉与用词）
- **严重度**：P2

### F-ST-05 空态行动建议：组件已支持 CTA，却常外挂或省略
- **类别**：D一致性
- **位置**：
  - 组件契约：`BTEmptyState.swift:7-8, 31-34`（`actionTitle` + `BTButtonStyle.primary`）
  - 内置 CTA：`FavoriteDrillsView.swift:18-26`（「浏览动作库」）；`StatisticsView.swift:86-93`（「开始训练」）；`ActiveTrainingView.swift:666-673`（「选择训练项目」）；`DrillListView.swift:242-247` / `AngleHomeView.swift:393-398`（清除搜索）
  - 外挂 CTA：`TrainingHomeView.swift:445-455`（`BTEmptyState` **无** `actionTitle`，下方另挂 `BTButtonStyle.secondary`「创建计划」）
  - 无行动：`PlanListView.swift:40-44`（「计划内容正在准备中」，无按钮）；`AngleHistorySection.swift:16-18`（仅说明，无去训练入口）
- **现状**：同一「空列表」场景，有的主按钮在组件内、有的次按钮在外、有的完全不给下一步。
- **问题**：对照 **D4 / C6**——手写了组件已有能力；行动建议权重不一致（primary vs secondary）。
- **建议**：凡「用户可立刻行动」的空态，优先走 `BTEmptyState(actionTitle:action:)`；训练首页自定义计划空态把「创建计划」收进组件（可保持 secondary 若需降权，则给 `BTEmptyState` 增加 style 参数，避免外挂）。纯系统占位（计划未就绪）可保留无 CTA，但文案与统计/收藏族区分清楚。
- **语义影响**：无（不增删入口语义，只统一 CTA 承载位置与按钮样式）
- **严重度**：P2

### F-ST-06 空态标题语气与近义词未拉齐
- **类别**：C视觉 / D一致性
- **位置**：
  - 「还没有…」：`FavoriteDrillsView.swift:20`、`StatisticsView.swift:88`、`HistoryCalendarView.swift:271`、`BTSetInputGrid.swift:105`
  - 「暂无…」：`PlanListView.swift:42`、`TrainingHomeView.swift:447`、`AngleHistorySection.swift:17`
  - 搜索空：`DrillListView.swift:244`「没有找到相关**动作**」vs `AngleHomeView.swift:395`「没有找到相关**练习**」（副文案几乎相同）
  - 「训练记录」vs「训练数据」：`AngleHistorySection.swift:17` vs `StatisticsView.swift:88`
- **现状**：同一产品里空态开场词在「还没有 / 暂无 / 没有找到」间漂移；搜索空对内容的叫法（动作/练习）不一致。
- **问题**：对照 **C6**（同一概念同一叫法）。属可感知粗糙，非功能缺陷。
- **建议**：列表空态统一「还没有…」；占位/系统未就绪用「暂无…」；搜索空统一「没有找到相关{对象}」，对象名与 Tab 名对齐（动作库=动作，角度=练习）。
- **语义影响**：无（纯文案对齐）
- **严重度**：P3

### F-ST-07 `colorScheme ==` 中改布局 / 换语义色的分支应收编为 token
- **类别**：D一致性 / C视觉
- **位置**（排除「暗色清阴影」合理模式；下列会改变层级或语义色）：
  - **改容器层级**：`TrainingHomeView.swift:506-508`（暗色加 `btBGSecondary` 卡片壳，亮色透明无圆角——已有 F-TR-13，此处作横切索引不重复开单）
  - **改底栏材质**：`ActiveTrainingView.swift:518-527`（暗色实色 `btBGSecondary` + 顶部分割线；亮色 `.ultraThinMaterial`）
  - **换图表语义色**：`StatisticsView.swift:79-80`（暗色 `btAccent`，亮色 `btBallTarget`）
  - **芯片选中硬编码 RGB（跨页复制）**：`TrainingHomeView.swift:315-329`；`DrillListView.swift:15-18`；组件内同类：`BTTogglePillGroup.swift:10-16`
  - **登录主按钮反色**：`LoginView.swift:104-114`（暗色白底黑字 / 亮色黑底白字——偏 HIG Sign in with Apple，可保留为例外）
- **现状**：多数 `colorScheme` 分支只是关掉 Light 阴影（C5 合理）。但上述几处等于「明暗两套皮肤逻辑」，未进语义 token，易与 `Color.bt*` 自动适配分叉。
- **问题**：对照 **D3 / C5**——手写分支是明暗不一致温床；图表色在明暗下换了完全不同的语义色相。
- **建议**：① 芯片选中色抽 `Color.btChipActiveFill` / `btChipActiveText`（TrainingHome、DrillList、BTTogglePillGroup 共用）；② 统计图琥珀线用单一语义色（如 `btAccent`）+ 必要时调 opacity，避免 Light 用球色；③ ActiveTraining 底栏统一「暗色实底 / 亮色 material」为命名样式（如 `BTChrome.toolbarBackground`），避免页面内联 if。Login Apple 按钮标注为例外即可。
- **语义影响**：无（颜色/材质收编，不改信息架构或交互）
- **严重度**：P2

### F-ST-08 `BTPremiumLock.fullMask` 文案写死统计场景，progressive / fullMask CTA 形态也不统一
- **类别**：D一致性
- **位置**：
  - `BTPremiumLock.swift:72-80`（硬编码「统计功能为 Pro 专属」/「升级 Pro 解锁训练统计…」）
  - `BTPremiumLock.swift:131-167`（progressive：描边「解锁 Pro」+ PRO 小标；fullMask：实心金钮 + crown）
  - 复用方：`StatisticsView.swift:36`；`PremiumGateModifier`（`BTPremiumLock.swift:192-197`）同样套 fullMask，会带上**统计专用文案**
- **现状**：组件名是通用锁，实现却绑死统计文案；两种 mode 的主 CTA 视觉权重不同（描边 vs 实心），且与角度页「解锁全部内容」再分裂（见 F-ST-04）。
- **问题**：对照 **D4**——通用组件不可复用；同类解锁钮同 App 内形态不一（**D2**）。
- **建议**：`fullMask` 增加 `title`/`subtitle` 参数（统计页传入现文案）；渐进/全遮 CTA 统一一种（建议实心金为主操作）；`PremiumGateModifier` 必须传入上下文文案，禁止默认统计句。
- **语义影响**：无（参数化既有文案，不改锁定范围）
- **严重度**：P3

## 存疑项（待主控裁决，不算 finding）

1. **历史日历紧凑空态 vs 统计整屏 `BTEmptyState`**：07 已存疑；横切确认仍是刻意取舍（防 Tab 遮挡）。若只统一图标字号/链接色而不改布局，是否单开 DR？
2. **求解中顶栏 mini `ProgressView`（走位/翻袋/斯诺克等）与列表转圈**：同属加载，但场景是「计算中」非「拉列表」——是否保持两套（顶栏状态 vs 页中占位）即可，不必强行骨架化？
3. **Login Apple 按钮明暗反色**：接近系统 Sign in with Apple 惯例；是否排除出 token 收编范围？
4. **`BTSetInputGrid` 手写「还没有组数」**：嵌在记分卡内，用整屏 `BTEmptyState` 会过重——保持紧凑是否定为模式并写入组件文档？
