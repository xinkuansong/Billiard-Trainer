## 页面概述

**ActiveTrainingView（active 子态）**  
训练进行中全屏：顶栏霜化计时 + 暂停/休息/更多/完成；主体在「总览列表」与「TabView 分页记分」间切换；组间休息时 ZStack 居中双环覆层；底栏五钮（最小化 / 更多 / 添加 / 心得 / 切换）。空态（自由模式无项目）上半仍挂大计时卡 + `BTEmptyState`。最小化 `dismiss` 后由训练 Tab「继续训练」或其它 Tab 的 `BTFloatingIndicator` 接回。

**DrillRecordView + BTSetInputGrid**  
单 drill 记分页：练习行、本项备注、休息时长、计时/成功率开关、组数网格（数字键盘录入进球/总球、勾选完成、删除）、进行中统计条、可折叠球台示意。本组完成会触发 VM 休息倒计时——是全 App 停留最久的高频路径。

## Findings

### F-AT-01 记分 numberPad 无可靠收起，键盘易卡住底栏
- **类别**：B微交互
- **位置**：`QiuJi/Core/Components/BTSetInputGrid.swift:247-248`、`274-275`；对照 `DrillRecordView.swift:39-69`（ScrollView 未挂收起）；姊妹页 `TrainingNoteView.swift` 已用 `scrollDismissesKeyboard`
```swift
TextField("-", text: madeBallsText)
    .keyboardType(.numberPad)
```
- **现状**：进球/总球用 `.numberPad`（无 Return/完成键）。`DrillRecordView` 外层 `ScrollView` 未设 `.scrollDismissesKeyboard`；同流程心得页已显式 `scrollDismissesKeyboard(.interactively)`。键盘顶起后底栏五钮与「添加一组」易被挡，且组间休息覆层弹出时键盘可能仍悬着。
- **问题**：对照 **B3**（进行时反馈与可退出路径）——记分是最高频输入，缺少对称的「收起」路径会明显拖慢组间节奏。
- **建议**：`DrillRecordView` 的 `ScrollView` 对齐心得页加 `.scrollDismissesKeyboard(.interactively)`；可选在键盘期用 `safeAreaInset`/`toolbar` 提供「完成」收起（不改录入语义、不加新业务字段）。
- **语义影响**：无（只补系统键盘收起，不改 made/target 数据模型）。
- **严重度**：P1

### F-AT-02 勾选完成与活动行左边条硬切，无完成瞬间反馈
- **类别**：A动效 / B微交互
- **位置**：`BTSetInputGrid.swift:195-201`（完成底/活动条）、`285-305`（勾选圈 `.plain`）；触发链 `ActiveTrainingViewModel.swift:353-368`（toggle 后常立刻 `startRestTimer()`）
```swift
.background(rowState == .completed ? Color.btPrimary.opacity(0.06) : Color.clear)
.overlay(alignment: .leading) {
    if rowState == .active {
        Rectangle().fill(Color.btPrimary).frame(width: 4)
```
- **现状**：点勾选后空心圆→实心勾、行底色、4pt 活动条跳到下一行均为瞬时硬切；无 scale/opacity/`contentTransition`。随即可能盖上休息覆层，用户甚至来不及确认「这组已记下」。
- **问题**：对照 **A6**（突现突消）、**B1/B3**（最高频主操作应有即时完成反馈）。
- **建议**：勾选加短按压 style（≤100ms scale 0.96–0.98）；完成态与活动条用 `spring(response: 0.28, dampingFraction: 0.86)` 或 `easeOut(0.15)` 过渡；不必加新功能。
- **语义影响**：无（仍是 toggle 完成 + 既有休息触发）。
- **严重度**：P2

### F-AT-03 球台示意折叠：chevron 硬换 + 内容无 transition
- **类别**：A动效
- **位置**：`DrillRecordView.swift:272-290`
```swift
withAnimation(.easeInOut(duration: 0.2)) {
    showBallTable.toggle()
}
// ...
Image(systemName: showBallTable ? "chevron.down" : "chevron.right")
if showBallTable, drill.animation != nil {
    BTBakedDrillTable(drillId: drill.drillId)
```
- **现状**：有 `withAnimation`，但 chevron 是两个 SF Symbol 互换（非旋转）；台面块以裸 `if` 插入，未声明 `.transition`（如 `opacity + move(top)`）。展开时下方统计条/底栏被突然顶开，收起同样跳。
- **问题**：对照 **A6**、**A5**（展开/收起应对称）；时长 0.2s 可接受（A3 高频），缺的是空间过渡。
- **建议**：chevron 用 `rotationEffect` 单一图标；内容加 `.transition(.opacity.combined(with: .move(edge: .top)))`；动画收编短 spring `0.28/0.86`（与面板档接近）。
- **语义影响**：无（仍是示意开合，不改 drill 内容）。
- **严重度**：P2

### F-AT-04 最小化无空间交接：本 Tab「继续训练」与他 Tab 浮标两套语言
- **类别**：A动效 / D一致性
- **位置**：`ActiveTrainingView.swift:449-451`；`MainTabView.swift:74-81`；`TrainingHomeView.swift:552-563`
```swift

// MainTabView: 仅 selectedTab != .training 时出 BTFloatingIndicator
// TrainingHome: 同 Tab 改为全宽「继续训练」primary
```

- **现状**：点「最小化」直接 `dismiss` 全屏 cover，无共享元素/缩放回源；留在训练 Tab 看到的是底栏级全宽 CTA「继续训练」，切到其它 Tab 才是右下呼吸浮标（`move(trailing)+opacity` + `spring(duration: 0.3)`）。同一「恢复会话」语义两套形貌，且最小化按钮与浮标出场无路径对应（**A5**）。
- **问题**：对照 **A5**（进出同路径）、**D2**（同类恢复入口同形态）。浮标 spring 参数漂移见 F-GL-06，此处不重复开号。
- **建议**：最小化出场与浮标/「继续」入场用同一短 spring，并统一恢复控件形貌（优先浮标语汇，或本 Tab 也用紧凑 pill）；不改变 `minimizeTraining` / `resumeMinimizedTraining` 状态机。
- **语义影响**：无（仍是挂起会话 + 点按恢复）。
- **严重度**：P2

### F-AT-07 休息自然结束停在 0:00 约 800ms 才收覆层
- **类别**：A动效
- **位置**：`ActiveTrainingViewModel.swift:413-437`；覆层仍由 `isRestTimerActive` 驱动（`ActiveTrainingView.swift:54-57`）
```swift
} else {
    self.restSecondsRemaining = 0
    self.onRestComplete()
}
// onRestComplete: 音效 + success haptic 后
try? await Task.sleep(for: .milliseconds(800))
isRestTimerActive = false
```
- **现状**：倒计时到 0 后数字停在 `0:00`、环走空，仍显示「+30S / 完成休息」约 800ms，再淡出覆层并可能翻页到下一 drill。完成反馈（音效/haptic）合理，但 **UI chrome 滞留 >300ms**（基准 A2），且 0 秒态仍可点「+30S」延长已结束的休息。
- **问题**：对照 **A2**（chrome ≤300ms）、**B3**（完成态应清晰结束，避免可误触的僵尸控件）。
- **建议**：到 0 后立即禁用双按钮或换成「休息结束」静态态；滞留收至 ≤300ms，或环/卡片用短 scale-down+opacity 出场后再 `isRestTimerActive = false`。
- **语义影响**：无（不改休息时长、自动进下一 drill 的业务规则）。
- **严重度**：P2

## 存疑项（不确定是否越红线，待主控裁决，不算 finding）

1. **勾选列 `Button` + `highPriorityGesture(TapGesture)` 双绑定**（`BTSetInputGrid.swift:304-305`）：是否存在双触发 toggle？未真机验证，不记 finding。
2. **「每组计时」只在完成后写 `duration`，进行中无 live 秒表**（`DrillRecordView.handleCompleteSet` + 网格 `timerColumn` 显示 `-`）：补 live 读秒可能被视作功能增强。
3. **`showingOverview` 默认 `true`**（VM）：计划模式进会话先看总览再进记分——是否刻意？若改默认进第一项可能动 IA。
4. **`noteText` 仅 `@State`，VM 有 `drillNotes` 未接线**：01 已存疑；本轮确认仍未绑定。
5. **记分是否应提供 ± 步进代替纯 numberPad**：用户手感上缺「连按 ±」；加步进器会改交互模型，可能触红线「不改变交互模型」——仅存疑，本轮用 F-AT-01 解决收起痛点。
6. **休息自然结束后自动 `currentDrillIndex = next`**：TabView 翻页有无系统默认动画、是否应伴随短提示「进入下一项」——属微文案/引导，可能越 C6 产品语气，交主控。
