# UI 打磨审阅：我的与订阅 / 引导 / 登录（PF）

审阅范围：`QiuJi/Features/Profile/Views/` 下全部 11 个 View（ProfileView、SettingsView、SubscriptionView、SubscriptionStatusView、LoginView、PhoneLoginView、OnboardingView、PersonalInfoView、TrainingGoalView、FavoriteDrillsView、AboutView）。基准：`docs/ui-polish/00-打磨基准.md`。

## 页面概述

- **ProfileView**：Tab「我的」根页。游客展示登录入口、数据不同步警告与 Pro 推广卡；已登录展示头像信息、本月概览占位与菜单组（收藏 / 个人信息 / 训练目标 / 订阅 / 设置 / 关于）。核心交互是导航下钻与拉起登录 / 订阅 sheet。
- **OnboardingView**：三页首启引导（两页卖点 + 一页品牌汇总）。底部「继续 / 跳过」或「开始使用 / 登录已有账号」；低频页，允许 delight。
- **LoginView / PhoneLoginView**：账号入口。Apple / 微信 / 手机号三路；Apple 有 loading + 错误文案，手机号有验证码倒计时与登录按钮。
- **SubscriptionView**：近黑 Paywall。Hero + 权益列表 + 三档定价卡 + 主 CTA + 法律/恢复。转化关键路径。
- **SubscriptionStatusView**：已是 Pro 时的订阅管理（状态卡、跳转 App Store 管理、恢复购买、已解锁权益列表）。
- **SettingsView**：外观 / 声音 / 教学辅助 / 数据管理 / 账号安全分组列表；破坏性操作有确认 alert。
- **PersonalInfoView / TrainingGoalView**：资料编辑与周目标设置；大量列表单选 + pill / Toggle。
- **FavoriteDrillsView**：收藏列表；加载中 ProgressView，空态复用 `BTEmptyState`。
- **AboutView**：品牌身份 + 反馈/好评 + 法律链接。

## Findings

### F-PF-01 订阅购买失败后界面静默，无错误反馈
- **类别**：B微交互
- **位置**：`QiuJi/Features/Profile/Views/SubscriptionView.swift:365-370`
  ```swift
  let success = await subscriptionManager.purchase(product)
  if success { dismiss() }
  ```
  （Manager 侧失败会写入 `errorMessage`：`SubscriptionManager.purchase`，但本页未读取展示；对照同文件恢复购买 `372-379` 有 alert。）
- **现状**：购买失败或非取消错误后，按钮仅从 `ProgressView` 回到文案，用户看不到任何失败说明；恢复购买路径却有完整 alert。
- **问题**：对照基准 **B3**（失败要有诚实反馈）。转化关键路径上失败静默，用户无法区分「取消」与「扣款/校验失败」。
- **建议**：失败时（`success == false` 且非用户取消）用与「恢复购买」同形态的 `.alert` 展示 `subscriptionManager.errorMessage`，或在主 CTA 上方用 `btDestructive` 脚注文案；成功保持 dismiss。
- **语义影响**：无（只补齐已有错误态的可见性，不改购买/权益逻辑）。
- **严重度**：P1

### F-PF-02 手机号登录进行中无进行时视觉反馈
- **类别**：B微交互
- **位置**：`QiuJi/Features/Profile/Views/PhoneLoginView.swift:101-106`、`180-188`
  ```swift
  Button("登录") { login() }
      .buttonStyle(BTButtonStyle.primary)
      .disabled(!canLogin || isLoggingIn)
  // …
  isLoggingIn = true
  // … sleep … isLoggingIn = false
  ```
- **现状**：`isLoggingIn` 仅禁用按钮，标签仍为「登录」，无 `ProgressView` / 文案切换。对照 `LoginView` Apple 按钮在 loading 时替换为 `ProgressView`（`LoginView.swift:102-107`）。
- **问题**：对照基准 **B3**；同登录流内反馈形态不一致（**D2**）。
- **建议**：`isLoggingIn` 时在主按钮内显示 `ProgressView`（与 Apple 登录一致），或临时文案「登录中…」；发送验证码的 `isSendingCode` 也可同样处理。
- **语义影响**：无（不改变登录步骤，只暴露进行时）。
- **严重度**：P2

### F-PF-03 订阅主 CTA / 定价卡缺少按压态
- **类别**：B微交互
- **位置**：`QiuJi/Features/Profile/Views/SubscriptionView.swift:271`（定价卡 `.buttonStyle(.plain)`）、`297-319`（手写主按钮，无 `BTButtonStyle` 按压缩放）
  ```swift
  .buttonStyle(.plain)  // pricingCard
  // subscribeButton: 自定义 background + height 44，无 scaleEffect/isPressed
  ```
- **现状**：定价选择与「立即订阅」是转化路径上最高频点击点；`.plain` / 手写 chrome 无 `BTButtonStyle` 已有的 `scale 0.98` + 背景压暗（见 `BTButton.swift` Primary）。
- **问题**：对照基准 **B1**（主要操作按钮无按压态 = P2）；兼 **D4**（手写替身）。
- **建议**：主 CTA 复用或局部对齐 `BTButtonStyle.primary` 的按压参数（`scaleEffect 0.98` + `easeInOut 0.1`）；定价卡可用轻量 `ButtonStyle`（选中态 spring 可保留）。
- **语义影响**：无（仅按压反馈，不改选档/购买语义）。
- **严重度**：P2

### F-PF-04 登录页三路主按钮均为 `.plain`，无按压反馈
- **类别**：B微交互
- **位置**：`QiuJi/Features/Profile/Views/LoginView.swift:117`、`134`、`151`
  ```swift
  .buttonStyle(.plain)  // Apple / 微信 / 手机号
  ```
- **现状**：三枚等高主按钮手写背景 + `.plain`，按下无 scale / 高亮；同仓库 `BTButtonStyle.primary` 已提供标准按压。
- **问题**：对照基准 **B1**。
- **建议**：抽共享 `LoginProviderButtonStyle`（保留 Apple 黑白 / 微信绿品牌色），加入 `isPressed → scale 0.98` 与背景 opacity；或在 label 外包一层带按压的 `ButtonStyle`。
- **语义影响**：无。
- **严重度**：P2

### F-PF-05 注销账号请求进行中无视觉反馈
- **类别**：B微交互
- **位置**：`QiuJi/Features/Profile/Views/SettingsView.swift:213-223`
  ```swift
  private func deleteAccount() {
      isDeletingAccount = true
      Task {
          do {
              try await BackendSyncService.shared.deleteAccount()
              …
  ```
  （确认 alert 在 `40-45`；失败 alert 在 `46-54`。进行中无 ProgressView / 禁用态 UI。）
- **现状**：用户点「确认注销」后至网络返回前，设置页无任何进行时指示；失败才弹「注销失败」。
- **问题**：对照基准 **B3**。
- **建议**：`isDeletingAccount` 期间在账号安全行或全页 overlay 显示 `ProgressView`，并禁用重复点击；成功路径保持现有 logout。
- **语义影响**：无。
- **严重度**：P2

### F-PF-06 Paywall「恢复购买」对比度过低，次要合规动作几乎不可见
- **类别**：C视觉
- **位置**：`QiuJi/Features/Profile/Views/SubscriptionView.swift:345-349`
  ```swift
  Text("恢复购买")
      .font(.btMicro)
      .foregroundStyle(.white.opacity(0.2))
  ```
- **现状**：法律说明与「恢复购买 / 条款 / 隐私」统一 `white.opacity(0.2)`。权益列表与主 CTA 层级正确，但恢复购买作为付费用户必要出口，视觉权重过低，暗色 Paywall 上接近不可读。
- **问题**：对照基准 **C2**（权重应与重要性匹配；危险/合规次操作不应抢主 CTA，但也不应「看不见」）。
- **建议**：法律正文可保持 ~0.2–0.25；「恢复购买」单独提到 `.white.opacity(0.45–0.55)` 或 `btTextSecondary` 等价亮度，字号可升为 `btCaption2`，仍明显弱于主 CTA。
- **语义影响**：无（不改入口位置与购买主路径，只提高可读性）。
- **严重度**：P2

### F-PF-07 订阅状态页「恢复购买」无进行时反馈
- **类别**：B微交互
- **位置**：`QiuJi/Features/Profile/Views/SubscriptionStatusView.swift:92-101`、`177-185`
  ```swift
  Button {
      Task { await handleRestore() }
  } label: {
      Text("恢复购买")
  …
  .buttonStyle(.plain)
  ```
- **现状**：恢复过程无 loading / disabled；完成后才 alert。用户可连点，且等待期无反馈。对照 `SubscriptionView` 恢复时至少 `disabled(subscriptionManager.isLoading)`（`350`）。
- **问题**：对照基准 **B3** / **D2**。
- **建议**：绑定 `subscriptionManager.isLoading`：文案旁 `ProgressView` + `.disabled`，结束后再弹现有 alert。
- **语义影响**：无。
- **严重度**：P2

### F-PF-08 登录页标题逃逸 Typography token
- **类别**：D一致性
- **位置**：`QiuJi/Features/Profile/Views/LoginView.swift:29`
  ```swift
  .font(.system(size: 26, weight: .bold, design: .rounded))
  ```
- **现状**：字号/字重/圆角设计与 `Font.btChapterNumber`（`Typography.swift`：`size: 26, weight: .bold, design: .rounded`）完全一致，却直接写 system。
- **问题**：对照基准 **D3**。
- **建议**：改为 `.font(.btChapterNumber)`（若产品希望弱于展示级，也可用 `btLargeTitle` 并接受 32pt，但优先收编到已有 26pt token）。
- **语义影响**：无。
- **严重度**：P3

### F-PF-09 About 行图标使用系统 `Color.blue` / `Color.gray`
- **类别**：D一致性
- **位置**：`QiuJi/Features/Profile/Views/AboutView.swift:74-75`、`113-114`
  ```swift
  iconBG: Color.blue.opacity(0.12),
  iconColor: .blue,
  // …
  iconBG: Color.gray.opacity(0.12),
  iconColor: .gray,
  ```
- **现状**：「意见反馈」「用户协议」图标底/前景未走 `btPrimary` / `btTextSecondary` 等语义色；同页「好评」「隐私」已用 `btAccent` / `btPrimary`。
- **问题**：对照基准 **D3**；暗色下系统蓝/灰与设计体系表面层级易脱节（**C5** 轻相关）。
- **建议**：反馈可用 `btPrimary`；协议可用 `btTextSecondary` + `btBGTertiary` 底，与 `ProfileMenuRow` / `BTIconBadge` 体系对齐。
- **语义影响**：无。
- **严重度**：P3

### F-PF-10 训练目标进度环 UI 动画 0.6s，偏长
- **类别**：A动效
- **位置**：`QiuJi/Features/Profile/Views/TrainingGoalView.swift:46`
  ```swift
  .animation(.easeInOut(duration: 0.6), value: weeklyProgress)
  ```
- **现状**：调整「每周训练天数」时进度环带动画 600ms。该值随列表点选频繁触发，属 UI chrome 而非演示回放。
- **问题**：对照基准 **A2**（UI chrome ≤300ms）与 **A3**（中高频操作应短）。
- **建议**：收编为 `easeOut` / spring `response: 0.34, dampingFraction: 0.86`，时长感 ≤300ms；或 `easeInOut(duration: 0.25)`。
- **语义影响**：无（不改进度计算，只改过渡时长）。
- **严重度**：P3

## 存疑项（不确定是否越红线的，单独列出待主控裁决，不算 finding）

1. **Profile 游客底栏「跳过，以游客身份继续」空 action**（`ProfileView.swift:420`）：点击无任何反馈。补反馈/接线会触及「是否 dismiss 或等同已在游客态」的行为，可能碰功能语义；建议主控决定是删入口还是接到既有匿名态说明。
2. **微信登录按钮可点但无实现**（`LoginView.swift:120-121` 空 body，注释 pending H-05）：视觉上与 Apple 同级主按钮。灰显/加「即将支持」会改变入口可发现性，偏产品决策。
3. **Paywall / Pro 卡近黑 `Color(red:…)`**（`SubscriptionView.swift:12`、`ProfileView.swift:11`）：注释写明刻意与 `btBG` 区分营造 premium。是否收编为 `Color.btPaywallBG` token 属设计系统扩展，本轮不强制列为 finding。
4. **微信品牌绿硬编码**（`LoginView.swift:11`）：第三方品牌色，通常豁免收编；仅登记。
5. **Onboarding 强制 `.preferredColorScheme(.light)`**（`OnboardingView.swift:41`）：是否与全局外观偏好冲突属产品策略，不在本轮「不改 IA」下强改。
6. **退出登录无确认**（`ProfileView.swift:398-408`）：基准 B4 示例为清空/删除/覆盖；登出是否纳入破坏性确认待产品裁决。
