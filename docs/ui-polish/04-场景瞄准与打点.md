# UI 打磨审阅：场景瞄准与打点（SceneAimingView / AimPointTrainingView / AimPointSceneTrainingView / ShotSimulationView）

## 页面概述

**SceneAimingView**（2D/3D 角度训练）：全屏台面为主角，顶栏 HUD 显示进度/结果，观察态右侧动作列「辅助 / 答题」，答题键盘浮层提交角度，结束后总结卡。进页先弹训练设置 sheet。台面演示与取景是内容，HUD/键盘/按钮是 chrome。

**AimPointTrainingView**（瞄准点训练·2D 特写）：上方 `BTTableFigure` 特写拖假想球，下方 prompt/result 卡提交与反馈；顶栏统计 capsule。内容是假想球与瞄准点几何，chrome 是统计条与提交/下一题胶囊。

**AimPointSceneTrainingView**（2D/3D 瞄准点训练）：全屏台面 + 瞄准轮/提交，提交后顶栏结果 HUD（「1.5 秒后几何瞄准验证」或「按你的瞄准验证」，DR-031）→ 物理击球 → 自动下一题。击球回放属内容豁免；chrome 重点在瞄准控件进出、结果 HUD、限免卡。

**ShotSimulationView**（分离角与走位）：与自由击球同一布局语言（贴边瞄准轮/仪表柱/动作列 + 底栏球库），教学上限 2 目标球；击球中文案与求解 ProgressView 已有进行时反馈。SpinPad 弹出用基准弹簧。

## Findings

### F-SA-01 答题键盘与总结卡无动画进出场，突现突消
- **类别**：A动效
- **位置**：`QiuJi/Features/AngleTraining/Views/SceneAimingView.swift:63-66`（条件插入）；`:134-144`（`keypadOverlay` 声明了 transition）；`:402-434`（`summaryOverlay` 无 transition）
- **现状**：`phase == .inputting` / `testFinished` 时直接 `if` 插入浮层。键盘虽写了 `.transition(.move(edge: .bottom).combined(with: .opacity))`，但外层 `ZStack` 未对 `vm.phase` / `testFinished` 挂 `animation`/`withAnimation`，SwiftUI 下 transition 不会播放；总结卡更无 transition。
- **问题**：对照基准 A6（突现突消 = P2）。
- **建议**：在承载这两个 `if` 的 `ZStack` 上对 `vm.phase`（及 `testFinished`）使用 `easeInOut(0.2~0.25)` 或基准弹簧；总结卡补 `.transition(.opacity.combined(with: .scale(0.95)))`（勿用默认 `scale` 从 0）。
- **语义影响**：无（仅进出场过渡，不改答题/总结逻辑）。
- **严重度**：P2

### F-SA-02 动作列进出场使用默认 `.scale`（等价从 0 放大）
- **类别**：A动效
- **位置**：`QiuJi/Features/AngleTraining/Views/SceneAimingView.swift:251`、`:258`
- **现状**：`positioned` 内 `.transition(.scale.combined(with: .opacity))`；系统默认 `AnyTransition.scale` 从 0→1。观察态 ↔ 结果态切换时右侧「辅助/答题」与「下一题」会从点弹出。
- **问题**：对照基准 A6（从 `scale(0)` 进场 = P2；应 `scale(0.95)+opacity`）。
- **建议**：改为 `.transition(.asymmetric(insertion: .scale(scale: 0.95).combined(with: .opacity), removal: .opacity))`，或与 `AimPointSceneTrainingView` 控件一致仅用 opacity；弹簧参数保持现有 `0.35/0.75`（已与基准模式切换吻合）。
- **语义影响**：无（不改按钮语义与布局锚点）。
- **严重度**：P2

### F-SA-03 自动击球阶段顶栏退回统计 pill，锁定输入无进行时 chrome
- **类别**：B微交互
- **位置**：`QiuJi/Features/AngleTraining/Views/AimPointSceneTrainingView.swift:488-494`（仅 `showingResult` 显示结果 HUD）；`:185-188`（`strike()` 将 `phase = .striking`）；`:480-482`（非 aiming 时 `interactionMode = .none`）
- **现状**：`showingResult` 时 HUD 有「1.5 秒后自动击球验证」；进入 `.striking` 后顶栏落到 `else` 分支的 `statsPill`，用户看不到「击球中」类提示，同时手势已锁死。对比同范围 `ShotSimulationView` 动作列 `strikeTitle: vm.isPlaying ? "击球中" : "击球"`（`:125`）。
- **问题**：对照基准 B3（进行时反馈）与 A4（锁定期间视觉反馈要到位）。台面球体动画是内容豁免，但 chrome 提示不属于豁免。
- **建议**：`phase == .striking` 时顶栏继续用结果 HUD 变体或独立 pill（文案如「击球验证中…」），颜色/字号与现有 `resultHUD` 一致；不延长物理时长、不改变自动下一题。
- **语义影响**：无（只补锁定态可见性，不改自动击球与进题流程）。
- **严重度**：P2

### F-SA-04 假想球拖动对 `userPhi` 施加 easeOut，破坏 1:1 跟随
- **类别**：B微交互
- **位置**：`QiuJi/Features/AngleTraining/Views/AimPointTrainingView.swift:375-387`
- **现状**：`DragGesture.onChanged` 已实时写 `vm.userPhi`，但同一 `ZStack` 挂了 `.animation(.easeOut(duration: 0.1), value: vm.userPhi)`，拖动中假想球/瞄准线会滞后插值。
- **问题**：对照基准 B2（拖动中元素应 1:1 实时跟随）。
- **建议**：拖动态去掉该 `animation`（或 `transaction { $0.animation = nil }`）；若需松手微吸附再在 `onEnded` 单独 `withAnimation(.easeOut(0.1))`。
- **语义影响**：无（不改 φ 计算与提交误差语义，只改跟手手感）。
- **严重度**：P2

### F-SA-05 瞄准点页主操作胶囊使用 `.plain`，无按压态
- **类别**：B微交互
- **位置**：`QiuJi/Features/AngleTraining/Views/AimPointTrainingView.swift:304-313`（`sceneCapsuleButton`）；`QiuJi/Features/AngleTraining/Views/AimPointSceneTrainingView.swift:629-639`（限免「解锁全部内容」）
- **现状**：提交/下一题/解锁均为手写 `Capsule` + `.buttonStyle(.plain)`，按下无 scale/高亮。同文件几何训练注释写明场景页不用常规 `BTButtonStyle.primary`，但未补场景专用按压反馈。`BTButtonStyle.primary` 已有 `scaleEffect(0.98)`（`BTButton.swift`），形成同 App 主按钮手感落差。
- **问题**：对照基准 B1（主要操作按钮无按压态 = P2）。
- **建议**：抽/复用轻量 `ButtonStyle`（按下 `scale 0.96–0.98` + 可选 opacity，时长 ~0.1s），视觉仍保持品牌绿胶囊；勿改成 52pt 矩形 `BTButtonStyle.primary`（以免破坏场景页形态）。
- **语义影响**：无（只加按下反馈，不改 action）。
- **严重度**：P2

### F-SA-06 Prompt / Result 卡条件切换无过渡
- **类别**：A动效
- **位置**：`QiuJi/Features/AngleTraining/Views/AimPointTrainingView.swift:142-150`；卡片本体 `:224-279`
- **现状**：`if vm.showResult { resultCard } else if … { promptCard }` 直接替换，无 `animation`/`transition`。提交瞬间整块文案与主按钮跳变。
- **问题**：对照基准 A6。
- **建议**：对承载卡片的 `VStack` 使用 `.animation(.easeInOut(duration: 0.2), value: vm.showResult)`，卡片加 `.transition(.opacity)`（内容特写图不必动画）。
- **语义影响**：无（不改提交/下一题逻辑）。
- **严重度**：P2

### F-SA-07 UI chrome 大量逃逸 `Font.bt*`，硬编码 `.system(size:)`
- **类别**：D一致性
- **位置**（抽样，均为 chrome 非台面标注）：
  - `AimPointTrainingView.swift:228`、`:253`、`:307`（题面/误差/按钮）
  - `AimPointSceneTrainingView.swift:554`、`:633`（结果 HUD / 解锁）
  - `SceneAimingView.swift:314`、`:405`（评级字 / 总结图标字号）
  - `ShotSimulationView.swift:177-185`、`:225-234`、`:387`（导航状态、厚度名、banner）
- **现状**：同页已混用 `.btFootnote` / `.btCaption` / `.btHeadline` 与裸 `.system(size:)`；展示级误差用 22/26 heavy rounded，未走 `btTitle`/`btTitle2` 等 token。
- **问题**：对照基准 D3 / §1.1（页面直接写 `.system(size:)` 属 D 类；台面 Canvas 文本豁免——本条不含 `AimPointDragFigure` 内绘制）。
- **建议**：chrome 文案映射到既有 `Font.bt*`（展示误差可用 `btTitle`/`btTitle2`）；按钮字重与 `GeometricAngleQuizView` 场景胶囊对齐时，优先收成共享 helper，避免四页各写一套 size。
- **语义影响**：无（换 token，不改文案含义）。
- **严重度**：P3

### F-SA-08 装饰球库底栏 `Color(white: 0.11)` 与 `spacing: 3` 三页复制
- **类别**：D一致性
- **位置**：
  - `SceneAimingView.swift:157`、`:170`
  - `AimPointSceneTrainingView.swift:512`、`:525`
  - `ShotSimulationView.swift:271`、`:289`
- **现状**：底栏背景与球行间距均为魔法数，未用 `Color.btBG*` / `Spacing`；三页结构几乎相同却各自拷贝。
- **问题**：对照基准 D3（硬编码颜色/间距）与 D2（同类底栏应同形态同源）。
- **建议**：收成共享 `decorativePalette`/`ShotPaletteBar` 背景 token（若无完全匹配的 btBG，先在 DesignSystem 增语义色再引用）；行距用最接近的 `Spacing.xs`（4）或接受 3 并命名常量一处定义。
- **语义影响**：无（装饰不可点，不改摆球/高亮逻辑）。
- **严重度**：P3

## 存疑项（不确定是否越红线的，单独列出待主控裁决，不算 finding）

1. **SceneAiming 总结卡是否加遮罩/变暗台面**：当前玻璃卡浮在亮台上，层级偏弱；加 scrim 可能被视作削弱台面展示（红线 2），故不进 findings。
2. **`BTTextActionButton` 全局无按压态**（`BTShotPageChrome.swift:87`）：SceneAiming / ShotSimulation / AimPointScene 的贴边主按钮都依赖它；属组件级收编，是否放本范围整改需主控定边界（本文件 F-SA-05 仅覆盖页面手写胶囊）。
3. **AimPointScene 提交后不可取消自动击球**：属交互模型，红线禁止改语义；若只加「可跳过等待」会改变流程，故不提。
4. **SceneAiming 进页强制 `showSettings = true`**：每次进页弹设置是否疲劳（B6）；「记住上次设置并跳过」可能改变入口流程语义，待产品裁决。
