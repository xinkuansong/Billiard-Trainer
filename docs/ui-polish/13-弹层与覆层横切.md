# UI 打磨审阅：弹层与覆层横切（OV）

> 对照基准：`docs/ui-polish/00-打磨基准.md`。本文件只做**跨页对比**；单页已记问题（如 SceneAiming 总结卡 transition、休息覆层字号、Silu 清空无确认、批量台 banner 成败同色等）见 `01`–`10`，此处不重复。

## 概述

全库弹出性 UI 盘点（`QiuJi/`，2026-07-13 Grep）：

| 类型 | 约数量 | 主要位置 |
|---|---|---|
| `.sheet(` | 29 处 | 订阅 Paywall、登录、开球/休息/球形选择、知识说明、Drill 选择、设置、历史详情、训练分享等 |
| `.fullScreenCover(` | 2 处 | `TrainingHomeView` 开训会话；`DrillTutorialView` 媒体全屏 |
| `.alert(` | 14 处 | 结束训练、保存失败、删除计划、清除缓存/注销、恢复购买、激活计划、相册已保存、数据同步等 |
| `.confirmationDialog(` | 4 处调用（含 `BTOverflowMenu`） | 自由击球清空、编排台清空/重来、溢出菜单 |
| `BTSpinPadOverlay` | 9 个宿主页 + 组件定义 | PositionPlay / Snooker / Bank / Diamond / ShotSimulation / BatchAuthoring 等 |
| 顶栏 toast `bannerView`/`flash` | ≥8 页近乎复制 | FreePlay / PlanThree / Silu / Composer / Snooker / ShotSimulation / BatchAuthoring；Extraction 另写红底版 |
| 底栏/状态 banner | 1 套（语义色正确） | `AngleDynamicView` `statusBanner` |
| 自定义居中/浮层 | 多处 | 休息倒计时、场景总结卡、试打说明卡、Premium 锁、NumericKeypadHUD、结果 HUD |

**呈现方式粗分**：系统 sheet（多数无 detent）→ 半高/固定高度选择 sheet → 系统 alert / confirmationDialog → ZStack 自定义覆层（有/无 scrim）→ 顶/底临时横幅。

D1 全库动效总表见 `09`；弹层进出场例外在 Findings 内说明。

## Findings

### F-OV-01 选择类 / 设置类 sheet 的 detent 与拖拽把手未收编
- **类别**：D一致性
- **位置**：
  - `QiuJi/Features/PositionPlay/Views/FreePlayView.swift:77-84`（开球选择 `.height(360)` + `.presentationDragIndicator(.visible)`；同型见 `PlanThreeView.swift:79-82`、`SiluTrainerView.swift:76-79`）
  - `QiuJi/Features/Training/Views/DrillRecordView.swift:206-208`（休息时长 `.height(250)`，**无** drag indicator）
  - `QiuJi/Features/AngleTraining/Views/SceneAimingView.swift:82-83`（训练设置 `.medium`，无显式 drag indicator）
  - `QiuJi/Features/Training/Views/CustomPlanBuilderView.swift:423`（单项 drill 设置 `.medium`）
  - `QiuJi/Features/AngleTraining/Views/BankShotView.swift:69-70` / `DiamondSystemView.swift:70-71`（知识说明 `.medium, .large`）
  - `QiuJi/Features/DrillLibrary/Views/DrillDetailView.swift:186-187`（球形选择 `.medium, .large` + 强制 dark）
  - 对照：绝大多数 `SubscriptionView()` sheet（如 `ProfileView.swift:86-87`、`HistoryCalendarView.swift:61-62`）**不设** detent，走系统默认大 sheet
- **现状**：同属「短列表/轮盘选择」的开球 vs 休息：一个 360+把手、一个 250 无把手；同属「页内配置」的场景训练设置 vs drill 设置均为 `.medium` 但与知识说明的 `.medium+.large`、订阅全高 sheet 再分裂一套。用户跨页拉起底部面板时高度与可拖暗示不一致。
- **问题**：对照 **D2**（同类交互同形态）。
- **建议**：按内容族收编 3 档即可——① 短选择（开球/休息/wheel）：统一固定高度 + `.presentationDragIndicator(.visible)`；② 表单/设置：`.medium`（可加 large）；③ 长文说明：`.medium, .large`；Paywall/登录保持默认大 sheet。不改各 sheet 内业务字段。
- **语义影响**：无（仅呈现高度与系统把手可见性，不改变选项与回调）。
- **严重度**：P2

### F-OV-02 破坏性确认混用 alert 与 confirmationDialog，按钮声明顺序也不一
- **类别**：D一致性 / B微交互
- **位置**：
  - `confirmationDialog`：`FreePlayView.swift:69-76`（「清空桌面」destructive →「取消」）；`PositionPlayComposerView.swift:125-140`（清空/重来同型）
  - `alert`：`SettingsView.swift:34-45`（清除缓存/注销：destructive 声明在前，cancel 在后）；`PlanListView.swift:88-93`（删除计划：**cancel 在前**，destructive 在后）；`ActiveTrainingView.swift:106-113`（结束训练：cancel「继续训练」在前，destructive「结束」在后）
- **现状**：桌面清空走底部 action sheet；设置/计划删除/结束训练走居中 alert。同属「不可轻易撤销的破坏/结束」，形态与按钮书写顺序跨模块不一致（系统虽会按 role 排版，但文案角色命名也不统一：「确认清除」vs「删除」vs「清空桌面」vs「结束」）。
- **问题**：对照 **D2**、**B4**（破坏性确认应有一致壳，而非有的 sheet、有的 alert）。
- **建议**：破坏性「清空/删除/注销」统一 `confirmationDialog`（与编排台/自由击球对齐）；「结束训练」可保留 alert（有补充说明文案），但 cancel/destructive 声明顺序与用词结构与 PlanList 对齐（取消/安全项在前，破坏项在后）。不改各操作实际副作用。
- **语义影响**：无（仍是同一确认后执行同一删除/清空/结束）。
- **严重度**：P2

### F-OV-03 临时提示横幅：语义色、锚边、材质三套并存且未共享
- **类别**：D一致性 / C视觉
- **位置**（横向对比；单页「成败同色」细节见 `06` F-PP-05、`10` F-BD-02，此处只收「全库未收敛」）：
  - 顶栏绿胶囊复制族：`FreePlayView.swift:496-515`（含规则限制文案仍 `Color.btSuccess`，见 `:256` `flash("按当前规则不能打…")`）；同结构 `PlanThreeView.swift:545-564`、`ShotSimulationView.swift:383-402`、`SnookerTacticsView.swift:376-395`、`BatchAuthoringView.swift:948-967`（时长 **1.8s**，其它多为 **1.6s**）
  - 顶栏红胶囊：`BallExtractionView.swift:617-630`、`BatchBallExtractionView.swift:626-636`（一律 `btDestructive`）
  - 底栏 HUD 玻璃 + 按态着色：`AngleDynamicView.swift:114-125`、`:259-284`（提示 `btPrimary`、不可行 `btDestructive`，transition 自 **bottom**）
- **现状**：台面页把成功/限制/失败都塞进同一绿 toast；建球形把提示也画成错误红；角度动态页则正确按语义着色且贴底。位置（顶 60pt vs 底 inset）、材质（实心胶囊 vs `btHudGlass`）、时长（1.6 vs 1.8）同时漂移。无共享 `BTToast`/`flash(tone:)`。
- **问题**：对照 **D2**、**C2**（颜色权重应匹配重要性）、**D4**（重复手写已有模式）。
- **建议**：抽一层共享临时提示（tone: success / info / warning / error + 默认顶栏、时长 1.6s）；AngleDynamic 的底栏状态条可保留为「常驻状态」特例并文档化。迁移时只换外壳与色，不改文案与触发时机。
- **语义影响**：无（仍是同一句提示出现/消失；不增删业务分支）。
- **严重度**：P2

### F-OV-04 短暂「完成」反馈：有的强制点 alert，有的自动 toast
- **类别**：D一致性 / B微交互
- **位置**：
  - 需点确认：`TrainingShareView.swift:37-39`（`.alert("已保存到相册")` +「好的」）；`SubscriptionView.swift:48-52` / `SubscriptionStatusView.swift:28-32`（「恢复购买」结果 alert +「好的」）
  - 自动消失：台面族 `flash`（如 `FreePlayView.swift:511-515`「已移回球库」类，1.6s 自清）
  - 对照错误类已统一走 alert：`ActiveTrainingView.swift:119-127`、`CustomPlanBuilderView.swift:67-75`（「保存失败」+「确定」）
- **现状**：同属「操作已完成、无后续分支」的成功反馈，分享页用阻断式 alert，台面用非阻断 toast；恢复购买用 alert 尚可理解（文案可能较长），但「已保存到相册」与「已移回球库」信息量同级却形态分裂。成功按钮文案「好的」vs 失败「确定」也不统一。
- **问题**：对照 **D2**、**B3**（完成反馈应一致且不过度打断）。
- **建议**：无分支的短成功（相册已保存、已移回球库）统一非阻断 toast；保留 alert 给「需阅读的结果/错误/双路径决策」。按钮文案收编为「确定」或「好的」二选一。
- **语义影响**：无（不改变保存/恢复逻辑，只改反馈壳）。
- **严重度**：P2

### F-OV-05 自定义「居中结果/休息」覆层：scrim 与进出场策略不一致
- **类别**：A动效 / D一致性
- **位置**：
  - 有 scrim + opacity 进出：`ActiveTrainingView.swift:54-60`（`.transition(.opacity)` + `easeInOut(0.25)`）、`:548-551`（`Color.black.opacity(0.3)` 遮罩）
  - 无 scrim、且无有效 transition（单页已记驱动问题，此处只比「罩层」）：`SceneAimingView.swift:66`、`:402-430`（总结卡直接叠在台面上，无 dimming）
  - 轻浮层无罩、有淡入淡出意图：`PositionPlayComposerView.swift:268-279` + `DrillTryoutBrief.swift:117-153`（说明卡 `btHudGlass`，点卡/`easeOut(0.25)` 退出；**不阻断**操作，属有意非 modal）
  - 对照：`BTSpinPadOverlay`（`BTSpinPad.swift:331-340`）用近不可见命中层 `opacity(0.001)` 专供点外关闭——合理例外
- **现状**：同为「盖住主内容的阶段性 UI」，休息倒计时有 30% 黑罩强调模态；场景训练结束总结卡无罩、视觉上像普通 HUD；试打说明卡明确非 modal。用户对「这是不是必须先处理完才能碰台面」的预期靠猜。
- **问题**：对照 **A5/A6**（覆层进出应有过渡且路径对称——休息已有 opacity；总结卡见 `04` F-SA-01 不重复改 transition）、**D2**（modal vs non-modal 应用 scrim 的规则未写死）。
- **建议**：定义两档——**Modal 覆层**（休息、测验总结）：统一浅 scrim（如 `black.opacity(0.28–0.35)`）+ opacity 进出（≤300ms，或基准 spring `0.34/0.86`）；**Non-modal 提示**（试打说明、SpinPad）：无可见 scrim。总结卡加 scrim 时保持台面仍可见（半透明），避免违反「不削弱内容展示」。
- **语义影响**：无（不改变休息跳过/总结「下一题」等操作，只加视觉模态暗示）。
- **严重度**：P2

### F-OV-06 知识说明 sheet 与场景内设置 sheet 同为「辅助信息」但可拖高度档位不同
- **类别**：D一致性
- **位置**：
  - `BankShotView.swift:69-70`、`DiamondSystemView.swift:70-71`：说明 → `.medium, .large`
  - `SceneAimingView.swift:82-83`：训练设置 → 仅 `.medium`
- **现状**：用户在角度训练族内，点「原理/说明」可拉到 large 读长文；点齿轮设置锁在 medium。设置内容若略长会出现内滚拥挤，而说明页却允许扩展——同模块辅助面板手感不齐。
- **问题**：对照 **D2**。
- **建议**：场景设置与知识说明统一 `.medium, .large`（或设置若字段少则文档标明「短表单锁定 medium」）；两者均建议显式 `.presentationDragIndicator(.visible)`。
- **语义影响**：无（仍是同一设置项与同一说明文案）。
- **严重度**：P3

### F-OV-07 成功/失败 alert 确认按钮文案：「好的」与「确定」混用
- **类别**：D一致性 / C视觉（文案）
- **位置**：
  - 「好的」：`TrainingShareView.swift:38`；`SubscriptionView.swift:49`；`SubscriptionStatusView.swift:29`
  - 「确定」：`ActiveTrainingView.swift:123`；`CustomPlanBuilderView.swift:71`
- **现状**：同为单按钮关闭的结果/错误 alert，用词不统一（C6：同一概念同一叫法）。
- **问题**：对照 **C6**、**D2**。
- **建议**：全库单按钮 dismiss 统一「确定」（或统一「好的」）；破坏性确认继续用具体动词（删除/清空/注销）。
- **语义影响**：无（仅文案）。
- **严重度**：P3

## 存疑项（待主控裁决，不算 finding）

1. **试打进场 `easeIn(0.45)`**（`PositionPlayComposerView.swift:154`）：基准 A1 倾向 P1，但 `06` 已标存疑并与 Brief 卡时序绑定——是否划入动作库/试打专项，本横切不重复定罪。
2. **订阅 sheet 是否统一加 detent**：Paywall 全高是有意「沉浸促销」还是应与其它辅助 sheet 同族？改 detent 可能影响转化观感，需产品点头。
3. **AngleDynamic 底栏状态条**是否并入共享 toast：它更像「持续状态」而非 flash；强行顶栏化可能削弱拖球教学提示（红线 2 风险）。
4. **结束训练用 alert 而非 confirmationDialog**：有说明性 message，保留 alert 可能合理；是否与 F-OV-02 一并收编由主控定。
5. **`BTPremiumLock` 全罩 vs 订阅 sheet**：锁是页内门闸、订阅是交易流，两套呈现合理；是否要给锁加统一 transition 属锦上添花，证据不足未列 finding。
