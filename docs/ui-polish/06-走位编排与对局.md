# UI 打磨审阅：走位编排与对局（PP）

审阅范围：`PositionPlayComposerView`、`FreePlayView`、`SiluTrainerView`、`PlanThreeView`、`SnookerTacticsView`、`BallExtractionView`。  
未审：`DrillTryoutBrief`（归动作库）。试打变体专属动画仅列入存疑。  
基准：`docs/ui-polish/00-打磨基准.md`（2026-07-13）。

---

## 页面概述

**PositionPlayComposerView（自由走位 / 编排台）**  
摆球编排与连续击打推演页：台面全宽取景，顶栏进袋/自由切换与读数胶囊，右柱打点+力度+击球/上一杆/回放，底栏两排球库拖放落位。录制/清空走菜单；求解态与状态文案上移导航栏。台面与解线是内容主角。

**FreePlayView（自由击球）**  
从开球开始的完整对局页：布局与编排台同构，但球库只读参考、左下开球入口真实可用；开球「完成」后可挂规则引擎 HUD。底栏在开球条与球库间切换。

**SiluTrainerView（思路训练）**  
走位反解器：顶栏工具 chips（落区/落点/过点/摆球）画约束，左柱求解/下一解/开球，右柱仪表+击球列，底栏球库。导航栏 ProgressView +「求解中…」是进行时反馈主通道。

**PlanThreeView（打一走二想三）**  
在思路训练骨架上叠加底部角色横排（①球/①袋/②球/②袋/③球）与扇形引导；「打一」动作列文案替换「击球」。角色武装态有独立 spring。

**SnookerTacticsView（做斯诺克）**  
布局对齐思路训练：顶栏目标球/障碍球/摆球，左柱求解列（开球按钮禁用态占位），无开球流程。求解/无解反馈走导航状态行。

**BallExtractionView（拍照建球形）**  
四步向导（选图→标定→标球→2D 确认），确认步复用球库拖放语言，产出 `BoardSnapshot` 送入编排台/思路/打一走二想三。UI chrome 以步骤头、底栏按钮、球库为主。

## Findings

### F-PP-01 求解系三页「清空桌面 / 恢复默认」无确认，与自由击球不对齐
- **类别**：B微交互 / D一致性
- **位置**：
  - `QiuJi/Features/PositionPlay/Views/SiluTrainerView.swift:446-447`
  - `QiuJi/Features/PositionPlay/Views/PlanThreeView.swift:534-535`
  - `QiuJi/Features/SnookerTactics/Views/SnookerTacticsView.swift:365-366`
  - 对照：`FreePlayView.swift:69-75`、`PositionPlayComposerView.swift:125-140`
- **现状**：思路训练 / 打一走二想三 / 做斯诺克菜单直接 `vm.clearTable()` / `vm.resetAll()`；自由击球对清空一律 `confirmationDialog`；编排台在录制中清空与「清空并重来」亦有确认。
- **问题**：对照 **B4**（破坏性操作应有确认或可撤销）与 **D2**（同类交互同形态）。误触会瞬间丢整桌球位与约束，且无撤销入口。
- **建议**：三页对「清空桌面」「恢复默认」复用编排台/自由击球的 `confirmationDialog` 文案模式（仅加确认壳，不改清空语义）。
- **语义影响**：无（仍执行同一清空/恢复，仅补确认闸）。
- **严重度**：P2

### F-PP-02 本范围主操作按钮普遍无按压态
- **类别**：B微交互
- **位置**：
  - 共享击打列：`QiuJi/Core/Components/BTShotPageChrome.swift:87`（`BTTextActionButton` → `.buttonStyle(.plain)`），被 Silu / PlanThree / Snooker / Composer / FreePlay 的「求解/击球/上一杆」使用
  - `FreePlayView.swift:542`、`:558`、`:586`（开球条「取消 / 完成 / 开球」）
  - `BallExtractionView.swift:540`、`:552`、`:598`、`:613`（「下一步 / 选择照片 / 送入…」等手写胶囊）
- **现状**：可点主操作仅靠颜色区分启用态，按下无 scale / 高亮；同库 `BTButtonStyle` 已有 `scaleEffect(0.98)` + 0.1s 反馈（`BTButton.swift:49-50`）。
- **问题**：对照 **B1**（主要操作按钮无按压态 = P2）。击球/求解/开球/下一步均为本范围最高频 CTA。
- **建议**：给 `BTTextActionButton`（及本页手写胶囊）加与 `BTButtonStyle` 同参数的按压 scale（0.96–0.98）或抽共享 `ButtonStyle`；不改 action / disabled 语义。
- **语义影响**：无（仅视觉按下反馈）。
- **严重度**：P2

### F-PP-03 拍照建球形四步切换无过渡，整屏硬切
- **类别**：A动效
- **位置**：`QiuJi/Features/BallExtraction/Views/BallExtractionView.swift:82-88`
```swift
switch vm.step {
case .pickPhoto: pickStep
case .calibrate: ...
```
- **现状**：`content` 按 `vm.step` 直接换子树，无 `animation` / `transition`；从选图→标定→标球→确认时整屏控件突现突消。
- **问题**：对照 **A6**（出现/消失无过渡造成跳变 = P2）。步骤指示条颜色会变，但主内容区无配对过渡。
- **建议**：对 `content` 加短 opacity（或 matched 步骤头）过渡，时长 200–250ms、ease-out / 基准 spring `0.34/0.86`；保持四步状态机不变。
- **语义影响**：无（不改变步骤顺序或校验）。
- **严重度**：P2

### F-PP-04 选图异步加载无进行时反馈
- **类别**：B微交互
- **位置**：`QiuJi/Features/BallExtraction/Views/BallExtractionView.swift:707-720`
- **现状**：`loadPhoto` 在 `Task` 中 `loadTransferable`，成功后才 `vm.step = .calibrate`；期间无 ProgressView / 禁用「选择照片」/ 顶栏状态。
- **问题**：对照 **B3**（加载中要有明确进行时反馈）。大图或相册慢时，用户会以为点了没反应。
- **建议**：加载期设 `@State isLoadingPhoto`，顶栏或主区显示 mini `ProgressView`，并临时 disable PhotosPicker；失败时沿用现有 banner 通道提示。
- **语义影响**：无（不改选图结果或后续标定）。
- **严重度**：P2

### F-PP-05 拍照建球形横幅一律用破坏色，提示与错误不分
- **类别**：B微交互 / C视觉
- **位置**：
  - View：`BallExtractionView.swift:624`（`.background(Color.btDestructive, in: Capsule())`）
  - 触发例：`BallExtractionViewModel.swift:399`（`flash("…号已在桌上")` — 属操作提示非失败）
- **现状**：所有 `vm.message` 横幅固定 `btDestructive` 红底；编排台等同系页成功/提示用 `btSuccess`（如 `PositionPlayComposerView.swift:635`）。
- **问题**：对照 **B3**（反馈类型应诚实）与 **C2**（危险色权重应留给真正破坏/失败）。提示性文案被渲染成错误，削弱警示色可信度。
- **建议**：横幅按语义分流（提示 → `btSuccess`/`btPrimary` 弱底；错误 → `btDestructive`），或给 `flash` 增加 level 参数；不改文案内容本身。
- **语义影响**：无（只改反馈配色层级）。
- **严重度**：P2

### F-PP-06 「打一走二想三」角色芯片 spring 过弹且偏离基准
- **类别**：A动效 / D一致性
- **位置**：`QiuJi/Features/PositionPlay/Views/PlanThreeView.swift:325-326`
```swift
.scaleEffect(armed ? 1.03 : 1)
.animation(.spring(response: 0.3, dampingFraction: 0.7), value: armed)
```
- **现状**：武装态 scale 1.03 + `dampingFraction: 0.7`；同页 SpinPad 已用基准 `0.34/0.86`（L63）。角色芯片在底部横排，用户会连续点选。
- **问题**：对照 **A7**（无手势动量的 UI 用 dampingFraction < 0.75 = 过弹）与 **A3**（高频操作动画应极短或克制）；**D1** 相对 §1.2 面板 spring 漂移。
- **建议**：收编为 `spring(response: 0.34, dampingFraction: 0.86)`，或降为 opacity/描边切换、去掉 scale bounce。
- **语义影响**：无（不改变角色武装/赋值逻辑）。
- **严重度**：P2

### F-PP-07 自由击球打点盘浮层未贴底对齐，与同系页不一致
- **类别**：D一致性
- **位置**：
  - `FreePlayView.swift:161-165`（仅 `transition`，无贴底 frame）
  - 对照：`PositionPlayComposerView.swift:289-294`、`SiluTrainerView.swift:202-207`、`PlanThreeView.swift:204-208`、`SnookerTacticsView.swift:172-177`（均有 `.frame(..., alignment: .bottom)`）
- **现状**：同组件 `BTSpinPadOverlay` + 同 spring(0.34/0.86)，唯自由击球缺少铺满 stage 并底对齐的 frame，浮层垂直落点依赖 ZStack 默认布局，易与其它页视觉不一致。
- **问题**：对照 **D2**（同类交互同形态）。
- **建议**：补上与编排台相同的 `.frame(maxWidth: .infinity, maxHeight: .infinity, alignment: .bottom)`。
- **语义影响**：无（不改变打点读写）。
- **严重度**：P3

### F-PP-08 开球模式进出时顶栏/底栏 chrome 硬切
- **类别**：A动效
- **位置**：
  - `FreePlayView.swift:287-302`（`if vm.isBreakMode` 顶栏）、`:406-415`（底栏 `breakRunner` ↔ 球库）
  - 同模式：`PositionPlayComposerView.swift:377-383`、`:477-483`；`SiluTrainerView.swift:110-117`、`:338-344`；`PlanThreeView.swift:113-120`、`:424-433`
- **现状**：`isBreakMode` 切换时顶栏胶囊与底栏整块 `Group` 互换，无 `animation`/`transition`；台面内容可连贯，但 UI chrome 瞬间替换。
- **问题**：对照 **A6**（chrome 突现突消）。开球是低频模式切换，适合短 crossfade，而非硬切。
- **建议**：对顶栏/底栏内容加 opacity 交叉淡入淡出（≤250ms，基准 spring），保持开球状态机与按钮语义不变。
- **语义影响**：无（不改开球流程或完成交付）。
- **严重度**：P3

### F-PP-09 底栏与角色强调色大量 Token 逃逸
- **类别**：D一致性
- **位置**：
  - 底栏底色：`PositionPlayComposerView.swift:486`、`FreePlayView.swift:418`、`SiluTrainerView.swift:347`、`PlanThreeView.swift:436`、`SnookerTacticsView.swift:266`、`BallExtractionView.swift:336` — 均为 `Color(white: 0.11)`
  - 角色色：`PlanThreeView.swift:32-34` — `Color(red: 0.36, …)` / `0.20,…` / `1.0,…` 硬编码
- **现状**：六页重复 magic 灰底；①②③角色用不经 `Color.bt*` 的 RGB。台面/球体渲染豁免不适用（此为 UI chrome）。
- **问题**：对照 **D3**（硬编码颜色属收编对象）。暗色层级与 DesignSystem 四级 bg 脱节，后续改主题需改多处。
- **建议**：底栏收编为语义 token（如 `btBGTertiary` 或新增 `btHudBar`）；角色色若需固定语义，定义为 DesignSystem 命名色后引用。
- **语义影响**：无（仅替换色值来源，不改布局/交互）。
- **严重度**：P3

### F-PP-10 确认页拖球回库无完成反馈，编排台有横幅
- **类别**：B微交互 / D一致性
- **位置**：
  - `BallExtractionView.swift:492-497`（`removeFromTable` 后无 flash）
  - 对照：`PositionPlayComposerView.swift:594-595`、`SiluTrainerView.swift:429-430`、`PlanThreeView.swift:517-518`、`SnookerTacticsView.swift:348-349`（`flash("已移回球库")`）
- **现状**：确认步同样支持拖回球库删除，但无「已移回球库」类完成反馈；用户只能靠球库透明度变化推断。
- **问题**：对照 **B3**（完成要有完成反馈）与 **D2**（同类拖回交互同反馈）。
- **建议**：与编排台对齐，删除成功后走现有 `message`/`flash` 通道（并注意 F-PP-05 的配色分流）。
- **语义影响**：无（不改变删除行为）。
- **严重度**：P3
