## 页面概述

**BatchDrillStudioView（目录入口，Core）**  
列出项目 15 截图源目录下待出片 drill：开工勾选、截图数/已存球形数、未登记警告；点行进入拍照建球形。工具栏刷新重扫磁盘。

**BatchBallExtractionView（拍照建球形）**  
四步向导（选图栅格 → 四角标定 → 标球 → 2D 确认），逻辑对齐生产版 `BallExtractionView`，图源改为 drill 文件夹；已存图可「重做」跳过标定直接进编排台续接。确认后 `goAuthor` 推入编排求解页。

**BatchAuthoringView（编排求解二合一）**  
复用 `PositionPlayViewModel` 录制机 + `BatchShotSolver` 反解层：顶栏 chips（落区/落点/过点/摆球/自由）+ 求解行；台面贴边仪表/击球列/辅助线/点换；底栏保存横排 + 两排球库。序列按 drill×图 token 直写内容库。

## Findings

### F-BD-01 同图「保存」静默覆盖内容库 JSON，无确认闸
- **类别**：B微交互
- **位置**：
  - `QiuJi/Features/BatchDrillStudio/BatchAuthoringView.swift:906-923`（`save` 直接 `BatchSequenceArchive.archive`，无 `confirmationDialog`）
  - `QiuJi/Features/BatchDrillStudio/BatchDrillStudioCore.swift:269-274`（同 `stemPrefix` 先 `removeItem` 再写入）
  ```swift
  for file in (try? fm.contentsOfDirectory(atPath: directory)) ?? []
  where file.hasPrefix(stemPrefix) {
      try? fm.removeItem(atPath: "\(directory)/\(file)")
  }
  ```
  - 入口侧注释已标明覆盖语义：`BatchBallExtractionView.swift:222`「保存时按同一 token 覆盖原存档」
- **现状**：点「保存·选下张图 / 保存·下个drill」即删同图旧序列文件并写新文件；从已存缩略图「重做」进入再保存时同样静默覆盖。成功路径多为 `dismiss()`，无「已覆盖」完成态文案。
- **问题**：对照 **B4**——破坏性覆盖应有确认或可撤销。内容库 JSON 误点即丢上一版杆序，且 `try? removeItem` 失败亦无表面反馈。
- **建议**：仅当目标 `stemPrefix` / legacy 文件**已存在**时弹 `confirmationDialog`（「覆盖已存 N 杆序列？」）；首存仍一键写盘，不打断新建流水线。
- **语义影响**：无（仍按同 token 覆盖写库；只补确认壳，不改归档键或导出语义）
- **严重度**：P2（折算前相当于面向用户的 P1）

### F-BD-02 编排台 banner 成败一律 `btSuccess`，失败看起来像成功
- **类别**：B微交互 / C视觉
- **位置**：`QiuJi/Features/BatchDrillStudio/BatchAuthoringView.swift:947-967`
  ```swift
  .background(Color.btSuccess, in: Capsule())
  // …
  flash("保存失败：\(error.localizedDescription)")  // :941 亦走同一 banner
  ```
  - 对照同范围建球形页：`BatchBallExtractionView.swift:629-631` 用 `Color.btDestructive` 提示 `vm.message`
- **现状**：`flash` 承载成功（载入存档、点换完成）、告警（无母球）、**失败**（保存失败）三类文案，视觉全是绿色成功胶囊。
- **问题**：对照 **B3**（失败要有诚实反馈）与 **C2**（权重/语义色应匹配重要性）。保存失败被绿胶囊包装，易误判为已写入。
- **建议**：`flash(_:tone:)` 分 `.success / .neutral / .error`，错误用 `btDestructive`（与建球形 banner 对齐）；或错误改走与 Extraction 相同的 `message` 通道。
- **语义影响**：无（文案与触发条件不变，只改胶囊语义色）
- **严重度**：P2

### F-BD-03 求解进行时导航栏未接 `solver.isComputing`，与工具行双轨
- **类别**：B微交互 / D一致性
- **位置**：
  - 导航栏：`BatchAuthoringView.swift:371` — `composer.isComputing ? "求解中…" : composer.statusText`
  - 求解态：`BatchAuthoringView.swift:135-136, 441` — `solver.isComputing = true` + 工具行 `ProgressView`
  - 对照用户页：思路训练把「求解中…」放在导航进行时通道（见 `06-走位编排与对局.md` 概述）
- **现状**：`BatchShotSolver.solve` 只置位 `solver.isComputing`，**不**驱动 `composer.isComputing`。求解中工具行有 mini ProgressView +「求解中…」，导航栏仍可能显示编排引擎旧 `statusText`。
- **问题**：对照 **B3**（进行时应一致可见）与 **D2**（同类「求解中」形态）。高频出片时抬头扫导航栏会漏掉进行时。
- **建议**：`navStatus` 副文案改为优先 `solver.isComputing` / `solver.statusText`（求解工具激活时），与工具行同源；或导航栏副行在 computing 时显示 ProgressView（对齐 Silu）。
- **语义影响**：无（不改变求解触发、禁用条件或结果写回，只统一状态展示源）
- **严重度**：P3

### F-BD-04 保存 / 求解 / 向导主 CTA 手写 Capsule + `.plain`，无按压态
- **类别**：B微交互 / D一致性
- **位置**：
  - `BatchAuthoringView.swift:640-651, 657-666` — `actionPill` 保存横排，`.buttonStyle(.plain)`
  - `BatchAuthoringView.swift:448-456` —「求解」手写 Capsule + `.plain`
  - `BatchBallExtractionView.swift:565-581, 604-622` — `primaryButton` / `columnPrimary` 等手写胶囊 + `.plain`
  - 对照：`QiuJi/Core/Components/BTButton.swift:123-124` — `BTButtonStyle` 已有 `scaleEffect(0.98)` + `easeInOut(0.1)`
- **现状**：出片最高频 CTA（保存两去向、求解、下一步、送入编排台）按下无 scale/高亮；与组件库按压规范分裂。台面侧已复用 `BTTextActionButton` / `BTShotActionColumn`，底栏却另起一套。
- **问题**：对照 **B1**（主操作无按压态）与 **D4**（手写替身）。内部工具折算后仍可感知「点了没反应」的迟疑。
- **建议**：暗色矮胶囊抽共享 `ButtonStyle`（或给现有 `darkPill` 加紧凑高度变体），挂到 `actionPill` /「求解」/ Extraction 主次按钮；按压缩放 0.96–0.98，不改 disabled / tint 语义。
- **语义影响**：无（仅按下视觉，不改保存/求解动作）
- **严重度**：P3（折算前相当于面向用户的 P2）

### F-BD-05 已存勾选使用系统 `Color.green`，同流程拖放成功态用 `btSuccess`
- **类别**：D一致性
- **位置**：
  - `BatchBallExtractionView.swift:192-197` — 缩略图勾与描边 `Color.green`

  - 同流程对照：`BatchAuthoringView.swift:865`、`BatchBallExtractionView.swift:520` — 拖放命中台面描边已用 `Color.btSuccess`

- **问题**：对照 **D3**（硬编码色属 token 逃逸）与 **D2**（同一「成功/已完成」概念同色）。
- **建议**：勾选、描边、「已存」文案统一 `Color.btSuccess`（及 `btSuccess.opacity(…)`）。
- **语义影响**：无（同义替换语义色，不改变已存判定或入口）
- **严重度**：P3

### F-BD-06 建球形四步 `switch` 硬切，步骤条进度无过渡
- **类别**：A动效
- **位置**：`QiuJi/Features/BatchDrillStudio/BatchBallExtractionView.swift:72-78`
  ```swift
  switch vm.step {
  case .pickPhoto: pickStep
  case .calibrate: …
  ```
  - 步骤条：`BatchBallExtractionView.swift:86-90` — Capsule 填充随 `vm.step` 瞬时切换，无 `animation`
- **现状**：选图→标定→标球→确认整屏替换；顶栏三段进度条色块跳变。生产版同构问题已在 `F-PP-03` 记录，本工具为平行实现，出片路径仍走此页。
- **问题**：对照 **A6**（出现/消失无过渡造成跳变）。步骤切换是低频但每次建球形必经。
- **建议**：`content` 包一层 `.animation(.spring(response: 0.34, dampingFraction: 0.86), value: vm.step)` + 轻量 `opacity` 过渡；步骤条 `Capsule().fill` 同绑该 spring。勿改步骤状态机。
- **语义影响**：无（仍四步同一顺序与校验，只补切换过渡）
- **严重度**：P3

### F-BD-07 Banner 进出场动画未收编基准 spring / 缓动不一致
- **类别**：A动效 / D一致性
- **位置**：
  - `BatchAuthoringView.swift:963-967` — `withAnimation { banner = … }` 无参数（系统默认）
  - `BatchBallExtractionView.swift:635-636` — `.animation(.easeInOut, value: vm.message)`（默认时长）
  - 同页已吻合基准：`BatchAuthoringView.swift:322` — spin pad `spring(response: 0.34, dampingFraction: 0.86)`
- **现状**：提示条进出台用默认/`easeInOut`；同一编排页 spin pad 已用面板 spring。Extraction 与 Authoring 提示条缓动也不统一。
- **问题**：对照 **D1**（相对 §1.2 漂移）与 **A1**（进出场宜 ease-out / spring）。
- **建议**：两处 banner 统一 `withAnimation(.spring(response: 0.34, dampingFraction: 0.86))` 或 `.easeOut(duration: 0.22)`；保留现有 `move(edge: .top)+opacity` transition。
- **语义影响**：无（只改提示条动效曲线，不改文案时长策略以外的业务；自动消失 1.8s 可保留）
- **严重度**：P3

## 存疑项（待主控裁决，不算 finding）

1. **覆盖确认 vs 批量手感**：F-BD-01 若每次同图保存都弹确认，可能打断「改一杆→保存→下一张」节奏。是否改为「仅首次覆盖确认 + UserDefaults 记住本会话不再问」，还是始终确认——需内容工程使用频率拍板（加「记住」接近功能，可能触碰红线边缘）。
2. **`Color(white: 0.11)` 底栏**：`BatchAuthoringView.swift:615`、`BatchBallExtractionView.swift:401/480/561` 与全库击打底栏同值，已在 `F-GL-03` 全局收录；本范围不重复记 finding，整改应跟全局 token 收编。
3. **大面积 `.font(.system(size:))`**：三文件 chrome 几乎未用 `Font.bt*`。内部工具可读性优先、且击打页暗色 chrome 在用户页亦常见 system 字号；是否对本范围强制收编 token——与「不削弱内容」无关，但是否值得投入待定。
4. **确认页「移除」无确认**：`BatchBallExtractionView.swift:454-456` 单球删除；标球步有 undo/redo，确认步亦有。是否算 B4 破坏性——因可撤销，倾向不记；若 undo 栈在进编排后丢失，则另议。
5. **目录空态**：源目录不可读时 `drills` 为空，List 仅空 Section，无 `BTEmptyState` / 路径错误说明。偏工具运维提示，是否纳入打磨轮次待定。
