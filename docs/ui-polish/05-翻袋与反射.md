# UI 打磨审阅：翻袋与反射（BK）

审阅范围：`BankShotView` / `DiamondSystemView` 及其 ViewModel；本页用法中的 `BTShotInstrumentColumn`、`BTAimWheel`、`BTChipRow`、`BTShotPageChrome`（含 `BTAimModeToggleButton` / `BTTextActionButton` / `BTShotActionColumn`）、`BTSceneFAB`（本页已不直接使用，见存疑）。  
对照基准：`docs/ui-polish/00-打磨基准.md`。日期：2026-07-13。

## 页面概述

**翻袋解球器（`BankShotView`）**：2D 顶视求解页。用户摆母球/目标球、点选袋口与库数 chip，引擎反解翻袋路线；顶行「求解/自由」切换，右缘力度柱（求解输入），右下击打/下一解/重置，底栏球库拖障碍球；求解态可「击打」演示回放，自由态可瞄准试打、上一杆/回放/恢复球形。

**反射解球器（`DiamondSystemView`）**：与翻袋同构的 kick 求解页（母球先碰库再碰目标球），无袋口点选与切角读数；其余 chrome（模式、chip、力度柱、动作列、球库、演示/自由试打）镜像翻袋。两页刚完成双模式重构，交互语义定稿；本审阅只评呈现手感。

## Findings

### F-BK-01 演示/击球中瞄准轮无锁定视觉，与同屏其它控件不对称
- **类别**：A动效 / B微交互（A4、B3）
- **位置**：`QiuJi/Features/AngleTraining/Views/BankShotView.swift:124-128`（`DiamondSystemView.swift:124-128` 同构）
  ```swift
  BTAimWheel(onNudge: { vm.nudgeFreeAim(byDegrees: $0) })
      .btStageFrame(proxy.aimWheelFrame())
      .allowsHitTesting(!vm.isPlaying)
  ```
  对照同文件力度柱 / 顶行：`BankShotView.swift:142-143`、`101-102` 在 `isPlaying` 时另加 `.opacity(… ? 0.42 : 1)`。
- **现状**：自由模式下击球/回放时，瞄准轮仅关闭命中测试，外观仍为满不透明度玻璃尺；同屏顶行、力度柱、球库带均变暗，左下「恢复球形」与动作列按钮走 `disabled` 降透明。
- **问题**：对照基准 A4（锁定期间视觉反馈要到位）与 B3（进行时状态可见性）。用户看到「击球中…」pill，但左缘尺子看起来仍可操作，锁定反馈不完整。
- **建议**：与力度柱对齐——`isPlaying` 时对 `BTAimWheel` 加相同锁定透明度（建议统一常量，见 F-BK-04），或给轮身加一层禁用态遮罩；保持 `allowsHitTesting(false)` 不变。
- **语义影响**：无（不改变自由瞄准或演示锁定语义，只补锁定外观）
- **严重度**：P2

### F-BK-02 `isPlaying` 切换无动画，演示 pill / 锁定变暗 / 动作列形态跳变
- **类别**：A动效（A6）
- **位置**：`BankShotView.swift:178-181`（stage 动画绑定）与 `101-102`、`220-225`、`291-301`；`DiamondSystemView.swift` 对应 `179-182`、`102-103`、`221-226`、`291-301`
  ```swift
  .animation(.spring(response: 0.35, dampingFraction: 0.75), value: vm.solutionCount)
  .animation(.spring(response: 0.35, dampingFraction: 0.75), value: vm.hasSolution)
  .animation(.spring(response: 0.35, dampingFraction: 0.75), value: vm.mode)
  .animation(.spring(response: 0.34, dampingFraction: 0.86), value: showSpinPad)
  // 无 value: vm.isPlaying
  ```
  求解演示动作列：`else if vm.isPlaying { BTTextActionButton(title: "停止", …) }` 与常态三钮列硬切。
- **现状**：模式/有解/打点盘有 spring；进入/退出演示或自由击球时，「演示中…」pill、顶行/力度柱/球库 opacity、求解态三钮→单「停止」均为瞬时跳变。
- **问题**：对照基准 A6（出现/消失无过渡 = P2）。演示是低频状态切换，适合短 spring/opacity，而非硬切。
- **建议**：在 `topRow` 与 `stage` 增加 `.animation(.spring(response: 0.34, dampingFraction: 0.86), value: vm.isPlaying)`（或与模式切换同一套 `0.35/0.75`）；「停止」钮与三钮列用 `.transition(.opacity)` 包裹，避免布局瞬移。
- **语义影响**：无（仍在演示中锁控与显示停止，只补过渡）
- **严重度**：P2

### F-BK-03 场景主操作与顶栏 chrome 无按压态
- **类别**：B微交互（B1）
- **位置**：
  - `QiuJi/Core/Components/BTShotPageChrome.swift:87` — `BTTextActionButton` 使用 `.buttonStyle(.plain)`，无 `isPressed` scale/高亮
  - `QiuJi/Core/Components/BTShotPageChrome.swift:59` — `BTAimModeToggleButton` 同为 `.plain`
  - `QiuJi/Core/Components/BTChipRow.swift:38` — chip `Button` 同为 `.plain`
  - 页面主路径：`BankShotView.swift:228-231`「击打」、`84-87` 模式切换、`105-113` 库数 chip（`DiamondSystemView` 同构）
  - 对照已有按压态：`QiuJi/Core/Components/BTButton.swift:49-50`（`scaleEffect(0.98)` + 短 easeInOut）
- **现状**：击打/下一解/重置/停止、求解↔自由、库数 chip 按下无即时缩放或亮度变化；抬起后才看到状态结果。
- **问题**：对照基准 B1（主要操作按钮无按压态 = P2）。本页主操作密度高，缺按下反馈会感觉「点了没反应」，尤其在黑场玻璃底上。
- **建议**：为 `BTTextActionButton` / `BTAimModeToggleButton` / `BTChipRow` 增加轻量 `ButtonStyle`（按下 `scaleEffect(0.96…0.98)` 或背景略提亮，时长 ≤100ms），与 `BTButtonStyle` 家族对齐；勿引入重动画（A3 高频）。
- **语义影响**：无（不改点击结果与禁用逻辑，只加按下反馈）
- **严重度**：P2

### F-BK-04 锁定透明度三套数值，力度柱未走组件 `isDisabled` API
- **类别**：D一致性（D2）
- **位置**：
  - 顶行 / 力度柱：`BankShotView.swift:102`、`142-143` → `0.42`（Diamond 同构）
  - 球库带：`BankShotView.swift:430-431` → `0.55`
  - 组件内建：`BTShotInstrumentColumn.swift:22`、`63` — `isDisabled` 时 `opacity 0.5`
  - 编排台正确用法：`FreePlayView.swift:136-141` 传 `isDisabled: vm.isPlaying`
  - 本页绕开 API：`BankShotView.swift:132-143` 用外层 `.disabled` + `.opacity(0.42)`，未传 `isDisabled:`
- **现状**：同为「演示/击球中锁定」，顶栏与力度柱 0.42、球库 0.55、组件文档化禁用 0.5；翻袋/反射与编排台对同一 `BTShotInstrumentColumn` 的锁定写法不一致。
- **问题**：对照基准 D2（同类交互同形态）。用户在多页间切换时，锁定「灰掉多少」手感漂移。
- **建议**：页面改为 `BTShotInstrumentColumn(..., isDisabled: vm.isPlaying)`；抽出共享常量（如 `ShotChrome.lockOpacity = 0.5`）统一顶行/轮/柱/球库；删除外层重复 opacity（避免将来双叠）。
- **语义影响**：无（仍锁定输入，只统一锁定外观与 API）
- **严重度**：P2

### F-BK-05 球库底栏背景硬编码 `Color(white: 0.11)`
- **类别**：D一致性（D3）
- **位置**：`BankShotView.swift:426`；`DiamondSystemView.swift:424`
  ```swift
  .background(Color(white: 0.11))
  ```
- **现状**：底栏不用 `Color.btBG*` / `HUDStyle` 材质，直接灰阶字面量；与顶行纯黑、台面区并置时层级靠 magic 数撑起。
- **问题**：对照基准 §1.1 / D3（硬编码颜色属收编对象；台面球体渲染豁免，chrome 底栏不豁免）。
- **建议**：收编为语义色（例如扩展 HUD 底栏 token，或复用最接近的 `btBGTertiary` 并在暗场下验证），两页共用同一常量。
- **语义影响**：无（不改球库交互与高度，只换色值来源）
- **严重度**：P3

### F-BK-06 HUD 控件圆角与球库行距使用 magic number
- **类别**：D一致性（D3）
- **位置**：
  - `BankShotView.swift:198` — `RoundedRectangle(cornerRadius: 10, …)`（「恢复球形」）；`DiamondSystemView.swift:199` 同
  - `BankShotView.swift:421` — `VStack(spacing: 3)` 球库两行；`DiamondSystemView.swift:419` 同
  - `BankShotView.swift:227` / `BTShotPageChrome.swift:123` — 动作列 `VStack(spacing: 8)`（数值等于 `Spacing.sm` 但未引用 token）
- **现状**：`BTRadius` 仅有 6/8/12/…，页面写 10；球库行距 3 不在 `Spacing` 阶梯（xs=4）。动作列 8 与 token 同值但字面量漂移风险仍在。
- **问题**：对照基准 D3。两页完全复制，改一处易漏另一处。
- **建议**：恢复球形圆角收编到 `BTRadius.sm`(8) 或新增 HUD 专用 radius 常量并两页/开球钮共用；球库行距改为 `Spacing.xs`（或接受 4pt）；动作列改为 `Spacing.sm`。
- **语义影响**：无（不改控件职能与布局分区，只对齐 token）
- **严重度**：P3

## 存疑项（不确定是否越红线的，单独列出待主控裁决，不算 finding）

1. **`BTSceneFAB` 未在本页出现**：重构后主操作已统一为 `BTTextActionButton` 竖列（`BTShotPageChrome` 条 15.5/18.2）。若产品仍视 FAB 为「2D 球桌页」规范，属信息架构/组件选型，超出本轮「不改交互模型」；若 FAB 已退役，应在组件头注释标明以免误用。
2. **拖球中 `infoPill` 直接 `EmptyView()`**（`BankShotView.swift:278-279`）：pill 瞬隐可减少干扰，也可能被视作 A6 跳变。更偏求解过程 UX，改淡出可能被当成「拖动时仍显示旧解」的语义噪音——交主控定。
3. **自由态动作列在击球中仍展示三钮（标题变「击球中」、其余 disabled）**，求解态则收成单「停止」：属定稿交互差异，不评对错；若只打磨求解侧过渡（F-BK-02），自由侧是否也要整体降透明，避免与 F-BK-01 轮子问题叠加，待主控决定范围。
4. **HUD 大量 `.font(.system(size: 13…))`**：与 `HUDStyle` 自身用 system 字的取向一致，若强行改 `Font.bt*` 可能破坏暗场仪表语法；未单列 finding，是否收编进 `HUDStyle.label/value` 由设计系统轮次处理。
