## 页面概述

**TrainingHomeView（计划区块）**  
有激活计划时顶部「今日安排」最多三卡 + 底栏固定「开始训练/继续训练」；下方 `BTSegmentedTab` 切官方/自定义，官方侧 chips 过滤 + 双列海报，自定义侧行卡进编辑器。`TodaySessionInfo` 已带计划名与周主题，但标题区未消费。

**PlanListView**  
按等级分组的官方海报网格 +「我的计划」行卡；行内 Menu 提供编辑/激活/删除（删除有确认）；顶栏「新建」进构建器。激活写 `UserActivePlan` 后列表本身无「已激活」态。

**PlanDetailView**  
杂志 Hero + 要点条 + 周时间轴 + 仅「周」级手风琴（天/drill 为展开后的静态轨）；底栏三态：开始此计划 / 解锁 / 已激活横幅；激活有确认，成功后就地改态。

**CustomPlanBuilderView**  
名称 TextField、每周天数 ± 步进（`snappy` + `numericText`）、常驻 editMode 的可拖拽 List、添加项目 sheet、单项设置 sheet（组数/球数/移除）、工具栏「保存」Menu 双路径（仅保存 / 保存并激活）。

## Findings

### F-PL-01 激活计划后返回训练首页不刷新，今日安排仍是旧态
- **类别**：B微交互
- **位置**：`QiuJi/Features/Training/Views/TrainingHomeView.swift:37-45`；对照写入侧 `PlanDetailView.swift:530-542`、`PlanListView.swift:244-251`、`CustomPlanBuilderViewModel.swift:138-145`
```swift
.task {
    await viewModel.load(context: modelContext)
}
// fullScreenCover onDismiss 才会再次 load；push 详情/列表激活后 pop 无 onAppear/通知
```
- **现状**：首页只在首次 `.task` 与结束训练 `fullScreenCover` dismiss 时 `load`。`NavigationStack` 根页在 push 子页时不会消失，因此从详情「确定激活」、列表 Menu「激活此计划」、构建器「保存并激活」返回后，`hasActivePlan` / `todaySession` 仍是旧值；底栏与今日卡可能仍显示未激活或上一计划。
- **问题**：对照 B3——激活是低频关键状态变更，完成反馈的闭环应落到「训练」根页可见结果；当前详情页本地「已激活」与首页脱节。
- **建议**：根页对 `scenePhase`/`onAppear` 或 `UserActivePlan` 变更（Notification / 轻量 publisher）再次 `load`；或激活成功时统一发通知由 Home 收。不改激活语义本身。
- **语义影响**：无（只补齐既有激活结果的可见刷新）。
- **严重度**：P1

### F-PL-02 今日安排标题未展示已加载的计划名与周主题
- **类别**：C视觉 / B微交互
- **位置**：`TrainingHomeViewModel.swift:168-175`（数据已备）；`TrainingHomeView.swift:142-172`（UI 未消费）
```swift
todaySession = TodaySessionInfo(
    planNameZh: plan.nameZh, weekNumber: ..., weekTheme: week.theme, ...
)
// 视图仅渲染「第 N 周 / 第 N 天」+「今日安排」，无 planNameZh / weekTheme
```
- **现状**：ViewModel 为官方/自定义路径都写入 `planNameZh`、`weekTheme`，全工程无其它读取点；标题区只有周天序号与「今日安排」，用户在浏览区换计划后（若刷新修好）仍难一眼确认「当前跟的是哪份计划」。
- **问题**：对照 C2（身份信息权重过低）、B3（激活态可见性不完整）。
- **建议**：在「今日安排」主标题旁或副行展示 `planNameZh`（可加一行弱化 `weekTheme`）；不增入口、不改开训流程。
- **语义影响**：无（展示已有字段）。
- **严重度**：P2

### F-PL-03 列表「激活此计划」成功后无完成反馈（无标、无 toast）
- **类别**：B微交互
- **位置**：`PlanListView.swift:168-172`、`244-251`；对照详情成功态 `PlanDetailView.swift:188-199`
```swift
Button { activateCustomPlan(plan) } label: {
    Label("激活此计划", systemImage: "play.circle")
}
// activateCustomPlan：写库 save 后无 UI 状态；customPlanCard 无「已激活」徽章
```
- **现状**：Menu 一点即写库（确认缺失见 F-TR-04，此处不重复）；成功后卡片外观不变、无横幅/toast，与详情底栏「当前已激活此计划」不对齐。用户只能猜是否生效，再叠加 F-PL-01 更容易误判。
- **问题**：对照 B3、D2（同类激活完成反馈应同形态）。
- **建议**：激活成功后：① 行卡加「已激活」弱标（读 `UserActivePlan`）；② 或短时 toast「已激活「…」」。确认弹窗仍按 F-TR-04 单独收。
- **语义影响**：无（不改激活副作用，只补完成反馈）。
- **严重度**：P2

### F-PL-04 详情底栏三态切换无过渡，激活成功瞬间硬切
- **类别**：A动效
- **位置**：`PlanDetailView.swift:187-214`、`530-542`
```swift
Group {
    if isCurrentPlanActive { /* 成功横幅 */ }
    else if !plan.isPremium || subscriptionManager.isPremium { Button «开始此计划» }
    else { Button «解锁此计划» }
}
// activatePlan() 直接 isCurrentPlanActive = true，无 withAnimation / transition
```
- **现状**：确认后主 CTA 与成功横幅互换为即时替换；无 opacity/spring，和同页周折叠已有的 transition 手感分裂。
- **问题**：对照 A6（突现突消）、A1（状态切换宜 spring）。
- **建议**：对 `isCurrentPlanActive` 包 `withAnimation(.spring(response: 0.34, dampingFraction: 0.86))`，横幅用 `.opacity`（可选轻微 `.move`）。
- **语义影响**：无。
- **严重度**：P2

### F-PL-05 官方 / 自定义分段内容区硬切，无进出场过渡
- **类别**：A动效
- **位置**：`TrainingHomeView.swift:270-274`；分段控件自身动画在 `BTSegmentedTab.swift:18-19`（下划线有动画，内容无）
```swift
if viewModel.selectedTab == .official {
    officialPlanBrowsing
} else {
    customPlanBrowsing
}
```
- **现状**：Tab 下划线有 `easeInOut(0.25)`，下方海报网格 ⇄ 自定义列表无 `animation`/`transition`，整块内容瞬间替换，易感知为「闪一下」。
- **问题**：对照 A6；高频分段切换应用短过渡或共享元素节奏，避免内容零过渡。
- **建议**：对 `selectedTab` 加 `.animation(..., value:)` + 内容 `.transition(.opacity)`（时长 ≤200ms 或短 spring）。不改分段语义。
- **语义影响**：无。
- **严重度**：P2

### F-PL-06 周手风琴行头可点但无按压态
- **类别**：B微交互
- **位置**：`PlanDetailView.swift:285-296`
```swift
Button { withAnimation(.spring(duration: 0.3)) { ... } } label: {
    chapterHeader(week)
}
.buttonStyle(.plain)
```
- **现状**：整行是展开/折叠主控件，`.plain` 无 scale/高亮；仅靠 chevron 符号切换表达状态。弹簧参数漂移见 F-TR-12，此处只评按压。
- **问题**：对照 B1（主要可点元素应有按下即时反馈）。
- **建议**：自定义 `ButtonStyle`（scale 0.98 或背景短暂 `btBGTertiary`），与列表行按压惯例对齐。
- **语义影响**：无。
- **严重度**：P2

### F-PL-07 「添加训练项目」主入口无按压态

- **位置**：`CustomPlanBuilderView.swift:289-307`

- **语义影响**：无。

### F-PL-08 构建器训练列表高度按 `count * 80` 硬跳，增删无布局过渡
- **类别**：A动效
- **位置**：`CustomPlanBuilderView.swift:187-201`；增删 `CustomPlanBuilderViewModel.swift:61-69`、`76-78`
```swift
.frame(height: CGFloat(viewModel.drillItems.count) * 80)
// addDrill / removeDrill 直接改数组，无 withAnimation
```
- **现状**：List 嵌在 ScrollView 里用固定行高估算锁高度；从 picker 回来增一项或设置里移除时，外框高度瞬间跳变，列表项亦无插入/删除 transition。拖拽排序本身由系统 List 跟随（B2 合格）。
- **问题**：对照 A6；行高 magic `80` 亦属 D3 边缘，但主伤是跳变。
- **建议**：增删包 `withAnimation`（短 spring）；高度用 `animatable` 或改为非嵌套 List 的 `VStack`+`onMove` 以避免估高；行高收为命名常量并对齐真实 row 高度。
- **语义影响**：无。
- **严重度**：P2

### F-PL-10 Hero PRO 标 `padding(.top, 60)` 硬编码避让

## 存疑项（不确定是否越红线，待主控裁决，不算 finding）

1. **详情「天/drill」不可折叠**：概述写「可折叠周/天/drill」，实现仅周级手风琴；为天级加折叠会改变信息展开模型，是否本轮只维持周级？
2. **首页自定义行无激活/删除 Menu**：能力只在 `PlanListView`；补齐属跨页能力对称，还是改交互模型？
3. **今日已全部完成时底栏仍「开始训练」**：会再次开训当日项还是应降级文案？改文案/禁用可能碰功能语义。
4. **PlanList `NavigationLink` 包裹整卡再内嵌 Menu**：偶发手势抢占；若改为 swipeActions/独立按钮是否算交互模型变更？
5. **构建器「移除此训练」无确认**：编辑会话内软删除，补确认可能落入基准 B4「过度确认 = P3」反面，暂不升条。
