# ADR-v53：本地用户数据按 owner 隔离

- 状态：已采纳（代码完成，真实多账号环境待 H-26 验收）
- 日期：2026-09-03
- 关联：`问题集合_v53.md` W2/W3/W5

## 决策

六类顶层 SwiftData 用户数据统一持有非空字符串 `ownerKey`：设备游客为 `guest:<deviceGuestUUID>`，登录账号为 `account:<serverUserId>`。关系子对象通过父对象继承归属。所有生产查询、写入、恢复查重、删除保护和同步队列都以当前 owner 为边界。

V3→V4 时，旧无 owner 数据只能归入稳定设备游客，禁止根据“最近登录账号”猜测所有权。guest 数据登录后默认不可见且不可上传；只有用户明确确认迁移，才在可回滚事务中转给当前 account。用户拒绝时 guest 数据原样保留。普通退出不改 owner；账号注销成功按“本地数据保留”承诺转回 guest，并清理旧账号队列。

## 原因

最近账号不是数据所有权证据。猜测归属会造成 A/B 账号互见，甚至用 B 的 JWT 上传 A 的队列。显式 owner 同时保护界面、统计、计划、收藏、恢复和离线补传，且让游客迁移取得可审计的用户同意点。

## 兼容与回滚

- V1→V4 继续走既有分阶段迁移；V3→V4 保留数量、ID、日期、训练详情及计划关系。
- owner transfer 保存失败时回滚存储事务，并显式恢复已注册对象的内存 owner。
- 目标 owner 已有相同 session/angle/custom-plan ID、相同收藏、相同 active-plan 身份或相同 queue identity 时去重，不制造重复。
- 不提供降回 V3 的破坏性迁移；回滚应用版本前必须先备份 V4 store。
