# 文字提示与弹窗规范

版本：2026-09-25。用户要求：一致、美观，信息完整前提下避免冗余。适用全项目；每日清台为首个完整页面验证点。

## 信息分层

| 类型 | 目的 | 形式 | 生命周期 |
|---|---|---|---|
| 常驻状态 | 说明现在轮到谁、允许做什么 | 固定位置轻量状态标签 | 状态变化时更新，不因Toast消失 |
| 临时反馈 | 解释刚发生的结果或纠正误操作 | BTNoticeContent中性深色提示，图标少量语义色 | 自动消失；规则提示按优先级覆盖、重复续期 |
| 必须决策 | 用户必须选择下一步 | BTDecisionPanel；BTDecisionActionStyle | 选择后关闭，阻止透点；保留必要处置选项 |
| 阶段结果 | 解释结束原因与后续操作 | 结果区域/面板 | 用户操作后离开，不同时叠加同义Toast |

系统权限、系统错误Alert及平台选择器保留原生形式；普通业务不得自行创造另一套浮层。常驻教学状态不是Toast，不强制迁移为短时消息。

## 视觉

- 普通提示使用HUDStyle.panelBackground，白色正文，BTRadius.md，细描边。正文btFootnote；图标用成功/信息/警示/错误的语义色，禁止大面积高饱和底色用于高频提醒。
- 决策表面BTRadius.lg、Spacing.lg内边距；按钮至少44pt、BTRadius.sm。单一主操作为品牌绿，其余中性底；每日清台的阶段结果操作也复用该样式（常规宽112pt），避免iOS版本改变原生按钮形状；危险动作不可伪装成成功提示。
- 提示文字自然换行，不使用截断或缩字号来塞长文案。图标不能代替文字提供必须信息。
- 2D/3D使用相同HUD位置及样式。每日清台球桌最大化优先：仅保留原有44pt顶部工具栏，状态/临时提示使用台面overlay，不参与球桌尺寸计算，不得增设占位行；3D场景仍铺满底层；模态或打点盘展开时隐藏非必要反馈，避免叠层争抢。
- 计算状态在击球控件内表达，不额外弹底部气泡。主要操作仍有稳定的无障碍名称。

## 文案

先列必须信息，再压缩：原因、合法下一步、球的重置、换手、摆球范围、终局原因按事件保留。状态已显示的信息无需每杆重复弹出。

| 场景 | 文案示例 |
|---|---|
| 选错球组 | 当前打全色，请选择同组球 |
| 尚未定组 | 尚未定组，请选全色或花色球 |
| 黑八未解锁 | 先打完全色球，再打黑八 |
| 九球选错目标 | 请先碰1号球 |
| 试图直接选9 | 先碰1号球，可组合进9 |
| 没有直进路线 | 无可直进袋口，暂用自由模式 |
| 调方向 | 已调整方向，暂用自由模式 |

犯规信息不能统一删后半句；“自由球”与“线后自由球”必须区别。普通合法进球继续击球不弹重复消息；完成/失败由结果面板承载。结束兜底只写“本局已结束”，不再重复按钮已说明的“可重新开球”。

## 实施边界与验证

共享BTToastBanner已采用新提示表面，现有调用方保留业务时机与时长；每日清台接入统一决策面板、固定状态及规则优先级。其它原生Alert/confirmationDialog未批量改造。BTToast.present旧闭包式计时器仍有独立生命周期，尚未全项目迁移到BTRuleNoticeCenter；不能把视觉统一称为调度机制全部统一。

构建、规则测试、截图视觉、动态录屏分别验收。具体设备、失败、改进及实际证据见tasks/ui-reviews/UR-20260925-提示与弹窗体系.md。不得把待验证要求写为已经通过。
