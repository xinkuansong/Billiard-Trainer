# 球迹 v47 UI 精修护栏

版本：2.4 · 2026-08-30
状态：v47.9 生效。整体设计目标与全 App 覆盖保留，但停止代码先行；当前采用“逐张截图共同讨论 → 定向生成图 → 用户审核 → 通过后记录”的设计共创流程。`tmp/designer-screenshots/` 实测 66 张，用户口径 67 张，缺少的 1 张在核清前保持门禁。业务结构以当前 App、`route-coverage.csv` 与产品文档为准，详细流程见 `问题集合_v47.md`。

## 1. 目标

球迹已有完整的 SwiftUI Token、共享组件、页面结构和专业球桌视觉。v47 要让全部生产页面形成一致的专业训练系统，但通过全页审计、复用现有能力和渐进精修完成，不重建设计系统或重画全部组件。

视觉关键词：冷静、精确、数据化、可信赖、克制。共通方向是专业训练仪表盘、冷调与球路工程图语言；训练、数据、长内容、表单和暗场工具仍保持各自正确的页面语法。

## 2. 现有体系优先

- 优先复用当前 `Color`、`Font`、`Spacing`、按钮、卡片、列表、表单、Badge、空态与训练组件。
- 不直接改变共享默认外观；确有缺口时新增局部、opt-in variant，并先扫描全部调用方。
- 保留系统 Tab Bar、NavigationStack、Sheet、Alert、返回手势和五个无大标题的 Tab 根页。
- 不改变业务文案含义、数据、路由、统计口径、训练剂量、订阅门控、登录流程或几何。

## 3. 全 App 覆盖

1. 五个根页：无大标题、首要状态/动作明确、共享品牌语言一致。
2. 训练计划与流程：任务导向、输入状态连续、总结与分享层级清晰。
3. 动作库与练习：紧凑列表、真实球形优先、筛选/锁定/空态一致。
4. 学页与理论页：专业训练手册式排版、图解与正文节奏明确。
5. 认知训练与暗场工具：场景反馈一致，球桌/轨迹保持唯一重视觉。
6. 历史/统计：数据优先、减少无意义套卡、趋势和记录层级明确。
7. 个人、设置、认证、Onboarding 与订阅：训练档案、表单和品牌承诺一致。

每个生产可达页面都参与“保持 / 轻调 / 重点调整”审计和最终验收。达标页面允许保持原实现，不要求为了全覆盖制造代码改动。

复审证据见 `tasks/ui-reviews/UR-20260830-v47-full-app-baseline.md`。当前分级：

- 保持并保护：球桌、轨迹、真实球形、计划 Hero、暗场图谱与求解器；
- 轻调：训练/计划/动作/练习根页与账户子页；
- 重点调整：历史/统计、Profile 根页、登录/引导、精讲/学页/理论页；
- 先补证据：训练闭环、历史详情、完整 Paywall、错误/键盘/Dark/AX 与被门控遮挡页面。

## 4. 局部视觉规则

- 单屏只突出一个主动作；核心数字强于标签，次级信息主动降权。
- 分组优先使用对齐、留白和细分隔，不机械增加或删除卡片。
- 保持现有冷调与品牌绿；不新增暖色背景、霓虹 HUD 或通用科技网络。
- 球路工程图只使用球、假想球、碰撞点、瞄准/目标线、切线、分离角、库边/钻石刻度和坐标校准；禁止随机网络。
- 主题强度分为根页 `subtle`、长内容顶部 `editorial`、认证/引导 `hero`、已有球桌/SceneKit/Canvas 工具 `none`；不新增持续装饰动画。
- 页面左右边距、字号、圆角与控件尺寸优先使用现有 Token，不另建平行数值体系。
- 触摸目标至少 44pt；正文、关键图形、Dynamic Type 和 VoiceOver 继续满足现有无障碍要求。

## 5. 色彩、排版与表层基准

以下是全 App 设计评审目标，不授权直接全局改 Asset Token；实施先复用现有最接近的语义色，只有审计证明缺口时才新增 opt-in Token。

| 语义 | Light 参考 | Dark 参考 | 用途 |
|---|---|---|---|
| Canvas | `#F3F6F7` | `#071012` | 冷白 / 石墨页面底层 |
| Surface | `#FFFFFF` | `#111B1E` | 必要卡片、表单与分组 |
| Surface muted | `#E8EEF0` | `#1A292D` | 输入、搜索、提升层 |
| Primary text | `#11191C` | `#F2F6F7` | 正文与关键数字 |
| Secondary text | `#58686E` | `#A8B7BC` | 标签、时间与说明 |
| Separator | `#C7D2D6` | `#34474D` | 细分隔与边界 |
| Brand green | `#145C3A` | `#2FAD6B` | 主 CTA、选中与训练成功 |
| Engineering | `#6F8993` | `#78949E` | 球路、刻度与辅助线 |

- `btAccent` 的暖金只保留 Pro、收藏、警告和既有图表系列等前景语义，不扩散到页面背景。
- 核心数字显著大于标签并使用等宽数字；Section、行标题、正文和辅助文字保持稳定层级。系统字体与 Dynamic Type 是最终真源，不因设计稿引入 Web 字体。
- 间距沿用 4pt 基准与现有 `Spacing` Token；页面边距、Section 节奏、圆角和按钮高度优先复用既有值。
- 指标优先通过对齐、留白和 1px 分隔组织；阴影只用于真正悬浮层，避免连续卡片墙和玻璃拟态堆叠。

## 6. 页面语法

- **仪表盘根页**：一个首要状态或数字、一个主 CTA、次级信息清晰降权；主题背景为 `subtle`。
- **紧凑列表与表单**：动作库、设置、账户、订阅保持 iOS 原生感，通过行高、分隔、图标槽和状态标签建立节奏。
- **编辑式长内容**：精讲、学页、理论页突出标题、导语、结论、图解、正文和练习提示；背景只在顶部使用 `editorial`。
- **暗场工具**：球桌/轨迹为唯一重视觉，主题背景为 `none`；只统一 chrome、字号、工具按钮、状态和转场。
- **认证与引导**：可使用石墨、蓝黑或冷深绿 `hero`，但不改变登录方式、协议和业务流程。

## 7. 设计与验收工具

- 当前 SwiftUI、真实业务结构和原始截图是讨论基座。
- 每张截图先形成“保持项 / 修改项 / 禁改项”，再生成定向视觉稿；只有用户明确通过的版本才进入设计裁定。
- ImageGen 负责材质、光线、氛围、Hero 与构图探索；文字、按钮、状态、数据、教学几何和真实球路仍由原生实现承担。
- Stitch 既有产物冻结为历史探索，不再生成 Gate A/B。
- Figma、SnapSwift 只作为可选辅助，不是设计共创或后续实现的门禁。
- 设计阶段以用户审核为准；进入实现后仍以真实 App 的 Light/Dark before/after、相关测试和用户点验为准。

## 8. 样板门禁与抽象顺序

- v47.7/v47.8 的 TrainingHome、Statistics 和未完成的 Login/Onboarding 代码 Hero 降为历史探索，不视为已通过设计。
- 先用 `01-training-home`、`41-history-statistics`、`70-login + 72-onboarding` 校准根页、数据页和品牌页的共同语言。
- 校准后按页面族逐张讨论和生成；一个页面族全部“通过/保持”后，才允许制定该族 SwiftUI 实施计划。
- 不先改共享默认值。至少两个已确认页面出现同一缺口，且页面内组合会重复时，才提取共享 opt-in variant。
- 每张生成图通过前必须检查品牌、层级、同族、跨族和可实现性；单页更漂亮但破坏整体关系时不得锁定。
- 设计图通过不等于真实 App 通过；实现阶段另行补齐 Light/Dark、AX、键盘、状态、交互和回归证据。

## 9. 禁令

- 不重做全部组件，不建立新的完整 Design System；全页面覆盖不等于全页面都要产生代码 diff。
- 不预设必须新建 `BTBlueprintBackground`；只有全页审计证明现有能力不足时，才新增显式 opt-in 的主题能力。不得直接全局调整 `btBG`、默认字体、圆角或卡片样式。
- 不新增 Tab、路由、业务模块、数据维度或订阅能力。
- 不把 Figma/Stitch 假数据、生成文案、HTML 或截图直接并入 App。
- 不修改 `BTPlanCover`、`AngleGridCard.coverArea`、`AtmosphereCatalog` 的逐卡映射与 `cover*` 图片。

## 10. 判断标准

每个生产页面都必须判断是否符合整体设计要求；一次代码改动只有在以下条件同时成立时才进入实现：差距可从真实页面观察；现有组件复用方案已检查；改动范围可独立回退；验证方式明确；收益足以覆盖回归成本。
