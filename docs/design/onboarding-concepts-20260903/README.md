# 新用户引导页内容与视觉方向（待选）

日期：2026-09-03
状态：A/B/C 已被用户否决；D 聚焦系列待反馈。尚未替换 App 资源、尚未修改交互逻辑

## 1. 设计目标

把现有“功能罗列式”引导改为一条用户能立刻理解的价值路径：

1. **学：先看懂**——理解球路、碰撞点与角度关系。
2. **练：再练成**——通过官方计划和专项动作形成稳定训练节奏。
3. **记：看见进步**——沉淀训练量、成功率与薄弱项，让下一次练习更有方向。

保持现有三页结构、游客体验和登录入口，不在方向选择前改动认证或路由逻辑。

## 2. 推荐文案

### 第 1 页｜学

- 上眉：`看懂球路`
- 标题：`看清这一杆怎么走`
- 说明：`瞄准点、碰撞点、母球和目标球的路线，一眼看明白。`
- 视觉语义：母球、目标球、瞄准线、接触点；强调“理解”，不伪装成某个真实 Drill 的几何答案。

### 第 2 页｜练

- 上眉：`系统训练`
- 标题：`把训练做到球台上`
- 说明：`每天按计划摆球、练球、记录完成情况，不再漫无目的地打。`
- 视觉语义：连续训练单元、球形进阶或球台序列；强调“有路径地练”，不只是动作库数量。

### 第 3 页｜复盘到行动

- 上眉：`训练复盘`
- 标题：`练完，马上知道下一步`
- 说明：`从记录里找到薄弱项，直接进入下一项针对性训练。`
- 视觉语义：只突出一个薄弱点和一项对应训练；不再使用泛化的趋势图。

### 底部操作

- 第 1–2 页主按钮：`继续`
- 第 1–2 页次按钮：`稍后了解`
- 第 3 页主按钮：`开始体验`
- 第 3 页次按钮：`登录 / 注册，同步记录`

按钮仅改呈现文案时仍沿用现有语义：主按钮进入游客模式，次按钮打开登录页。

## 3. 视觉系列

### A/B/C｜已否决

用户反馈：三组都不好看，图片没有体现重点。共同问题是三页重复使用“绿台面 + 球 + 线”，训练和复盘只能靠抽象符号猜测，主视觉没有给每页建立唯一命题。

### A｜真实台面 · 编辑式光影

文件：`series-a-photoreal-triptych.png`

- 与 App 当前训练计划、练习封面的真实台面材质最一致。
- 专业、可信、球馆氛围强。
- 风险：整页容易偏暗；正式实现需把图片控制在上半部 Hero 卡内，并保留浅色正文区。

### B｜轻量 3D · 训练系统

文件：`series-b-soft-3d-triptych.png`

- 白底、圆角、卡片层级与当前 iOS 页面融合最好。
- 三页语义最直观，对新用户最友好。
- 风险：比现有真实台面封面更“产品插画化”；正式版需要收掉星形等奖励装饰，避免幼态。

### C｜几何球路 · 数据编辑式

文件：`series-c-editorial-triptych.png`

- 兼顾专业球路语言与数据复盘，品牌识别最集中。
- 深绿、米白、金色小点与现有 Token 体系容易统一。
- 风险：生成图中的线路只能作为构图示意，正式版必须移除并由 SwiftUI/Canvas 确定性绘制。

### D｜单一焦点 · 真实训练过程（待反馈）

目录：`series-d-focus/`

- 第 1 页只突出碰撞点：母球 → 接触点 → 目标球进袋。
- 第 2 页只突出训练动作：用户正在把最后一颗球摆到明确训练位。
- 第 3 页只突出复盘后的行动：一个薄弱点直接指向一项下一步练习。
- 三张均为 1536×1024 独立横图，不再用三联拼图平均视觉重心。
- 正式版不直接使用生成线路、球形和手机 UI：分别由 Canvas、确定性摆球和真实 App 截图替换。

## 4. 当前反馈闸门

- 先只判断 D 的三个页面重点是否正确，不在这一步评判生成细节。
- 若重点正确，再修材质、构图和真实业务叠层。
- 若重点仍不正确，先重写三页命题，不继续堆风格变体。

## 5. 选定后的实施边界

1. 按选定系列逐页生成 3 张独立无字底图，不把中文和按钮烤进 PNG。
2. 球路、接触点、训练节奏与数据线由现有 Token 和 SwiftUI/Canvas 叠加；生成图片不是几何真源。
3. 接入 `OnboardingView` 后补 Light/Dark、紧凑屏、Dynamic Type 和首次启动持久化截图验证。
4. 登录页复用同一视觉母题，但不重复堆三条功能列表；文案聚焦“同步记录与换机不丢”。
