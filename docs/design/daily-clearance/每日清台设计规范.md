## 1. 范围、依据与使用方式

覆盖顶栏/球库、2D/3D构图、仪表/击球、打点/透明度、菜单/显示、选球/选袋/临时自由、相机/手势/摆球、特写/提示/决策、开球/重打/回放、入口/草稿/结果、声音/触感、背景/几何、可访问性与跨尺寸取舍。规则引擎、物理参数、相机数学、资产制作仍保留各自真源，本规范只规定其界面含义及边界。

- **用户明确决定**与后续已记录的替代决定优先。历史DR按后续覆盖关系解释，不因编号或在文档中出现得早就仍然生效。
- **“设计目的”是据记录与画面归纳的解释**，不是冒充用户逐字原话；各节规则链接具体历史记录/实现锚点。
- **截图观察**只陈述画面可见内容；静态图不证明动作时序、触点舒适、温升、音色或所有球位无遮挡。
- **当前实现**提供事实证据，不自动决定规范；用户本轮纠正的单行易点、剩余空间按钮增长等，应进入未来验收。
- **适配要求**说明必须保留的关系与待实现方向；近方形结构、触点改善及极小窗口分支没有被写成“已完成”。

v1.0编制时检索仓库 `docs/`、`tasks/` 中“每日清台/dailyClearance”相关记录，建立210个文件的发现索引；重点提取、核对35个规范/专项/源码路径，目视检查50张历史原图。索引命中不等于210份全文逐条验完，也不宣称已读取所有聊天或覆盖全部历史截图。

发生冲突时，优先使用已确认的最新页内决定；通用Token用于材质与复用，不能覆盖页内明确例外。新发现矛盾须附来源与当前行为，再修正本规范。此版未批准归档手机竖屏概念、未重启暂停的相机构图提案，也不自动扩展其他球桌页能力。

## 2. 总原则与冲突处理顺序

1. **真实且可操作。** 合法动作、正确物理/业务事实、必要触点、关闭/返回与读数是前提。
2. **球桌优先。** 在满足操作的方案中尽量扩大实际桌面；不让重复说明、卡片外壳或无效留白长期挤占它。
3. **关系比常量稳定。** 目标球列居中、双尺等长对齐、主次动作层级、2D/3D操作记忆，比某一机型上的60/48/144更值得继承。
4. **高频直达，低频收纳。** 瞄准/杆速/打点/击球近手；显示与临时玩法集中更多，且当前值与末项可找。
5. **调试意图不等于执行。** 选中、合法、可直进、预测进球和真正击球各自表达，系统不得暗中换用户这一杆。
6. **辅助不能破坏被辅助的事。** 特写不挡关键几何，反馈不改物理，弹层不漏触，背景不争抢注意。
7. **连续操作可预期。** 模式切换、松手、重开、恢复、后台与窗口变化有明确状态边界，不兑现过期回调。
8. **空间按用途分配。** 手机是有限高度下的平衡；平板新增空间首先给桌面，再改善有收益的控件，尺长/大盘有上限。

局部冲突按“事实与操作约束 → 桌面可用面积 → 关键触点与触达 → 对齐/视觉节奏 → 装饰留白”评估。不是先把按钮无限放大再用剩余空间塞桌，也不是先铺满桌再把按钮压成不可点。临时决策允许覆盖台面，但不永久压缩舞台。每个重大候选要说明收益、代价和被排除方案。

## 3. 28项设计契约与截图证据

每项依次给出目的、现行规则、取舍、适配/验收、截图观察及来源。完整原图在图册内可点击放大；旧版图的使用范围在每张图下单独标注。

### DC01 球桌是主要工作区

依据性质：历史明确决定＋当前源码核对；目的表述含归纳。

**设计目的（归纳）：**用户需要持续判断球形、线路和落点。球库与仪表服务这项工作，不能通过不断增加说明行挤压桌面。

**规则：**在完整可操作的约束下尽可能扩大球桌；2D保持真实比例和完整桌框/六袋。常驻统计、副标题和普通提示不另占一行；新增能力先考虑现有分组或覆盖层。

**取舍与例外：**面积最大化不允许牺牲必要触点、把球桌拉伸、裁掉袋口；临时模态可以覆盖任务区，但不得永久挤小舞台。

**适配及验收：**分别量测window、page、stage、桌外框与台呢内框，解释宽/高哪个限制大小；不能用stage面积冒充桌面面积。

**截图观察与边界：**参考图中桌面是最大连续区域，球库和两侧操作围绕它展开；没有统计底栏或标题说明行。

### DC02 2D与3D的画面目标不同

依据性质：历史明确决定＋当前源码核对；目的表述含归纳。

**设计目的（归纳）：**2D用于全局几何判断，3D提供沿杆与球房空间感；相同的“利用空间”目标不能变成相同的裁切要求。

**规则：**同一窗口和方向下，每日2D/3D共用HUD布局关系与对局状态，切换模式本身不触发方向变化。手机当前设计范围为横屏，iPad明确支持横/竖屏设计；这不表示iPad原生已完成适配。2D在中央有效舞台拟合球桌；3D场景铺到HUD后方，中央区为主要可读区。

**取舍与例外：**3D沿杆机位不要求每一帧六袋全见；全局观察应有完整桌面。不能把3D强行塞进2D矩形，或以全屏SCNView面积证明取景好。

**适配及验收：**保持单一renderer及各层坐标一致；窗口变化同步投影与命中。跨模式保护操作位置，同时按各模式目标审构图。

**截图观察与边界：**2D桌框完整；3D近端桌面超出画面底边且房间铺满背景。临时俯视仍叠在3D壳中，并非完整切换到2D。

### DC04 球库以目标序列为中心

**2026-10-08 用户决定 / DR-361：**球库不显示母球；单行去掉母球及镜像空翼，只保留目标序列。正常横屏始终单行；只有特别窄的窗口/临时竖屏实际不足才允许双排。常规iPad竖屏不自动双排。锁定原桌框、其他控件和球库下沿，只向上利用空间。以下DR-357/已实现母球翼为历史状态，由本条覆盖。

依据性质：历史明确决定＋当前源码核对；目的表述含归纳。

**设计目的（归纳）：**球库同时是剩余球与合法目标的状态图。位置固定有助于快速查找球号和感知进度。

**规则：**空间足够时单行；母球独立在左，目标球序列相对桌面/HUD中线居中，右侧镜像留白只用于平衡。中八按1–7｜8｜9–15分区，8号在中心；其他玩法按固定集合居中，偶数集合以中间间隙为轴。

**取舍与例外：**DR-357（2026-10-07）：单行放不下时改两行，母球独立在左、各排对桌心居中，底排贴桌；保留球号顺序和槽位。C48 r4暂排1–7／9–15，母球和黑8分列两侧，具体分组待看图；黑8居中仅适用单行，玩法与合法目标逻辑不变。不是把含母球的整排机械居中，也不是所有玩法都锁黑8。进袋后保留槽位，不能删除球导致全排跳动。短球库不必伸展铺满。

**适配及验收：**2D彩球胶囊下沿紧贴球桌外框上沿，设计间距0；以真实可见边界量测，不能只对齐带透明留边的父框。目标序列中心对球桌中心，母球独立，不居中整个球库。3D继承对应2D的稳定HUD锚点，不跟随透视袋口漂移。发生侧边入口碰撞时先按分册容量顺序调整，不擅自放弃贴边/居中。

**截图观察与边界：**中八有明确分隔，短玩法只显示自己的球集；四/五/六球的终局球为9，不能从名称推成4/5/6号终球。

### DC05 球库颜色表达三种不同事实

依据性质：历史明确决定＋当前源码核对；目的表述含归纳。

**设计目的（归纳）：**合法目标、当前选中、已经进袋的含义不同，需要同时可读，避免只有一层“选中绿”。

**规则：**本轮合法目标使用淡绿底；当前瞄准球用白色细圈；已进袋球暗显并保留位置。开放局/待开球不提前假设球组。球库点击沿用合法目标规则，已进袋提示而非补球。

**取舍与例外：**按下背景不重染球面或球号；选中不等于这一杆一定能进。球库不是自由摆球工具，不因为适配其他页面增加拖回/补球能力。

**适配及验收：**分组高亮端部贴合胶囊，内部连续而不过度切碎。不能仅靠颜色表达全部状态，保留AX标签与必要规则提示。

**截图观察与边界：**球面、合法底色、白圈及暗球是分开的视觉层；待开球时球库不提供选球操作。

### DC06 球的视觉大小与手指触点分开

2026-10-08 / DR-361：[C51原位放大](../../../tasks/daily-adaptive/C51.md)替代被否决的C50缩桌稿。原生上限36pt；SE横屏30，标准手机按真实标题空间取34，iPad横竖36。Figma校准稿中的Pro36不作为硬编码。正常横屏不能以换行为降级方案，不得挤小球桌或改变侧栏。原生按实际容量实施，用户观感与真机手感待反馈。

依据性质：用户本轮明确要求；现有窄触点仍待重新验收。

**设计目的（归纳）：**球库密度需要适应最大球数，但可见球面尺寸不等同于实际可点区域。

**规则：**优先保持单行且支持手指点选；用户于2026-10-08明确“不要强行把球库做成两行”。仅实际容量不足时采用DC04双排，不能为统一大球径强迫全屏手机换行。独立量测球径、槽宽、槽高及间隔；不得用重叠热区假装每球都可点。参考Pro30pt球面/32×44ptAX、小屏25/27×44是历史事实，不能自动外推为所有尺寸合格。

**取舍与例外：**宽裕空间达到球径上限后留白；小屏先回收装饰空间。DR-361限定仅特别窄的窗口/临时竖屏可按容量采用两行，正常横屏绝不换行。不能只为全显示无限缩球，滚动也不能成为无需解释的默认布局。

**适配及验收：**首末球、分组边缘、已进袋/非法球逐一真点；与球桌拖动/相机手势分开检查。手指舒适度需真机，不由AX矩形或中心点自动点击证明。

每个改动先列所影响的DC编号，写明现状问题、拟保留关系、预期收益与代价，再给同条件原生前后图。结构变化至少比较一个相关备选；相机、音效与手势用真实操作/录屏或专项数据补足，不用合成UI冒充运行结果。
