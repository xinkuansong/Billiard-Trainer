## 3. 三类 tutorialKind × 形态差异

| | `multiShot` 应用课 | `singleShot` | `ruleset` |
|---|---|---|---|
| 技能 | **tutorial-authoring** | **tutorial-migration** A | **tutorial-migration** C |
| digest | ✅ 每条序列必跑 | ⏭ | ⏭ |
| **形态判定** | ✅ 写逐杆前必判（DR-062） | n/a | n/a |
| 读图 | ✅ 逐张 Read PNG（证伪） | 常无图 | 常无图 |
| 骨架标题 | 技术原理 → 开局与击球顺序 → 第N杆 → 常见错误 → 进阶练习 | 技术原理 → 动作要领 → 常见错误 → 进阶练习 | 技术原理 → 怎么摆 → 怎么计分 → 失败判定 → 常见错误 → 进阶变体 |
| params / image | digest 原样抄；多球形现行 token | 默认不写 | 默认不写 |
| **重点分配** | **走位链**：指认一个胜负手；**独立阶梯**：2–4 个锚点档全文，中间档仅一条自检 | 关键控制点 | 规则压力点 |
| 自查 | authoring 15（含 12/12b） | migration 0–12 | 同左 |
| C4 | 逐杆节数 == 序列杆数 | 无序列 → warn | 同左 |

### 3.1 独立阶梯 · 混合式结构（必遵）

1. **`技术原理`**：讲透**唯一变量**（切角/距离/塞量/力度），一次讲完；失败模式如何随它变化。  
2. **`开局与击球顺序`**：摆位 + **阶梯总表**（每档一行：杆序、变量值、一句差异；数值抄 digest）。  
3. **逐杆节保留**（配图/`params`/C4），但：  
   - **锚点档**（每形 2–4 杆）：写全 `为什么`/`怎么打`/`自检`（入门基准、教学锚点如半颗球≈28–30°、上限档、缺陷档）。  
   - **中间档**：⛔ 不写「为什么/怎么打」，**只留一条 `自检`**（进袋 + 母球落点参照，抄 digest）。  
4. **多球形**：第 2 形起，`技术原理` 首段先答关系三问——共享什么 / 变了什么（数值对数值）/ 为何此顺序。  
5. ⛔ 禁用「胜负手/关键档」措辞；上限档可写「全组最薄一档」。

### 3.2 走位链写法（默认）

- 每杆全文三条目；全组指认**一个胜负手**（客观依据：容差/落点苛刻/达标难点）。  
- 「为下一杆」必须有实义（落点因果）。

### 3.3 语域规则（全字段，DR-062）

面向用户字段（`description` / `coachingPoints` / `standardCriteria` / `tutorial` 正文）⛔ 禁止：

- 仓库工作流词：退役/retired、profile、序列文件、manual01、digest、出片、录制、待重录、W 批次号  
- 验收自证话术：「与已退役的旧 X 球形不同」「现行示范」等  
- 「轻力 2.1 档」式标签+数值堆叠 → 力度只写「力度 2.1」；定性词仅可在技术原理出现一次  
- 示范缺陷：只写用户视角一句（「示范动画里母球也落袋了，这不是标准答案——以母球留台为合格」）；待重录写交付说明  

> 注：`image` / `formations[].id` 中的 `manual01` 等是**资产标识符**，不是正文措辞，允许保留。

### 3.4 多球形 / §8.15

- `formations[]` 顺序与序列 token 顺序一致。  
- profile `retired`：问 2 降级，正文**不要提**退役史。  
- §8.15：image 改现行 token 后收紧 `i5_legacy_token_exempt` / `c3_dead_refs_baseline`。

### 3.5 红灯

digest 报 scratch / 未进袋 / 文件缺失 → 上报。结构若需占位：正文仅用户视角缺陷句，禁止硬圆成功示范。
