## 一、需求回显（用户拍板结论，语义基准）

1. **核心问题**：现有 72 个 drill 的球形/训练序列来自「网上博主 + 个人经验」，**撑不起官方、权威的产品定位**。要把每个 drill 的球形序列设计得足够专业、全面。
2. **方法论共识**：drill 序列设计是**约束下的组合覆盖问题**——先识别每个 drill 的变量空间（固定变量 / 目标变量档位 / 条件变量），用**最少的球形数**系统覆盖训练目标变量，条件变量合理采样；变量间有约束耦合（角度定了白球位被约束在射线上），要先画约束结构。例：中袋角度球 = 袋口钉死（中袋）+ 角度全覆盖 + 目标球距袋/白球位采样。
3. **已有调研的定位**：2026-03-23 两份调研解决了**体系层**（8 分类、五级、57–70 项清单、6 套计划），是可靠的，**不推翻**；缺的是往下一层的**球形层**——每个 drill 内部具体摆哪几个球形、为什么。现状是每个 drill 只有 1 个示范球形（单点采样），不是系统覆盖。
4. **权威性三来源**：① 锚定外部权威体系做交叉验证（BU Exam / PAT 等有坐标级球形图纸的体系）；② 第一性原理变量覆盖（内部自洽）；③ 可度量达标线（后续数据闭环，本轮不做）。
5. **既定路径**：下钻调研（坐标级基准）→ 方法论样板（1 个 drill 走通）→ schema/承载升级 → 全库审计与重构。
6. **执行方式**：形成方案后**通过子智能体委派执行**。

## 二、代码现状关键事实（拆批依据，2026-07-16 探索核实）

- **单杆假设在运行时**：`DrillShotResolver.shotInput(for:)` 只取 `shots.first`；`DrillBoardBuilder`、`DrillSceneView`、缩略图同。全库仅 `drill_c042` 的 `shotIntent.shots` 有 3 杆。
- **多球形已有承载线**（ADR-P12-02）：多条 `PositionPlaySequence`（`content/position_play/sequences/` → `make tryout-sync` → `Resources/DrillBoards/`）+ 精讲 `tutorial.formations` 分段。**「多球形」与「多杆 shots」是两条语义不同的线**。
- **烘焙管线**：`ShotBaker`（Swift 库内）经 `DrillBakeRunnerTests` 跑测打印 `animation` JSON 人工拷回；无独立 CLI。
- **校验**：`DrillContentValidationTests`（72 条加载/字段/坐标界）+ `schema.md`（人读文档）；无机器 jsonschema。
- **⛔ 存量红线（2026-06-13 用户拍板）**：示范击球以编排台人工录制为准，**禁止从存量 `shotIntent` 批量反推生成序列**。
- **⛔ 几何红线**：涉及切角/坐标/球位推导的任务，执行前必读 `geometry-spatial-reasoning` 技能，数值用脚本验算，禁脑算。
