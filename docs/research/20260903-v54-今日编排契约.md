## 1. 固定术语

| 术语 | 唯一语义 |
|---|---|
| `currentOrdinal` | 当前官方计划第一节尚未完成课程的零基全局序号 |
| `review` | 选择序号小于当前游标；完成只记复练，不移动游标 |
| `advanceEligible` | 从当前游标开始、选中集合中的最长连续前缀 |
| `preview` | 位于连续前缀缺口之后的未来课程；完成不跳过缺口 |
| `neutral` | 模版或动作库来源；不参与官方计划推进 |
| `activePlanAtCompletion` | 完成时仍激活的官方计划；必须和 item 冻结的 planId 一致才可结算 |

## 2. 分类与结算规则

1. 对同一官方计划的已选课程去重并按 ordinal 判断；UI 顺序不改变分类。
2. `ordinal < currentOrdinal` 为 `review`。
3. 从 `currentOrdinal` 起，选中集合里的最长连续前缀为 `advanceEligible`。
4. 位于该连续前缀之后的未来课程为 `preview`。
5. 完成顺序可以不同于课程顺序；每次完成后重新结算“已完成 eligible 的连续前缀”。
6. `scheduleItemId + lessonId` 是结算幂等键；回调重复任意次数最多推进一次。
7. item 对应计划在完成时不再 active，则不推进；训练记录仍保存来源与完成事实。
8. preview 不因后来补齐缺口自动升级；成为当前课后必须重新加入今日安排。

机读样例位于 `QiuJiTests/Fixtures/V54/today-schedule-cases.json`。

## 3. Stable lesson ID 规则

内置旧计划迁移时使用：

```text
<planId>.stage<weekNumber:02>.lesson<dayNumber:02>
```

示例：

```text
plan_beginner + week 2 + day 1
→ plan_beginner.stage02.lesson01
```

约束：

- ID 只由既有 `planId/weekNumber/dayNumber` 首次迁移生成，不包含中文标题。
- 首次发布后，改标题、剂量、阶段名或数组位置都不得改 ID。
- 同一 plan 内全局唯一；跨 plan 由 `planId` 前缀隔离。
- 新增课程必须显式分配 ID；不得在运行时继续从数组下标临时生成。
- 旧 OTA 兼容解码可临时生成同规则 ID，但新格式内容必须显式落盘。

当前 bundle 基线位于 `QiuJiTests/Fixtures/V54/plan-content-baseline.json`：12 个计划、129 节旧 session。W2/W3 迁移后，计划数、总课程数、每计划课程数和所有 drill 引用集合必须保持；经产品明确调整内容时另升契约版本。

## 4. 旧 active row 迁移口径

机读样例位于 `QiuJiTests/Fixtures/V54/legacy-active-plan-cases.json`，至少覆盖：

- official only：恢复官方 active，并将 week/day 映射到 stable lesson ID；
- custom only：模版保留，custom active 转成迁移当天的 template schedule item；
- official + custom：官方保持 active，模版进入今日安排；
- duplicate official：按最新 `startDate` 选 active，其余有效计划进度变 paused；
- reopen after partial migration：相同 migration key 重开不重复创建 schedule item。

迁移不得删除 `TrainingSession` 历史。无法解析的 plan/session 只能进入诊断和安全失效路径，不能数组越界或随机选择第一条。
