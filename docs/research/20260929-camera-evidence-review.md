# 每日清台相机深入调研：稳定站位、构图与操作复杂度

日期：2026-09-29。性质：研究结论与首轮改进边界。本轮未修改生产相机、默认参数或手势代码。

**用户最新范围裁定**：先只看、只改每日清台；每日清台验证后，再应用到其他场景。以下旧版页面和视频仅作为参考，不构成本轮修改对象。共享类中的改动也必须以每日清台显式启用为边界，不能借共享代码同步改变其他页面。

这次研究要回答的不是“哪个 FOV 最好”，而是：哪些关系必须稳定，哪些自由度值得保留，自动取景应当解决什么问题，以及现有比较是否真的测到了这些问题。

## 1. 结论与置信边界

**较有把握的判断**：先保证沿杆关系、站位、手势含义与切换记忆，再讨论自动构图。当前没有足够证据支持“按长台、短台、切角分类，然后自动切换多组参数”。也没有证据支持“一个完全固定的世界机位适用于所有球形”。

这两件事并不冲突：可以用少量固定规则，根据母球位置和杆向算出不同机位。例如旧版“沿杆向后找到球库，再后退固定距离、保持固定眼高”本身已经随球形变化，不是一个固定世界坐标。

**仍需实验的判断**：是否需要在这个站位基础上，增加一次有限的俯仰修正；横屏是否需要独立镜头；观察拖动到底应以原地转头还是绕球移动为主。外部资料不能替用户决定这些手感问题。

**应纠正的推断**：无 roll 不等于不眩晕；多加平滑不一定更舒服；截图两球入镜不等于相机可用；竖屏舒服不等于其世界机位更合理；自动相机也并非一概有害。

## 2. 直接竞品证据

### Virtual Pool 4：值得借鉴的是操作的边界与可返回性

官方说明将瞄准、自由查看、临时俯视和临时后退区分开；瞄准距离可记忆；自由查看后可返回瞄准。还区分三维旋转中心与画面中显示中心的位置。它并没有要求一张画面同时承担所有判断。

对球迹的启发：查看过程中应保留已决定的击球关系，返回时应可预测；“暂时看不见袋口”可以通过明确查看动作解决，不必让默认机位不断后退。但它是鼠标键盘产品，不能据此证明手机应增加同样多的入口，也不能照搬它的击球后返回规则。官方文档未公开相机求解源码或完整参数。

来源：[VP4 Control Reference](https://vponline.celeris.com/support/view/id/19)。

### Pure Pool Pro：简单、固定的取景也会失败

开发者首周补丁明确调整了相机与母球的距离、居中行为和鼠标灵敏度。这个案例说明，减少模式或自由度并不能保证默认机位舒服；距离、对齐和输入增益仍需验证。开发者使用的“居中”没有给出数学定义，不能翻译成“目标球必须位于屏幕中心”。帖子中的玩家反馈只作线索，不能当成代表性用户研究。

来源：[Pure Pool Pro 开发者补丁说明](https://steamcommunity.com/app/3456930/discussions/0/766311130382583452/)。

### ShootersPool：证据不足的部分保留为空

已查官网与 FAQ；官方说明面向 Windows PC，操作围绕外接鼠标设计。本轮没有实际运行这款游戏，也没有取得足够的官方细节来确认其眼高、自动拟合或缩放算法。因此不将其列为某种具体算法的成功证明。

来源：[ShootersPool FAQ](https://www.shooterspool.net/faq-frequenly-asked-questions.php)。

## 3. 真实台球与感知研究能支持到什么程度

| 证据 | 能支持的判断 | 不能推出的结论 |
|---|---|---|
| Dr. Dave 的视觉对齐与站姿教学 | 站着判断到俯身瞄准时，保持视觉中心与击球线的关系；站姿需要一致、舒适 | 人人同一眼高；真实人眼高度可直接当成手机最佳机位 |
| Banks 等，2014，图片透视与观察距离实验 | 画面尺寸、观看距离、成像参数共同影响空间感，不能只报一个 FOV | 手机台球应使用某个固定角度；50mm 等于人眼，或等于 50° |
| Naftis 等，2021，SpaceBall 研究 | 不同任务下玩家会选择不同相机 | 每种球形都应自动换镜头；三模式对所有台球玩家最优 |
| Burelli 与 Yannakakis，2015，自适应相机研究 | 平台游戏中，适配玩家类型可能改善部分人的偏好及表现 | 自动相机必定较差，或自动构图能改善手机台球 |
| Guo 等，2013，主动操作与被动观看实验 | 自己操作与看录像的体验不能互相替代 | 视频看着舒服即可证明触控舒服；任何自动运动都会引起眩晕 |
| Microsoft XAG 117 | 控制额外相机运动，允许调节视角和灵敏度，是可借鉴的无障碍设计方向 | 某个阻尼、速度或 FOV 已经被实验确认为最佳 |

来源与范围：

- [Dr. Dave：Vision Center](https://drdavepoolinfo.com/faq/eyes/vision-center/) 与 [Stance Advice](https://drdavepoolinfo.com/faq/stance/advice/)，属于专业教学建议。
- [Banks 等论文全文](https://www.princeton.edu/~epiazza/papers/Banks%20et%20al%20%282014%29.pdf)，研究图片感知与观看行为，不是台球操作实验。
- [SpaceBall 论文](https://arxiv.org/html/2109.03750v1)，30 位参与者均为自述游戏玩家及游戏编程学生；观察情境中的相机选择，不是固定与自动相机的随机对照。
- [自适应相机论文及摘要](https://vbn.aau.dk/en/publications/adapting-virtual-camera-behaviour-through-player-modelling/)，本轮使用摘要级证据，不据此声称具体效应大小。
- [Guo 等论文全文](https://www.ieda.ust.hk/dfaculty/so/pdf/Guo-et-al-2013-EHF2013.pdf)，两个小样本实验分别 12 人、7 人，使用 Mirror's Edge，不能直接迁移成台球参数。
- [XAG 117](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/117)，是设计指南，不是效应量研究。

还有一个反例需要保留：[Bos 等 2010 年研究](https://pubmed.ncbi.nlm.nih.gov/20042182/) 区分渲染 FOV 与屏幕在眼前张开的实际视角，实验结果没有支持作者原先的简单匹配假设。因此，“缩小 FOV 就不晕”或“匹配真实视角就不晕”都不能作为保证。

## 5. 横竖屏比较复算：现有结果混入了什么

对现有 `output/observer-matrix-20260929/parameters.json` 全部 150 对横竖截图，重新计算母球、目标球的 `screenY / viewportHeight`：最大误差约 **7.45×10⁻⁸**。也就是同一机位、同一垂直 FOV 下，两颗球在画面中的相对高度相同。

但矩阵的横图是 1170×540，竖图是 540×850；原始渲染高度相差 **1.574 倍**。网页按容器适配还可能进一步改变实际显示尺寸。竖屏更舒服这一反馈有效，但眼位、纵向显示尺寸、裁切和 HUD 占用必须分开比较。

另一个真实差异来自 App 自己的镜头规则。把上述两种视口代入当前 `dailyFOV`，横屏垂直 FOV 约 **27.58°**，竖屏 **40°**；矩阵用的固定垂直 48° 又是另一组条件。这两类结果不能混为一谈。

公式：`hFOV = 2 atan(tan(vFOV / 2) × width / height)`。同样的垂直 48°，在这两个矩阵视口上，水平覆盖分别约 **87.94°** 和 **31.59°**。这些是几何复算，不是舒适度结论。

透视也需区分：固定眼位和朝向，仅改变理想透视相机的 FOV，主要改变投影缩放与裁切；改变眼位，会改变物体之间的透视关系。两种方式都能让球在屏幕上变大，却不是同一种操作。主观纵深还受观看尺寸和距离影响，见前述 Banks 研究。

## 6. 怎样降低复杂度，同时保留三种用途

建议优先固定“什么动作会改变什么”，而不是先固定全部数值。

| 使用意图 | 优先保持的关系 | 允许主动改变的内容 | 不应暗中发生的事 |
|---|---|---|---|
| 瞄准 | 杆向、母球、瞄准点的对应关系 | 左右调整瞄准；有限调整观看 | 为构图自动改击球选择、突然转为自由环绕 |
| 观察 | 初始沿杆站位、舒适眼高；用户已调的视角可返回 | 查看角度与倍率；具体运动方式待比较 | 为目标居中持续抬高拉远；回切时悄悄换成另一颗球 |
| 全局 | 桌心是旋转与构图中心；倍率可记忆 | 绕桌旋转与受限整桌缩放 | 捏合锚点变成局部球；缩小隐式换模式 |

以上源于用户已有要求，并非竞品给出的统一标准。三种作用隔离，不意味着内部必须建立三套重复、互相切换的庞大系统。

有三类“适配”值得区别对待：

1. **必要的几何更新**：新母球位置、新杆向、视口尺寸改变。用清楚的规则计算，不需要给球形贴长台/短台标签。
2. **用户偏好与状态恢复**：记住倍率、观察方向、关注对象。这减少重复操作，不需要相机猜测意图。
3. **主动构图调整**：因目标移动或球形变化而自动升降、后退、改 FOV。这才需要额外证明收益，并明确触发、幅度、退出与恢复规则。

对第三类，当前优先级应低于前两类。外部自适应相机研究表明它可能有益，但我们尚未证明球迹需要它，更未证明应当持续运行。

“地面固定”的合理产品解释是空间稳定、运动可预期，不是把地面纹理锁在屏幕像素上。相机移动时背景必然产生相对运动；若强行锁死背景，又移动球桌，就会破坏同一空间的投影。当前更值得验证的是：上下拖动是否不必要地让人升空、轴心是否跳变、松手后是否拖尾过长、一次输入是否同时改变太多参数。

## 7. 下一轮实验应比上一轮少，但更有辨别力

用户已确定以每日清台作为首个修改场景。保留可回退旧版；先处理上表的操作契约，再把输入手感与取景比较分成两个独立阶段。尚未选择的机位候选用每日清台对照入口呈现，不直接推广为跨页默认。

**阶段一：相同画面，比较控制规则。** 保持眼位、FOV、初始球形一致，比较原触控与更低增益/小干扰过滤的触控；不要同时更换自动取景。动作包括纯横拖、带小幅竖向抖动的横拖、纯竖拖、有意斜拖、短拖微调、快拖、松手、反向、双指两端、球附近起手。记录主轴响应、误带另一轴的角度、松手后剩余运动和用户判断；阈值由对照确定，不把任意数字包装成研究结论。

**阶段二：相同控制，比较两种取景规则。**

- A：旧版库外站位、固定眼高，沿杆进入；保留手动调整和记忆。
- B：与 A 完全相同，只在显式进入/重新取景时允许一次有限俯仰修正，尝试让关键球更易读；不同时移动眼位或修改 FOV，不强制目标居中。若不可兼得，记录失败，不追加隐式兜底。

B 是待验证的最小自动化候选，并非最终建议采用。只有它在相同条件下减少调整负担、又不损害空间感，才值得讨论更进一步的适配。

使用六类球形即可覆盖不同失败机理：长距离直线、短距离近景、中距离大切角、母球贴库需抬杆、目标袋在画外的反打/翻袋、邻球遮挡与贴库目标。复用旧矩阵能覆盖的夹具；新增角度球需由真实杆向和进袋解生成，不能只拿两球连线代替瞄准方向。

横竖屏分两遍比较：第一遍等显示高度，隔离裁切/覆盖差异；第二遍在同一手机、真实 HUD 下横竖握持，判断真实体验。静态图评“看清楚什么”，连续操作评“是否跟手、是否需要反复找回视线”。两者结果分开记录。

最后跑完整流程：选球 → 观察 → 瞄准 → 全局 → 返回观察 → 放大/缩小 → 击球 → 目标进袋后返回保存的观察视角。并覆盖未进袋、目标失效、过渡被手势打断。此前批准的“目标球进袋才站起”继续作为用户要求，不以竞品规则替代。

通过标准先看行为是否正确、两球/瞄准关系是否可读、是否减少不必要操作，再比较喜好。截图漂亮或单测通过，都不能独立构成整套相机体验验收。

## 8. 当前尚缺的证据

- VP4、Pure Pool Pro、ShootersPool 的同一套真实操作录像与定量机位记录；本轮是官方文档/开发者说明研究，没有假称实机体验。
- 同一手机、相同球形、完整 HUD 的横竖屏对照；现有离屏矩阵不足以替代。
- 用户拖动时眼位/俯仰/倍率/轴心的同步记录。代码能揭示耦合，但尚不能把某一项认定为眩晕的唯一原因。
- A/B 的连续使用反馈。因此不发布“最佳机位参数”，也不把建议直接写回生产实现。

本次可交付的结论是：回到旧版舒服的站位关系，有针对性地整理手势和恢复规则；让任何额外自动化用对照实验证明必要性。无需先建立一个按球形分类的复杂摄像头系统。
