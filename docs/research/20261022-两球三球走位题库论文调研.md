# 两球、三球走位题库：论文调研与生成方案

日期：2026-10-22。状态：研究完成，方案待小样本实验；本轮没有修改 App、运行生成器或产出经验证的新题库。

用户已确认：**两球＝两颗目标球＋母球；三球＝三颗目标球＋母球。** 本文研究的是连续进攻走位训练，不把花式三球、三库开伦或论文中的其他“3Pool”直接等同于本需求。

## 1. 结论与适用边界

建议采用 **训练意图约束下的球形生成＋短序列搜索＋物理逐杆验证＋误差评估＋题库多样性筛选**。

核心产物不是只有球坐标，而是“初始球形、训练目标、至少一条完整可回放解、容错证据、难度特征”的组合。只有名义条件下的一条成功轨迹，足以作为仿真可解的见证；它还不能证明球形适合某级别真人，也不能证明解唯一、模型完全准确或连续参数区间内都成功。

- **两球题**：第一杆进 A，实际停球状态允许第二杆进 B，全程满足该题约束。
- **三球题**：第一杆进 A 后，必须存在“第二杆进 B 并留给 C，第三杆进 C”的完整延续。第一杆只留下容易进 B 的角度，仍可能不利于接 C。
- 推荐先做固定 A→B→C 顺序的技术训练，再扩展允许选择顺序的路线规划题。此顺序规则是本报告建议，用户目前只确认了球数口径。
- 最后一杆以完成进球和该题规定的合法性条件收束，通常无需附加无意义的母球落区。

本轮找到的公开文献覆盖了相关算法模块，但**没有找到可直接照搬、已验证适用于本项目两球/三球教学题库的完整生成标准**。这不是对所有相关文献不存在的证明。

## 3. 从“会打球的 AI”到“教学题库”的差异

比赛 AI 通常关注获胜、清台或回合收益。教学题库还需要回答：这道题主要练什么，为什么值得练，答案是否足够宽容，同类内容是否重复，以及其他合理路线是否也应得分。

因此建议将工作拆成以下三个层次，而不是让一个总分负责所有判断：

1. **可解性**：在给定物理配置和规则下，找到一条完整成功序列。
2. **可练性**：在明确的执行误差模型下，成功率与容错范围适合预期训练档位。
3. **教学价值**：题目突出目标技术，有清楚解释，并对题库覆盖面有贡献。

一题可能可解但难度过高；也可能非常容易清台，却不需要做任何有意义的走位选择。两者都不应只凭“搜索器打进了”进入正式题库。

## 4. 建议的生成与验证流程

以下是基于文献与现有代码提出的工程方案，**不是任何单篇论文已经验证的组合算法**。

```mermaid
flowchart LR
    A[训练目标与约束] --> B[构造候选球形]
    B --> C[搜索完整两杆或三杆解]
    C --> D[同一物理引擎逐杆回放]
    D --> E[独立误差样本评估]
    E --> F[题型覆盖与相似题筛选]
    F --> G[带答案和证据的版本化题库]
```

### 4.1 先确定训练目标和约束

每次生成先指定目标技术，例如自然走位、定杆、跟进、拉回、一库走位，以及控制力度或留下一杆角度。题型是生成条件；最终标签必须由实际轨迹复核。

需要区分硬约束与偏好：指定顺序、禁止白球落袋、杆法上限等若属于题目要求，就必须严格满足；更短线路、更少库数可以作为偏好。是否固定袋口、是否允许薄碰其他目标球、是否要求下一球保持原位，应由题型明确声明，不能隐含在评分器里。

首批建议采用常规合法出杆，限制跳球、扎杆、组合球等复杂技术；基础接续题可要求未轮到的目标球保持原位。后续专门的碰球解团题再放开，避免混淆不同训练目的。

### 4.2 两种构造方式并用

**前向构造：** 从已验证的第一杆及其停球分布出发，在候选接球区域安排后续目标球，再放回完整初始球形重跑整段。优点是能利用现有单杆搜索和力度扫描。新增目标球可能挡路、被误碰或改变出杆空间，因此不能仅在第一杆结束后“补摆”第二球作为成功证据。

**从末杆向前构造：** 先选 C 的可完成状态，再寻找能进 B 且留给 C 的上一状态，最后寻找能进 A 并接上该 B→C 序列的初始状态。两球则从 B 向 A 构造。这是在逆向安排约束，**不是把有摩擦的真实运动倒放**；每个候选仍由正向仿真验证。

建议保留一个“随机摆球＋相同求解器筛选”的基线，用相同模拟预算比较三条路线的有效题产出率。不要预先把任一种构造方式认定为最优。

### 4.3 两球与三球的搜索状态

状态必须包含母球及所有剩余目标球的真实位置、在台/入袋状态、待完成顺序、台面配置和规则。每杆结束后，从实际静止状态开始下一杆；不能把母球吸附到理想落点或重置其他球。

| 项目 | 两球题 | 三球题 |
|---|---|---|
| 第一杆的评价 | 进 A，并留下可完成 B 的状态 | 进 A，并留下可完成 B→C 的状态 |
| 中间接续 | 无第三球要求 | B 杆既要进球，又要留下 C 的可完成状态 |
| 终点 | B 进球，满足末杆合法性 | C 进球，满足末杆合法性 |
| 常见错误 | 用“落入扇区”替代第二杆验证 | 把两条分别可行的单杆拼起来，却没有同一条真实状态链 |

搜索可先按袋口、路线、杆法族组织候选，再优化瞄准、速度、打点等连续参数。为避免提前丢掉关键解，应保留多种后继状态，而不是每层只留当前最容易进球的一杆。可尝试有限宽度搜索和状态聚类，但宽度与计算预算必须通过试验确定。

聚类时建议选取真实模拟状态作为代表，不把若干落点简单平均成未经模拟的状态。粗搜索发现候选后，最终每个收录解都要回到正式引擎复核。

### 4.4 接球区应由后续任务决定

如果需要向用户展示接球区，建议将它定义为“后续任务达到要求的母球状态集合”的近似投影，而不是先画一个统一扇区，再默认该区内都能接续。

- 两球接球区对应“下一杆能进 B”。
- 三球第一杆的接球区对应“后面能完成 B→C”；三球第二杆的接球区才对应“下一杆能进 C”。
- 当允许碰动其他球时，只画母球落区可能不足以描述状态，必须保留其他球的位置条件。
- 区域可能不连续；不能把采样成功点直接包成一个大凸区域，误把其中失败位置也显示成可接区域。
- 不能把“小角度更容易进球”直接推广为“三球一律追求直球”。第三球的方向和可用杆法会改变第二球所需角度。

### 4.5 最终收录的硬检查

每条答案至少验证：

1. 初始球形合法，无重叠、越界；所有后续目标球从第一杆开始就在场。
2. 每杆满足目标顺序、指定袋口及该题规则，母球不落袋，出杆可达。
3. 未完成静止结算、仿真超时或数值异常的结果不算成功。
4. 下一杆直接继承实际状态；若基础题规定其他目标球不动，逐杆检查。
5. 题目设置的最大杆法、速度或库数属于硬约束时，不接受“超限但能打”的兜底解。
6. 保存参数后从初始球形独立重放，仍能完成全部目标球。

状态应区分 `validated`、`rejected_by_rule`、`insufficient_robustness`、`search_budget_exhausted`、`simulation_incomplete`。有限预算没找到解，应标为“未找到”，不能标为数学意义的“无解”。

## 5. 容错和难度：必须分清测量对象

### 5.1 三类结果分别存储

| 结果 | 如何测量 | 能说明什么 |
|---|---|---|
| 名义可解见证 | 固定参数完整重放 | 至少找到一条在当前模型下成功的序列 |
| 参数容错切片 | 固定其他参数，扫描力度或方向 | 指定切片上的离散成功范围，不代表整个参数空间 |
| 扰动下完整完成率 | 从原始题面开始，多次执行带误差的整段策略 | 在指定误差模型与策略下的模拟表现 |

连续力度区间不能仅由几个成功采样点作保证。若展示范围，应注明步长、失败间隙和是否只是离散验证；必要时在边缘与内部加密复核。

### 5.2 正确模拟逐杆误差

一次扰动试验应从原始题面出发，给这一杆已选定的参数加入误差，再模拟其实际结果。不能加入瞄准误差后立即让求解器重新修正同一杆方向，否则把本应测量的误差消掉了。

如果前一杆成功，下一杆可以根据真实停球状态重新规划，这对应球手看清实际球形后再击球。但必须注明使用的是哪类策略：

- **完整求解器每杆重新寻优**：衡量强规划能力下的可完成性；可能高估教学对象能力。
- **限定路线和杆法的教学策略**：更接近这道题要教授的操作。
- **真人记录**：用于后续校准，而非从模拟成功率直接推定。

首杆成功率、首杆成功条件下的接续率、从开局开始的整段完成率要分别报告。整段完成率分母包括第一杆失败，不能只统计已打进第一球的样本。

寻找解使用的随机样本与最后评分使用的样本应分开，避免反复挑选后得到过于乐观的结果。记录样本量、随机种子、误差分布与置信区间；尚未校准真人时，命名为“模拟误差档 A/B/C”，不要直接宣称对应初/中/高级球员。

击球执行误差与台呢摩擦、库边等模型不确定性也要分开。前者测“人打得不一样”，后者测“模型和台子不一样”，不能混成一个无解释的难度值。

### 5.3 难度和教学价值建议

先保存四组可解释特征，再决定是否压缩成星级：

| 维度 | 可测特征示例 |
|---|---|
| 进球 | 距离、实际切角、袋口有效容差、首杆进球率 |
| 走位 | 可接区域宽度、路线、落点对后续可完成性的影响 |
| 执行 | 力度/方向/打点容错、所需杆法、贴库出杆条件 |
| 规划 | 可用顺序与路线数、局部容易但接续差的选择、替代解数量 |

为排除“摆了三颗球却不需要走位”的低价值候选，可增加对照：同样题面和误差条件下，比较只求眼前进球的策略与完整规划策略的整段完成率。差异大小是教学价值的候选指标，不应未经真人验证就设成通用硬阈值。

## 6. 去重、答案与版本化

建议将“题目”与“解”分开建模。一种初始球形可以有多条合理路线；不能因用户走了另一条也能完成的路线，就按与参考轨迹距离较远判错。

题库覆盖按实际特征分层抽样，例如杆法族、库数与触库顺序、下一球方向、容错档位、距离。质量筛选保证可解与可靠性，多样性筛选保证不同技术均被覆盖。这是对 R14 的产品化迁移建议。

镜像球形可以作为左右手视角训练变体保留，但应归入同一球形家族。统计独立题量、划分训练/验证集和评估泛化时，避免把同一家族镜像当作完全独立新题。是否改变现有题库抽样权重需另行实验，本报告不修改既有权重。

建议每题至少保存：

| 数据组 | 内容 |
|---|---|
| 身份与版本 | 题目 ID、球形家族 ID、生成器版本、物理引擎与台面配置标识/哈希 |
| 原始题面 | 所有球初始状态、球数、顺序/袋口规则、训练目标、硬约束 |
| 解族 | 每杆参数、真实结束状态、进球/碰球/触库事件、解所属路线族 |
| 验证证据 | 独立重放结果、仿真终止原因、参数扫描配置及结果 |
| 容错评估 | 策略定义、误差模型、样本数/种子、成功率与不确定性 |
| 教学索引 | 难度特征、解释所引用的事件、替代解、人工审阅状态 |

教学说明应从已保存的事件与条件生成，例如实际经过的库边、实际下一杆角度和失败风险；生成后检查描述与轨迹一致。不让语言模型凭球坐标自行宣布“这条线路一定能到”。

## 8. 建议的第一轮实验

建议先制作可人工逐题检查的小样本研究集，例如两球 30 题、三球 30 题；这只是试验规模建议，不是本轮已生成或用户已批准的题库数量。优先覆盖自然走位、定杆、跟进、拉回、一库走位、力度/角度选择等训练目标，最终分类以真实解为准。

比较以下三个生成方法，并共享求解器、验收规则、题型配额和模拟预算：

1. 随机球形＋搜索过滤。
2. 已验证首杆出发的前向构造＋全链复验。
3. 末杆约束出发的逆向构造＋全链复验。

记录候选量、名义可解量、容错达标量、最终独立题量、每题模拟次数/耗时、失败原因、题型覆盖和替代解数量。将“预算耗尽”和“明确违反约束”分开统计；运行前不承诺生成速度。

实验的通过条件应包含：每题独立重放成功；每杆状态真实传递；所有硬约束满足；误差评价可复现；教学标签与轨迹一致；人工能解释题目主要练什么。真人难度校准另列，不与仿真通过混为一谈。

优先实现顺序建议：**全链验证器 → 两球小样本 → 三球完整延续 → 容错和多样性 → 批量生成与教学解释**。暂不把训练 GAN、完整强化学习球手或照片识别作为首批题库的前置依赖。
