## 2. 核心设计（第一性原理）

**最大浪费：用完整多球事件模拟去回答本可解析回答的问题。** 在 elevation=0 恒成立的约束下，一杆球四段中前两段可解析：

1. 母球接近段：无 swerve，直线路径 + 分段常加速度闭式解；
2. 碰撞瞬间：squirt（`CueBallStrike` 已是解析模型）+ collision throw（引擎碰撞解算器内已是解析模型）；
3. 目标球段 / 4. 母球走位段：需要 rollout，但可用**单球 + 静态障碍**的轻量模拟替代全场多球模拟。

### 分层求解管线（目标架构）

```
第 0 层  纯几何（ns 级）：切角闸门、母球挡线、障碍挡直线路径（线段-圆测试）
第 1 层  解析（µs 级）：瞄准偏移牛顿反解（补偿 squirt+throw）→ 碰后双球状态
第 2 层  单球 rollout（ms 级）：母球走位段 / 目标球段各自单球+静态障碍模拟；
         走位段撞上障碍球 ⇒ 该候选升级为全模拟（少数）
第 3 层  全保真终验（仅每桶代表解）：现有 buildPrediction 完整多球模拟 = 唯一真相；
         不通过则局部修复或降级
```

对 D-D2「双景观错位」的回应：搜索允许近似，**呈现给用户的解必须通过第 3 层真实全保真终验**——比现状（搜索解无独立二次校验）更严格。

### 搜索策略换代：网格 → 连续曲线求根

固定 spin 组合时，母球停点随 velocity 是台面上一条连续曲线（拓扑变化处断开）。情形 A = 曲线与落区**求交**（自适应采样 + 变号处二分），同时取代 19 档力度网格与 Hooke-Jeeves 精修；情形 B 的速度分段 = 同一条曲线上「经过 P」的参数区间。

### 优化空间估算（推测，B0 校准）

| 路径 | 现状 | 目标落点 | 倍数 |
|---|---|---|---|
| 情形 A | ~2.3s | ~100–250ms | 10–20× |
| 情形 B | ~1.6s | ~100–200ms | ~10× |
| 斯诺克 | ~2.5–5s（推算） | ~0.3–0.5s | 8–15× |

方差最大项：解析层与引擎物理模型的对齐难度（若滑动摩擦细节无法闭式表达，瞄准层收益从 ~4× 降至 ~2×，见 B2 的对拍验证）。

## 3. 任务批次

依赖图：`B0 → B1 → (B2 → B3) 与 B4 可并行 → B5`。每批次一次会话可完成并验收。

### B0 — 基线 benchmark 与 profile（一切优化的前置）

- **范围**：
  - 为四条路径各建独立墙钟 benchmark：情形 A（带/不带精修）、情形 B、`solveSnooker`（**目前无基线，必须补**）、`BatchShotSolver` 单张出片。放入 `PositionPlaySolverTests` / `SnookerSolverTests` 或新建 `SolverPerformanceTests`。
  - 分段计时：瞄准记忆化 / 候选评估 / 精修 / 后处理（polyline 等）各占比，打印到测试输出。
  - Instruments Time Profiler 跑一次情形 A + 斯诺克，确认 `engine.simulate` vs 后处理的真实占比。
- **依赖**：无。
- **完成标准**：基线数字（模拟器 + 至少一次真机）落档到本文件 §1 表格；分段占比数据写入 `tasks/phases/` 对应 Phase 文件；测试可重复运行。

### B1 — 打分与出片分离 + 引擎早停（低风险热身）

- **范围**：
  - `buildPrediction` / `simulateFree` 增加 scoring-only 模式：搜索候选跳过 `polyline` 120Hz 采样、共线简化、`extraBallPaths`；只保留停点、末速、事件流、进袋标志。完整 prediction 仅对每桶代表解重建。
  - `passInfo`（`PositionPlaySolver.swift` L591）改为扫事件段做线段-点距离，替换 dt=0.01 全程回放采样。
  - `EventDrivenEngine` 增加早停选项：母球停稳/落袋且目标球命运已定时提前结束（走位反解不关心残余障碍球滚动）。
  - 顺手：`refineCandidate` 的 ±spinY / ±velocity 邻居复用种子 `aimOffset`（squirt 只随 spinX 变，与主网格记忆化同一物理事实），velocity 邻居用窄括号热启动。
- **依赖**：B0（有基线才能量化收益）。
- **完成标准**：全部金标准测试通过（`PositionPlaySolverTests` 13 条 + `SnookerSolverTests` 4 条 + `PhysicsBenchmarkTests`）；B0 benchmark 显示情形 A 带精修降幅 ≥30%（预期 1.5–2×）；解列表与基线**逐条一致**（scoring-only 不改物理）。

### B2 — 解析瞄准层（收益最集中、技术最关键）

- **范围**：
  - 从引擎/`CueBallStrike` 抽出（**复用而非重写**）：直线弹道闭式解（滑动→滚动分段常加速度）、squirt、collision throw 解析式，组成「给定 (aim, spinX, velocity) → 碰点母球状态 → 目标球碰后方向」的解析函数。
  - 用牛顿/割线迭代替换 `positionAimOffset` 的黄金分割（评分函数同口径：碰后方向对齐 `d_pipe`）。
  - **对拍验证先行**：在改线上路径前，先写对拍测试——解析瞄准 vs 现有黄金分割在全量金标准案例 + 随机抽样局面上的 aimOffset 偏差分布；偏差超阈值（建议 0.05°）的案例逐个归因。若无法对齐，降级方案为「粗解析 + 1–2 次短模拟校正」。
  - 第 0 层几何早筛：障碍球挡母球直线路径的线段-圆预测试，提前判无效候选。
- **依赖**：B1（scoring-only 已就位）。
- **完成标准**：对拍报告落档（偏差分布 + 归因）；金标准全过；情形 A 瞄准记忆化阶段耗时降 ≥70%；每个上屏解仍经第 3 层全保真终验。**命中 ADR 触发清单（替换求解架构），在 `tasks/phases/P13-position-play-solver.md` 末尾补 ADR。**

### B3 — 停点曲线求根替换力度网格 + 精修

- **范围**：
  - `solveRestRegion`：固定 spin 组合，velocity 维改为自适应采样（粗采 5–6 点 → 符号距离变号/拓扑变化处二分加密），落区入口/出口二分求根；删除 Hooke-Jeeves `refineCandidate`（其职责被求根吸收）。
  - `solvePassThrough`：速度分段改为同一曲线机制上的区间求解。
  - 母球走位段用第 2 层单球 rollout；撞障碍球升级全模拟。
  - 保持现有产品语义：吃库分桶、加塞少优先排序、`maxCushions` 优先+兜底、降级最接近解——**不改任何对外行为约定**。
- **依赖**：B2。
- **完成标准**：金标准全过（含 `test_refine_notWorse_andDeterministic` 语义等价改写）；情形 A ≤300ms、情形 B ≤300ms（模拟器，B0 口径）；解质量不劣于基线（每桶代表解的 margin/signed 距离对比落档）。ADR 与 B2 合并或单开。

### B4 — 斯诺克分层搜索（可与 B2/B3 并行）

- **范围**：
  - 几何早筛：合法首触张角、blocker 视线几何，剔除必败候选。
  - 两阶段粗细搜索：7 档瞄准 × 粗力度找可行邻域 → 邻域内加密至当前分辨率；用 `SnookerSolverTests` 金标准防「漏窄可行带」。
  - `simulateFree` 走 B1 的 scoring-only + 早停；候选主体换单球 rollout（B2/B3 完成后二次受益，但不阻塞——先做粗细两阶段即可独立交付）。
- **依赖**：B1（scoring-only）；与 B2/B3 无硬依赖。
- **完成标准**：`SnookerSolverTests` 4 条全过；B0 新建的斯诺克 benchmark 降幅 ≥60%（第一阶段）；B3 完成后回头接入单球 rollout，目标 ≤500ms。

### B5 — 收尾：真机验证 + 批量出片回归 + 文档回写

- **范围**：
  - 真机跑全部 benchmark，落档模拟器/真机对照表。
  - `BatchShotSolver` 批量出片全流程回归（62 drill 抽样）。
  - `PHYSICS-DEBT.md` 更新 D-D1/D-D2 状态；`PROGRESS.md`、Project Hub 状态卡、本文件 §1 基线表回写终值。
- **依赖**：B1–B4。
- **完成标准**：真机情形 A/B <0.5s、斯诺克 <1s（未达标则如实记录差距与原因）；文档回写完成。

## 4. 红线（每批次强制）

1. **诚实交付**：声称完成必须附真实测试输出；解析层任何偏差不得靠调阈值掩盖，必须归因。
2. **物理单一真源**：解析层必须复用引擎同一套常数与碰撞模型（`BTPhysicsConstants` / `CueBallStrike` / 引擎碰撞解算器），禁止重写一份平行物理。
3. **画面=物理**：所有上屏解必经第 3 层全保真终验，终验失败不得上屏。
4. **几何任务**：动坐标/角度代码前遵循 `geometry-spatial-reasoning` 技能，坐标契约回显。
5. **可止损**：每批次保留旧实现对拍路径（feature 开关或并行函数），回归失败可立即回退。
