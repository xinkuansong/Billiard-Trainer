> **真源声明**：本文件是「动作库 drill 试打模式」功能的本轮需求真源。

> **排期前置**：原定 P18 收尾后启动；2026-07-10 用户显式拍板豁免前置、一次性执行（P18 仅余 S6/S7 人工项，无代码冲突面）。

## 1. 需求回显（用户拍板结论）

1. **做什么**：动作库每个 drill 的球形，加「用物理引擎自己打」的选项——自由模式（非进袋闭环求解）下的模拟试打。
2. **不做计分统计**（用户拍板砍掉）：不加自动判定/成绩记录/SwiftData 改动；功能定位=「看完演示后自己上手试线路」，不是训练成绩。进袋类自动计分留二期候选。
3. **不做预览页**（用户拍板）：入口按钮直进试打页；预览价值由试打页内部消化（要点条、首次提示、进场衔接）。多球形选择 sheet 仅在未来 formations 带布局后才做。
4. **复用不新建**：基于 `PositionPlayComposerView` 加试打变体，不新建整页，不基于 `FreePlayView`（其开球流程/规则引擎/禁摆球语义全部冲突）。
5. **多球形**：当前数据层不存在「一个 drill 多套球局」（`tutorial.formations` 只有文案且 Bundle 零实例；`shotIntent.shots[]` 是多杆序列）。MVP 只试打根级球局（`shots[0]` 含障碍球；无 shotIntent 从 `animation` 兜底双球局）。多杆 drill（现仅 c042）只摆首杆局面，用户自行连续击打。
6. **入口位置**：详情页顶部球台演示 `DrillSceneView` 覆层「上手试打」胶囊按钮（与既有回放按钮同层）；Premium drill 按钮跟随 `isLocked` 显示皇冠、点击弹订阅页（Freemium 钩子）。底栏「关闭/加入训练」不动。
7. **试打页裁剪拍板**（v1.1 修订：球库与拖球放开）：
   - 保留：进袋/自由模式切换、切角胶囊、轨迹详细度 chip、瞄准轮、打点+力度柱、SpinPad、击球/上一杆/回放、**底部球库（可编辑）**、**全部球可拖**（用户拍板：自由度给用户，破坏球形靠「重摆」零成本恢复，不做锁定/解锁开关）。
   - 隐藏：开球按钮、重命名序列菜单项。
   - 替换：清空桌面/清空重来 → **「重摆球形」**（一键回 drill 初始布局，做成一等公民放击球动作列旁，不藏菜单）。
   - 标题 = drill 名称。
8. **进场说明卡**（用户拍板加入，要素由本方案定）：桌面球落位后淡入一张半透明说明卡（贴球桌上方），内容**三行、全部从现有 JSON 字段自动生成**（硬约束：不新增文案字段，否则变成 72+ drill 的内容工程）：
   - **局面目标**：从 `shotIntent.shots[0].pocket`（或 `animation.pocket` 兜底）生成，如「把目标球打进右下底袋」；多杆 drill 从 `shots.count` 补「本局共 N 杆，进球后继续走位下一杆」。
   - **训练重点**：`coachingPoints[0]` 原文一句。
   - **参考打法**：`shotIntent` 的 velocity/spin 转人话，如「参考：中等力度 · 低杆」（无 shotIntent 的 drill 省略此行）。
   - **明确不放** `standardCriteria`（实球计分口径，无计分模式下有误导）。
   - 交互红线（守住「不做预览页」拍板）：非 modal、无确认按钮、不阻断操作；用户**首次交互（拖瞄/拖球/击球）自动淡出**或点卡关闭；顶栏 info 图标可召回。该卡取代原设计的「要点条」；D3 的首次手势提示可合并为卡底部一行。

## 2. 关键代码事实（拆解依据）

- 交互底座已完整：拖瞄→出杆→`ShotPredictor` 模拟→`TrajectoryPlayback` 回放，在 Composer/FreePlay 等页已落地；`AimMode.pocket/.free` 已存在。
- `PositionPlayComposerView` 已有外部初始化入口（拍照建球形同模式）：`init(initialBoard: BoardSnapshot?, initialMode: AimMode?)`，`onAppear` 中 `vm.loadBoard` / `vm.aimMode`。
- **缺口 1**：不存在 `DrillContent → BoardSnapshot` 转换器（`DrillShotResolver` 只产出首杆 `ShotInput`，且忽略 `obstacles` 球号映射）。
- **缺口 2**：`AngleRoute` 全部无参 case，无法带 drill 进页——但入口在动作库导航栈内，直接 `navigationDestination` push 即可（详情页已有 `showTutorial` 同模式），**不动 `AngleRoute`**。
- 项目裁剪惯例：无 Config 类型/子类，各 View `onAppear` 设 VM 属性 + View 层显隐（参照 `ShotSimulationView` 的 `vm.maxTargetBalls = 2`）。本方案遵循同惯例。

## 3. 批次表

依赖图：`D1 → D2 → D3(可选)`

### D1 — 数据通路：DrillContent → BoardSnapshot 转换器（量级：小）✅ 2026-07-10

- **范围**：
  - 新增转换器（建议落 `QiuJi/Core/Physics/` 或 `Core/PositionPlay/`，命名如 `DrillBoardBuilder`）：
    - 有 `shotIntent`：`shots[0].cue → "cueBall"`、`shots[0].target → "_8"`（与详情页 `DrillSceneController` 演示用 8 号一致）、`shots[0].obstacles[] → "_1","_2",…` 依序编号跳过 `_8`（obstacles 在 JSON 中无球号，此为本方案约定，执行时如发现更优惯例可调但须回写本节）。
    - 无 `shotIntent`：从 `animation.cueBall.start / targetBall.start` 兜底双球局。
    - 坐标：drill JSON 为归一化 `CanvasPoint`（x∈[0,1], y∈[0,0.5]），`BoardSnapshot.onTable` 同为归一化 `CanvasPoint`，理论上直传；**执行时须按 `geometry-spatial-reasoning` 技能钉死坐标契约核对一次**（对照 `.kiro/steering/table-geometry.md` 与 `DrillShotResolver` 的现成转换），禁脑算断言。
  - 单元测试：c001（无障碍单杆）、c042（3 杆+obstacles）、纯 animation 兜底 drill 各一条，断言球数/键名/坐标。
- **依赖**：无。
- **完成标准**：`make build` 通过；新增单测全绿（附真实测试输出）；转换器对全库 drill 跑一遍 smoke（不 crash、球数 ≥2、坐标在界）。

### D2 — Composer 试打变体 + 详情页入口（量级：中）✅ 2026-07-10

- **范围**：
  - `PositionPlayComposerView` 增试打模式（建议加 `sourceDrill: DrillContent?` init 参数，内部据此驱动 §1.7 裁剪：标题=drill 名、隐藏开球/重命名；球库与拖球保持编排台原样不裁）。
  - 「重摆球形」按钮进动作列（VM 层即 `loadBoard(初始快照)`；注意 `loadBoard` 有 `!isPlaying` 闸，回放中禁用按钮即可）。
  - **进场说明卡**（§1.8）：三行内容生成器（pocket 方位转中文、velocity/spin 转档位/杆法用语——注意与既有力度档名、`BTSpinMiniIcon` 语义同口径）+ 淡入/首次交互淡出 + 顶栏 info 召回。
  - `DrillDetailView` / `DrillSceneView`：演示区覆层「上手试打」胶囊按钮（`ZStack(alignment: .bottomLeading)` 已有回放钮，试打钮放对角 `bottomTrailing`）；`isLocked` 时按钮带皇冠、action 改 `showSubscription = true`；解锁态 `navigationDestination` push 试打页（复用 `showTutorial` 同模式）。
- **依赖**：D1。
- **完成标准**：`make build` 通过；模拟器截图核验（明/暗）：① 详情页试打按钮（解锁/Premium 锁两态）② 试打页布局（无开球/重摆按钮在位/标题=drill 名/球库在位可编辑）③ 进场说明卡三行内容正确（对照 JSON 字段）且首次交互淡出、info 可召回 ④ 载入 c042 球形正确（母球+8 号+2 颗障碍）且说明卡含「共 3 杆」⑤ 击球→重摆回初始布局闭环 ⑥ 拖球改摆后重摆仍回 drill 初始布局；如有既有 UI 测试巡游（`ScreenshotTourUITests`）受影响则同步并复绿。

### D3 — 体验润色（量级：小，可选，可延后）✅ 2026-07-10

- **范围**：首次进入手势提示（建议合并为进场说明卡底部一行，`@AppStorage` 记忆首次，参照「角度与打点」首拖提示既有模式）；载入球形进场淡入动画。
- **依赖**：D2。
- **完成标准**：`make build` 通过 + 截图核验首次提示出现/二次进入不出现。

### 明确不做（二期候选，另立方案）

- 进袋类 drill 自动判定计分 + `DrillEntry` 写入（须加 source 标记区分模拟/实球，防统计失真）。
- 走位类 drill 成功区域判定（需 schema 加可判定 `successCriteria`，内容工程大头）。
- 多球形选择 sheet（等 `tutorial.formations` 挂上布局数据且有实例后）。
