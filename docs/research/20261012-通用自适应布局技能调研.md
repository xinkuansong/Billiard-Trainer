## 建议落点

先完善 `.cursor/skills/swiftui-design-system/SKILL.md`：新增短的通用自适应入口，详细准则放其 `references/adaptive-layout.md`，入口明确按需读取。项目适配器和实现/复核角色沿原路由消费，避免新增第二套同职责真源。后续确有跨项目复用时再提取独立技能。现有设计系统文件已有约1500行，避免继续往入口累积长案例。

职责：通用技能管决策与验证方法；Design System管token/组件；页面卡管宽度、内容和例外；球桌技能管投影与交互；app-live-review管设备控制权、问题闭环和用户确认。

## 应补的规则

| 主题 | 当前不足 | 建议与可验证条件 |
|---|---|---|
| 实际窗口 | window/page/stage规则偏每日专用 | 依据所属窗口/内容宿主bounds和safe area，不用机型名推容量；区分逻辑pt、像素、窗口和渲染容器；旋转/缩窗/放大后读数与内容同步更新，避免重复扣safe area。 |
| 宽度语义 | 640/720pt历史限制容易被当全局默认 | 每页说明阅读、表单、网格、媒体、操作区各自宽度与对齐；限宽需有用途/适用范围。功能展示可扩宽，长文章可保留阅读栏，不能统一全宽或统一720pt。 |
| 容量与降级 | 有局部ViewThatFits，缺统一决策 | 优先弹性Stack/Grid；内容不足再换行、重排或滚动，不能整页压缩、删操作或压小正文凑进窗口。断点由内容所需空间决定，验证临界两侧与恢复。 |
| 测量与状态 | 局部保护场景，缺普通页面规则 | 避免子测量改父frame导致反馈循环；自定义Layout测量/放置使用一致约束；切布局后保留输入、选择、滚动和播放状态，不为适配重建业务模型/SceneKit场景。 |
| Dynamic Type | 系统字体不等于真实缩放 | Typography.swift当前正文等为Font.system(size:)固定字号。另立字体审计任务，核实际字形增长、换行、按钮与滚动，不能仅凭dynamicTypeSize分支或完整AX标签宣称通过。此次详情修订不顺带修改全局字体。 |
| 长内容/本地化 | 缺统一容量样本 | 核长标题、多标签、大数值、日期/计时；适用本地化时用leading/trailing并检查RTL。物理坐标/公式/方向图按语义处理，不能机械镜像。 |
| 固定底栏/键盘 | 历史固定留量和局部overlay较多 | 普通长页优先让safeAreaInset实际预留底栏高度；overlay需说明动态占位和避让。验证页尾、最后输入与提交可达，以及键盘关闭恢复；每日专用overlay不直接替换。 |
| 图像/球桌 | 已有丰富专属规范 | 通用层要求保持比例、真实坐标和触点映射；区分容器与投影。全桌模式核必要桌框/袋口，局部3D视角按任务验，不能一律强制全桌。 |
| 评审矩阵 | 技能间分散 | 按风险选窄/宽、短/高、近方形、适用横竖、真实缩窗回程、浅深、大字号、长内容、键盘、浮层。机器通过、目视通过、用户确认分别记录。环境异常先核宿主/系统，不用App padding掩盖。 |

## 不推广的页面特例

- 每日清台的固定侧栏、球径、144pt标尺、打点盘尺寸和提示位置。
- 本次动作详情扩宽决定：只覆盖DrillDetail，不扩到训练记录和长文。
- 所有iPad自动改为侧栏导航、所有页面一律支持所有方向。
- 全面禁止固定frame、GeometryReader或场景缩放；应按职责与实际消费者判断。

## 官方依据

- [HIG Layout](https://developer.apple.com/design/human-interface-guidelines/layout)：跨空间布局、安全区及适应性。
- [UIView safeAreaInsets](https://developer.apple.com/documentation/uikit/uiview/safeareainsets)：实际宿主安全区。
- [readableContentGuide](https://developer.apple.com/documentation/uikit/uiview/readablecontentguide)：阅读行宽与动态字号；不规定统一720pt。
- [ViewThatFits](https://developer.apple.com/documentation/swiftui/viewthatfits)：按候选理想尺寸选择布局。
- [WWDC22 Compose custom layouts with SwiftUI](https://developer.apple.com/videos/play/wwdc2022/10056/)：Layout量测、组合与身份。
- [WWDC25 iPad设计](https://developer.apple.com/videos/play/wwdc2025/208/)：窗口变化与任务适配。
- [Larger Text evaluation criteria](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/larger-text-evaluation-criteria)：真实文字可读性和功能可达。
- [ScaledMetric](https://developer.apple.com/documentation/swiftui/scaledmetric)：随字号缩放数值。
- [LayoutDirection](https://developer.apple.com/documentation/swiftui/layoutdirection)：方向语义。
- [safeAreaInset](https://developer.apple.com/documentation/swiftui/view/safeareainset(edge:alignment:spacing:content:)-4s51l)、[keyboard safe area](https://developer.apple.com/documentation/swiftui/safearearegions/keyboard)：底栏、键盘与安全区。
- [containerRelativeFrame](https://developer.apple.com/documentation/swiftui/view/containerrelativeframe(_:alignment:))：最近受支持容器并非任意父HStack，避免重复扣安全区。
- [onGeometryChange](https://developer.apple.com/documentation/swiftui/view/ongeometrychange(for:of:action:))：采用时核具体重载与availability。

API边界：safeAreaInset iOS15；ViewThatFits/Layout/AnyLayout iOS16；safeAreaPadding/containerRelativeFrame iOS17。onGeometryChange单值action支持回部署，old/new双值action要求iOS18，不能无条件进入iOS17目标。

## 本轮实例与边界

APP-I029/030：旧P15明确720pt规则，用户本轮要求详情扩宽并删除正文重复标题、等级移至灰标签右侧；以页面卡修订处理，不变成所有页全宽的规则。
APP-I028：04mini红rdar/黑边。Apple论坛有同型问题和Display Zoom临时恢复报告；这不是Apple官方根因结论。用户切换过程中报告卡死，主控仅重启04并保留数据，回放响应恢复但红条/黑边重现，问题未关闭。
来源：[Apple论坛现场报告](https://developer.apple.com/forums/thread/807280)。不可据此修改App padding、删除系统框架或宣布真实设备同样有问题。
