# 球迹渲染计算分工与参数评估

日期：2026-10-11。范围：当前工作区的 SceneKit 交互渲染，重点为每日清台 R 配置。用于判断性能投入是否合理及后续测量重点；不是参数修改或引擎迁移方案。

针对保持画质、物理精度和交互效果的120FPS目标，详见[同画质稳定120FPS与持续温升分析](20261011-同画质稳定120FPS与温升分析.md)，其中补充短时120实测、持续热反例、已失败的优化和后续投入顺序。

**总体判断：房间烘焙、反射预计算和静止停绘的方向合理；台呢的动态遮挡及其采样范围最值得继续研究。现有证据不支持直接降低全部画质参数，也不足以采用已有阴影候选。**

10 月 11 日的新测量比 9 月参考管线更接近当前实现：固定全桌镜头下，关闭当前 R 反射仅减少约 0.9% 的 GPU 命令跨度；关闭直接球影的两次结果约为 11.8% 和 12.5%。但阴影候选的短测收益未在持续测试中稳定重现，正式配置仍保留 R 与 4×MSAA。[当日分项报告](../../output/render-system-audit-20261011/r2/REPORT.txt) · [持续测试结论](../../output/render-system-audit-20261011/r8/REPORT.txt)

## 计算发生在什么时候

| 部分 | 计算阶段 | App 中仍需做的工作 |
|---|---|---|
| 房间墙面、家具、地板的颜色与直接及间接光照 | Blender 离线烘焙 | 绘制几何、读取光照贴图；不重新求解房间光照 |
| 球桌对房间地板的静态遮挡 | 离线烘焙进地板 | 读取已有明暗；运动球影不在其中 |
| 库边台呢 AO、袋内 AO | 离线生成遮挡贴图及数据 | 根据表面位置取样；不是运行时追踪遮挡射线 |
| 球桌、球、球杆的模型与材质纹理 | 预制资源 | 投影、光栅化、纹理采样和材质着色；预制纹理不等于光照全部烘焙 |
| 房间反射探针与环境光系数 | 外观组合首次使用、缓存未命中时生成 | 球面按当前法线和视角取样；球位及观看相机不参与缓存键 |
| R 路径的反射预过滤图、材质响应查找表 | 探针或设备资源初始化时生成并复用 | 运行时查表和局部灯板、台呢反射计算 |
| 天花板纹理及部分装饰 | App 加载所选房间时生成并缓存 | 普通几何和纹理绘制；不逐帧生成纹理 |
| 球面明暗、高光和反射响应 | 每次实际渲染 | 根据当前位置、法线、相机和环境计算 |
| 台呢照明、高光、动态球影、接触暗部 | 每次实际渲染 | shader 求光照及遮挡；CPU 读取呈现球位，参数变化时提交 |
| 木框、皮革、球杆表面响应 | 每次实际渲染 | 使用预制纹理与自定义 shader 求最终颜色 |

房间墙面和地板使用包含光照的贴图及 `.constant` 材质；房间几何不投实时阴影。但球和部分桌面材质虽然也使用 `.constant`，仍在自定义 shader 中计算光照，不能只看材质枚举判断是否有实时成本。

反射探针捕获静态房间和球桌，不每帧捕获其他运动球。它按房间、球桌、台呢、瞄准点显示及渲染配置等输入缓存，当前容量为三种房间风格的数量。转动相机时倒影仍会变化，是采样方向变化，不代表重新烘焙环境。

源码入口：[房间](../../QiuJi/Core/Scene/BakedTrainingRoom.swift)、[遮挡与参数提交](../../QiuJi/Core/Scene/MobileTableRendering.swift)、[反射探针](../../QiuJi/Core/Scene/RoomReflectionProbe.swift)、[预过滤](../../QiuJi/Core/Scene/PrefilteredReflection.swift)、[实时材质](../../QiuJi/Core/Scene/MobileReferenceLighting.swift)。

## 当前参数与合理性判断

下表的数值来自工作区源码；判断为结合项目需求和测量的工程意见，不是跨设备通用阈值。

| 参数或策略 | 当前配置 | 判断与处理方向 |
|---|---|---|
| 活动帧率 | 用户可选 30、60、120，默认 60；受屏幕、热状态与低电模式约束 | 60 作为训练交互目标合理；120 是可选目标，不等于已验证所有设备稳定达到 |
| 静止调度 | 有明确活动状态且无手势、动作及过渡时暂停绘制与 DisplayLink | 合理；未传活动状态的调用方仍可能按活动处理，应逐页核实 |
| 抗锯齿 | `AngleSceneView` 默认 4×MSAA | 保留为画质基线；测实际 pass 和 resolve 成本，不把 4×误解成 shader 必然执行四倍 |
| 像素尺寸 | 按实际视口与显示比例；当日诊断为 2622×1206 | 诊断尺寸不是所有正式页面尺寸。原生清晰度有价值，先减少无贡献计算，再评估质量分档 |
| 台呢高采样 | 每灯 8×4，两灯合计 64 次；低档每灯 2×2，合计 8 次 | 高低档分级合理，但触发域及遮挡范围仍有优化空间；不能直接减采样后宣称等画质 |
| 反射方案 | 每日清台与已接公共配置页面启用 R；共享基础仍保留 A/reference 及失败回退 | R 方向合理；确认真实运行配置，旧 64 次积分不能当作当前 R 成本 |
| 反射资源 | 六个 128²捕获面、512×256 环境图、128²响应 LUT；预过滤每纹素 256 样本 | 没有明显过大证据；256 样本发生于资源生成，不是每帧。优先核初始化卡顿和缓存命中 |
| 房间烘焙与局部 AO | 房间固定光照，库边及袋内预制遮挡，球底接触 AO 动态计算 | 分工合理；保留球贴地与袋内深度线索，暂不作为首要删减项 |
| 各向异性过滤 | 地毯最高 16×，皮革 shader 8× | 偏高质量；低机位有清晰度价值，缺少当前独立成本，不宜先判为浪费 |
| 原生阴影 | 基础路径配置 1024²阴影图、8 样本，参考光照随后将旧灯强度置零 | 抓帧核实际剩余 pass 与可见贡献；不能凭零强度认定无成本，也不能凭历史消融认定可直接删除 |
| SSAO | 移动正式路径关闭 | 现有烘焙与接触遮挡已承担部分功能，没有证据要求重新开启 |

参数入口：[场景配置](../../QiuJi/Core/Scene/AngleTrainingScene.swift)、[视图与调度](../../QiuJi/Core/Scene/AngleSceneView.swift)、[帧率偏好](../../QiuJi/Data/Services/UserPreferences.swift)、[皮革纹理采样](../../QiuJi/Core/Scene/TableSurfaceTextures.swift)。具体页面接入会继续变化，以调用链及实际材质断言为准。

## 当前配置的真机证据

### 固定球架的分项测量

10 月 11 日 r2：iPhone 16 Pro／A18 Pro、iOS 27.0.1，独立诊断 App 使用生产源码、每日清台 R 配置及 `ModelTrial20261010` 模型候选。固定 16 球、全桌镜头、2622×1206、4×MSAA、60FPS 目标；没有击球物理、预测和完整 SwiftUI 页面。无线、未充电，所有窗口起止为 Nominal。

指标为每窗 GPU 命令 buffer 执行跨度的中位数，变化相对前后基线中位数的均值。22 窗、2054 个有效 GPU 样本；每对基线漂移不超过 0.51%。

| 隔离项目 | 原配置 → 变体 → 原配置 | 变化 |
|---|---|---:|
| 关闭台呢原生 PBR | 9.747 → 9.174 → 9.797 ms | −6.1% |
| 关闭整套台呢着色 | 首轮 9.775 → 8.616 → 9.763 ms；反序 9.746 → 8.164 → 9.791 ms | −11.8%／−16.4% |
| 关闭逐球直接阴影 | 首轮 9.763 → 8.549 → 9.775 ms；反序 9.717 → 8.580 → 9.746 ms | −12.5%／−11.8% |
| 关闭当前 R 球面反射 | 9.767 → 9.663 → 9.734 ms | −0.9% |
| 关闭接触阴影 | 9.734 → 9.534 → 9.733 ms | −2.1% |
| 4×MSAA 改成 1× | 9.733 → 8.557 → 9.786 ms | −12.3% |
| 宽高各降至 75% | 9.786 → 8.524 → 9.764 ms | −12.8% |

**这批结果修正了对当前优先级的判断：当前全桌镜头的 R 反射不是首要热点；直接球影仍有可重复的边际影响，MSAA 也并非零成本。** 球体近景、散台和其他页面可能不同。

部分变体的 P95 明显变差，命令跨度分布约为 6–15ms；关闭整套台呢的差值也未形成稳定的包含关系。因此不可把这些百分比相加、直接分配为模块占比，或据此推算省电幅度。没有 GPU 频率及硬件忙碌计数，Nominal 不等于频率恒定。

来源：[r2 完整报告及证据索引](../../output/render-system-audit-20261011/r2/REPORT.txt)。

### 阴影候选的短测与持续表现

r5 的 `support-full-height` 保留原 R 的全部光照采样，仅在独立保守范围判断确认没有原球影贡献时，跳过原遮挡循环。静态球架两次减少约 7.5%–7.8%，散台约 19.7%–20.0%；已测静态截图逐像素一致。另一个会降低采样的 `quality-full-height` 有像素变化，属于近似候选。[r5 报告](../../output/render-system-audit-20261011/r5/REPORT.txt)

这说明减少无贡献遮挡有研究价值，也说明不能把短测收益主要归因于减少 BRDF 采样：优先候选并没有减少这些采样。

r6 动态夹具曾把球心高度错传为台呢高度，导致球下沉一个半径；该轮动态与持续结论已撤回。r7 修复后，50 个抽样时刻的候选与返回基线图逐像素一致；真实轨迹短测 GPU 均值约减少 10.73%，不代表全部连续帧或正式页面事件流验收。[r7 纠错与复测](../../output/render-system-audit-20261011/r7/REPORT.txt)

r8 持续对照采用每 720 帧一个循环，其中 480 帧为生产物理轨迹回放，240 帧为人工边界场景。比较双方共同完成的四个循环，每配置 2880 帧：

| 相同输入区段 | 原 R GPU 跨度均值 | 候选均值 | 变化 |
|---|---:|---:|---:|
| 整个循环 | 14.300 ms | 13.702 ms | −4.18% |
| 真实轨迹段 | 11.213 ms | 13.059 ms | +16.47% |
| 人工边界段 | 20.476 ms | 14.989 ms | −26.80% |

原 R 约 54.46 秒触发 Serious 停止，候选约 120 秒到时结束且为 Fair。但候选先运行，候选结束至原 R 开始约 88 秒，内部温度未测，存在顺序与余热混杂。不能据停止时间证明温升改善，也不能把真实段变慢直接归因于算法本身。

**当前处置：候选保留但暂不正式采用；生产维持 R＋4×MSAA，本批测试已结束。** 后续若恢复研究，应先解释短测与持续结果为何不同，而不是重复引用最好的一组收益。[r8 报告](../../output/render-system-audit-20261011/r8/REPORT.txt) · [浏览页](../../output/render-system-audit-20261011/r8/review.html)

## 调研依据与工程取舍

### 台呢采样需要按贡献范围评估

当前 8×4 与 2×2 由 `shadowPossible` 控制。样本数还影响等面积光样本圆盘的滤波半径，两个灯板的照度比值又跨灯归一化，所以改变样本数并非只减少循环次数，也可能改变软影与亮度。

LTC 可用解析近似处理面积光的材质积分，是值得比较的算法路线，但它不自动解决遮挡或软阴影。当前已有矩形灯漫反射解析计算，也已有候选范围筛选；不能把论文方法名称当成尚未做过的全部优化，更不能承诺替换后的净收益。[LTC 原作者资料](https://eheitzresearch.wordpress.com/415-2/)

### 反射预计算符合成熟实时渲染方法

Filament 使用预过滤环境图与预积分材质响应重建环境反射。我们的 R 路径采用同类方法，同时保留局部灯板和台呢近似。缓存环境避免每帧捕获整个房间，适合当前固定场景。[Filament 技术说明](https://google.github.io/filament/main/filament.html)

反射图的空间位置近似和运动物体缺失属于画质边界；是否需要更精确处理，应由近景画面需求决定，而非为了追求技术完整性直接增加实时探针。

### 抗锯齿及纹理质量应由画面收益决定

Apple GPU 对 MSAA 有高效支持，正确使用片上 tile memory、瞬态附件及 resolve 可以减少内存带宽。SceneKit 的内部附件生命周期仍需抓帧核实。当前 4×MSAA 可继续作为球缘、球杆和辅助线清晰度的对照基线，不把关闭效果的诊断数据当成正式降档建议。[Apple Metal 优化说明](https://developer.apple.com/videos/play/wwdc2019/606/)

mipmap 同时降低远处纹理走样和带宽压力，应保留。地毯及皮革的高各向异性过滤需在低机位、镜头运动中对照，单张远景截图不足以决定是否可以降低。[Apple mipmap 指南](https://developer.apple.com/documentation/metal/improving-texture-sampling-quality-and-performance-with-mipmaps)

### 稳定帧节奏与持续负载必须独立验收

60FPS 的显示周期为 16.67ms，120FPS 为 8.33ms；单个命令 buffer 跨度不能直接等同整帧独占 GPU 时间或利用率。短测达到目标帧率不能证明长期温升合理。Apple 建议从真实长时间运行观察问题，再进入具体帧、shader、资源与同步分析，最后评估功耗与设备分档。[Apple 游戏性能与功耗方法](https://developer.apple.com/videos/play/meet-with-apple/242/)

以上外部资料于 2026-10-11 查询；算法及工具资料提供方法依据，不提供本项目具体毫秒数，也不意味着要接入 Filament、迁移引擎或采用新系统专属 API。

## 后续验证顺序

1. **冻结当前可复现基线。** 记录实际源码、模型哈希、R 配置、视口像素、4×MSAA、帧率及回放输入；诊断宿主与完整页面分别记录。禁止使用已撤回的 r6 动态数据。
2. **解释持续结果的变化。** 若重启真机研究，以成对且交错顺序、可比起始条件验证 r8 真实轨迹段；分开统计真实与人工边界，尽可能补硬件计数、频率或可靠 GPU 调度证据。
3. **拆剩余渲染 pass。** 核对台呢自定义着色与原生 PBR 的实际工作、原生阴影、几何及纹理带宽、MSAA resolve。关闭台呢 PBR 有差值不等于它可无损删除，具体冗余仍是待证假设。
4. **优先验证保留采样的遮挡范围候选。** 覆盖散台、球架、近景、低机位、相机运动、抬球、淡出与真实入袋。短测图像一致、短测时间收益、持续表现分别判定。
5. **再评估采样和质量分档。** 减少光照样本、过滤级别或渲染像素均单列画质变化，不混入等画面优化结果。最终回到真实页面的瞄准、击球、相机切换与停稳流程。

测量须分别报告 CPU 编码、GPU 命令跨度、实际呈现间隔、内存、系统热状态和用户温感。没有瓦数或焦耳证据时，不报告省电百分比；长时收益不稳定时保持正式配置。当前没有启动新测试或修改渲染参数。
