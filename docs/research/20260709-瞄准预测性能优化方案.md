# 瞄准预测性能优化方案 v1.1（UI 实时管线提速）

> 日期：2026-07-09 ｜ 状态：**P1–P3 已完成（2026-07-09），P4 后备未触发** ｜ **本文件是本轮需求真源**
> 排期：独立性能专项，不与「翻袋反射页重构方案」（同日文档）挂钩；两者代码路径不同（本方案为 PositionPlay/共享 `predict` 管线，翻袋为 `BankShotCalculator`/`EngineCushionTracer` 管线）。
> 锚点核实日期：2026-07-09（全部读代码确认）。

## 0. 需求回显（2026-07-09 用户拍板）

1. **问题**：物理引擎单次瞄准计算（母球+目标球+袋口 → 轨迹线）与管道瞄准反解偏慢，体感为：自由模式轨迹线展示慢；进袋模式改目标球/母球/袋口时卡顿。
2. **方向拍板**：优先做「切解析瞄准快路径」+「搜索阶段截断」两个核心提速项；**解缓存与 120ms 去抖明确不做**（单次便宜后无必要，缓存 key 一致性风险不值得；20ms 去抖保留，跟手性更好）；补「在途合并」防队列积压。
3. **热启动窄括号**留作实测不达标时的后备批次，不默认做。

## 1. 现状诊断（已读代码核实）

两种模式共用 `PositionPlayViewModel.recompute()`（L639）：20ms 去抖（L679）→ 后台 `predictQueue`（L151）→ `PositionPlayShotSolver.solve`（L14）分流：

| 模式 | 路径 | 每次改动的模拟量 |
|---|---|---|
| 自由 | `ShotPredictor.simulateFree`（L314） | 1 次全保真模拟 |
| 进袋 | `ShotPredictor.predict`（L134）→ `solveAimOffset`（L663） | **75 次完整模拟**（三级网格 49+13+13，每次 `maxEvents=500/maxTime=15s`，**跑全程无截断**）+ 1 次全保真终验 ≈ **76 次** |

拖球（`dragMoved` L396）、选目标（`selectTarget`）、选袋（`selectPocket`）、改力度/塞（`onParamEdited` L90）均触发 `recompute()`。进袋模式卡顿的直接来源即 76 次模拟/次。

**关键事实（决定拆批方式）**：

- 走位反解管线（ADR-P13-01 / B1 / B2）已做出经对拍验证的快路径：`predictForPositionSolve`（L807）内层用 `positionAimOffset`（L835）——黄金分割 ~15 次评估，默认走 `AnalyticAim.outcome` 闭式解评分（`useAnalyticPositionAim = true`，L833），**不进事件循环**。对拍结论（`AnalyticAimParityTests`）：评分偏差 P95 0.013°、求解 Δoffset 全量 0°、零丢解。
- 快路径 vs `predict` 的进袋判定一致性已有硬校验：`PositionPlaySolverTests.test_fastPath_matchesPredict_potOutcome`（L328）。刀锋景观下母球停点允许合法分歧（±0.02° 扰动停点可移 ~2m，两优化器落窗口内不同微位置均合法，L348–351 注释）。
- `predict()` 是共享核心：`DrillSceneView`（L93）、`DrillThumbnailRenderer`（L37）、`ShotBaker`（L52）与约 15 个物理测试文件直接消费。**直接改 `predict` 内核波及面大**（刀锋案例展示轨迹可能微移 → 缩略图烘焙基线漂移），故 UI 提速走「换调用入口」而非「改内核」。
- `solveAimOffset` 搜索评分 `score()`（L681–699）只消费「碰后目标球首帧方向 + 未命中时 cueGhostMinDist」，与 `positionAimScore`（L875）**完全同口径**；后者已证明加 `earlyStop: true, stopAfterContact: true` 后**评分值与整程逐位一致**（L882–883 注释 + `EventDrivenEngine.simulate` L92–93 文档）。`AimScoring` 里「搜索必须与最终同保真否则双景观错位」的注释（L648–649）写于 B1 之前，对「截断」不适用（截断≠降保真）。
- **降保真已被否决**：B4 曾试关 `highFidelityBounds` 换性能，被 `ScoringOnlyConsistencyTests` 打回（多球盘面近库子步会微移轨迹甚至改碰撞拓扑，`ShotPredictor.swift` L350–353 注释）。本方案**不含**任何降保真项。
- 在途任务不可中断：`DispatchWorkItem.cancel()` 只能取消未开跑的任务；已在跑的 76 次模拟会跑完才轮到下一个，快速拖动时队列呈「跑完一个作废一个」。
- 已有量测基建：`PerformanceProfiler`（`ProfilerLabel.predictorSimFreeEngine` / `predictorRunShot`）、`PhysicsPerformanceTests.medianPredictMs`（L65）。

## 2. 明确不做（用户拍板 + 红线）

| 项 | 不做理由 |
|---|---|
| 解缓存（LRU） | 优化后单次≈1 次模拟+15 次闭式评估，重算与命中无感知差；缓存 key 漏成分是「球形变了展示旧解」类 bug 的高发源。翻袋页做缓存有其特殊性（`solveAll` 多库多解枚举 + 恢复球形高频命中场景），本管线无对等场景。 |
| 120ms 去抖 | 去抖是「计算太贵只好少算」的补偿；单次便宜后 20ms + 代际作废够用，120ms 反而给拖停后多加 0.1s 主动延迟。 |
| 拖动中降保真 | B4 已试已否（`ScoringOnlyConsistencyTests` 红线：scoring 与全保真必须逐位同物理）。 |
| 改 `PositionPlaySolver` 离线反解 | 该管线已是快路径本尊（E 系列已优化），非本轮瓶颈。 |
| 改 `predict()` 三级网格内核参数 | 波及缩略图烘焙基线与全部物理测试套；P2 只加「逐位一致」的截断，不动网格。 |

## 3. 批次拆解（每批一次会话完成并验收）

### P1 — UI 进袋预测切快路径（S，核心收益）

**范围**：`PositionPlayShotSolver.solve`（L14）袋口分支由 `ShotPredictor.predict(input)`（L44）改为 `ShotPredictor.predictForPositionSolve(input, includePresentation: true)`。一处改动，只影响 PositionPlay 三页 UI 管线（编排台/分离角/自由击球），`DrillSceneView`、缩略图烘焙、测试套照旧走 `predict` 零影响。成本：76 次模拟 → 15 次闭式评估 + 1 次全保真模拟。
**依赖**：无。
**完成标准**：
- 既有对拍测试 `PositionPlaySolverTests.test_fastPath_matchesPredict_potOutcome` 与全量物理测试套通过（`make build` + 测试输出附会话）。
- 基线对比：改动前后各跑一次 `PhysicsPerformanceTests`（或 `PerformanceProfiler` 采样），记录进袋模式单次预测中位耗时，结论写入本文件 §5。
- 模拟器实测：进袋模式快速拖母球/切袋口，轨迹线跟手无可感知卡顿；自由↔进袋切换正常。
- 注意消费字段口径：`aimOffsetUsed` 会被填充（`predict` 路径为 nil），核查 `PositionPlayViewModel.apply` 及下游无对 nil 的依赖。

### P2 — `solveAimOffset` 搜索阶段截断（S，惠及其余 `predict` 消费者）

**范围**：`solveAimOffset.score()`（L681）的 `runShot` 调用加 `earlyStop: true, stopAfterContact: true`（与 `positionAimScore` L884–889 同参数）；同步改写 `AimScoring` L648–649 过时注释（截断≠降保真，评分逐位一致的论证引 B1）。最终终验模拟不动。受益方：`DrillSceneView` 实时预览、缩略图烘焙、物理测试套整体提速。
**依赖**：无（与 P1 可并行/换序；P1 落地后 UI 不再依赖此路径，本批价值仍在离线消费者）。
**完成标准**：
- 全量物理测试套通过（重点：`ScoringOnlyConsistencyTests`、`PhysicsMatrixTests`、`PocketBehaviorDiagTests`、`PhysicsInvariantTests` 确定性用例 L184–188）。
- `PhysicsPerformanceTests` 前后对比记录 `predict` 中位耗时降幅。

### P3 — 在途合并（S，防队列积压）

**范围**：`PositionPlayViewModel` 预测调度改为「单飞 + 末班车」：在途任务跑完后若期间有新请求，只重跑**最新**一次（丢弃中间态），替代现在「排队跑完一个作废一个」。保留 20ms 去抖与 `predictGeneration` 代际作废。实现建议：`isInFlight` 标志 + `latestPendingIntent`，任务收尾时检查补跑；不引入新队列。
**依赖**：无（P1 落地后单次已便宜，本批是极端快速拖动的兜底）。
**完成标准**：
- build 通过；快速连续拖动 + 疯狂切袋口场景实测：松手后最终轨迹与球形一致（绝不展示旧解），无积压等待。
- 一致性红线自查：任何最终上屏的解必须对应最新一次 intent（代际检查逻辑保留）。

### P4 —（后备）拖动热启动窄括号（S–M，仅实测不达标时启动）

**范围**：拖动会话内缓存上一帧 `prediction.aimOffsetUsed`，拖动中 `positionAimOffset(center: 上帧 offset, halfRange: ±0.6°)` 窄括号精修（先例：B1 邻居精修，L828–829 注释，~15 次压 ~9 次），`dragEnded` 做一次全幅求解兜底并清缓存。
**依赖**：P1。
**触发条件**：P1–P3 完成后模拟器实测进袋模式拖动仍有可感知卡顿，才立项；否则本批作废。
**完成标准**：build + 全幅兜底语义单测（拖中窄括号解与拖后全幅解进袋判定一致）+ 实测。

依赖图：

```
P1 ──┐
P2 ──┼──（互相独立，可并行/换序）
P3 ──┘
P1 ──→ P4（后备，条件触发）
```

## 4. 红线约束

1. **物理零漂移**：P1 换的是已对拍验证的入口，P2 加的是已证逐位一致的截断；任何测试套红了立即回退，禁止调容差让测试变绿。
2. **画面=物理**：不引入任何「预览线与真实解不同物理」的路径（降保真、粗网格预览均已排除）。
3. **一致性**：绝不出现球形/参数变了还展示旧解（P3 代际检查保留）。
4. **诚实交付**：每批完成标准中的构建/测试/耗时对比须附真实输出，不凭体感宣称提速。
5. 几何/坐标类改动（P4 括号语义）动代码前遵循 `geometry-spatial-reasoning` 坐标契约回显。
