## 二 语域规则

### 2.1 教练话怎么写

1. **主语是「你这一杆」，不是「本法则」**。写「碰撞那一瞬间，母球总是先沿切线走」，
   不写「切线法则指出母球沿切线运动」。
2. **先给结论，再给原因**。每节第一句就是读者要带走的那句话。
3. **动作可执行**：凡「怎么用」类内容，写成球台上能照做的动作（「把球杆贴着目标球摆」），
   不写抽象步骤（「确定切线方向」）。
4. **句子短**。一句一个意思；超过约 40 字就断句。原文的从句嵌套一律拆开。
5. **力度 / 杆法以定性词为主，数值退括号**（v26 DR-063）：写「力度越大」「打了高杆或低杆」，
   不写「v = 2.0 m/s 时」。
6. **允许口语连接词**（「其实」「起码」「最见效」），但不写网络语、不写感叹句、不用 emoji。

### 2.3 禁用句式与禁上屏内容

| ⛔ 禁 | 原因 | 正确做法 |

| 「根据定理 T03」「本法则告诉我们」「由 T01 可知」 | 教材腔（红线 3） | 直接说结论；要引别的定理就用**页名**（「30° 法则」） |

| `Status: candidate`、`Owner-Question`、Tier 标注、字数统计「(58 字)」 | 调研元数据 | 一律剔除 |
| 推导过程、跨源共识论证、自检清单、调研待办 | 面向研究者不面向球手 | 剔除；结论已由正文承载 |

| 「图待补」「敬请期待」「更多内容后续上线」 | 空洞占位（既有纪律） | 要么给一个真能点的去处，要么整块省略 |
| 16 原文没有的断言 | 红线 2 | 缺口登记回传 16，⛔ 不脑补 |

### 2.4 数值纪律

- 数值、单位、区间**逐字照抄**来源（`14°–49°`、`87.5%`、`9 档`）；⛔ 不四舍五入、不换算区间。
- 需要换单位时（英寸 → 毫米）**必须与仓内常量交叉核对**并在取舍表注明依据。
  试点实例：三指宽 `2.25 inch` → 「约 57 毫米」，依据 `BTPhysicsConstants.diameter = 57.15mm`
  （中式八球球径与美式一致，故原文该条在本仓语境下成立）。
- 原文口径未定义的数字**不上屏**（试点实例：T08「自己可击 OB% 47% / 11%」），登记回传 16。

**公式的取舍口径（W1 细化，覆盖组件规范 §三「不删公式」的一刀切表述）**：

- **可操作口径公式留**（几何 / 数值换算，如 `d = 2R·sinθ`、切线 ⊥ 连心线）→ `LearnDocFormulaNest`。
- **解释性公式剔**（只用于说明"为什么这么想"，读者不会代入计算，如 T08 的期望值
  `EV = P(make)×P(position)×V(continue) − P(miss)×V(opponent)`）→ 剔除，语义由正文承载；
  在取舍表记「剔除 + 理由」。

### 3.1 配图决策树（r1 重写 —— 原「可以只深链、可以无图」的口径已作废）

> ⛔ **硬性前提**：每篇理论页**至少一张页内说明图**，放在对应正文节的
> `LearnDocSectionCard` 内。深链只能是「看更多」，**不能代替页内图**。
> 详细骨架与约束见组件规范 §四。W1 人工验收就是栽在这一条上。

逐篇按下面四步走，结论写进该篇的取舍对照表：

**第 1 步 · 这篇属于哪类？**

| 类 | 判据 | 例 |
|---|---|---|
| A 物理几何类 | 断言是两球 / 球与库 / 方向角度的几何关系 | T01 30° 法则、T02 90° 法则、T03 切线、T04 投掷、T05/T06 库边 |
| B 战术决策类 | 断言是「什么条件下该怎么选」，与具体球位无关 | T08 三问、T10 安全球分级、清台 5 步流程 |
| C 具体局面类 | 只有摆出某个真实盘面才讲得清（哪颗球挡了哪颗） | 「被挡死」的实例、开球后典型球形 |

**第 2 步 · 用哪种图？**

- A → **真台标注图**：`BTTableFigure` + `FigureLine` + `BTFigureBall` / `BTGhostCircle` /
  `BTContactDot` / `BTFigureTag`，主图 250pt + `BTRadius.md`。
  先查能不能直接复用：`SeparationPathsFigure`（碰后三路径，`emphasizeAll: true` 三条同显）、
  `AimingFigure`（切角全景）、`thicknessCanvas`（厚薄特写）；不能复用才写本页 `private struct`。
- B → **非球形抽象图示**：`GeometryReader`（或 `Canvas`）+ `Path` / `RoundedRectangle` + token 色。
  样板：`ThreeQuestionFlowFigure`（判定流程）、`RiskRewardZoneFigure`（二维分区）。
  ⛔ 图里不许出现球，也不许标正文没给的连续标度 / 概率数字。
- C → ⛔ **不画**（命中红线 5：AI 不生成球形坐标）。改为按组件规范 §4.5 格式
  **登记文字描述**（球形要点 + 镜头 + 标注需求，不含坐标）交人工编排台录制，
  并在本批汇报「待人工录制」区列出。

**第 3 步 · 几何真源取哪个函数？**（仅 A 类；⛔ 禁手填坐标常量凑图）

| 要画的东西 | 真源函数 |
|---|---|
| 球形（母球 / 目标球 / 假想球 / 接触点 / 瞄准线 / 进球线 / 切角） | `AimingMethodsGeometry.scene(cutAngleDeg:)`（`SpinAndEnglishGeometry.scene` 转调同一入口） |
| 切线方向（⊥ 连心线） | `SpinAndEnglishGeometry.tangentDir(scene:)` |
| 碰后三路径（滑动 / 前旋 / 后旋教学折线） | `SpinAndEnglishGeometry.departureDir / pathEnd`；角度校验 `separationDegrees` |
| 进球线远端 | `SpinAndEnglishGeometry.objectBallEnd(scene:)` |
| 瞄准点 / 偏移 d | `AimPointGeometry` / `AimingMethodsGeometry.classicDOverR` |
| 球径 / 袋口 / 台面 | `AngleSceneCalculator`（`ballRadius` / `pocketMarkerPositions`） |

动手前**回显坐标契约**（技能 `geometry-spatial-reasoning` §1）写进视图注释；
出图后必须落一条不变量单测（范式 `TheoryFigureGeometryTests`：垂直 / 长度 = 2R / 端点不出取景框），
并在汇报里给「图元 ↔ 真源函数」映射表。⛔ 不许用「看着像」交付。

**第 4 步 · 红线 5 命中了吗？**
只要图里需要「某颗球具体在哪」才成立 → 命中 → 回第 2 步走 C 分支。
A 类不命中：球位由真源函数按角度参数算出，属于几何示意，不是编排战术局面。
