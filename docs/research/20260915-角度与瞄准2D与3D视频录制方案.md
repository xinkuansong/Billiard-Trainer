## 2. 坐标与球位

### 2.1 坐标契约

- 使用 SceneKit 世界坐标，单位米；X–Z 为台面，Y 向上。
- 有效台面：X ∈ [−1.270, +1.270]，Z ∈ [−0.635, +0.635]。
- 球半径 R = 0.028575 m，球直径 57.15 mm，保持球与球桌真实比例。
- 所有球心高度为 `scene.surfaceY + R`，不硬编码台面高度。
- 下表只列水平坐标 `(X, Z)`。袋口名称按世界坐标确定，避免横竖屏的“左/右袋”歧义。
- 尺寸及映射依据 `.kiro/steering/table-geometry.md`、`AngleSceneCalculator`；画面上方为+X、右方为+Z。

### 2.2 固定参数

| 对象／距离 | 数值／规定 |
|---|---|
| 目标袋口 | 画面右上角袋，+X/+Z，`pocketIndex = 3` |
| 目标球 T | `(0, 0.100000)`，黑色8号球 |
| 有效入袋点 A | 运行时由 `effectivePocketAimPoint` 计算，实际值与距离记录于 `keyframes.json` 与录制报告 |
| 假想球中心 G | `T − 2R·normalize(A−T)` |
| 初始母球 C₀ | `G − 0.520·normalize(A−T)` |
| 初始两球心距 | 577.15 mm |
| 初始两球表面间距 | 520 mm |
| 母球至假想球中心 | 全程固定520 mm |

### 2.3 母球运动定义

切角沿用页面定义：母球→假想球方向与目标球→有效入袋点方向的夹角。母球绕假想球中心旋转，不能直接绕目标球旋转并把转角当作切角。

```text
n = normalize(A − T)      // XZ二维向量
s = (n.z, −n.x)
G = T − 2R·n
C(α) = G − 0.520·(n·cosα + s·sinα)
α ∈ [0°, 89°]
```

每帧用生产切角计算复核实际角度；8号球和袋口不移动。关键帧检查先以0.1°间隔遍历891个角度，断言母球不出矩形台面、两球不重叠、相机不移动，再保存0°、30°、60°、89°两种视图。旧版红球/中袋坐标与数值验收不适用于本版。

## 3. 画面与机位

### 3.1 共用构图要求

- 画面主角是两球、假想球、瞄准方向和目标右上角袋；台呢与局部库边形成环境。
- 球桌为画面主体，完整台面与球房陈设共同构成3D画面；以拉远后的实际静帧确认占比。
- 两颗实球的屏幕直径以画面短边的 3.5%—5.5% 为目标，即 1080×1920 下约 38—59 px；拉远后的3D全程不低于28 px，2D仍保持原尺寸。
- 通过相机取景改变屏幕大小，不放大球模型、不缩小球桌、不改球径。
- 球体、假想球、目标袋口和角度标注距成片边缘至少 5%；动态瞄准线延伸到库边可自然止于台面。
- 保留杆头和母球后至少 200 mm 的前节，用于解释瞄准方向。允许杆尾自然出画，不为容纳整根球杆把两球缩小；杆头不得裁切或突隐。
- 禁止后期透视拉伸或不同方向缩放；输出裁切须固定，两段分别记录裁切矩形。

### 3.2 2D 竖屏俯视（社交媒体版）

- 正交俯视，球桌长轴竖直摆正。屏幕上对应+X，屏幕右对应+Z，与3D从−X短边观察的左右方向一致。
- 观察中心为`(0.24, scene.surfaceY, 0)`，相机位于正上方，为顶部信息栏预留空间，up向量为+X。
- 正交半高`orthographicScale=1.70 m`：垂直可视3.40 m，9:16下水平可视1.9125 m。
- 1080×1920版本的理论球径32.273 px；以最终实际投影复测为准。
- 目标+X/+Z角袋在画面右上方，母球沿重算后的圆弧移动；不镜像视频、不改变球形和切角。
- 完整台面与运动范围一次入镜，录制过程中不缩放、不平移。

### 3.3 3D 竖屏正向固定俯视（社交媒体版）

**用户最终要求：所有视频用于社交媒体，均为竖屏；画面基本都是球桌，球桌摆正，摄像头角度不变。** 此版本取代此前横屏机位。

- 相机从−X短边正中向桌面中心观察；球桌长轴沿画面竖直方向摆正，左右对称，不斜放、不环绕，保持自然透视。
- 尽量保留完整台面与四角；用户进一步要求有明显倾斜角和球房环境：保留库边厚度、部分桌裙/桌腿以及地面或球房陈设。桌框投影包围框目标占画面宽度85%—96%、高度60%—80%，以静帧测量为准；空间立体感优先于把背景全部裁掉。
- 目标+X/+Z角袋位于画面右上方，与2D方向一致。

| 参数 | 竖屏初始设定 |
|---|---|
| 观察中心 | `(0, scene.surfaceY, 0)` |
| 相机方向 | −X短边正中，Z=0；相对+X方位角180° |
| 相机仰高角 | 相对水平面35°，朝桌面中心向下看 |
| 相机至观察中心距离 | 5.10 m |
| 视场角 | 垂直FOV 40°，固定投影轴 |
| 滚转 | 0°，世界+Y为up |

上述相机距离随竖屏窄视口重新计算，不能沿用横屏2.5m机位再裁边。允许录制前在俯角30°—45°、距离4.8—5.5m内微调；方位180°、滚转0°保持。镜头位置、观察中心、俯角、FOV和裁切在静帧复核后一次锁定，片内不改变。

若完整球桌与球径目标冲突，优先满足摆正、主体完整和1080宽版本球径≥28px（用户要求进一步拉远后调整，须配合真实静帧判断）；记录实测占比，不放大球模型、不变形球桌。

### 3.3.1 社交媒体安全区

- 成片不带平台水印、按钮、鼠标、触点或App导航控件。
- 五行信息栏 1080×1920 基准原点：2D `(216,1250)`（台呢左侧）、3D `(68,392)`（沙发与远端库边之间地面）；2026-09-15 由左上 `(96,96)` 迁出，原因是左上角在社交媒体会被平台控件遮挡；不把重要信息放进底部15%或最右侧约10%的常见平台控件区域。
- 此安全区为通用发布留白，非任何平台当前官方UI尺寸承诺；本次不发布到外部平台。
- 球桌可以延伸至安全区外；两球、接触点、角度读数等教学主体须保持清楚。杆尾允许自然出画。

### 3.4 可见信息与外观

- 固定小型读数 `切角 0.0°` 位于上述面板内，字体使用等宽数字，推荐成片 32—36 px。
- 恢复页面完整指标：角度、厚度重叠图与名称、d/R、横移毫米、偏移百分比；隐藏的是操作按钮，不是教学信息。
- 台面完整保留现有瞄准线、目标球进球线、假想球环、接触点、角度弧，以及“瞄准线”“进球线”和角度文字。直接复用`DiagramLabelOverlay`，不另写标注算法；导出须验证三个标注均可见。
- 不显示“拖动中”“编辑请切回2D”等交互提示；没有手指、鼠标、点击圆圈、按钮或倒计时。
- 外观在启动时冻结并记录实际资源/偏好键；标准绿台呢、标准8号球和白球一致用于两段。不改全局用户已保存的外观偏好。
- 运动表示几何摆位，不模拟白球沿圆弧自行滚动：球皮姿态保持稳定，无拖动脉冲放大、无滚动音效、无出杆。

### 89° 边界

当前 `pocketFeasibility` 在 `angle >= maxCutAngle`（89°）时返回不可行，`updateCalculations` 随后隐藏辅助线和球杆。

录制专用显示层应允许 **[0°,89°] 的理论几何**持续显示，将教学展示与正式可进球判定分离。不能全局修改 `maxCutAngle`，不能伪造正常可行性，不能停在 88.9° 却标成 89°。最终角度以生产函数复算，浮点误差验收 ≤0.01°。

## 6. 执行顺序与交付物

1. 保存当前工作区基线及资源版本，确认相关球径、袋心和页面入口无漂移。
2. 实现最小录制模式，运行生产计算得到 A、G 和 891 个样本，核对本文数值及边界。
3. 两种机位分别生成 0°、30°、60°、89° 原始静帧，共 8 张，附一张对照联系表。
4. 按第 3 节测量球径、关键对象边距、遮挡、标注和杆头；在规定范围内校准并冻结镜头，把最终参数写入录制记录。
5. 在模拟器宿主内预热场景，以SCNRenderer按60fps绝对时间逐帧生成真实4K画面，用VideoWriter写入900帧。
6. 输出两段 MP4，核验编码、分辨率、时长、实际画面节奏及首尾状态；抽帧复核，不只看文件成功生成。

## 7. 验收标准与降级规则

- 几何：0°—89°单调变化；复算角度误差≤0.01°；全程球体不重叠、不越界，目标球与目标袋口不变。
- 一致性：两段同时间球位差≤0.1 mm、切角差≤0.01°；捕获同步误差不超过一个交付帧，不能仅靠肉眼“差不多”。
- 端点：确实到达89°；终点2秒内球杆前节、假想球和辅助线不消失。
- 构图：实际球径：2D≥32 px，拉远后的3D≥28 px；优先达到38—59 px；目标袋口、两球、假想球与读数满足边距要求，无相互遮挡导致的教学信息丢失。
- 稳定性：相机不漂移，线条不闪烁，贴纸不跳转，标签不频繁换边；出现标签跳变需在录制布局中稳定安排。
- 纯画面：没有按钮、操作提示、加载画面、系统栏、鼠标或触点；无片内切换镜头。
- 流畅性：按每秒60个独立时间样本导出，编码、帧数与几何账本交叉核验；不通过重复帧补齐运动段。逐帧导出不等于App实时4K60fps性能证明。
- 原始场景帧为2160×3840；2K/1K仅从该母版等比例缩小，不上采样。
