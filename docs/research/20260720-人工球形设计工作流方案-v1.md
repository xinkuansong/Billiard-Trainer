## 一、需求回显（用户拍板结论，语义基准）

1. **对 B5 审计存疑，坐标人工出**：72 drill 的球形序列由用户本人设计，AI 不生成球形坐标（延续 2026-06-13「禁反推」红线并扩展：**本轮 AI 不代做球形设计**）。审计的变量/覆盖结论仅作参考。
2. **设计场所 = 批量出片台**：用户在出片台（`BatchDrillStudio`）内完成摆球与保存，因此需要一个**「新增球形」操作——不走截图来源**，直接摆球建形。
3. **AI 侧交付三样**（2026-07-20「按照你的建议」拍板）：
   - **权威基准图集**：B1 基准库坐标渲染成本项目台面风格示意图（渲染图为主 + 官方原图引用为辅），按 8 分类组织，标注可信度；
   - **变量清单（轻量版）**：全局变量词典 + 8 分类各一页「常用变量组合菜单」，**不做逐 drill 变量档案**（用户自己按菜单挑）；
   - **设计后验算脚本**：读用户存的球形序列，算实际切角/距离/变量取值 + 覆盖矩阵，作为设计后质检（几何红线：脚本验算不脑算）。
4. **出片台改动三点确认**（同轮拍板，采纳推荐）：
   - **initial-only 保存放开**：只摆球不击打即可保存（示范击打仍走人工录制线，后补）；
   - **「从已有球形克隆」起点**：新增球形时可复制该 drill 已有球形的初始布局再改；
   - **无截图 drill 支持**：出片台列出 `index.json` 全部 72 条 drill，即使项目 15 无截图文件夹（标注「无源图」）。
5. **边界**：审计缺失清单 M2–M5 的**全新 drill** 不在本轮（它们尚无 drill JSON / index.json 登记，属 R11 另案）；本轮工具只服务既有 72 条。

## 二、代码现状关键事实（2026-07-20 读码核实）

- **球形↔截图绑死**：存档键 `drill_cNNN__<token>-<名>-<N>杆.json`，token 从截图文件名派生（`BatchDrillCatalog.formationToken`，`BatchDrillStudioCore.swift` L83–93）；无图时保存退回 `drillId` 单键（`BatchAuthoringView.swift` L884 stem fallback），即无图路径现在只能存一个球形。
- **人工 token 已有先例**：c053 的 8 条序列 token = `A1`–`A8`（B4 管线直写，非截图派生），文件名如 `drill_c053__A1-中袋角度球 · 球形1-0杆.json`——证明**人工 token + 0 杆文件在归档命名、`loadSavedFormationMap` 解析、`tryout-sync`、`DrillTryoutBoardStore` 全链路已可用**。
- **initial-only 下游已支持**：`PositionPlaySequence.steps` 默认 `[]`（`PositionPlayModels.swift` L141–163）；`DrillTryoutBoardStore.formations` 对空 steps 仅 `hasSequence=false`（序列模式降级，试打/重摆正常，L45–47）。**唯一拦截点是出片台 UI**：`BatchAuthoringView.requestSave` L858–863 的 `steps.isEmpty` 检查。
- **drill 列表来自截图目录扫描**：`BatchDrillCatalog.load()`（`BatchDrillStudioCore.swift` L96–127）只列项目 15 `shooterpools录制/` 下有图的文件夹；`index.json` 仅用来补 category/登记态。无截图 drill 不出现。
- **跳过拍照直进编排台已有先例**：「改存档」路径 `editArchive`（`BatchBallExtractionView.swift` L224–235）设置 `context.confirmedBoard + editingSequence` 后直接 `goAuthor`——新增球形入口可仿此结构（confirmedBoard 置空/克隆快照，editingSequence=nil）。
- **选图栅格**（新增球形入口落位）：`BatchBallExtractionView.pickStep` L113–177（LazyVGrid 两列缩略图）。
- **覆盖确认**：`hasExistingArchive`/`archive` 按 `drillId__token-` 前缀判同覆盖（`BatchDrillStudioCore.swift` L241–294），人工 token 语义自然兼容。
- **序列命名**：`BatchAuthoringContext.defaultSequenceName` L328–333 依赖 `imageURLs.firstIndex` 编「球形K」号，无图路径需另编号。
- **几何脚本口径现成**：`scripts/b5_audit_drills.py` 头部有袋口坐标表、袋口轴向、切角双口径（cut_travel/cut_apparent）、入袋角定义；`scripts/b2_variable_coverage_midpocket.py` 是变量覆盖推导先例。scripts 目录尚无 matplotlib 绘图先例（B2 图集脚本为新建）。
- **B1 基准库坐标可用度**：`20260716-权威球形基准库.md` 已含归一化坐标（diamond 换算协议 §〇），估读项标 `[推测]`（误差 ±0.03），少数 `[未转写]` 仅文字描述——图集须把可信度画到图上。
- **变量词典种子**：`content/drill_profiles/drill_c053.profile.json` 的 `fixedVariables`/`targetVariables`/`conditionVariables` 结构与命名（cutAngle/side/dtp/d/nearRail）。

### B1 出片台「新增球形」操作（App 代码）— ✅ 2026-07-20（合并 `00866d7`，返工 0）

- **范围**：
  1. **入口**：`BatchBallExtractionView.pickStep` 选图栅格加「+ 新增球形」项（截图缩略图并列）；点击直进 `BatchAuthoringView`（仿 `editArchive` 结构，跳过标定四步）。起点二选一：空台面（仅母球置位）或**克隆该 drill 已有球形**（列出已存球形选一个，取其 `initial` 快照）。
  2. **人工 token**：无图球形生成 `manualNN` 递增 token（避开「-」等分隔符，复用 `formationToken` 清洗逻辑；与既有 `A1` 式 token 及截图 token 并存互不覆盖）。`defaultSequenceName` 无图路径按人工 token 编「球形」号。
  3. **initial-only 保存放开**：人工球形路径允许 `steps: []` 保存（0 杆文件）；有截图来源的既有路径保持「≥1 杆」拦截不变（避免误存空序列）。
  4. **无截图 drill**：`BatchDrillCatalog.load()` 合并 `index.json` 全部 drill；无截图文件夹的条目照常列出（`imageURLs=[]`，行标「无源图」，进入后选图栅格只有「+ 新增球形」）。
  5. `savedStems` 打勾/计数、覆盖确认对人工 token 正常工作。
- **红线**：仅模拟器 target（`#if targetEnvironment(simulator)`）内改动；不动归档文件名协议（下游 `tryout-sync`/`DrillTryoutBoardStore`/出片 runner 依赖）；不动 `PositionPlaySequence` 模型。
- **量级**：1 会话（App 代码 + 模拟器验证）。**依赖**：无。**模型**：`cursor-grok-4.5-high-fast`（已确认）。
- **完成标准**：`make build` SUCCEEDED（附输出）；模拟器实操录证：① 无截图 drill 出现在列表并可新增球形；② 空台/克隆两种起点各存 1 个 initial-only 球形，`content/position_play/sequences/` 落盘 `drill_cNNN__manualNN-…-0杆.json` 且回到栅格打勾计数正确；③ 同 token 重存弹覆盖确认；④ 既有截图路径回归不变（任选 1 drill 走老流程存 1 杆序列正常）；⑤ 截图逐张核验。

## 五、用户人工设计循环（非批次，人工环节）

B1–B4 交付后进入设计循环（用户主导，AI 按需辅助）：

1. 用户对照 **B2 图集** + **B3 变量菜单**，在出片台里逐 drill「新增球形」摆位保存（initial-only）；
2. 每完成一个 drill 的一组球形，跑 **B4 脚本**出覆盖矩阵，自查空档/切角偏差；
3. 示范击打后续按既有人工录制线补（H-xx 机制不变，c053 的 H-21 为先例）；
4. 设计定稿的 drill，后续再走既有管线：`make tryout-sync`、profile sidecar、精讲 formations、缩略图重烘焙（沿用 B4/c053 范式，不在本方案范围内逐批展开——届时按设计产出的实际节奏另立执行批）。

## 六、红线汇总（每批执行前回显）

1. ⛔ **AI 不生成球形坐标**（本轮核心语义）：B1–B4 均为工具/资料，不得代用户设计球形；克隆起点只复制既有 `initial`，不得算新位。
2. ⛔ 禁止从存量 `shotIntent` 反推生成序列；示范击打人工录制（沿用 2026-06-13 拍板）。
3. ⛔ 几何/坐标推导必读 `geometry-spatial-reasoning`，数值脚本验算留档，禁脑算；口径对齐 `b5_audit_drills.py`。
4. ⛔ 诚实交付：声称通过必须附真实 build/test/脚本输出。
5. B1 不得破坏既有截图流程与归档文件名协议（下游同步/出片 runner 依赖）。
6. B5a/B5b 审计结论仅作参考素材，不作为指令性输入写入交付物。
