# 球迹渲染引擎研究

日期：2026-10-02。状态：研究及交叉讨论完成；工程实验未开始。用户授权多个子智能体调研、分析与讨论，输出画质、能耗和场景适配的综合推荐。本轮不实施引擎迁移、不改生产代码，不启动真机负载。

## 共同目标

以真实球迹需求比较现有 SceneKit 优化、定制 Metal、RealityKit、Filament 等路线。保持物理预测与训练规则独立；覆盖 2D/3D、相机/拾取、球杆与球体、六袋高亮/袋内呈现、回放、缩略图和教学视频。最低系统 iOS 17。不要用框架新旧、同模型多数票或未测收益替代证据。

用户同意开始推荐分工，统一继承本会话模型；不指定不可用的 Cursor slug。当前最多三路同时研究，独立评审在下一阶段执行。研究采用共享工作区只读生产代码，各角色只写自己指定的报告，无需实施型 worktree。

## 基线与证据

baseline.json 与 baseline-source/ 保存开始时 HEAD、dirty 列表及渲染/媒体关键源码和配置（不含整个物理目录）。工作区存在其他任务的房间、相机和资产改动，不能把 HEAD 当完整运行版本。报告代码证据以该快照或明确注明的后续工作区读取为准；历史性能以日期、profile 和测试宿主标注。

- 当前每日清台 configureDailyClearanceRendering 为 R 预积分反射、原直接球影；共享其他消费者默认 A/reference，DEBUG 候选不等于生产。
- 房间并发任务在本轮期间更新：当前 PROGRESS 与 ROOM-SIZE-STUDY 已记录用户选定 8×6m、三风格重烘及正式试用集成。源码快照时间、08:17资产读取、后续状态核实分列；本研究不复验房间任务的测试或舒适度，也不把旧排名视作该房间版本结果。
- 09-21 固定场景消融排名仅支持热点假设；09-27 配对与呈现归属未闭合；10-01 已有代码优化方案保持 SceneKit/画质/物理且尚未实施。
- 本轮不会宣称实测最低功耗或已达稳定帧率。可形成有条件技术推荐、最小原型及可证伪验收计划。

## 工作规范与技能

所有角色遵循 cursor-project-adapter、00-orchestrator 的诚实证据和范围约束。架构角色读取 ios-architect 与 ios-architecture；资产角色读取 blender-ios-assets，实际操作才读相邻专项；评审角色读取 test-engineer/qa-reviewer 与 ios-device-performance。Metal/选型专项知识以官方文档、官方源码和原论文核实，不声称已安装不存在的专项技能。

独立研究先不要阅读同伴结论，以免锚定。每份报告包含事实、推断、假设、最强反对理由、尚缺证据和明确停止条件。外部变化事实必须联网核验，优先一手资料，给 URL、查询日期、API 最低版本；新 API 不默认回溯至 iOS 17。禁止只用搜索摘要下结论。

## 比较及验收

先区分两个问题：同画质降低成本，以及同预算提高画质。两者分别评分，不能降低分辨率、帧率或删阴影后宣称最省电。相同回放输入/相机/像素尺寸/帧率/可见球数量；静止、瞄准、满台播放、近景/低机位、落袋、模式切换、冷启动和持续使用单列。

先短配对测量且超过基线噪声，再长时热对照；CPU/GPU 执行、提交/呈现与功耗分列。没有瓦数/焦耳证据时仅报能耗代理，温感和 thermal 单列。不得用模拟器、截图、CADisplayLink 或孤立 command buffer 指标证明全页帧率/温升。

当前研究交付标准：三份独立报告、独立评审、至少一轮实质交叉回应、主控核实决定性代码/外部事实、明确当前建议与未来迁移触发条件；实测待办不伪装为本轮已通过。
