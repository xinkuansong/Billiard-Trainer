# 渲染结构优化：第二轮议题

2026-10-02。用户纠正上一轮方向：需要站在代码、数学方法与架构层面提出大幅减少工作量的方案；不要把新的真机测试作为下一步。此轮只读代码、理论推导、官方资料与报告，不构建、不运行设备负载、不改生产实现。

模型沿用本会话已接受的继承配置。三个专项先并行分析，理论反方下一阶段介入。各角色只写指定报告；不采用实施型 worktree/合并流程。主控收口并保留前轮数据的边界，架构方案是否值得提出不以先跑测试为条件。

## 目标与议程

1. 当前每像素×面光样本×球影工作是否选错计算域？哪些量与相机、球旋转、球位、材质变化真正有关？
2. 提出可落地的球桌局部渲染架构：世界空间动态照明/遮挡场、静态照明响应、材质与几何语义分区、必要的局部实时例外。
3. 给出成本公式与覆盖率/分辨率/局部更新交叉点，不把复杂度比称实际fps/能耗倍数。
4. 分清精确重排与近似：逐样本遮挡乘积、灯光权重、微法线、视角相关镜面、抬球/袋口/库边不可偷换；严查“平均visibility可替代完整加权积分”。
5. 确定单帧状态所有权、版本失效依赖和CPU/GPU在途生命周期。已有缓存、批量上传、停绘不重复计作新设计。
6. 明确现有SceneKit的承载路径及何时需要局部Metal compute/SCNProgram/完整Metal；结论不能再次退化成引擎能力列表。
7. 给出最值得先实施的一个结构切片及阶段计划；验证留在实施后的正确性/质量关口，不作为本轮理论分析启动门槛。
