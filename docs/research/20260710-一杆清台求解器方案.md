## 一、需求回显（用户拍板结论）

1. **目标**：中式八球「一杆清台」求解器——给定任意球形（手摆 / 拍照导入 / `BreakFlowRunner` 开球停稳），输出完整清台杆序：每杆的目标球、袋口、塞（spinX/spinY）、力度、瞄准，直至黑 8，可在现有回放骨架中播放。
2. **时限**：单次求解墙钟 **≤ 2 分钟**（暂定，模拟器口径；anytime——到点返回当前最优）。
3. **理论对齐**：基于项目 16（`/Users/song/projects/16.billiard_theory`）的 10 定理 + 6 模块 + 5 步决策流；`contracts/` 为接口真源。
4. **复用**：现有反解器（`PositionPlaySolver`）、打一走二想三/思路训练交互资产、全保真物理引擎（`ShotPredictor`/`EventDrivenEngine`）、开球（`BreakSimulator`/`BreakFlowRunner`）。
5. **算法路线**（三轮讨论定稿）：**解析势能场 + (S, x) 状态空间反向价值迭代（DP）+ 残局精算库 + 引擎具现化**。文献结论支持：启发式 + 前向模拟优于端到端 RL（pix2pockets 2025：标准 RL 全部无法无犯规清台，简单启发式基线 30% 整局清台率）；确定性搜路径 + 噪声只评稳健性（CueCard, IJCAI 2009）；反向规划先验（T05/T06/M04）。
6. **球形分类学**（第三轮补充，全部纳入）：对方 7 球 = 永久静态障碍 + 首触犯规约束；单球 7 型（袋口球/贴库/贴球对三子类/贴对方球/中央球/死球分级/长台孤球）与球团 6 型（C1–C6）差异化处理；黑 8 非对称规则耦合；球形指纹分诊路由 A–F。
7. **一等输出**：不只完整方案——「不可行证书」（哪颗球被谁挡死、为何 bank/kick 也无解）与「最长可验证前缀 + 命门诊断」同为正式产出（真实球形中不可一杆清占相当比例，能说清"断在哪"才是教练）。
8. **明确不做（v1 范围红线）**：防守分支（T10/M05）、对抗博弈、RL/训练模型、跳球/扎杆（引擎无此能力）、组合球瞄准搜索（仅 `simulateFree` 验证兜底）、真机性能调优（模拟器口径先行）。

## 二、总体架构（执行时的设计基准）

### 2.1 核心洞察

清台过程中**目标球静态**（每颗球要么不动、要么被打进消失），真正移动的只有母球。状态空间精确为：

```
状态 = (剩余己方球集合 S ⊆ 2^7,  母球位置 x ∈ 台面网格)
```

|S| ≤ 128、网格 32×16 = 512 胞 ⇒ 可做**严格反向动态规划**，非 beam search。唯一破坏静态假设的是球团破解（breakout）与贴/撞对方球 ⇒ 分段拼接处理（§2.5）。对方 7 球全程为永久障碍，只改变场的构造、不进状态。

### 2.2 分层管线（新目录 `QiuJi/Core/RunOut/`）

```
L1 Survey 层（BoardSurvey）
   球形指纹：单球标签 7 型 + 球团连通分量 C1–C6 + 死球分级 + 母球态 + 8 号状态
   → 分诊路由 A 开放 / B 单团 / C 拥堵 / D 残局 / E 斯诺克开局 / F 不可行
   → 廉价证书：8 号真死 ⇒ 立即返回不可行（最便宜的提前终止）

L2 解析场层（PotabilityField + ReachabilityKernel）
   可打性场 M[b,p](x)：解析瞄准可行性 + 切角(15°–45° 最优)/距离/遮挡/袋口接受角
   可达性核 R[b,p](x→x')：打 b 进 p 后母球可达分布（AnalyticShotRollout 粗档采样，
     spin 3 档 × velocity 5 档 = 15 combos/胞；表示 = 每 (b,p,x,combo) 一条终点胞 + 途经吃库数）
   ⚠️ 场分解（G1，硬性规格）：预计算只含**静态遮挡**（对方 7 球 + 台面几何）；
     己方球遮挡随 S 变化，在 DP 迭代时**在线**做线段-圆遮挡修正（每次 |S| 个圆测试，µs 级）
     ——否则"打掉挡路球后此球变通"的时序场景（T05 核心）会被系统性漏解或高估。
   引擎对拍校准（沿库/近库/多库形态分层统计误差，超阈形态强制引擎）

L3 规划层（RunOutPlanner = DP 反向价值迭代 ＋ EndgameSolver 残局精算库）
   V(S,x) = max_{b∈S,p} [ M̃[b,p](x|S) · E_{x'~R} V(S\{b}, x') ]
     （M̃ = 静态场 M × 在线己方遮挡修正，见 L2 场分解）
   目标取链质量分（log 和）或 maximin。⚠️ 诚实口径：M 为**序数质量分、非校准概率**，
     链目标只用于候选排序；面向用户的"成功率"一律来自 L5 扰动认证，禁止把 DP 分数当概率呈现。
   终端 |S|≤3 接残局精算库（引擎穷举精确值）
   黑 8 非对称惩罚：最后一杆 scratch 权重远高于中盘（Tom Ross 87.5%）
   选组决策（G2）：开放局输入时对 S_全色 与 S_花色 各跑一次 DP，输出"建议选组"+ 两组对比；
     用户已定组/中局输入则单组。DP 双跑近乎零边际成本（场与核共享）。
   产出：top-K 球序+袋口方案 + 每个中间状态的价值热力图

L4 具现化层（RunOutRealizer）
   自动落区 = 下一状态价值热力图高值等高线（V > 0.7·Vmax 连通域）→ SolveRegion
   逐杆 PositionPlaySolver.solve 反解 → finalPositions 滚盘 → 犯规校验（首触/误进8/scratch）
   失败走计划空间局部修复：换袋口 → 相邻两球换序 → 回退 DP 次优动作（查表不重算）

L5 整合层（RunOutSolver facade）
   anytime 预算管理（2 分钟墙钟）、扰动认证（每杆 ~10 次加噪重放 → 每杆成功率 + 漏斗
   最窄处 = 命门杆）、降级输出（最长前缀 + 卡点诊断，T08 语言）、不可行证书装配
```

### 2.4 球形分类学（Survey 层规格，量化判据）

以球半径 R=0.028575m、钻石=1/8 桌长为量纲。

**单球标签**：S1 袋口球（距袋 < 1.5 袋口半径且袋线无遮挡；早耗施机会成本罚）｜S2 贴库（球边距库 < 5mm）/近库（< 2R）——可达性核该形态强制引擎评估（沿库走位解析失真，W3 对拍单列）｜S3 贴球对（间距 < 1mm/< 0.5R）三子类：天然组合球（连心线指袋，容差 ~2°，`simulateFree` 验证兜底）/可分离对（微 breakout）/互锁死对（准死球）｜S4 贴对方球（击打后强制重建遮挡场 = 跳出静态快路径）｜S5 中央球（距四库均 > 1.5 钻石；DP 自然倾向早清，不硬编码）｜S6 死球分级：一级 = 六袋线全被**对方球**永久遮挡且 `predictBankAll`/`predictKickAll` 无解 ⇒ 真死；二级 = 被己方球遮挡 ⇒ 时序死球（DP 天然处理）｜S7 长台孤球（距最近己方球 > 4 钻石且在角落；命门标注）。

**球团分型**（间距 < 2.5R 连通分量）：C1 纯己方双球（按 S3 三子类）｜C2 己方多球团（标准 breakout + insurance 强制）｜C3 混合团（breakout 分支采样加倍 8–12 支，逐支首触合法性校验）｜C4 贴库团（先评「不破」对照分支）｜C5 含 8 团（**任何"8 号入袋概率 > 0"的破法一票否决**，硬约束）｜C6 袋口堵塞团（对方球悬袋 ⇒ 该袋可打性置零）。「见团必破」禁止默认——先跑不破团对照分支。

**母球态**：贴库（spinY 网格裁剪——低杆档物理打不出）｜被斯诺克（第一杆 kick 特解，`predictKickAll`）｜袋口悬崖（第一杆 scratch 高危约束）｜**自由球模式**（母球位置成决策变量：argmax_x V(S_full, x)，热力图峰值即最优摆球点——零额外成本的高价值副产品）。

**黑 8**：8 号真死 ⇒ 全局立即不可行（Survey 第一检查项）；终端值 V({8},x) 用引擎全保真 + scratch 检测，不用解析近似。

### 2.5 球团分段拼接

清台切成「布局₁ → breakout 杆 → 布局₂」：布局₁ 段 DP 目标改为"到达破团窗口（key ball 前 + insurance 存在）"；breakout 杆引擎采样 4–12 种散开结果；每个结果的布局₂ 重新跑 DP（DP 便宜，跑得起）。breakout 力度低档优先——**最小化布局₂ 熵，不是最大化散开**。

### 2.8 技术风险与对策

1. **可达性核解析精度**（最大风险）：多库/沿库走位解析近似失真 → W3 对拍先行（仿 `AnalyticRolloutParityTests` 模式），按形态分层统计误差，超阈形态强制引擎回退——判定不降级，只损性能。
0. **场分解正确性（G1，v1.1 补）**：己方遮挡烘进静态表是最容易犯、最难在测试外发现的错误（表现为"漏解但不报错"）→ W3 API 层面禁止（静态表构建入参不收己方球位），W4 时序死球复活局面为强制单测。
2. **自动落区质量**：热力图等高线过松/过紧 → 两档松紧兜底（0.7·Vmax 与 0.5·Vmax），落区无解自动放宽一档再回溯。
3. **DP 网格离散误差**：胞内 V 值代表性不足 → 具现化层是全保真终验，DP 只负责排序候选；误差表现为多试几个候选，不产生假物理。
4. **引擎能清 ≠ 人能清**：DP 偏好项挂 `DifficultyModel.score` + 切角 > 60° 罚项，把搜索压向人类可执行方案；扰动认证输出逐杆成功率供用户判断。

### W4 — DP 反向价值迭代（RunOutPlanner）

- **范围**：新建 `RunOutPlanner.swift`：(S,x) 状态空间反向价值迭代（§2.2 公式），目标 = 链质量分（log 和，序数口径——禁当概率呈现），终端值接 W2 残局库（|S|≤3 时用精算值）；**每次动作评估调 W3 的 `occlusionAdjusted` 做在线己方遮挡修正（G1）**——单测必须含"时序死球复活"局面（某球被己方球挡死，打掉挡路球后 DP 正确给出可行序）；**开放局双组 DP（G2）**：S_全色/S_花色各跑一次，输出建议选组；`DifficultyModel.score` + 薄球罚进动作偏好；输出 top-K 球序+袋口方案与逐状态价值热力图（供 W5/W8 消费）。S4/破团动作本批不进（W6）；对方球遮挡在 W3 静态场已生效。
- **量级**：L（算法核心，但输入输出都已就绪）。
- **依赖**：W2 + W3。
- **完成标准**：a) `RunOutPlannerTests`：构造 4–5 球开放型局面，DP 方案的每一杆经引擎复核可行率 ≥ 80%（DP 是排序器不是判定器，允许具现化淘汰）；构造「中央球阻塞」局面断言 DP 倾向早清（验证 §2.4 S5 涌现性）；构造「时序死球复活」局面断言在线遮挡修正生效（G1 专项）；构造开放局断言双组对比输出（G2 专项）；b) 性能：7 球全空间迭代 ≤ 5s（双组 ≤ 8s）；c) 确定性：同输入两次结果逐位一致；d) 回归绿。
