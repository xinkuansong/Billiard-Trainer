## 2. 横屏构图：留足本杆纵向空间

坐标约定：SceneKit 世界 XZ 水平、Y 向上、米制；X 为球桌长边、Z 为短边，桌面高度读取 scene.surfaceY，不硬编码模型的世界高度。屏幕坐标左上为原点，x 向右、y 向下。本稿构图比例相对于实测 HUD 可读区 R，u/v 均在 0–1。正交横桌存在两个相反方向，不能将某个世界轴符号固定解释为所有视角的屏幕左右。

R 根据当前窗口、安全区、顶部球库、左右控制条及展开中的打点盘求出。优先用稳定中央可读区域建立构图，再用实际控件遮挡区域验收；不因短暂提示每帧改变镜头。不得通过挤小球桌为不存在的整列 HUD 空白预留空间。

横屏纵向空间有限：下方安排母球与必要杆身，中上方安排目标球和目标袋口，左右展开侧向球形。杆尾、桌腿和房间只提供空间参照，不因要求它们完整而缩小本杆主体。

| 观察状态 | 画面重点 | 允许的取舍 |
|---|---|---|
| 默认第三人称 | 母球—目标球—袋口及关键邻球/库边 | 可裁远离本杆的桌框、桌腿和无关球；无需强制六袋全见 |
| 向前观察 | 沿杆纵深、目标球厚薄、接触区域 | 可裁近端桌边和更多无关布局；本杆球/袋保持可读 |
| 向后观察 | 更多球形、障碍及走位区域 | 不以六袋完整为由无限退远；全局需求由俯视补充 |
| 左右观察 | 本杆侧向关系、球与库的遮挡 | 允许杆轴斜向，视野逐步兼顾桌心；不改变瞄准 |
| 第一人称 | 沿当前实际杆轴的瞄准感 | 不承担全桌；真实近库遮挡须处理，不能让球杆/库体盖住母球主体 |
| 临时俯视 | 全桌、六袋、完整球形 | 桌外透明，长轴水平，等比例最大适配 R |

|---|---|
| 默认母球 | u≈0.50；v 在 0.65–0.75 内选合适位置 |
| 靠近母球 | 逐渐下移至 v 约 0.70–0.82，避免与底部控件/杆身混成一团 |
| 退远母球 | 逐渐向上回收，v 约 0.55–0.68，留出更多近侧台面 |
| 目标球与袋口 | 使用母球前方空间，允许随真实切角偏左或偏右；不强制它们在同一屏幕竖线上 |
| 侧向观察 | 母球由中线约束过渡为中央区域约束；桌面主体避免长期贴边 |

这些区间不是严格的逐帧 clamp。真实画面若证明不适合短球、长台或小屏，就修订统一政策，不能为某一球号/袋号添加特例。

## 3. 选定目标后建立本杆默认机位

事件链：现有推荐/手动选球 → 最新有效目标、袋口、杆姿提交 → 建立本杆相机基准 → 平滑进入第三人称。

“确定目标”以业务提交为准，不以每次 View 刷新或预测任务结束为准。使用 sceneGeneration、选球请求版本、目标/袋口身份和实际杆姿版本拒绝过期请求；同一次选择只触发一次转镜。同球改袋属于新的本杆构图请求；力度/打点的一般重算不重复触发入场动画。

默认站位以现有规则为依据：沿实际击球点的杆向后退起点 1.65m，眼高至少 scene.surfaceY+0.90m，抬杆及近库/两球遮叠会改变实际站位。它们是生成默认姿态的参考，不是所有球形和所有轨道位置的固定答案；向前观察时允许连续降眼，真实库体/球体遮挡决定下限。

在该参考附近联合选距离、眼高、俯角和视野分配，保证：

1. 母球与杆轴在默认视图具有明确的中线方向感；杆尾允许裁切。
2. 母球和目标球主体可辨，目标袋嘴而非仅袋心处于可读区域。
3. 长台给远侧球/袋足够的上方空间，避免顶部球库遮住袋嘴。
4. 短球优先改善观察位置来区分两球轮廓；单独调俯角/FOV 不能解除实体遮挡。
5. 薄切时保留目标球到袋口的侧向空间，不为把目标球移到正中而扭转杆轴。

冲突处理顺序：实际模型与相机安全 → 本杆球/袋可见且可读 → 默认沿杆方向感 → 母球位置偏好 → 更多布局/台面面积 → 背景美观。若母球位置候选与袋口冲突，先放宽候选位置；若参考站位遮挡主体，调整眼位；镜头参数只在有界的构图范围内参与，不用持续超广角缩小所有主体来隐藏冲突。

默认视角不按某一固定俯角生成。当前真实方向、球距、袋位、近库关系和 HUD 共同决定该杆需要的俯角。相机不得替换推荐球/袋来使自己更容易取景。

## 4. 连续轨道与输入

### 4.1 轨道的自由度

保留两个用户输入：纵向观察层级 s 与相对于本杆默认方位的偏角 θ。s=0 表示默认，s<0 向前，s>0 向后；这只是方案语义，现有 0…1 存储可在接口处映射，无需为了符号重写全部状态。

眼位轨道保留球桌作为空间参照。母球、目标球和袋口是构图对象；屏幕母球位置由共同姿态解决，不在 CameraRig 提交之后再加一套母球锁定平移。眼位方位与光轴朝向分别表示：绕桌时可以连续改变朝向，使视野中心逐步向桌心收拢，不死锁单一焦点。

距离、眼高、俯角、水平朝向由同一(s,θ,本杆,布局)共同生成，选择同一个连续分支。FOV 按本杆/横屏布局建立，优先在同一本杆的连续观察期间保持；布局失效或明确重新构图才重建，避免拖动过程中推拉与变焦相互抵消。

### 4.2 上下：改变并保留观察层级

- 上滑：靠近、降低眼位、放平视线，母球略向下，前方细节变大。
- 下滑：退远、提高眼位、增加俯看，展开球形和库边；母球适度上移。
- 停住或松手：保持当前实际可见姿态；释放时清除未兑现的拖动目标，不额外惯性漂移，也不启动自动回位。下次拖动从该姿态继续，直到显式点击模式按钮或新目标选择触发新机位。
- 近端按本杆主体、远袋可读性、实体遮挡和房间安全确定；长台与短球可达到的低位姿态不同。
- 远端按主体可读尺寸、实际台面占比和新增可读布局确定，避免空地增加而球桌持续缩小。
- 当前“至少保留默认球/台面尺度的一定比例”可作辅助护栏，但默认图本身也要先合格；不允许以过小默认图为参照证明远端足够大。
- 极限附近渐渐降低响应，达到端点后继续同向拖动不积累不可见位移；反向立即有效。有限工作量内找不到连续合法改进时停在最后有效姿态，不跳到另一个远处解。

### 4.3 左右：保持观察层级，改变观察方位

小角度偏转优先让母球留在稳定区域；较大偏转逐步提高桌面主体与目标区域的构图权重，视野中心线自然趋向台内。全过程保留本杆瞄准，杆轴可以斜向，不追求每帧竖直。

左右输入只推进 θ；s 保持当前值。为维持同一观察层级，算法可以连续调整距离/眼高/俯角，这是姿态适配，不是采纳竖向手指噪声。不得把“主轴隔离”误写成所有世界相机参数都不许变化。

横向使用拖动场景的屏幕语义：右拖时选定参照的初始水平位移应向右，左拖相反；符号须由真实投影验证，不能直接按世界 yaw 的正负定义。母球本身可能被构图稳定，应选可辨认的前方库边/目标区验证方向。

可达左右范围取包含默认位的连续合法区间，优先保留有用侧视；不预先承诺所有球形都能绕满一圈。近/远端和各方向的范围由同一通用约束产生，不能逐球形硬编码。

### 4.4 主轴与接管

沿用起手累计位移、主轴优势与整次手势锁轴。现有 12pt/1.25 是待手机手感确认的起点，不是参考视频测出的数值；未形成明确意图前不接管镜头、不积累隐藏位移。

锁定后忽略另一轴输入，直到抬手；要换轴就抬手重新开始。第三人称释放后保留两个观察参数，下次只推进新锁定轴，另一轴继续保留，支持先上下再左右组合观察。显式归正或选球转镜途中重新触摸，从当前可见姿态接管，不跳回默认；释放后停在新位置。

球体附近与空白处起手规则一致；既有摆球/力度/打点/方向控件按其明确命中域处理，不能让相机拖动意外进入移球或改瞄准。捏合如保留，映射同一个观察层级，松手也保持当前位置，不新增独立倍率记忆。

## 5. 三个按键、保持与归正行为

| 按键 | 点按/长按 | 结果 |
|---|---|---|
| 站立人形（第三人称） | 点按 | 进入最新本杆第三人称基准；已在 TP 时也能明确归正 |
| 俯身瞄准人形（第一人称） | 点按 | 进入本杆沿杆第一人称；已在 FP 时回正视线 |
| 六袋球桌（临时俯视） | 长按，松手结束 | 显示透明桌外的横向全桌叠层，释放后恢复底层观看状态；短点不触发复位 |

第一人称横滑是临时转头，保本次眼位与实际瞄准；松手回第一人称正向。纵向不新增独立飞行自由度。第一人称与第三人称高亮互斥，临时俯视只高亮持有状态，不把底层模式改成第三种 3D 模式。

临时俯视使用当前真实桌/球外观，正交等比例最大适配 R，六袋与桌框完整、长轴水平；背景继续显示进入前的 3D 场景，桌外透明，不黑屏、不调暗房间、不改变主相机。依当前第三人称方向在两个相反横桌朝向中选较近者，开球线侧短库落在相应左右；近歧义沿用同画幅上次方向以避免反复翻转。FP 入口依据本杆 TP 基准，避免头转导致俯视翻桌。

主相机不需要飞到顶部或绕圈。叠层淡入淡出时保球/袋清晰；静止盘面仅生成一次，按住不常驻第二渲染循环。按下冻结实际姿态和正在进行的合法转场，释放恢复该姿态；第三人称普通观察不会因此回到默认位。只有进入前确实存在的按钮/选球转场或第一人称回正，才按有效上下文继续。期间有新的有效选球请求时，只在释放后执行最新且未被用户取消的请求，不先回旧球再转新球。

### 观察保持与选球冲突

| 事件 | 规则 |
|---|---|
| 第三人称观察松手 | 保留实际眼位、朝向、镜头和观察层级，清除残余拖动目标；不回默认 |
| 第一人称转头松手 | 沿用既定规则回本次正向 |
| 点击第三人称按钮 | 显式回到最新有效本杆默认第三人称 |
| 归正/选球转镜中再次拖动 | 停止旧转场，从可见姿态接管；第三人称松手保持新位置 |
| 系统/手动提交新目标 | 生成一次新 TP 请求，晚到的旧解/旧动画不得覆盖 |
| 转镜途中用户点 FP/TP 或开始有效观察 | 用户显式输入取消尚未完成的旧自动请求；后台刷新不能重新触发它 |
| 长按俯视中后台完成选球 | 暂存最新请求，释放后校验并执行；持续长按期间不改变底层画面 |
| 力度/打点重算 | 不创建选球入场事件；必要杆姿避让修正由同一控制者连续提交 |
| 本杆已失效、重打/重开/离页 | 作废旧返回目标和异步回调，按新业务状态建立观看基准 |
| 无有效目标或合法解 | 保留业务失败/无解状态，不用旧目标假装已经进入新目标视角；只提供与当前状态匹配的观察 |

第三人称松手没有回位计时或延时复位。时间候选仅适用于第一人称转头回正（约 0.8s 起点，小幅位移可更短），以及选球和按钮切镜（约 0.35–0.55s 范围），具体以真实横屏过程图/手机手感收敛。直接拖动与自动返回使用不同响应目标，不能给拖动叠加长时间尾随来掩盖轨道不连续。Reduce Motion 使用短过渡，交互语义相同。

原有击球、捕获、杆末回放时机独立保留，避免本次构图重设计顺手改变击球规则或推荐时点；新目标的入场请求接在真实球局结算与有效选球提交之后。

## 6. 实现组织与成本边界

沿现有 VM → CameraRig → TwoViewCamera → 实际相机提交链路增量实施，不再增加并行写节点的相机控制器。

| 职责 | 输入/输出与边界 |
|---|---|
| PositionPlayViewModel/每日控制器 | 保现有推荐、目标、袋口、实际瞄准、力度/打点及有效版本；发布一次选球意图 |
| AngleSceneView | 控件命中、主轴识别、持触/释放/取消；输出观察意图，不直接修改相机节点或瞄准 |
| 本杆构图与轨道 | 用实际模型、球/袋、HUD 生成默认位和连续可达姿态；可见性、尺度和构图偏好分别表达 |
| TwoViewCamera/CameraRig | 唯一推进观察、保持、显式归正/选球转镜及 FP 回正；从实际姿态接管，统一提交 eye/orientation/lens |
| 临时俯视 | 独立冻结画面、透明快照和撤层；主相机、共享材质及场景不被复制流程污染 |

本杆/布局变化时预建有限候选，滑动期间优先查表/插值与有限验证。禁止每帧遍历全桌选最优解、重跑推荐或重建场景。仅几何安全和构图约束必要时重建，稳定后停止无必要的相机更新。

横屏轨道设计可以控制可见范围与计算调度，但不能凭此宣称降低到某个功耗。SceneKit/材质/Metal 的原渲染研究另行推进，不能通过缩桌、牺牲袋口或限制用户观察来制造性能收益。

## 7. 验收：先看画面是否完成任务，再看操作闭环

下列为目标验收标准；本轮执行结果逐项以[实施审查](ui-reviews/UR-20261003-landscape-camera-v31.md)为准，不能把未覆盖项视作通过。现有 v2.1 测试和截图只作基线。

| 场景 | 必须审看的帧/过程 | 通过条件 |
|---|---|---|
| 长台直球及长台斜切 | 默认、推进中段、最近、松手保持、按钮归正 | 母球/目标球可辨，实际目标袋嘴完整可读且不被顶部 HUD 吃掉；靠近有低位观察变化 |
| 短球/两球接近 | 默认与最近 | 两球关系可读，不以放大重叠球团代替改善观察位置 |
| 母球近长库、近短库、近袋角 | 默认、近端、左右过程 | 实体库边/杆身不盖住关键主体；无穿模取景 |
| 薄切/中袋/目标球贴库 | 默认、左右过程、松手保持、按钮归正 | 目标球到袋嘴的关系清楚；不为强制沿杆居中切掉袋口 |
| 母球偏角、球形集中与分散 | 退远全过程和极限 | 桌面及关键球仍可读，退远增加有效布局；不能出现空地占主导、球桌缩成小块的失败图 |
| 短库/长库/斜向连续转动 | 连续截图带及录屏 | 同一观察层级连续；母球/桌面主体不突跳，中心向台内变化自然，远侧范围连续展开 |
| 主轴抗干扰、触边反向 | 空白/球附近起手，带横/纵噪声 | 只采纳锁定轴；允许算法配套姿态变化；端点反向立即有效，无隐藏超量拖动 |
| TP 松手与连续操作 | 松手前、松手后停留、第二次拖动首帧、最终 | 松手保持实际姿态，无回弹/尾随漂移；先上下再左右只推进新轴，无跳镜或旧回调夺权 |
| 显式归正与中断 | TP 按钮归正中段、新拖动首帧、释放；另验 FP 回正 | TP 按钮回本杆默认，中途拖动接管后保持；FP 仍按既定回正规则 |
| 推荐/手选/改袋/力度打点 | 真实页面操作全链路 | 有效新选择一次进入对应 TP；旧解不转镜；一般重算不重复入场；选择结果与旧业务一致 |
| TP/FP/临时俯视 | 两种底层模式、相反方位、连续长按 | 图标状态正确，横向全桌最大适配，六袋完整，桌外透明，底层保持，退出正确恢复 |
| 小屏/常规横屏及左右横置 | 相同球形完整 HUD 截图 | 依实际安全区适配，不复用另一设备的预设屏幕坐标 |

截图需来自真实 App，包含 HUD；至少覆盖默认/中途/端点/释放，不只给某个好看的终点。每张标清球形、目标球/袋、设备/可用区域、操作状态及版本。数值记录母球/目标球尺寸、袋嘴轮廓与 HUD 距离、台面可见面积、球投影位置以及实际姿态，辅助解释图片；不可用“球心在屏幕内”代替可见性验收。

对比图发现主体明显过小、关键袋口被挡或镜头突变即判该场景失败，即便功能断言通过。照片式静帧不能单独证明保持/归正/接管顺畅；录屏不能证明触摸延迟/能耗；最终手机手感由用户试用确认。

## 8. 推荐实施顺序与交付

1. 先形成横屏默认/近/远/左/右的构图示意，锁定本杆信息优先级；重点讨论长台、短球和贴库三个冲突场景。
2. 先改默认 TP 与沿杆联合纵向轨道，保留推荐和三个按键接线；用真实连续截图审这一条链。
3. 再收敛左右视野中心、主轴隔离、松手保持、显式归正与中断接管；避免在未稳定的基础构图上继续叠修正。
4. 复核 FP 和透明横桌叠层、真实推荐/手选联动，再进行适配范围内的功能与截图验收。
5. 构建并覆盖安装一个明确候选供手机试用；不要同时引入渲染引擎迁移或推荐算法变化。
