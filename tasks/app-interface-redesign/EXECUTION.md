# 执行、并行与持续记录协议

需求：[PLAN](PLAN.md)；恢复入口：[CURRENT](CURRENT.md)。本文件规定怎样工作，不另存一份需求或批次状态。

## 1. 每批开始

1. 读取 CURRENT→PLAN 当前批→页面清单对应条目→相关决定/反馈。按项目适配器加载本批角色与技能，不默认通读历史归档。
2. 核实最新用户授权、设计版本、源码基线和前置证据。已有明确授权继续沿用；设计获准与实现/体验通过分开。
3. 创建 `batches/<ID>.md`，填写范围、P-ID、DoD、模型、文件白名单、禁止改动区、源码/设计输入、产物目录和恢复动作。不存在批次卡，不派发写任务。
4. 再核对实际代码与近期交接。行号、旧截图、HEAD、文件修改日期均不能单独证明“最新版”；按 §2 核验。

## 2. 每页的现行版本核验

设计前必须区分四份事实：

| 对象 | 必记字段 | 如何核实 |
|---|---|---|
| 当前源码 | 分支/HEAD、相关 dirty/untracked、文件 hash、符号、核对时间 | 读当前工作区及真实调用链，不能只看旧文档/HEAD |
| 最近设计 | Figma file/node、版本/日期、用户选择、本地/云端状态 | 读取实际稿及最近有效决定；未找到就写未找到 |
| 原生画面 | 构建来源、设备/Runtime、数据/权限、截图/录屏 | 从真实生产入口进入；测试深链只作补充 |
| 最近验收 | 哪个版本、哪些状态/设备、用户原意、尚未验什么 | 链接具体记录，不能把“旧批完成”移植到新版本 |

先填页面版本记录；代码/设计/实际画面对不齐时写明差异和采用依据。未核验的页面状态为“现行视觉待核”，不得用于 Figma 重设计基线。历史文档保留但标注用途为历史参考；新日期文件也不能直接取代明确获准版本。

**设置示例**：当前全局设置位于 `Profile/Views/SettingsView.swift`；每日菜单在 `PositionPlay/Views/DailyHUDPanel.swift` 等。两者不是同一页面。“设置声音”为全局设置内联分区，并不是已经核实的独立声音页。旧 PROGRESS 的 T-P8-05“球种+周目标”仅记录早期交付，不能作为当前设置页全量内容。

## 3. 所有权与并行

用户确认：页面批 **gpt-6.1-sol**；公共组件/架构边界/验收 **gpt-6-astra**。本会话已确认，后续直接按 PLAN 模型列执行。

- 主控写 PLAN、CURRENT、PAGE-INVENTORY、ARTIFACTS、DECISIONS、PROGRESS 和 Hub。子智能体只写分配的批次报告/页面文件，回传待合并增量；同一表不多人编辑。
- 只读调查可以共享工作区并行，最多 3 个子智能体；每个返回来源锚点、未知项、范围交集与产物位置。
- 代码实现采用独立 worktree、`codex/` 分支和同一已核验基线。当前主仓有其他任务 dirty work：先保留原树，记录 HEAD/diff/必要 untracked/hash；构造仅包含明确依赖的整合基线再派生。不能全仓 reset/stash，也不能盲复制 `tmp/` 或递归快照。需要提交时遵守当次授权，不擅自把所有无关改动提交或推送。
- 波前用具体文件清单求交，代码、测试、共享 fixture、配置、产物目录、Figma 节点都计入。有业务交集则调波或先做共享批；不能凭“都在不同 Feature”判独立。
- `AppRouter`、`MainTabView`、`RootView`、全局 token/组件、`project.yml`/工程配置、共享资源与中央台账默认归主控协调的共享批。页面批申请公共变更，不能顺手修改。
- 实际已发现：`DrillPickerSheet` 定义在 ActiveTraining 文件且供模版编辑复用；`CustomPlanAtmosphere` 定义在 PlanList 且供首页复用；分享页在 Training 但被历史详情使用；DrillDetail/Subscription 多入口共享。派发时以这些实证交集排波。

## 4. 工具与资源锁

| 资源 | 默认规则 |
|---|---|
| Figma 桌面/同一浏览器会话 | 单操作员；其它执行者可准备规格、资产和审图。操作前后记录文件/node/版本，不并发抢焦点或选区 |
| Figma 共享组件库 | 共享批单写；页面稿使用冻结版。组件变更后列受影响实例，逐批更新 |
| 模拟器/真机 | 同一 UDID 只给一个批次；采集排队。实际设备占用写入批次卡和 CURRENT |
| 构建与测试 | 默认串行排队。资源充足且已确认隔离后才允许独立 worktree＋DerivedData＋UDID＋xcresult＋截图目录并发 |
| 测试输出 | 优先显式批次环境路径；旧 `/tmp/qiuji-v50/shot_dir` 和 `/tmp/qiuji-uitest/*` 是全局共享接口，未隔离前禁止并发使用 |
| 本地预览服务 | 记录端口、服务目录、负责批次和进程；禁止覆盖其他任务服务 |

每批资源表字段：资源、持有人、开始时间、用途、释放条件。取得资源前同时核对其他活动工作包与实际进程/设备占用；每日/球桌等其他聊天正在使用同一资源时排队，不能以本工作包无锁认定空闲。中断后先核实真实进程/设备状态再恢复，不根据旧锁记录重复启动。

## 5. 集成与独立验收

1. 执行者自证：白名单 diff、逐条 DoD、完整日志/xcresult、前后原图、生成条件及所有未完成项。只汇报“测试通过”不足以交付。
2. 主控/astra 逐文件审查并亲自打开原始证据；核对成功/失败/跳过数、覆盖项、截图内容、源码版本及有没有删改断言来放行。只读规划核对源码，不冒充正式 Phase QA。
3. 代码分批串行集成；每合一批，在整合树构建及运行该批适用检查后才合下一批。文档批不要求 iOS build。
4. 既有测试可复用，但必须确认对象未变化、证据可归属；合并冲突、跨批共享变化或证据存疑时补跑受影响的最小测试面。不能用旧截图验证新代码。
5. 业务代码冲突退回原执行者基于新基线修订，主控不随意拼接。失败保留原日志和 F-ID/适用 FL，返工用原批 ID 加 `r2/r3`，不把失败轮次覆盖掉。
6. 工程验证、模拟器视觉、用户确认、真机手感、安装、提交、发布分别登记。只有全部本批 DoD 满足才记 ✅；依赖用户体验的最终收口保持未完成。

## 6. 每次生成与每批结束的回写顺序

**生成时**：文件实际保存 → 写原始 manifest → 在 ARTIFACTS 增加 A-ID（可按组登记但 manifest 必须列全文件）→ 批次卡链接对应 DoD。包括研究、粗稿、精稿、弃用稿、失败截图、日志、源文件、备份和临时评审图；临时文件若不构成交付可归一组，注明用途和保留状态。

**批末/中断时**：

1. 批次卡写已过/未过 DoD、真实结果、返工和原始产物。
2. DECISIONS 记录用户选择与反馈；新需求更改 PLAN 版本、依赖和受影响批。
3. PAGE-INVENTORY 更新该页面当前阶段、已覆盖状态、采用的 A-ID 以及未覆盖项。
4. ARTIFACTS 更新适用/被替代关系、验证层级和保存位置；不删除旧候选。
5. CURRENT 更新唯一批次状态表、当前成果、阻塞与**一个明确下一动作**；带上活动 worktree/资源占用。
6. PROGRESS 与 Hub 写简短摘要和 CURRENT 链接；遵守近 10 条与体积门禁，必要时归档旧记录，绝不抬阈值。

不把同一份完整状态表复制到 PLAN/Hub。发生不一致时核对一手证据后修复 CURRENT，而不是猜哪个“最新”文件可信。

## 7. 批次卡模板

```text
# <ID> <标题>
日期/状态/PLAN版本/负责人/实际模型/返工轮次
输入：P-ID、需求R-ID、决定D-ID、Figma版本、源码基线/dirty说明
范围：做什么；保护区；具体允许/禁止写的文件
资源：worktree/分支/UDID/DerivedData/端口/Figma节点/持有者
依赖：前置批、证据、获准范围
DoD：[ ] 带编号的可验证标准
执行：时间、真实动作、结果、异常（不复制完整日志）
产物：A-ID、完整路径/manifest、证明哪个DoD、源码/图稿版本
独立验收：审查人、实际读过的证据、通过/失败/跳过、界限
反馈：F-ID、负责人、关闭证据
交接：完成到哪、未完项、精确下一动作、需释放/保留的资源
```

## 8. 归档与恢复

- 大图/日志统一放 `output/app-interface-redesign/<批次>/<修订>/`，稳定需求/决定/报告放本工作包。共享证据由 A-ID 引用，不复制成多个新“最终版”。
- 工作包文件少而稳定；批次卡按需建立，未开始的任务不生成空文件。CURRENT 只保留最近 10 个检查点，完整轨迹在批次卡。
- 新会话先核对 CURRENT 与实际文件/进程，读取当前批需要的材料；压缩上下文后同样恢复，不重跑已完成批。
- 清理仅限验证已安全归档的临时运行资源；历史候选、用户原稿、原始测试和未合并 worktree 不随进度收口删除。托管 worktree 通过工具归档，保留必要的 ignored 证据；GitHub 发布/推送不由此协议自动授权。

## E阶段补充

当前完整图层标准来自D012。图层包准备、Figma迁入、原生图对照、改字改色移位复原、本地保存/云端/回导独立计数。插件环境或字体失败时保留失败证据，先完成无依赖的矩阵与分层准备，不退回普通UI位图/轮廓文字。后续派发以E01及实际小批卡为准，域队列的候选容量不能当强制全矩阵截图配额。
