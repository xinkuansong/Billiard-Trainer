# 全 App 十设备页面视觉对比方案

**v5.3｜2026-10-13｜D028｜本文件是本工作包当前需求真源。**

**当前仅更新方案，执行保持暂停。不得据此启动、切页、点击、截图、安装、重启模拟器，或改动App/控制脚本。用户明确恢复后才开始现场操作。**

本版将目标收敛为多设备页面视觉对比，取代v5.2的常规功能回归要求。沿用轮次`LIVE-20261012-R1`、页面编号、问题编号和已有验收，不重新开始。旧版保存在[v5.2存档](PLAN-history-before-v5.3-20261013.md)，实际断点以[CURRENT](CURRENT.md)为准。D028优先于D025中“旧结果不继承”的功能部分、D027的“03/07默认跑业务流程”，也优先于通用评审技能中与本范围冲突的要求。

## 1. 目标与范围

目标：把真实App的同一页面和关键视觉状态在十个代表环境并排打开，方便用户对比设备之间的显示问题，发现后修复并复看受影响画面。

### 本轮检查

- 布局结构、两侧宽度、对齐、上下间距和多余留白。
- 字号、文字换行、截断、长标题/长文可读性。
- 安全区、导航栏、底部按钮、浮动控件之间的遮挡。
- 图片、球桌、图表的比例、裁切和控件位置。
- 手机/iPad横竖屏的自适应差异，浅色/深色的颜色与对比度。
- 为判断以上显示问题所需的页面顶部/中部/末尾、弹层、键盘展开、空状态、锁定状态等真实画面。

### 不作为本轮常规任务

- 不重跑创建、重复加入、保存、返回、计数、搜索匹配、持久化、训练规则、支付等已通过的功能测试。
- 不默认要求03和07各走一遍业务流程，不把每次点击拆成等待用户验收的小项。
- 不因功能报告存在空白勾选或历史未验项，就把它变成本次视觉对比的前置。
- 不启动全面重构、全量自动测试、真机性能/发布验收、Figma复建或批量长页采图。

打开弹层、点击切换、滚动或展示键盘的目的，是获得需要对比的画面；不因此附带要求验证其所有业务结果。若本次修改可能影响功能，只做有明确依据的定向回归，见§8。

## 4. 页面覆盖与进度

保留APP/P-ID、TABLE/P-ID、DAILY命名空间；沿用[页面清单](PAGE-INVENTORY.md)与`LIVE-COVERAGE-v5.csv`，不另建竞争目录，不重新清零。

**本轮视觉义务：页面/结构变体 × 必要视觉状态 × 适用设备与模式。**

- 同模板选普通与长内容等实际结构代表；只有内容不同但布局同构时不机械逐项复看。
- 独有图解/公式/球桌/图表等必须有代表画面；长文一次连续查看顶部、特殊段落和末尾，不逐屏立任务。
- 弹层、键盘、空态、锁定态按显示结构检查；不同点击若显示同一结构，不增加独立验收轮次。
- 各域开始前确认页面去向即可，不以全部候选状态预先冻结为启动前置。

原覆盖表保留，现有`reviewStatus`可能混合历史功能与视觉结论，不能直接据其计数推断视觉完成。恢复后在目标行`notes`注明「视觉：待看/部分/用户通过/待复看；功能：沿用〈来源及范围〉/定向回归〈原因〉/本轮不涉及」。历史功能已通过但当前设备画面未看时，视觉仍待看；视觉通过也不补写功能全通过。纯业务断言转为“本轮视觉范围外，沿用原记录”，不删除旧行、不伪造通过。

只报告已对比页面族、明确设备/模式、剩余视觉范围及未关闭显示问题，不用功能断言数量拖长本轮进度。本次仅确定口径，不批量修改覆盖表结果。已有本轮视觉验收继续保留；旧版本图片供参考，不冒称当前版本新验收。

## 5. 现场流程（用户恢复后）

1. **选页面**：按页面域顺序，每次1–3个相关页面/结构代表；只说明要看的显示重点。
2. **准备同页同态**：复用已有构建与现场数据，脚本统一定位；版本、内容、字号、方向等只核必要变化项，不每次重读全套基线。
3. **快速交接**：每台自动切页失败一次即列明手动入口，其他就绪设备立即交给用户；不反复找窗口、重启或展开控制器诊断。
4. **并排看画面**：用户自由滚动、打开所需弹层或切主题；一次集中反馈。用户查看期间停止自动点击、滚动、安装、焦点或窗口调整。
5. **集中修复**：记录显示问题、合并共享根因，按影响修复；新视觉方向先确认，已有明确要求不反复请示。
6. **只复看改动**：给出更新设备与受影响页面/位置，完成必要技术检查后由用户复看。未受影响页面和功能结论保留。
7. **推进**：本批视觉问题关闭或用户明确延期后继续下一页域，不要求顺带完成业务测试。

“下一页”授权切页，不代替不明确的视觉验收；清晰交接后用户“没问题”按该范围登记。无问题不强制截图，一页一次简要记录即可。

### 5.1 不再重复的工作

不把创建→计数→重复加入→返回拆成多轮；不默认03/07重跑；不追加空名/纯空格等纯业务边界来延长页面评审。已测试功能直接沿用。切页所需的正常导航只是准备工作；无新修改或异常时，不再为每个直达页面另跑一条进入/返回验收链。

## 6. 脚本、控制权与资源

复用现有页面/状态ID、内容ID和已验证入口；只在实际缺口影响视觉交接时讨论最小补充，不为了方案先改控制脚本。需要真实导航宿主的页面不得把裸View当成正常页面。

- 正常导航优先保留当前模版、记录和阅读现场；不为统一计数或准备新测试而清空、重建、重启。
- 同一构建复用十台，不逐台重编；安装只在相关修改后且已恢复执行时进行，通常不需重启模拟器。
- 设备寻址操作可按已有稳定能力有限并行，前台控制串行；不同时开十个测试Runner。
- 资源紧张时先暂停非必要回放，需调整运行设备时说明；不偷偷关闭窗口。
- 控制器状态沿用`IDLE → PREPARING → READY/PARTIAL → USER_REVIEW → IDLE`，用户说停立即停止新调度。
- 不建立截图图册、Figma导入或大型网页平台；只给实际问题保留必要截图/日志。

## 7. 基线和历史记录

已有构建SHA、版本、UDID、内容/主题/字号/方向等按需复用。恢复时先核需要准备的设备是否版本一致；旧安装包不能冒称当前源码。不同构建的显示结果按影响区分，不每次全域清零。

功能报告引用原版本和成功范围即可，不要求为继承结论重跑；若当前确实修改了对应行为，再走§8。旧失败、未验项及原始证据保持原状态。持久化、真实账号、支付、真机硬件等继续留在原测试/发布轨道，不纳入本轮页面对比完成门槛。

## 8. 问题修复与最小验证

继续使用[APP-ISSUES](APP-ISSUES.md)及既有编号。记录页面、设备/方向/模式、版本、原图与原话、显示预期、实际现象、共享消费者、修改和复验范围；未知信息如实留空。

| 情况 | 本轮处理与验证 |
|---|---|
| 字号、间距、颜色、标题、图片比例等显示调整 | 检查相关构建及必要布局约束，原问题设备与受影响尺寸/主题复看；不附带业务流程测试 |
| 共享布局调整 | 按消费者与尺寸分支扩展视觉复看；确实影响十环境时覆盖十环境，不机械要求每次全App重审 |
| 改动命中点击热区、手势、导航、状态绑定或键盘焦点 | 明确“修改了什么→可能影响哪个行为→最少检查哪一步”；只回归直接受影响行为，通常AI先验证，不整套转交用户重跑 |
| 新功能异常或阻断显示的卡死 | 单独编号、保留现场；能继续看其他页则先继续视觉工作，需业务修复另明确范围；阻断当前展示时做最小诊断修复，不开启全量回归 |
| 旧报告缺口/已知历史问题 | 保留原台账与限制；没有新证据或本次相关改动，不加入本轮测试队列 |

用户确认后关闭显示问题，技术通过与用户认可分开。问题可明确延期，保留理由；不因纯业务待验而把已经完成的页面视觉对比退回未完成。

### 8.1 交付给用户的信息

简短说明：改了什么、哪些设备已更新、需要看哪个页面/位置/主题、预期显示效果。只有存在明确行为影响时，额外列出必要的那一两步定向检查及原因。无改动、无问题时不输出一串回归清单。

## 9. 页面域顺序与完成标准

沿用L00–L10编号和已完成工作，不重新从头测功能。恢复时先去重L02已看画面，只补真实视觉缺口后进入L03；空名/重复计数等不再作为下一项。

| 批次 | 页面范围 | 本轮视觉完成标准 |
|---|---|---|
| L00 / L01 | 已有设备基线、控制与交接 | 复用既有工作；变化项按需核，不重做全部试点 |
| L02 | 动作库、详情、精讲、收藏、加入训练弹层 | 列表/长内容/多球形/锁定/弹层等结构在适用设备及浅深色下显示可读、无遮挡 |
| L03 | 训练首页、计划、模版、选择器、表单 | 卡片、列表、空态、长名称、表单及键盘展开的显示适配；创建规则沿用 |
| L04 | 训练过程、休息、最小化、心得、总结、分享 | 长计时、底栏、浮标、输入和结果画面适配；计分/保存规则沿用 |
| L05 | 练习五区、文章、教学、测验 | 入口卡片、正文/公式/独有图解与答题/结果画面适配；答案计算等沿用 |
| L06 | 记录、统计、详情、编辑弹层 | 日期、图表、长文本、空态、免费/Pro及弹层显示；统计口径/持久化沿用 |
| L07 | 我的、设置、目标、订阅、装备 | 设置子页、表单、提示与权益画面显示；不做真实登录、购买、同步测试 |
| L08 | 每日与各球桌页面 | 桌面比例、HUD、安全区、菜单、面板、2D/3D和结果的视觉适配；不重跑物理/规则/完整球局 |
| L09 | 特殊视觉条件 | 按用户指定或缺陷触发补大字号、缩窗等；系统/外部依赖缺口单列，不变成功能验收 |
| L10 | 视觉收口 | 各页面有去向，未看设备/模式与显示问题明确，无虚假完成；业务历史缺口独立保留 |
| R | 显示问题修复小批 | 原问题及受影响画面复看，用户确认；仅必要行为定向回归 |

每批1–3页族，重复模板有代表关系，独有显示结构不遗漏。按L02→L03→后续顺序，用户指定页面可调整。全App覆盖指视觉页面覆盖，不表示产品全部功能、真机或发布通过。

### 9.1 已确认模型、技能与分工

用户于2026-10-12回复“好的，你来定吧”，授权主控确定以下配置。仅适用于本工作包，不覆盖全仓其他任务；不继承Cursor旧Grok/Claude默认。后续按表执行无需重复询问模型，实际不可用时报告，不静默替换。

| 角色 | 模型 / 推理强度 | 读取的技能与角色规则 | 输出与边界 |
|---|---|---|---|
| 主控 | 保持当前会话模型，不宣称已切换 | cursor-project-adapter、app-live-review；拆批时issue-collection-restructure | 统一现场控制、覆盖/问题台账、版本部署、用户验证单；对子智能体结果验收 |
| 诊断（按需） | `gpt-6-astra` / `high` | app-live-review；按问题读取架构/SwiftUI/数据/几何技能与对应角色文件 | 根因、源码/运行依据、影响消费者；默认只读，不操作模拟器 |
| 实现 | `gpt-6.1-sol` / `high` | app-live-review、swiftui-design-system；对应swiftui-developer或其他专项角色 | 允许范围内代码/必要测试、检查结果、影响范围；默认唯一代码写者 |
| 独立复核 | `gpt-6.1-sol` / `high`；高风险改用`gpt-6-astra` / `high` | app-live-review、simulator-matrix-qa；QA/UI Reviewer/Test Engineer按检查对象加载 | 原始问题→修改→回归独立核对，返回缺陷及验证范围；不得自行修改后自审通过 |

简单明确问题省独立诊断，保留实现与独立复核；普通布局由Sol先定位，跨模块状态/共享布局大改/球桌几何/重复返工由Astra诊断或关键复核。不是每个问题都开满三个子智能体。当前最多主控加三个子智能体，实际按依赖调度。
