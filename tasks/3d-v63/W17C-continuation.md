## 改造前已核实的难点（历史）

| 位置 | 当前代码事实 | 验收影响 |
|---|---|---|
| `Core/Scene/PocketRailInventory.swift` | 状态保存为 SceneKit 克隆、弱源节点引用和槽位；10 Hz Timer 根据源节点可见性移除驻留球 | 没有可恢复的杆前/杆后库存快照，导出不能直接按视频时钟查询这个实时状态 |

| `Core/Media/SequenceVideoExporter.swift:458` | 创建 playback 不传库存，逐杆只处理 `step.before` 球集 | 前几杆支架球不参与槽位分配和导出 |
| 同文件 `placePredictionRest` / `placeBoard` | 杆末按预测进袋隐藏盘面球；下一杆重新摆作者 `before` | 仅让进袋节点保持显示会破坏桌面/支架身份隔离，不能作为完整修复 |

这是共享呈现状态的生命周期问题。简单复制实时库存到导出会引入第二套顺序、移除和回收逻辑；直接让离线导出驱动实时定时器又不能保证帧率无关。因此转入下述已获用户同意的共享状态改造。

## 已获授权的实施方案（2026-09-14 继续）

把支架的球标识、袋标识、顺序及杆前/杆后状态提取为纯值呈现状态；SceneKit 克隆只负责显示。由同一个状态推进逻辑处理入袋、球回桌、超容量移除，实时与导出消费相同的时间段与结果。物理裁定、评分、内容 JSON 维持现有契约。

分三个可验收步骤：

1. 纯值状态与固定用例：同袋多球、拿走中间球、同球重入、超容量、状态恢复；稳定球 ID 使用 boardKey，不能用跨杆复用的 `object` 别名。
2. 先接自由走位/序列及导出试点：完整八杆、30/60fps、原速/半速逐时刻核对支架球身份/位置/透明度。重播不改变播放前库存；重打恢复杆前库存；新局重置清空；普通清桌的库存行为需在接入前明确。
3. 迁移其余回放入口，补换球形、退出、取消在途下落及场景释放检查，再做实页截图与用户实看。

用户已确认继续该方案。普通清桌只清桌面球，新局清库存，撤销恢复杆前库存。扎杆与跳球由用户明确移至下版，不作为本轮关闭前置。
