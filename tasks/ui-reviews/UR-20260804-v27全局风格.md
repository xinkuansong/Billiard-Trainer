# UI 审查报告 — 问题集合 v27 全局风格（Light / Dark）

日期：2026-08-04

## 审查范围与证据

- v27 真源：`问题集合_v27.md`
- W1 / W2 / W3 当前实现截图：`build/w1-screenshots/`、`build/w2-screenshots/`、`build/w3-screenshots/`
- 立项前六页基线：`docs/research/20260804-风格统一截图/`
- 重点对照：训练首页、动作库首页、动作详情、试打页、练习首页四分区、角度与瞄准暗场页

## 总结结论

v27 的实现基本符合其书面范围，但没有实现用户真正期待的“更专业、更好看、像同一个产品”。

根因不是 W1 / W2 执行失败，而是方案把主矛盾定义成了“颜色与组件不统一”。截图显示，用户感知更主要来自：

1. 三个 Tab 的页面骨架、信息密度、卡片内容表达仍是三套语言；
2. 练习封面从“彩虹杂乱”变成了“同区单调”，大字水印无法表达功能差异；
3. 动作库首屏筛选与缩略图信息过密，和训练 / 练习页的呼吸感不一致；
4. W3 的 4pt 黑台垫是静态装饰，不是有效转场；练习首页到黑场路径仍未处理。

因此：**W1 建议保留；W2 保留色彩语义但需要二次设计；W3 不建议继续微调，当前收益不足以支撑该批目标。**

## U-01 方案解决了设计系统一致性，但没有解决视觉统一

- **类别**：产品规格 / 视觉打磨
- **严重程度**：P2
- **位置**：训练 / 动作库 / 练习三个 Tab
- **现状**：W1 统一了 chip、徽章和按钮 API；W2 统一了 palette 与 glyph token。但训练仍是“日程 + 计划海报”，动作库仍是“密集真台缩略图”，练习仍是“单字海报墙”。
- **预期**：三个 Tab 可以保留业务差异，但应共享栏目标题、卡片外壳、元信息节奏、留白和交互层级。
- **修复方向**：下一轮目标从“继续调 token”改为“表层语法统一”，先定义跨 Tab 的栏目头、卡片壳和元信息规范。
- **路由至**：SwiftUI Developer / iOS Architect
- **代码提示**：`TrainingHomeView.swift`、`DrillListView.swift`、`AngleHomeView.swift`

## U-02 练习封面从彩虹感转成同质化色块

- **类别**：视觉打磨
- **严重程度**：P2
- **位置**：练习 > 学 / 练 / 打 / 解
- **现状**：四分区色系清晰，但同一区域的卡片仅靠明度和单字区别。学区九张绿卡、练区六张金卡连续出现，视觉节奏平，功能辨识度弱。
- **预期**：色彩承担分类，图形承担内容预期；用户扫一眼应能区分原理课、训练题、沙盘和求解器。
- **修复方向**：保留四分区主色，逐卡改为台球几何微插图、真实台面局部或仪器示意；大字水印退为辅助，不再作为唯一视觉主体。
- **路由至**：SwiftUI Developer
- **代码提示**：`AngleHomeView.swift` 的 `AngleGridCard.coverArea`、`CoverPalette.swift`

## U-03 动作库首屏信息密度明显高于另外两个 Tab

- **类别**：布局 / 视觉打磨
- **严重程度**：P2
- **位置**：动作库首页
- **现状**：搜索框、筛选按钮、球种 chip、等级 chip、左侧分类和双列缩略图同时出现；单卡还叠加等级、距离/袋口、版本和收藏。W1 统一了 chip 外观，但没有降低噪声。
- **预期**：首屏应只保留最高频筛选和内容主线，其余条件进入筛选面板；卡片元信息应按优先级减少常驻项。
- **修复方向**：球种与等级合并为单行摘要或筛选 sheet；版本角标按 v26 收官计划移除；重新裁定卡片常驻元信息。
- **路由至**：SwiftUI Developer / iOS Architect
- **代码提示**：`DrillListView.swift`、`BTDrillCard.swift`

## U-04 训练计划封面换色明显，但品牌含义仍不稳定

- **类别**：产品规格 / 视觉打磨
- **严重程度**：P2
- **位置**：训练 > 官方计划
- **现状**：训练计划直接复用练习分区色对，视觉上更协调，但不同等级映射到绿、蓝青、石墨、金等颜色，颜色既像等级又像练习分区，语义不够稳定。
- **预期**：训练计划色彩应优先表达计划等级或训练阶段，不与“学 / 练 / 打 / 解”分类色产生歧义。
- **修复方向**：保留同一饱和度预算和 glyph 规范，但为计划建立单独、连续的等级阶梯；共享规范不等于共享具体色对。
- **路由至**：SwiftUI Developer
- **代码提示**：`CoverPalette.PlanStyle.forLevel`

## U-05 W3 黑台垫感知过弱，不能承担明暗转场

- **类别**：布局 / 视觉打磨
- **严重程度**：P2
- **位置**：动作详情 > 上手试打
- **现状**：`BTDarkStageMat` 仅在球台外露出约 4pt 黑边。静帧中可发现，正常使用几乎不构成“暗世界预告”；push 后仍直接进入全黑 HUD。
- **预期**：若 W3 目标是消除明→暗硬切，应以完整 push 过程为验收对象，而不是以源页出现黑色像素为完成标准。
- **修复方向**：停止继续调整黑边。若仍要做转场，应重新设计可感知机制；否则砍掉 W3，把预算投入页面表层语法。
- **路由至**：SwiftUI Developer
- **代码提示**：`BTDarkStageMat.swift`、`DrillDetailView.tableSection`

## U-06 练习首页到暗场路径实际没有被 W3 覆盖

- **类别**：产品规格 / 视觉打磨
- **严重程度**：P2
- **位置**：练习 > 角度与瞄准等暗色场景页
- **现状**：W3 最终放弃候选 C，因此练习入口仍是浅色白底卡片，点击后直接进入全黑场景。连续截图只记录了目的页，未证明源页与目的页之间存在新的衔接。
- **预期**：方案声明覆盖“详情→试打、练习→场景”两条路径时，两条都必须有可观察改进。
- **修复方向**：将 W3 判为“部分覆盖”，不要按原完成标准勾选收官；后续要么明确砍掉练习路径，要么另立真实转场方案。
- **路由至**：SwiftUI Developer / QA Reviewer
- **代码提示**：`AngleHomeView.swift`、`MainTabView.swift`

## 方案审核

- **W1 浅色组件收口**：通过。工程价值明确，视觉收益小但真实存在。
- **W2 封面色板分区收敛**：附条件通过。解决彩虹感，但引入同质化；需作为下一轮视觉重设计的底座，而不是最终结果。
- **W3 明暗转场衔接**：不建议按原目标通过。当前只实现详情页薄黑边，练习路径未覆盖，且连续帧无法证明转场机制改善。
- **v27 总体**：设计系统治理通过，产品视觉目标未达成。

## 建议的下一轮优先级

1. 先做三 Tab “表层语法”规范：栏目头、卡片壳、元信息、留白、筛选层级。
2. 重做练习封面内容表达：分区色保留，单字海报改为专业台球微插图 / 实况预览。
3. 动作库首屏减噪：两排 chip 收成一层，卡片角标减量。
4. 训练计划建立独立等级色阶，不直接复用练习分区具体色。
5. W3 停止微调；只有在明确转场目标后再重开。

## 审查统计

- 问题数量：6 项（P0: 0 / P1: 0 / P2: 6）
- 总体评价：工程收口有效，但方案没有命中“视觉专业感”的主矛盾。
