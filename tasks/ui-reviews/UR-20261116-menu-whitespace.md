# 菜单横向留白排查

日期：2026-11-16（北京时间）。当前角色：UI Reviewer。

## 范围与结论

用户先指出训练首页更多菜单右侧留白过多，再要求分析全 App 是否存在类似问题。本轮为截图分析与当前工作区源码审计，没有修改 App，没有操作现有人工评审模拟器，没有执行构建或 UI 测试。

已确认视觉问题 1 项（首页，P2）；另有两类直接可定位的自定义宽度风险，以及一组系统短菜单候选。其余页面没有同设备展开截图，不能写成已复现或全 App 验收。

扫描范围为 `QiuJi/` 下 484 个 Swift 文件，排除 research/tmp 的源码副本。词法扫描命中 26 个 `Menu` 声明、2 个 SwiftUI popover、1 个 contextMenu、18 个 confirmationDialog、2 个显式 menu Picker；另追查 UIKit popover 和自定义菜单。数字是源码声明数，包含嵌套、旧分支、Debug 与未调用组件，不是线上菜单或缺陷数量。

依据：`swiftui-design-system` 的信息密度与通用自适应准则，球桌规范 TP19/20 的分组、选项语义与连续选择，TP35 的证据边界。现行规范没有全 App 统一菜单宽度；下列收紧方向是提案，不是已确认的新规范。

## U-01 首页更多菜单：截图已确认，P2

- 位置：训练 Tab → 右上更多。
- 现状：四项均为四字标题，图标和文字集中于左侧，文字之后到右边缘的空白接近菜单宽度的一半；菜单覆盖了较大一块本周训练卡。
- 源码：`QiuJi/Features/Training/Views/TrainingHomeView.swift:478` 的 `headerActions`，使用原生 `Menu` + 四个 `Label`。44×44 的 frame 属于入口按钮，菜单内容没有手写宽度或撑宽的 Spacer。
- 判断：视觉留白与内容不匹配；源码不能证明系统采用了什么内部最小宽度，也不能证明机型、系统版本、字号或无障碍设置是根因。不能把入口按钮改窄当作弹层修复。
- 方向：以图标、最长文字和两侧合理内边距确定紧凑宽度，保留整行点击与右上锚点。先做原生实页候选对照，再决定是否需要受控的紧凑弹出组件。
- 路由：SwiftUI Developer；本轮仅诊断。

## R-01 训练设置多选弹层：宽度风险明确，视觉待验

- 源码：`QiuJi/Features/AngleTraining/Views/SceneTrainingSettings.swift:367–407`，`TrainingMultiSelectRow`。
- 容器为 `frame(minWidth: 250, maxWidth: 340)`；每行勾选标记与文字后有 `Spacer(minLength: 0)`。这是自定义内容的真实最小宽度约束，不是从截图猜测。
- 短内容：目标袋类型为“综合／角袋／中袋”；目标球离库为“综合／半贴库／贴库”。文案来自 `SceneTrainingRules.swift:55–66`，mixed 在弹层中转换为“综合”。
- 长内容：母球到目标球、目标球到袋口包含“短 · 0.30–0.60m”等距离范围，不能与短内容一律缩到相同窄宽。
- 消费范围：角度练习、瞄准点练习、准度练习、分离角练习、两球走位、三球走位六类设置页；共用四个条件入口。
- 方向：按各弹层最长选项与标记自然宽度确定宽度，并受当前窗口容量限制。先检查两个短文案入口；保留连续多选、至少一项、综合互斥、外点仅关闭及草稿语义。
- 更正本轮口头举例：“直线”不是这里已核对的选项，准确候选为上列袋型与离库条件。

## R-02 球桌短选项子菜单：复用主菜单宽度，视觉待验

- 源码：`QiuJi/Features/PositionPlay/Views/DailyHUDPanel.swift:114`，`DailyHUDMenuPanel.width` 为普通 252pt、辅助字号 360pt，再受 availableSize 限制。
- 其高度按内容测量，宽度不按内容长度区分。主菜单与子菜单共用该组件。
- 已追到的短子页：`FreePlayView.swift:1484` 的瞄准模式“进袋／自由”、轨迹档位“关闭／瞄准线／双线／全部”（具体词随宿主）；共享教学壳也使用该面板显示轨迹档位、开球玩法。
- 入口接线：`FreePlayView.swift:2106`、`BTTeachingTablePage.swift:639`；不是仅存在组件定义。
- 方向：主菜单与短选项子菜单分别量测。主菜单右侧存在 2D/3D 分段、详情、选中标记与下级箭头；子菜单也必须容纳返回、标题和关闭按钮，不能只按两字选项压宽。
- 影响条款：TP19/20 继承；普通选档原位更新并保持展开。TP02/03/08 作为遮挡、边界与命中的依赖项；TP35 标记本轮仅源码检查、原生视觉及交互未验。其他条款未复核，不标不适用。

## 不直接列为同类缺陷

- `BTGeometricReferenceTool.swift:167` 的测量选择和 `SiluTrainerView.swift:12` 的约束工具采用 112pt 的相对宽度；源码已按短选项紧凑处理，当前视觉仍未复验。
- 历史记录更多使用 `BTOverflowMenu`，实际是 confirmationDialog（TrainingDetailView.swift:436）。手机/iPad呈现方式与首页 Menu 不可直接等同；单列平台核验。
- `BTOverflowMenuPopup` 虽固定 220pt，但当前仅 Preview 调用；不能报作线上根因。`BTSceneObservationMenu` 仅检到定义；不以注释里的旧消费者名单计算现行影响。
- `BTSolverMoreMenu`、`ShotObservationMenu` 仍在 FreePlayView 留有引用，存在新旧布局分支；未经正常入口确认，不将所有共享宿主列为已受影响。
- Debug 相机对照、引导样式实验、内部批量工作台与普通用户入口分列，词法命中不代表线上可达。
- 设置页整行、表单左右列间距、滑条轨道和分段控件的空间有布局用途，不因有 Spacer 或固定宽度就判为缺陷。此次不延伸为全 App 卡片、正文或球桌尺寸审计。

## 建议顺序与验收

1. 首页原图作为视觉起点，做内容贴合的紧凑候选；同设备同字号比较宽度、文字、触区和关闭行为。
2. 共用 TrainingMultiSelectRow 按短选项／距离数值分开量测，覆盖六类消费者的真实设置入口。
3. 球桌仅先比较短子菜单，保留复杂主菜单容量；验证切换、返回、外点关闭、内部空白不穿透和连选不收起。
4. 对 R-03 中短动作菜单逐页展开确认，再决定统一组件覆盖范围。单动作删除入口的宽度调整不顺带改成无确认直接删除。

正常字号与普通页面大字号、窄手机与 iPad 受限窗口、浅深模式按影响选代表条件。当前仅用户提供的一张首页截图是本轮视觉依据；未采集其他页面，未确认用户原图设备/系统/字号；未做原生、真机或可访问性操作验证。没有把过去的测试或现有人工评审设备状态当本轮证据。

本轮交付为分析完成，修复未实施；没有新增 P0/P1 或 FAILURE-LOG，没有更改共用设计规范。
