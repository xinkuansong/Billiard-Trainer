## 2. 当前问题与真实原因

### U-01 同类操作分散在不同位置（P2 / 信息架构）

自由击球的 2D/3D 在导航栏；分离角与走位在顶部信息行；固定瞄准训练由两个路由决定模式；动作详情在球桌上方工具行。视角菜单又有顶部与底部两种位置。用户需要逐页重新学习。

代码：`FreePlayView.swift:647`、`ShotSimulationView.swift:210`、`SceneAimingView.swift:16`、`DrillSceneView.swift:672`。

### U-02 动作列按狭窄空隙设计，缺少主次（P2 / 布局与触摸）

截图中击球、重打、回放沿右侧竖排，开球在左下；同时有打点、力度尺、轨迹档位、瞄准模式、球库。`BTTextActionButton` 默认高度 30pt，`BTShotActionColumn` 以 8pt 间距堆叠。这里只能确认组件声明没有提供 44pt 最小高度；最终命中范围仍需运行时量测。轨迹按钮已经显式设置 44pt，不应一概判为过小。

代码：`BTShotPageChrome.swift:133`、`:178`、`BTTrajectoryDetailChip.swift:8`。

### U-03 不同能力的球库长得相同（P2 / 功能可发现性）

摆球页使用可交互球库；自由击球使用参考球库；瞄准训练使用装饰球库。截图中的整排球在不同页面看似同一类操作，实际能力不同，也挤占底部空间。

保留规则：自由击球不能任意摆目标球，每日清台更不能借 UI 重组放开规则限制。当前自由击球仅允许已有契约范围内的母球拖动。

### U-04 浮层与题目可见性没有形成完整契约（待复验 / 布局）

05 与 06 同题对照：答题键盘打开后，两颗题目球位于被遮盖区域。`SceneAimingView` 明确保留原场景高度而浮盖键盘，但保留高度不等于保证关键内容可见。先记为本次安装包的实际发现，待同源码稳定球形复现后正式定缺陷级别；不据此认定全部题目都被挡。

### U-05 镜头能力多，当前观察对象不明确（P2 / 摄像机与反馈）

现有菜单有全桌、母球、目标球、目标袋、回到瞄准，但 UI 多显示泛称“视角”。`CameraRig.observe(at:)` 主要改观察中心，沿用当前距离与仰角，并不是每次都构成适合该目标的特写。因此“查看母球”不能被设计文案误当作“母球已清晰放大”。

### U-06 页内显示与重开训练绑在同一设置中（P2 / 状态语义）

角度训练设置同时包含训练模式、题型与网格，确认按钮在已有题目时叫“重新开始”，调用 `startTest()`。用户只想改网格时不应承担重开一轮的语义。网格、瞄准特写和轨迹档位目前又是共享偏好；修改作用范围需要明确。

以上是讨论级审查，不代表整套视觉或功能验收。建议由 SwiftUI Developer 负责控件与布局，iOS Architect 配合明确相机状态边界；用户确定方向后再登记实施任务。

## 3. 调研所得与适用范围

1. Shooterspool 官方训练介绍强调：摆设真实球形、随力度/旋转更新物理轨迹、试打与慢动作分析。这支持保留专业训练闭环。官方也明确其为 Windows PC 产品，不能从它的功能价值直接推出手机按钮布局。
   - https://www.shooterspool.net/training-billiards-tool.php
   - https://www.shooterspool.net/promo/play-online-pool-games-billiards-simulation.html
2. 官方影像目录包含慢动作、真实球重建、比赛回放。此次读取了目录与训练说明，没有完成官方视频逐帧检查，也没有实际操作 Shooterspool；不声称已验证其全部快捷键和镜头切换规则。
   - https://www.shooterspool.net/images-and-videos-of-shooterspool.php
3. Apple 的 UI Design Dos and Don'ts 要求触摸控件至少 44×44pt，强调控制靠近被控制内容、对齐反映关系、内容适配设备。用于判断操作区与触摸尺寸，不代替用户握持测试。
   - https://developer.apple.com/design/tips/

我们的推导：保留“观察 → 判断 → 精调 → 试打 → 回看”的能力；采用触屏直达与有限的状态切换。常用动作不全部塞进设置，也不在台面周围展示所有能力。

## 4. 推荐布局：固定双手操作区，工具按阶段展开

以可击球页面为母版，逻辑区域如下。此处是结构草图，不是最终尺寸稿。

```text
┌────────────────────────────┐
│ 返回      页面名        设置 │  页面层
│ 当前模式 · 当前目标 / 状态   │  单行必要信息
│                            │
│       球桌 / 当前这一杆      │
│                            │
│ 瞄准微调              打点 │
│   ↕                    力度 │  双手操作区
│                            │
├────────────────────────────┤
│ [2D | 3D]  [瞄准 | 全桌]   │  后两项仅 3D 且有瞄准能力时出现
│ 球形/模式   回看    [击球]   │  当前阶段动作
└────────────────────────────┘
```

具体取舍：

- 左手只负责瞄准精调；右手负责力度与打点。改数值时在控件附近显示读数，避免眼睛来回找。观察态收起无关的长尺，保留“回到瞄准”。
- 主动作稳定在底部右侧，建议 48–52pt 高；同一时刻只有一个实心主动作。击球、提交答案、播放演示由页面任务决定。
- v0.2 收敛视图入口：固定窄行只保留 `2D / 3D`；可瞄准的 3D 页面另有 `瞄准 / 全桌` 两个明确选项，取消常驻“视角…”菜单和重复“回到瞄准”。点击“瞄准”即返回瞄准构图；手动偏离后显示“自由观察”状态，并用一个临时“复位”动作回到最后选用的预设。只读详情没有瞄准任务，只显示全桌复位。2D 只在放大后显示复位，不展示 3D 预设。
- 模式有必要时显示当前值入口“进袋辅助 / 自主瞄准”；点击展开明确选项，不再靠循环图标猜下一态。具体命名待用户确认，底层进袋/自由语义不改变。
- 球库按用途处理：摆球页在“编辑球形”时展开；自由击球参考库收成“桌上球 / 已进球”入口；测验装饰库建议移除，只显示题目涉及球。该变化需用户确认。
- 回看把“回放”和“重打/撤回”分组展示，但必须保留语义区别：回放不改当前局面；重打恢复本杆击球前；上一杆仅用于真正的多级撤回。首杆无历史时不堆满灰色按钮，可显示低调不可用入口与原因。
- 开球在准备新球局时突出，已有球局时进入“球局…”；每日清台保留已有放弃/重开的确认逻辑。
- 不采用自由拖动按钮位置作为首版能力。固定布局先达到可用，再由真机结果决定是否需要左右手镜像。

两行底部并非无条件增加高度：可击球页用它替代常驻球库和旧 3D 帮助栏。小屏必须以实际剩余高度核算，不能按图中示意比例直接实施。

## 6. 摄像机语言：每种镜头都有任务和退出方式

| 镜头 | 用户要看什么 | 进入 | 构图目标 | 退出 / 保留 |
|---|---|---|---|---|
| 俯视全桌 | 球形关系、选择球袋、摆球 | 俯视 / 全桌 | 可操作桌面、六袋可见 | 放大后可直接复位；不变更杆向 |
| 3D 全桌 | 整体走位与球间关系 | 全桌 | 与竖屏 2D 保持方向一致 | 手势后进入自由观察 |
| 3D 瞄准 | 母球、杆向、目标球关系 | 回到瞄准 / 新题 | 母球、杆头和目标处于控件外的安全区 | 手动观察保留瞄准快照 |
| 局部观察 | 接触点、目标球或袋口 | 特定分析任务下的二级入口 | 对象清楚，保留必要环境尺度 | 点击瞄准预设返回 |
| 击球过程 | 判断真实球路 | 击球 | 默认保留当前镜头，避免瞬间切走 | 停稳后保持结果供判断 |
| 回放 | 理解上一杆 | 回看 → 回放 | 默认全桌；可手动看局部 | 退出回到进入回放前的局面与视角 |

镜头细则建议：

1. **手动操作优先。** 用户开始转动或捏合后，自动取景不得在求解结果回调、球停稳、面板出现时把镜头抢回。新题、明确点“回到瞄准”、恢复本杆可以按约定取景。
2. **保持镜头与杆向分离。** 横滑转相机不能改球杆方向。瞄准轮改杆向；处在瞄准态时，相机可随杆向同步旋转，但保留用户距离/高度，不能每个增量都重新走默认 entryZoom。
3. **捏合只改远近，纵滑只改观察高度/仰角。** 当前手动 orbit 已基本做到，优先保留。FOV 不随一般捏合联动；预设切换的 FOV 变化另行比较再定。
4. **全桌与局部不共用裁剪要求。** 全桌应保证六袋与可操作台面；局部允许裁掉远端，但不能裁掉正在观察的对象。当前实际 viewport 拟合继续复用，并将覆盖控件区域纳入可用视区。
5. **不要把“观察目标球”自动视为近景。** 局部分析时显示观察对象名称（与击球目标分别表述）；是否自动调整到特写尺度，应以同球形镜头对比裁定。手动缩放能力保留。
6. **过渡由用户动作触发且可打断。** 当前 `enterAiming` 使用 0.6 秒，首轮不拍脑袋换成另一固定数；用录像比较近距/大角度移动，响应系统减弱动态效果。禁止展示“电影模式”却没有真实可用行为。
7. **击球默认稳镜头。** 自动拉高观看可作为后续可选偏好；首版不引入自动追球、入袋切特写或多机位剪切，以免错过碰撞和走位。
8. **键盘与面板不能遮掉问题本身。** 先为题图与输入保留稳定分区；若必须重取景，在输入前完成，输入期间不再漂移。不能边输答案边让球移动。

## 6A. v0.2：球桌占比、用户焦点与视角冗余（本轮修订）

用户补充：3D 必须考虑球桌在屏幕中的占比、不同视角的用户焦点，整体检视视角选项冗余。以下仍为方案建议，未实施、未做新构图对照。

### 三个层次不能混为一组按钮

- **呈现方式**：2D / 3D。
- **构图任务**：瞄准 / 全桌。它们在 3D 内直接可选，不再同时列出站立、俯身、俯瞰、观察等近义档位。
- **关注对象**：母球、目标球、袋口。它们是任务的内容，不天然对应三个常驻相机模式。

因此上一版 `[俯视 / 3D] [全桌] [视角…]` 的菜单确有重叠，本版主动收敛。底层仍可拥有多种镜头动作，但不必把每个 API 变成产品选项。不同页面只提供有用的子集；固定模式测验继续保护考试条件。

### 占比以可用视区和可判断性衡量

不能给所有镜头统一规定“球桌占屏幕 80%”：低机位下近端木框或桌腿占很多像素，仍可能看不清远端球。必须分别量测：

1. **整个屏幕中的场景区域**：扣除系统安全区、页面导航、必须的操作栏。
2. **场景里的可用观察区域**：继续扣除两侧仪表、打点浮层、键盘等遮挡区域。
3. **当前任务的关键内容**：全桌看六袋与台面；瞄准看母球、杆头、目标接触关系；局部分析看选定对象与必要的参照。

全桌构图：在所有关键边界完整可见的条件下，尽量填满限制轴，横向与纵向任一先到边界即停止放大。原型可比较可用视区限制轴占比 85% / 90% / 95% 三档，**只是待比较候选，不是验收阈值或当前实测结果**。同时检查球的屏幕尺寸和远端遮挡，不能单看面积占比挑赢家。

瞄准构图：母球安排在可用观察区下半部的中轴附近，杆头可见；目标接触关系在中上区域，避免被右侧打点和力度遮挡。优先展示母球、目标球和必要的目标袋关系，不强求六袋完整。允许裁掉桌腿、近端外框和与本杆无关的远端台面。长台薄球要单独比较，不能为塞进同一包围框把两颗球缩成点。

局部构图：允许裁桌，但应保留理解位置所需的参照，例如袋口与邻近库边。不能放大到用户只看到一颗球、不知道自己看哪侧。

环境的角色：球房提供空间与真实感，在训练构图中让位于台面和球。过大的天花/空墙不作为默认留白；需要临场低机位时也应说明训练目的。用户手动拉远看球房可以保留。

### 按任务确定视觉焦点与稳定性

| 状态 | 第一焦点 | 次要信息 | 构图和 UI 规则 |
|---|---|---|---|
| 观察布局 | 台面球形、球间通路 | 玩法、剩余球 | 全桌填充可用区，收起不需要的编辑长尺 |
| 瞄准 | 母球—杆向—目标接触关系 | 目标袋、角度 | 两侧仪表位置固定，关键球不在其背后 |
| 改打点 / 力度 | 正在编辑的参数与对应球路 | 其余参数 | 面板占位先确定，禁止每拖一下就重取景 |
| 击球 | 碰撞及后续走位 | 结果读数 | 默认稳定机位；不要为了追进袋切走母球走位 |
| 回看结果 | 母球落点、目标是否进袋 | 本杆参数 | 球停后不立刻回瞄准，让用户先判断 |
| 答题 | 题目球形 | 键盘 / 输入值 | 键盘不能遮题；输入期间保持题图稳定 |

焦点不等于把对象每帧强行拉回屏幕中心。只在明确换任务、切预设或复位时调整构图；轻微手动观察不应马上折叠控件、扩大 viewport 并再次移动相机。由此修正 v0.1 对“观察态收起长尺”的过宽表述：**只有明确进入全桌分析等阶段才重排，普通手势不触发整页布局切换。**

默认稳镜头仍有边界：局部镜头可能看不全击球过程。先提供直接的“全桌”预设，不悄悄把稳镜头改为自动追踪；是否新增“击球时自动全桌”偏好，应在对照录像后共同决定。现阶段不新增这种自动行为。

### 技术判断与验证边界

当前 `CameraRig.observeWholeTable` 使用 viewport 宽高比和桌体边界拟合，证明已有“装进视口”的能力，但没有表达这一整套“控件遮挡区域 + 任务焦点 + 最小可判断尺度”的产品规则。改造应从调用方传递当前任务和可用区域开始讨论，而不是继续仅调整 radius / height / FOV 数字。

下一轮构图对照至少包括：近台直球、长台薄球、母球贴库、目标靠袋、满台散球，同一球形对照 3D 瞄准和全桌，并在标准机与小屏分别打开参数面板。上述每项都需要原图与运动检查，当前不宣称已满足。

## 7. 手势与阶段矩阵

| 阶段 | 单指台面 | 双指 / 捏合 | 两侧仪表 | 底部主动作 |
|---|---|---|---|---|
| 编辑球形（仅有权限页） | 拖球、选择 | 2D 平移 / 缩放 | 收起 | 完成摆球 |
| 2D 自主瞄准 | 空白区调方向；球体操作按原权限 | 平移 / 缩放；全桌复位 | 左瞄准、右力度 | 击球 |
| 3D 瞄准 | 旋转 / 升降，明确是观察 | 捏合远近 | 左瞄准、右力度 | 击球 |
| 3D 自由观察 | 旋转 / 升降 | 捏合远近 | 明确进入分析观察时收起；短暂转动不立刻重排 | 原动作区稳定；通过瞄准预设返回 |
| 求解 / 球在运动 | 不允许修改球形或杆向 | 观察能力按页面保留 | 只读摘要 | 状态或已有暂停能力 |
| 答题 | 不改题目 | 依训练策略开放观察 | 无击球仪表 | 提交 |
| 回放 | 只观察 | 观察 | 只读参数 | 结束回放 / 已有暂停 |

嵌入训练页还有祖先翻页、纵向滚动。当前 DR-305 正在处理仲裁，本轮不覆盖该工作；建议契约为台面内起手操控相机，台面外起手滚动/翻页，并保留明确翻页按钮。不能让整个页面都吞纵向滑动。

## 8. 跨页面适配，不机械复制全部按键

| 页面族 | 保留的任务 | 同一套 UI 里的差异 |
|---|---|---|
| 分离角与走位、自由走位 | 摆球、调整、试打 | 编辑球形入口；3D 暂不摆球 |
| 自由击球 | 按球局击球 | 球局管理、只读球库，禁止开放任意目标球拖动 |
| 每日清台 | 单人清台挑战 | 规则 HUD、合法母球操作、结算后只观察 |
| 2D/3D 角度与瞄准点训练 | 作答与训练反馈 | 不放击球/球库工具；固定模式测验不随意跨 2D/3D |
| 思路训练、打一走二想三、斯诺克战术 | 规划 / 求解 / 观看 | 2D 编辑，3D 观察；无目标袋的页不显示目标袋按钮 |
| 动作详情、训练页球桌 | 看示范 | 简短视图行与回放；不占据整页底部的训练主动作 |
| 上手试打 | 序列 / 辅助进袋 / 自主试打 | 序列参数只读；保留杆边界暂停，不假装能逐帧暂停 |
| 球理图谱、拆球、批量编排 | 各自教学 / 标注任务 | 先复用视图入口规则，不自动增加本来没有的 3D / 击球能力 |

固定模式的 2D/3D 测验入口暂保留，避免改变训练题目条件与历史统计口径。是否合并首页两张卡另作产品讨论，不能借工具栏重构暗中合并。

## 9. 设置作用范围与状态恢复

- 页内设置只做即时显示与偏好；关闭即回原题，不调用 `startTest()`。训练模式/题型放独立“训练配置”，明确“应用并重新开始”。
- 现有共享偏好继续一份真源：轨迹档位、网格、特写。页内显示“应用于同类练习”，防止用户误以为只改当前题；测验仍由题目允许的辅助策略覆盖。
- 球桌/球房/台呢/性能沿用全局设置，不复制字段。
- 镜头位置、观察对象属于本页/本杆临时状态；不跨题保存同一世界坐标 pivot。可记用户偏好的镜头高度档位，但须经讨论确认。
- 2D → 3D → 2D 不丢球位、打点、力度、目标、解或未提交答案。恢复旧镜头前校验它对应当前杆；球形已变时不能恢复指向空处的快照。
- 回放退出恢复当前局面；重打恢复对应击球前快照；相机与球形/姿态快照必须配对。
- 无有效杆向时仍可看全桌和球，不能伪造一条球心连线用于“回到瞄准”。

## 10. 实施顺序与验收（提案，未执行）

1. 先确定四个取舍：球库收起、底部主动作、统一视图行、默认击球稳镜头。形成 2D 瞄准 / 3D 瞄准 / 观察 / 回看 / 设置的精确稿。
2. 以分离角与走位做完整试点：已有 2D/3D、摆球、仪表、击球与回放，覆盖最全。自由击球同步做规则差异审阅，防止试点设计无法迁移。
3. 再接瞄准测验与只读示范，解决键盘避让、只读参数、固定模式考试边界。
4. 最后接规划/求解页与 iPad，复用语义，按任务隐藏不适用项。

验收必须同时包含：

- 真机双手使用：连续瞄准、打点、力度、击球，无碰到邻钮和遮住母球；看完目标袋一键回来。
- 最小支持 iPhone、常规 iPhone、iPad；标准/大字号、深浅模式与回放/浮层/空桌/母球进袋/无有效解。
- 同一球形动态录像：拖到一半切模式、相机过渡中手势接管、打点面板开关、回放进出、重打和下一题。
- 状态断言：相机操作不改变球位/杆向/物理输入/成绩；轨迹档位修改不偷偷重开；回放不改本局；球库规则不扩权。
- 触摸命中实际量测 ≥44pt，文字与图形另看真实截图。新 UI 必须在可用视区内展示关键对象，单看控件 frame 不算通过。
