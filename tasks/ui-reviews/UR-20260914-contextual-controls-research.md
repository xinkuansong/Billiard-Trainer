# 情境显隐与现代移动端球桌界面：v0.3 调研

2026-09-14。用户否决前一张效果图，明确要求现代感、灵活可用、控件按需要出现和消失。本稿替代 v0.2 的常驻双排底栏方向，仍为设计讨论；未修改 App。

## 1. 前一张图的问题

- 上下实体面板把场景夹成中间窗口；底部两个分段器和三个按钮长期占屏。
- 按钮、读数、标签各有一块底，形成大量小盒子，层级琐碎。
- 两侧尺一直完整展示，即使用户只是看球形，也要承受编辑状态的视觉密度。
- 绿色同时强调 3D、瞄准和击球，主动作不突出；继续瞄准又与瞄准选项重复。
- 两张静态页面只能展示排版，未体现操作时如何展开、结束后如何收起。

## 2. 调研依据

### Apple：触屏游戏控件按情境变化

官方 WWDC26《Make your game great with touch》的 10:17 起章节讨论动态操作、隐藏无关控件和直接触摸。可借鉴：保留稳定的操作锚点，让控件在需要时显现；相机可以由台面手势控制，无需增加可见摇杆。这里借鉴交互原则，不意味着球迹需要接入其 Touch Controller 框架。

来源：https://developer.apple.com/videos/play/wwdc2026/358/

### Apple：内容与控制层分开

WWDC25 新设计系统强调浮于内容之上的控制层、功能分组与连续变化。可借鉴轻薄浮层、减少整条实色底板；不能仅给原先所有按钮加玻璃效果。球台本身纹理与轨迹丰富，材料必须保证文字可读。

来源：https://developer.apple.com/videos/play/wwdc2025/356/

### Shapr3D：选择决定工具

官方自适应 UI 说明介绍根据选中内容推荐相关工具。对球迹的启发：球形编辑、打点、回看分别呈现各自的工具，不共享一套常驻按钮墙。不能照搬 CAD 的大量菜单，也不能让“观察球”意外改变击球目标。

来源：https://support.shapr3d.com/hc/en-us/articles/7873882619548-Adaptive-user-interface

证据边界：本轮检索并读取官方页面/视频文字稿；未实际运行 Shapr3D，未做参考视频逐帧视觉研究。新交互以下均为从资料与球迹现状推导的提案，不冒充参考产品现有行为。

## 3. 新的视觉方向

球桌场景铺满页面底层，在系统安全区内叠放少量控件。取消常驻双排黑色底栏和整行信息卡。顶部为独立返回/更多，小标题或必要题目状态；下方以分离的轻薄工具组承载当前动作。

- 非主动作使用中性半透明材料、少量细边界；不要每段文字独立套底。
- 品牌绿主要用于击球/提交等主动作，当前视角以文字和中性选中背景表达。
- 打点入口本身就是母球图与当前打点，力度入口本身就是数值，不再叠三层标签。
- 缩略态视觉面积小，但命中区保持足够大；不能用透明窄条逼用户摸索。
- 玻璃只用于少量控制面，降低透明度与旧系统都要有可读的材质回退；不把全页改成玻璃。

## 4. 明确显隐，而不是统一倒计时

| 阶段 / 触发 | 显示 | 收起 | 如何重新出现 |
|---|---|---|---|
| 准备瞄准 | 主击球按钮；左侧微调短柄；右侧力度值与打点；紧凑视图入口 | 完整刻度、球库、回放工具 | 点对应入口 |
| 按住微调短柄并拖动 | 左侧完整刻度、角度反馈；允许时出现现有瞄准特写 | 无关说明降显著性 | 手指松开后回短柄；再次触摸直接继续 |
| 在力度入口拖动 | 右侧展开力度尺、当前数值 | 非必要标签 | 松开回到当前力度值；下一次仍同位置操作 |
| 点打点入口 | 紧凑打点面板；原入口作视觉来源 | 暂时隐藏可误触的击球按钮 | 完成/关闭后恢复；编辑不被超时关闭 |
| 已识别的相机拖动/捏合 | 场景、低调恢复工具入口 | 编辑尺、次要 HUD、击球操作暂退场 | 手势结束恢复紧凑态；显式纯观察态由恢复工具入口唤回 |
| 球在运动 | 必要杆号/状态；确有实现的播放操作 | 瞄准、力度编辑与球库 | 停稳后出现轻量结果/回看入口 |
| 球已停稳 | 本杆结果与回看入口；页面允许时显示下一步 | 不立刻展开编辑尺 | 用户继续操作时回紧凑瞄准态，不自动抢镜头 |
| 回放 | 当前杆、已有播放/结束能力 | 击球编辑工具 | 结束回放恢复进入前状态 |
| 编辑球形 | 有权限的球库、完成入口 | 击球与无关视角选项 | 完成后收回；固定题目和每日清台不扩权 |

优先基于手势起止、面板开关、回放阶段显隐。只有纯观看阶段的次要说明可以延迟淡出，时间待实测；用户正在瞄准、输入或读设置时不使用统一自动消失计时器。

## 5. 显隐的稳定性约束

1. 隐藏视觉必须同时关闭命中；屏幕上消失的击球按钮不能仍被触发。
2. 手势由起手时的区域与当前模式决定，并锁定到松手。相机滑动不能中途变成瞄准滑动；触摸力度后即使手指离开短柄也连续归力度控件处理。
3. 隐藏/恢复控件不重建场景、不改变 viewport 大小，不自动重算相机。采用稳定布局的覆层显隐；切换明确构图预设才重新取景。
4. 不自动迁移正在被拖动的控件；关键球与工具相撞应在构图阶段避免，不能靠按钮追着手指或球跑。
5. 纯观察下保留一个明确的恢复工具入口。若额外允许点空白唤醒，第一次点击只唤醒，不同时选球/选袋/击球；已有点击选择逻辑必须仲裁。
6. VoiceOver 焦点停留、触摸仍按住、输入未完成时不自动隐藏。重要功能具有明确点击入口，不只靠隐形手势。
7. 前后景恢复、弹窗取消后恢复此前工具状态；不清空参数。低动态效果模式以淡变/直接显隐代替明显形变。

## 6. 视角也按需展开

取消常驻的两组分段器。紧凑态只显示“3D · 瞄准⌄”之类的当前状态入口；点开临时小面板，里面明确区分 2D/3D 与 3D 的瞄准/全桌。选择后收回。固定模式测验只提供允许的观察选项。

手动离开瞄准构图时出现一个直接的“回到瞄准”；处于瞄准时消失。全桌不再与另一个视角菜单重复。这个方案比常驻分段器多一次展开，但换回大量持续占用的空间；通过直接返回瞄准保留最常用的回程。若实际用户高频往返全桌，后续可将该单一动作固定，不能未验证就重新加回一整排。

## 7. 下一版效果图的制作要求

同一手机、同一球形、同一瞄准机位做连续三态：紧凑待击 → 正在微调 → 球在运动时工具退场。不要再用两张不同机位的大面板图证明现代感。另配一张临时视角面板展开态，验证菜单不重复且可以理解。

场景使用当前球房/球桌原图作为参考，不额外重画材质体系。验图重点：台面连续、两侧入口能发现、操作时反馈够清楚、工具消失后没有大块空底板。球路仍仅是生成示意，实际手感和状态恢复需要后续原型验证。

用户本轮要求调研，因此不继续沿旧图生成；本稿作为下一轮共创依据。
