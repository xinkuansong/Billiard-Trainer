# DR-348 v3.1 横屏本杆相机实施与视觉审查

日期：2026-10-03。范围：每日清台 DEBUG 两视角候选；正式旧入口及其它页面不随本轮迁移。规格：[横屏方案 v3.1](../LANDSCAPE-SHOT-CAMERA-PLAN-20261003.md)。

## 实现

- 默认沿用实际杆轴与既有 1.65m 起点/台呢上 0.90m 参考站位及原避让适配；横屏俯角改用实际 HUD 可读域内母球约 70% 高度的构图偏好，共同球体包络和袋嘴可见区间优先。
- 纵向在同一轨道联合距离、眼高与俯角。靠近时母球位置偏好渐至 78%，退远约 61%；远端候选台面占比偏好 50%，仍受本杆球尺度/台面缩水与房间约束。比例均为软目标，不是每种球形强行达成的承诺。FOV 在本杆轨道保持。
- 横向小幅观察偏重母球稳定，大幅方位逐渐向桌心构图；位置方位与视线朝向分开。按独立投影检查修正候选 TP 横滑符号，使右拖时前方目标区初始向右；旧全桌轨道和 FP 符号保持。
- TP 松手冻结实际姿态、清除尚未兑现的目标，不自动归正；下次手势沿用精确观察层级。同一个缓存轨道不重复离散反解，正常拖动不再额外经过 0.25s 接入动画。中途转场接管仍从实际姿态连续连接。
- VM 释放事件仅对 FP 发当前杆正向请求。TP 按钮仍明确归正，选定新目标仍自动进入对应 TP；推荐算法、瞄准/力度/打点均未因本轮改变。
- 三个原图标与透明横向全桌长按叠层沿用，释放恢复进入前的实际视角。

默认与近端已补真实桌子树对球体切圆轮廓的检查；默认位必要时抬眼，并按新眼位重拟合镜头，近端拒绝遮挡候选。缓存构图预留最多 4pt 的屏幕边界余量，避免袋嘴贴边时插值微越界导致横转提前停止；母球居中不满足共同主体范围时，有界地让视线转向共同主体区域。这些工作在本杆轨道生成时执行，拖动不增加每帧 mesh 搜索。此有限采样仍不等于全连续网格证书。

## 标准横屏视觉结论

- FL-105 的近短库默认和向前图，母球下缘不再被库体盖住；靠近时眼高由台呢上约 1.15m 降至 0.79m，俯角由约 31.4° 减至 27.4°，袋嘴仍位于顶部控件下方。
- 长台向前同时降低眼位和俯角，图中目标区放大；后退保持本杆主体尺度。大切角仍保留偏侧袋口，未为居中而改杆向。
- 约束确实会收窄可用行程：本次近长库默认朝向的靠近端、近短库默认朝向的退远端未找到更优合法候选，镜头停在有效姿态。这不代表所有球形都能走满同样距离，手机舒适度仍待用户判断。
- 长按期间桌面为横向、六袋完整，桌外露出原房间而非黑底；松手后的原生姿态断言和截图确认恢复进入前的实际视角。录像抽帧按日志近似对齐，部分 `released` 帧已进入下一动作，不用它们单独证明释放时序。
- 三个按钮保留图标及无障碍名称，标准屏 44pt 触达、主轴隔离、图标选中态由原生检查覆盖。未新增字体/色彩 Token；本轮不宣称完整 Dark Mode、Dynamic Type 或 VoiceOver 审查。

几何读数仅用于与图像交叉核对：标准屏实际 HUD 区域内长台默认台呢面积约 30%，靠近约 46%；近短库默认约 36%，靠近约 54%。大切角默认目标球保守投影直径约 8.6pt、退远约 8.4pt，精细厚薄可读性仍有局限，不能把“入框”称为所有场景最优。完整数值见 `output/landscape-camera-v31-20261003/projection-metrics-r4.csv`。

## 实现落点与审查口径

- `QiuJi/Core/Scene/TwoViewCamera.swift`：构图、连续轨道、姿态所有权与释放保持；`CameraRig.swift`：现有站位衔接、真实桌模型可见性与缓存。
- `PositionPlayViewModel.endCameraObservation`：页面释放回调只为 FP 请求回正，避免覆盖 TP 手动姿态。
- 推荐/选球、三个图标、透明俯视复用前轮链路；本轮用实际页面手势复验，而非以底层状态变量代替最终镜头。
- 标准模拟器覆盖长台、短球、近短库、近长库、反向、腰袋、近球和大切角 8 个球形；其中 4 类补侧向和 FP 截图。小屏定向覆盖长台、近短库、近长库、大切角及连续分轴/俯视恢复；不冒充全设备全球形矩阵。
- 静态图确认占屏、主体/袋嘴与控件关系；录像抽帧确认长按期间的俯视叠层。图像只校正显示方向，不改变模型、裁切主体或重画效果。
