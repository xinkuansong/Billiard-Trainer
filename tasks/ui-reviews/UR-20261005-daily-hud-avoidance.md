# 每日清台 HUD 与瞄准特写验收（2026-10-05）

## 用户需求与实现

| 项目 | 结果 |
|---|---|
| 点击反馈 | 每日清台 HUD 可用按钮统一使用 `HUDStyle.selectedBackground` 淡绿按下背景；文字、图标不染色；持续开关仍保留选中态。共享组件通过环境限定此页。 |
| 力度条 | 每日清台标签和可访问性用语改为“杆速”。 |
| 顶部对齐 | 返回“每日清台”、2D/3D、更多按钮使用相同水平中心线，UI 检查中心 Y 差 ≤ 0.5pt。 |
| 设置 | 击球设置在上，显示在最下面；删除菜单内“重新开球”，保留页面开球入口。 |
| 窗口边界 | 整个特写圆盘（含半径）在球桌台呢内框，2D 跟随当前桌面投影，3D 以默认 2D 桌面内框的屏幕范围为准。 |
| 无空间 | 128 → 112 → 96pt 依次搜索；仍有硬遮挡则隐藏，不返回“遮挡最少”的错误位置。 |

## 原代码已经做了什么、缺少什么

原 `AimCloseupPlacement` 有焦点相对位置、边界收敛、进球线/瞄准线距离、目标袋口端点近似避让与位置滞回。问题有四类：

1. 每日清台实际画出的理想进球线和预测线路不总在快照 keepout 内；只使用快照线段会漏保护。
2. 目标袋口只是线终点半径，未覆盖六袋实际外形；完整球杆、母球碰目标球后到第一库的线路也未接入。
3. 旧逻辑只限制页面区域，还固定排除左侧候选，最后可能返回仍有遮挡的 soft fallback；3D 全屏 SceneKit 与中间 SwiftUI stage 的坐标也需换算。
4. 特写中心距被 3D 透视压缩，但仍绘制圆形球和圆形假想球，导致看起来相交。

新逻辑把实际 SceneKit 几何投影到特写层本地坐标，硬保护：母球、目标球、假想球、瞄准线、理想进球线、当前目标球实际预测线、母球到首次吃库的可见轨迹、六袋、完整球杆。袋口取真实节点包围体；球杆取经过相机近远裁面裁剪后的模型投影凸包并留间隔。其他普通球作为择位偏好；首库后的母球后续线路不作为硬禁区。打点面板或规则提示出现时暂隐特写。

特写内部改为与相机方向对应的等比例桌面映射，保持目标球/假想球中心距 2R、接触点到两球中心均为 R。外部摆放仍使用真实 2D/3D 相机投影，未改击球物理。

## 迭代与限制

初轮命令行偏好传入字符串，未真正打开特写，虽然 UI 操作通过但截图不足以验收；已改用 DEBUG 球形 fixture 设置真实偏好并重跑。中间测试把拖出按钮误当成取消击球，实际释放仍会击球；最终测试显式接受释放击球并重启球形后验证下一个控件，没有放宽产品断言。投影单测夹具起初漏建袋口节点，补齐真实场景初始化后通过。

这是模拟器功能、几何与截图验收，未安装真机、未验证长时间发热/手感，未提交、未发布。共享工作区含其他会话变更，报告仅归属上述需求。
