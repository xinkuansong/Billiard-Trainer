# H17阶段记录：Metal Compute高光/动态球影复用

2026-11-15；起点`dd6476979`。本轮完成4轮有效研究，以及1次原生宿主构建修正。**已获得近景完整3D动画场景的Compute净收益证据；尚未切换App默认渲染提交入口。**

## 本轮实际完成

1. 按依赖拆出完整64灯样本无遮挡高光；保留实际法线、粗糙度、视角；动态球影作同帧修正。没有再次采用失败的稀疏采样、低维方向矩、插值tile、旧逐像素输入匹配缓存等路径。
2. 实现Metal Compute生产者与当前SceneKit台呢材质消费者，同一命令缓冲内有序执行；外围/非平床面保留原算法。中央384²ROI，五张Float32纹理及球态缓冲共11.33MiB。
3. 从独立台呢到当前生产完整3D场景（C1/H9/H15、球反射、房间）逐步核收益。再加入真实SceneKit父节点动作和高度变化，显式推进一次动画后读取最终presentation，生成/消费相同球态版本。
4. 每轮都有原始帧、图像、阳性控制、AA/恢复对照、冻结源码身份、准备费用及保留/否决结论。未改生产App源文件或默认开关。

## 结果如何理解

| 轮次 | 场景与问题 | 主要结果 | 决策 |
|---|---|---|---|
| [R1](H17-R1.md) | 700×400真实台呢材质，是否有Compute净收益 | 近景约23%，低位退化 | 保留近景；不外推整页 |
| [R2](H17-R2.md) | 1400×800、直接配对、镜头重建 | 近景10.54%；高光复用额外2.10% | 进入当前完整场景 |
| [R3](H17-R3.md) | 当前完整3D，真实球几何/手动球态 | 近景12.47%、俯视2.70%、低位-1.39%；高光单独收益不稳 | 保留近景Compute，不强推缓存额外收益 |
| [R4](H17-R4.md) | 当前完整3D、真实动作和同帧更新顺序 | **近景GPU约降5.46%，6/6组更快；CPU编码约增0.010ms** | 作为后续主参考 |

R4为Apple M5 Pro原生iPad版研究宿主结果，不是手机、SwiftUI整页或省电比例。8组动作/高度/显隐/相机/粗糙度状态最大画面差1/255，AA/恢复零差；每帧动画只推进一次，编码球态与最终presentation中心/高度最大误差0。初次捕获+准备GPU约2.22ms，约46个稳态帧摊回；重建可达6ms，冷启动CPU编译仍未单独计全。

**收益来自整个Compute分离路径；“高光缓存本身普遍省多少”仍未证明。** R3没有稳定额外收益，R4虽有约3%信号也不是所有组一致，不反复测同一条件挑成功数字。低位已关闭；俯视回本慢，不默认全场启用。

保留SceneKit组织和材质，Metal生成数据，最终材质消费，符合原方案P2受控宿主路线。本候选是每视图的精确接收像素表示，**不是已经完成跨视角共享的世界空间低维场**。P3/P4未完成。

下一批只做有必要的实际接线：

1. 先建立受控present宿主的旧算法B，与当前SCNView A对照，单独核宿主自身代价及画面；不把本次SCNRenderer离屏结果当成迁移零成本。
2. 接入已验的`update → 最终球态 → Compute → render不再更新`顺序；使用事件/在途资源所有权，不采用每帧CPU等待或上一帧球影。
3. 以近景固定相机为首个启用范围；相机/材质/视口变更立即回退原算法，缓存重建完成且版本匹配再启用。低位不走新分支；多视图各自版本不能误共享。
4. 完成正式页面的瞄准/播放/标注、退出/重进/后台与内存压力，再决定默认接入及手机实测。旧失败算法不再列入下一批。
