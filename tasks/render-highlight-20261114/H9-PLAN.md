# H9：台呢球位直接从常量buffer读取

2026-11-14，用户在H8核查期间再次要求继续。依据[H8](H8-CAPTURE.md)的实际spill、指令与栈指标，调整数据读取方式，生产C1保持。

假设：逐片元`shadowBalls[16]`加动态索引可能产生额外局部存储。将256-byte的四个float4x4改为等布局的16个float4，只在shader声明层重述；从constant buffer动态取同一球。CPU提交字节、球顺序、原mask/分类、64/8采样、BRDF、球影/AO和累加顺序均保持。不能把数组大小与spill大小接近当作根因证明。

先做一个`constant-array`候选，不叠加逐灯mask，不降低采样/精度。新增GPU ABI探针：同一256-byte非重复哨兵输入同时按旧四矩阵与新数组读取，16项64分量必须精确相同；仍核球心世界高度。

700×400三镜头×6球态初筛，AA/AB要求零画面差；通过后每镜头6组AA及AB、ABBA/BAAB。沿H6目标门槛：近景下降>max(5%,abs AA)，其他镜头回退不超过max(3%,abs AA)。通过后才扩展1400、六色、边界及整页/生产接入。若性能不合格最多两次有明确依据的修改，不无穷调整。

画面或ABI失败即停止该候选；若结果改善，捕获目标程序确认spill是否变化。未取得手机或整页结果前不声称省电/降温。每轮原始shader、源码/资源哈希、图片、时序和判断保留在受管run；临时产品由生命周期回收。
