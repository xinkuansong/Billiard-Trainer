# H16：台呢样本组织与样本带球影筛选

2026-11-15，用户授权继续台呢优化、换方向，不重复淘汰路线。本批继承 v2 方案，基线是当前 C1＋H9＋H15，生产台呢完整程序 SHA256 为 `14a880284fffc793f01d0357b0a625559101609d7986c9ac0cac72e7085efa4f`。

## 新方向与边界

以两个或四个相邻 Z 样本为一组，用 Float32 向量同时求各自的光线、遮挡和 BRDF，最后按原 ix/iz 顺序累加 RGB。球索引仍按原掩码升序，各样本保留原透射累乘顺序。目的为减少内层循环控制和重复球数据访问；不是减采样、拆高光/球影、降低精度或新增光场纹理。向量化可能增加寄存器压力，不能按运算行数预测收益。

SceneKit 世界米：XZ 水平、Y 上，+X 长边／+Z 短边；球心、真实台呢高度、法线、粗糙度和当前视角不替换。保留 near/far 分类、64/8 个有效样本、原有固定灯、PBR 尾部及 H15 剔除。四样本版远区最后两条向量通道不累加，额外算术成本计入计时。

H1–H14 的减采样、分离高光、固定样本几何纹理、球状态系数、资源降采样、半精度、积分重排和台呢剔除继续关闭。木/腿已接入的约 4% 收益不重跑排名。

## 执行与接受

1. R1：两通道／四通道独立候选，小矩阵先核 shader、真实球高及水平相机，再取当前完整生产场景的 GPU 时间。候选不进入默认。
2. AA 与恢复必须零差，初筛最大新增图像误差 ≤1/255；保留全部失败结果，不通过即停止该候选计时。只有收益清楚的候选扩展动态球态、颜色、袋口、相反机位和尺寸验证。
3. 1400×800，三机位，六组 AA/AB，ABBA/BAAB 交替，各臂预热后记录 GPU timestamp、CPU 编码和墙钟，保留逐帧值。约 4% 的稳定收益可以接受，不设机械 5% 卡口；需明显超过 AA 波动、至少五组六组同向，其他机位不得有超噪声退化。
4. 无新增 CPU 每帧准备／上传及纹理资源，仍记录真实 renderer callback/编码；运行准备耗时与持续耗时分列。
5. R1 后只允许有具体证据支撑的修订（最多两轮），不重跑同版选择最好值。无净收益则保留原默认并关闭本路线；有合格候选完成共享接入与必要门禁。

这是原生 iPad-on-Mac 当前 SceneKit 场景实验，不能表述为手机节电、温升或 SwiftUI 整页收益。每轮写入独立记录，最终封存和回收托管临时资源。

## R2 事前修订

R1 两个完整样本向量化候选无净收益，关闭。R2 同属样本带组织，但改为**避免无贡献的逐样本球影求交**：每个 X 样本行（或相邻两行）先根据其灯源平面／两侧平面生成保守球掩码，然后保持原样本和原标量求交、BRDF、累加顺序。不同于 H7 的整盏灯筛选、H11 的 CPU 状态打包，以及 H10 的高光＋球影修正拆分；已有 H9 整盏灯掩码继续作为输入。

只对原 `diagnosticConeEligible` 域启用，域外保留当前掩码；沿用 H9 的滤波圆盘半径、浮点膨胀和球高约束。先用 GPU 原求交式作数值反例检查，再在当前生产场景比较单行与双行带。新的几何筛选不得遗漏任何原有非零遮挡；若有漏判直接淘汰，不以微小画面差掩盖。

## R3 事前修订（本路线最后一轮）

R2 实际画质零差，但新增筛选没有产生净收益。R3 将双行带的四组掩码集中构造：每个候选球只计算一次 U 上界/半径/尺度，再对四组左右平面判定；只有一组 uint4 掩码跨采样循环存活，原标量逐样本算法保留。避免 R2 每一带重复球支持计算及内层额外条件。只测此新版本，不复活 R1/R2。

新轮固定每种计时前预热 120 帧并保留原值；原六组 ABBA/BAAB、正式帧数和不裁剪规则不变。候选必须通过原求交反例预检、真实画质、实际收益后才能扩展；若仍无稳定净收益，本路线结束。
