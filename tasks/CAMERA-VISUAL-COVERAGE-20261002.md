# 两视角相机：截图判断与观察范围

2026-10-02；v1.3专项展开。用户明确要求从用户在各视角/操作下想看、应该看到的内容设计，再以截图判断相机效果。本稿补强[主方案](TWO-VIEW-CAMERA-RENDER-PLAN-20261002.md)与[验收契约](TWO-VIEW-CAMERA-RENDER-ACCEPTANCE-20261002.md)，只分析代码/历史原图与制定标准，未实现新相机、生成新候选截图或启动测试。

## 1. 什么叫观察范围合适

相机应让人完成观看任务，不只让相机节点在房间里、球心落在视锥内。必须分开检查五件事：**内容范围、主体屏幕大小、真实几何遮挡、HUD覆盖、操作过程连续性**。扩大FOV只改变范围/尺寸，不会解除球挡球；退距也受到房间限制。

用户要求截图判断是必过门槛。数学包络用于保证连续域、寻找失败边界；实际完整App截图用来判断模型/HUD/透视与舒适构图；原生手势序列用来判断可达性与运动。三类证据分别留存，不互相代替。

“各种情况”按合法观看域和任务族保证，不能写成任意手动角度下所有球同时无遮挡。**常规受支持场景必须有实际可用3D姿态；缺乏这个姿态是方案缺口，不是通过后的例外。** 用户主动转头离开目标或放大局部，则按其观察意图审查，不强迫镜头维持所有主体同框。

## 2. 先按任务确定必须看什么

设计顺序是**用户要回答的问题 → 必须看懂的信息 → 视角与操作 → 构图/镜头规则 → 截图验收**。第一人称帮助人完成瞄准，第三人称帮助人理解桌面空间与本杆过程，2D帮助人读取全盘平面关系；同一视角内允许任务改变，不为每个任务再增加命名模式。用户不应先学习找机位才能完成常规任务。

| 任务（不是新增3D模式） | 必须保留/可读的内容 | 允许牺牲的内容 | 失败判断 |
|---|---|---|---|
| FP显式进入/回到瞄准 | 母球击球参照、杆轴与前节、本杆目标轮廓及接触侧；有选袋时须能辨认进球方向和真实袋嘴关系 | 桌腿/房间、无关球、全桌全部六袋 | 母/目标无法辨认、杆遮关键接触侧、目标袋只剩旗标而实体不可读；即使中心入框也失败 |
| FP手动转头 | 眼位稳定，转向的局部内容符合输入；明确归正后恢复上述瞄准任务 | 原目标/袋暂离画面、完整杆身 | 不因主动转头丢目标就判失败；若无法可逆转回/归正、被后台夺回则失败 |
| TP全桌观察/初始全局 | 内台面范围、四角与六个真实袋嘴/库边关系、球阵分布；能辨认球而非像素点 | 完整房间、桌腿、远球号码全都正面可读 | 桌角/袋嘴被屏幕或HUD切掉；球阵无法读；未处理真实实体遮挡却称全盘无遮挡 |
| TP本杆标准观察 | 母球、目标球、选中真实袋嘴与必要库/接触参照；能理解本杆关系 | 无关桌角/房间/其他球、整条装饰线 | 关键主体太小、被挡、贴HUD边界；全桌可见不等本杆可读 |
| TP主动近景 | 用户正在看的球/两球/袋嘴局部和必要接触侧清楚；有可逆后退/回标准路径 | 远袋、无关球、全桌 | 允许主动裁切；若放大对象反而离画面、只能看空台呢/地板或回不去则失败 |
| 击球/回放观察 | 事件政策切镜后，碰撞、目标进袋和必要后续落位在所声明任务窗口可读；长距离过程能理解 | 非相关房间、按任务未要求的全部预测轨迹 | 切镜后关键事件持续在画外/被HUD盖住；不能仅展示杆末结果当过程可读 |
| 2D全盘 | 台面/六袋/所有有效球中心与关键标识，路线开关按声明显示，HUD不遮关键主体 | 3D体积/第一人称透视 | 2D用于全盘阅读；2D可用不自动使失败的3D任务通过 |

FP有些极长台/极薄角无法同时做到大目标与清楚袋嘴；“同框”与“能沿转头读到关系”须在W0按任务区分。推荐常规瞄准入口优先母/目标与接触侧，袋嘴允许通过明确、连续的小幅转头查看并归正；TP本杆标准承担两球/袋共同关系。此职责分配尚待裁定，不据此声称已保证用户期待。

若最终要求FP默认入口就同帧读清目标袋，不能以转头或TP另看替代该承诺；应调整FP entry/镜头/构图或明确记录仍未满足。不能借职责分配把用户需要的观察能力悄悄缩小。

每个任务需冻结：必见主体集合、允许裁切、最小可读大小、可接受遮挡、默认入口与最多操作代价。无选袋/自由击球不能拿过期袋口作必见对象；路线多库时定义当前参照，不能承诺全部未来轨迹都同框。

ObservationDomain从真实业务合法球形/杆姿、支持设备/HUD与观看任务独立定义，不能反过来只把当前profile成功输出的姿态称为常规域以排除失败。校准/调参样例与冻结保留样例分开，保留集失败不能事后移出范围。

### 2.1 从用户操作展开设计

“从用户意图设计”已由用户明确要求。下表是具体产品建议，默认入口、操作方向、观察锚点及出杆切镜时机仍待冻结，不能写成已获批准或生产行为。表中的问题同时作为V02/V05截图评审的问题。

| 场景/操作 | 用户此刻想知道 | 画面应提供什么 | 镜头与交互建议/不合格表现 |
|---|---|---|---|
| 进入训练、重开球形 | 球怎么分布，哪些球有机会，哪里有障碍？ | TP全局能读完整内台面、六袋、球群与当前选择；桌面是视觉主体 | 默认入口直接合适；不能先给大量地板、过近球堆或被HUD切掉的桌角，让用户先后退找全桌 |
| 选目标球/袋，判断这一杆 | 我要打哪颗、进哪个袋，两段关系怎样，有没有库或球挡住？ | TP本杆标准能理解母球→目标→真实袋嘴及必要障碍；选择/辅助线按当前开关可辨 | 选择反馈及时，异步推荐不突然转镜；手动视角中的主体若在画外，提供明确“观察本杆”路径，不能暗中抢镜。显式观察入口应直接给合适构图 |
| 从TP切到FP瞄准 | 沿杆看过去，我应该碰目标球的哪一侧？ | 母球击球参照、杆前节和目标接触侧清楚，进球方向可理解；空间方位与前一视角有可辨联系 | 新杆入口沿当前实际杆轴；不能朝错球、把杆当画面主角，或为了避遮挡改变瞄准。袋嘴同帧要求按第2节另冻结 |
| FP左右滑动 | 旁边有什么，袋口/障碍与瞄准线是什么关系？ | 朝用户转向方向展开局部，眼位和击球事实稳定；有明确回到瞄准的办法 | 转头与调瞄准是可区分的操作；放手停在用户方向。转头看不到实体后面的内容时不假称已解除遮挡 |
| TP左右滑动 | 从另一边看，球间距离、库边和袋口关系是不是更清楚？ | 绕桌时同一观察区域有可理解的空间连续性；侧面可用于判断此前的重叠/遮挡 | 保留远近意图与任务关注区域；不能突然绕大圈、变俯视或让关注主体无解释地换到画外。解除遮挡不必在每个中间方位都成立，但可达终点须可读 |
| TP上滑靠近（建议方向） | 这两球怎样接触，薄厚/贴库/袋口细节是什么？ | 已明确关注的球或袋逐步变大，关键轮廓留在可读区域；可裁无关桌面 | 推近不能只把白球放大、让目标/关注袋离开。纯台心轨道做不到时需明确任务构图；在无选中主体的自由探索中不擅自猜球或自动跟球 |
| TP下滑后退（建议方向） | 把细节放回整桌，它与其他球、下一步位置怎样关联？ | 可逆地扩大上下文，最终全局能读球阵；关注对象仍可定位 | 后退不应改观察方位或突然调FOV；不能长时间只得到更多房间、关键区域反而更小且仍没有全桌 |
| 调力度、打点、瞄准参数 | 我的修改影响哪里，方向/击球点和预测怎样改变？ | 当前本杆关系与参数反馈稳定可比；预测只在所选显示开关下出现 | 参数更新不反复重构镜头。打点盘/力度尺不可长期盖住本杆关键主体；隐藏预测时仍能理解实物球袋关系 |
| 点击击球、看回放 | 有没有碰对/进袋，母球去了哪里，为什么成功或失败？ | 可理解的出杆→碰撞→进袋或未进→母球落位过程；远距离和多球结果在声明任务窗口中可读 | 明确出杆观看政策，必要构图应在不遮断事件的窗口建立；不能在碰撞/进袋瞬间大幅转镜或只给杆末图。用户手动观察不被后台事件夺权；保留FP到进袋与提前TP观察的取舍仍待裁定 |
| 球停后准备下一杆、重打 | 最后落位怎样，下一杆在哪；重打是否回到刚才那一杆？ | 停球结果可读，下一杆选择明确；重打恢复与该杆相符的业务状态和观察上下文 | 杆末不无故绕桌；新杆按明确入口更新。不能恢复旧目标、旧选袋或在相同球形上给不可解释的方向跳变 |
| 切2D看线路再回3D | 平面距离/路线怎样，回去还能接着刚才观察吗？ | 2D读清全盘，返回保留有效的3D观察上下文和选择；方向转换有可辨联系 | 同一杆返回不重置成陌生方位；球形已改变则按新上下文处理。2D是独立阅读工具，不能要求用户切2D补救常规3D不可用 |

任务构图必须分清“全局看分布”和“本杆看关系”。全局不必强迫所有远球号码正面清楚；本杆不能只满足全桌边界；主动近景可以舍弃无关主体，但不能舍弃用户正要放大的对象。周边球是否必见取决于它是否构成障碍/结果参照，不等于只保留两个球。

镜头主动改变应有用户能理解的原因：显式模式/观察请求，或已冻结的击球阶段政策。关注区域可以由明确上下文决定并在手动操作期间保持；每次求解完成、选袋推荐、预测更新都重新猜关注点会破坏比较与掌控。跟球并非默认答案：多球运动时单球跟随可能丢掉进袋或母球落位，应先定过程职责再选择运动。

### 2.2 逐图以用户问题验收

评审每个操作的前/中/后画面，先写“用户正在回答什么”，再判：①能否立即找到当前主体；②能否在正常屏幕尺寸读懂所需关系；③该操作是否增加了所需信息；④过程中是否丢失方向或事件；⑤能否用明确操作回到原任务。建议评审记录为`用户问题｜操作与起始上下文｜必读信息｜原图/序列｜能否回答及原因｜缺失/遮挡｜恢复路径｜状态`，数值与截图来源附在其后。

例：近景截图中白球更大、目标袋离屏，若任务是看白球打点可以合适，若任务是看两球袋关系则不合适；TP横滑后实体遮挡解除但关注球落进力度尺下，仍未完成用户任务；回放杆末能看清落位不能证明用户看懂了碰撞。默认入口的常规任务不能靠用户反复绕桌和试错通过，“reachable”只用于明确允许操作完成的观察任务。

## 3. 三种结果，不能混为通过

1. **默认合适 adequate**：标准入口截图满足该任务，用户无需先找机位。
2. **可操作到达 reachable**：标准入口不承担该任务或有自然遮挡，但可沿明确允许的绕桌/进退/转头路径到达经截图确认的合适姿态；记录起终状态、操作数/角度/距离、完整过程和是否容易回到原观察。
3. **确实受限 provenLimited**：冻结的安全/镜头/实体条件中无法满足某要求，给出原因/边界证据，不能仅因算法没找到就宣称几何无解。

常规标准入口承诺的任务只接受adequate；W0明确允许操作完成的任务可接受有证据的reachable。provenLimited要单独登记未满足要求/是否属于开放域，不能作为常规任务PASS。存在独立已知安全姿态能看到主体，而固定轨道到不了，首先判轨道/构图能力不足，不用“受限”掩盖。

2D建议可帮助用户理解全盘，但不能抵消常规TP/FP观察任务失败。对于确实不可同时成立的要求，应在裁定时调整相机规则或任务职责；不能到交付时才删除主体。

## 4. 对固定算法轨道的架构影响

固定轨道是舒适的控制规则，不应提前把世界眼高、FOV、台心、俯角、所有方位的屏幕尺度、两球袋同框全部锁成硬条件。原稿固定H/FOV/台心只是推荐；**观察任务能否成立应先于这些推荐项是否保留**。

建议评估顺序：

- 首先按真实桌/房间与HUD构造基础轨道，检查TP全桌入口及近端可达的本杆范围；视线/俯角随r连续变化，阻尼仍在参数域。
- 若全桌合适但本杆主体偏小，定义标准段/近景段的任务职责，检查同一θ/s路径能否让两球/袋与必要细节兼顾，不能只把s拉到最近就宣布细看成功。
- 如固定台心使靠库/靠角局部越推越跑偏，候选是**显式观察请求时冻结的任务锚点**，仍由θ/s控制；不是跟随每次球位/推荐自动跳中心，也不增加第三个命名视角。是否采用及如何恢复全桌待裁定。
- 若安全退距与画幅冲突，先按资产/viewport确定统一可行profile；需要有界调整H/FOV/注视策略时，整profile/转场连续更新并重新审图，不能在运行时偷偷扩FOV或跳高。
- 遮挡可通过轨道横滑绕到另一个合法方位时，证明这条路径可达且局部截图真的改善；轨道域不存在可读方位时修改观察规则/明确未支持域，不能指望单纯变焦解除遮挡。

这里只分析必要候选，不授权实现任务锚点或自动适配。若保留纯固定台心方案，也须拿实际截图证明其足以完成冻结任务；不能因算法形式简单而降低用途要求。

控制域可继续是两个参数；profile上下文、FP眼位及转场实际视线变化会扩大渲染拟合域。世界V内容仍不随相机变化；空间重建与角压缩精度须按实际新域重新判定，原式退路保留，渲染不能阻止必要观看范围。

## 5. 实际截图怎样判读

有效可视区不是屏幕中央一个固定百分比矩形。取实际viewport减去Safe Area、顶部球库、两侧尺、打点盘、弹层/结果栏的覆盖区域；半透明HUD仍可能破坏关键轮廓和对比，不自动视为无遮挡。

逐截图检查并记录：

- **完整包络**：球面/杆前节、真实袋嘴/jaw/皮革边缘，而非球心/袋旗；背景/桌腿不能抢占主体空间。near clipping破坏轮廓也是失败。
- **可读尺寸**：母/目标投影直径、真实袋嘴屏幕宽度、球间投影间隙；同时记录实际px、pt和scale。目标只有几像素、即使号码渲染正确也可能无法读动作关系。
- **有效轮廓**：检查实体遮挡者、接触侧与袋入口是否可辨；自然库挡球底不能统一判为错误，关键击球轮廓被盖必须判任务失败。截图不支持精确可见面积百分比时不编数字。
- **HUD与边距**：关键轮廓到HUD/屏边的实际余量，覆盖程度、文字/预测线是否搅乱判断；默认入口不能把选中袋嘴放在球库下方。
- **透视与舒适性**：近远球比例、桌面压扁、镜头roll、地面/台面的稳定感；固定世界H不保证屏幕地板稳定，也不能仅靠球径数值评价舒服。
- **状态一致**：球阵/选袋/模式、轨道与实际姿态、HUD开关、视口、相机版本必须与截图元数据对应；一张“漂亮图”不能代表恢复后、转场中或新一杆。

最小可读尺寸应以任务尺度图/实际屏幕1:1观看先校准，再冻结数值。全桌读分布、近景读接触侧和FP瞄准不是同一个阈值；不沿用未经用户确认的7.34pt或任意单一球径作为合格线。原尺寸观看用于评判可读，局部放大用于找遮挡/裁边；放大图不能替代正常屏幕看不清的事实。

## 6. 场景覆盖：先覆盖故障机制

| 场景族 | 必须展开的边界 | 必审任务/截图 |
|---|---|---|
| 常规与长短距离 | 短/中/长台、反向、斜对角、目标近/远、六袋分别 | FP entry、TP标准、远/近及必要转头；不能只测母/目标在桌中央 |
| 角度/库袋 | 直球、薄球、大角度；四库/四角/两中袋，母球和目标分别靠库/袋嘴 | 球关键轮廓、杆前节、真实袋入口与HUD边界 |
| 紧邻/遮挡 | 相贴/极近两球、第三球在视线上、球堆、球与库/皮革 | 两球区分、contact侧、替代方位的可达前后对照；线路没阻挡不等眼睛视线没阻挡 |
| 击球上下文 | 当前选球/选袋、自由/无袋、实际杆姿与高低杆/抬杆、合法失败击球 | 最新业务主体，必要时重新FP entry；不改瞄准来让图好看 |
| 连续控制 | θ接缝与各极端方向、s近/中/远、触界反向、斜滑、纯横/纯纵/零输入 | 路径形状和主体尺度/位置连续；并保原生手势 |
| 生命周期 | 切FP/TP、转场25/50/75%与接管、2D往返、选球/袋后、击球capture/settlement、取消/重打 | 对应原图序列，不只终点；不裁掉异常中间帧 |
| viewport/HUD | 小屏/常用/iPad，支持方向与运行中resize/分屏；打点盘/结果栏/弹层各状态 | 实际完整页面及HUD mask；三个独立静态aspect不能代替A→B恢复 |
| 资产/照明 | 当前8×6房间/风格/桌型、材质反差与真实袋网/回球可见状态 | 暗目标/亮球/皮革边界，墙不能穿或遮主体；旧10×8图只作历史 |

保留确定的失败输入；在规则分支边界做小扰动、镜像、连续区间检查，不堆更多相似中央球形。记录独立布局数、重复视口数、原生页面图数、离屏图数和状态序列数，不能把它们相加宣称任意盘面覆盖。

## 7. 截图包与视觉必过条目

一个场景包至少含：完整原生App原尺寸图（真实HUD）、相同帧的关键区域索引/裁切说明、必要状态filmstrip与原生手势短录屏、manifest、对应CameraFrame/球/袋/轨道/owner/viewport与资产版本。EXIF方向、实际drawable与屏幕scale写明；缩略拼图只作目录。离屏纯SceneKit图标为offscreen，不能冒充整页HUD证据。

| ID | 必过条件 | 失败处理 |
|---|---|---|
| V01 | 新方案真实原生截图来源与manifest一致；原图/模式/上下文/HUD/实际pose可追溯 | 缺新候选/只历史图记UNVERIFIED，不给新方案PASS |
| V02 | 按第2/2.1/2.2节先声明用户问题、操作与必读信息，再审常规任务adequate或允许的reachable | 关键球/袋/参照丢失不能用受限/2D替代通过；默认任务不能靠反复找机位通过 |
| V03 | 任务尺度下球、接触侧与真实袋嘴可读；原尺寸合格，近远比例可接受 | 缩略图/局部放大好看不能抵消正常尺寸不可读 |
| V04 | 关键轮廓/袋入口不被实体或HUD破坏；声明reachable有实际前后图和允许路径 | 中心入框、袋旗可见或理想球路畅通都不足 |
| V05 | 第2.1节操作前/中/后按意图审信息增益、主体范围、空间连续与恢复；近/远/绕桌、转场接管、resize、新杆与击球序列有证据 | 终点图不能抵消中间丢主体/事件/跳镜；异常帧保留 |
| V06 | 第6节矩阵各任务族/分支有证据或明确未验证，常规域无未处理失败；连续安全另有证明 | 不能以截图总量替代遗漏分支/真实布局 |
| V07 | 支持屏幕/HUD/资产profile在实际整页上合适，运行时变更后重新判 | 旧尺寸/无HUD/独立新建viewport不能代表新状态 |
| V08 | 主控独立目视原图/关键序列并逐条写事实，用户审关键手感/视觉后结果单列 | 执行者自评/自动断言不代替截图判断；用户否决后对应项不放行 |

V01–V08作为C05/C06/C09–C11与S04的视觉子契约。W1数值/path准备不勾V；W2相机候选转正须相关V逐项完成；W6再整合画质/性能，不把后续设备能量当相机截图的前置。
