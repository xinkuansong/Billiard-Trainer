## 可信度与记录

- 预期 ID 用 EXP；执行 ID 用 RUN；问题用 QD。来源不明先记“预期待确认”。
- 证据层次：静态规则、内存单元、磁盘/集成、正常 UI、真机/真实服务分别表述。
- 问题分类：产品缺陷 / 测试缺口 / 文档漂移 / 环境限制 / 待确认。影响程度和可信度分开记录。
- 失败先取证，再判断环境或产品；不修改旧断言、不加无限重试。重大问题及时反馈，不自动修复。
- 非产品缺陷不写成已确认产品 Bug；诊断台账作为总索引，确认的严重产品缺陷再按仓库规则关联失败记录。
- 子任务输出由主控复核；当前资料子任务为 expectations，输出 EXPECTATIONS.md，禁止运行测试或修改产品。
- 完成不要求零失败，但要求覆盖承诺已落实，无法验证项说明原因、影响和可执行补测条件。
