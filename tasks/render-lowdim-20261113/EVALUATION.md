# 通用性能评价口径

2026-11-13 用户明确：单台真机的型号、电池状态有自身差异，不作为方案好坏的主判断标准。此文件更新 handoff 中初始设备/FPS/温升门槛的使用方式；原 handoff 原件保持不改。

## 比较对象

同一构建、同一实际场景、相同相机/球态/材质、相同分辨率/MSAA/HDR 下配对比较当前正式 R 与候选。结果报告硬件/系统/编译配置，不能把不同设备的绝对毫秒直接排序，也不能把某台机器的相对收益视为硬件无关定理。

## 主评价

1. **结果正确和画质保持**：生产 shader 生成核心对拍、真实材质/生产场景同输入图像、连续移动与边界；明确数值等价、最大/分位像素差及可见变化。不能用全图均值掩盖近球局部问题。
2. **完整成本**：CPU 准备/提交，GPU 生成/消费/额外 pass，传输和同步分别实测。完整场景、完整页面再独立计量。不能把并行 CPU/GPU 时间简单相加或用 command span 倒数冒充 FPS。
3. **规模曲线**：改变像素数、2/8/16球、全台/近球/台边视角、静止/镜头运动/球运动，说明成本随规模如何变化。空场、单/少球以及收益最差场景同样保留；不只测高负载。
4. **稳定性**：配对 A/B/B/A 与 B/A/A/B、合理预热、报告原始值、P50/P95/P99与基线漂移。短时微小变化低于测量波动时写“没有可靠净收益”。重复输入仅用于机制或放大计时，不称屏幕分辨率。
5. **资源与更新复杂度**：新增实际 GPU 分配、CPU内存、读写量、生成频率、缓存失效、同帧状态版本、首次进入与生命周期。算法检查次数用于解释收益来源，不替代硬件时间。
6. **可推广性**：有条件时在不同 GPU/性能档、系统和设备做同场景配对复验。仍只在单一硬件取得的结论明确标为局部证据。固定场景与可复现输入使后续设备结果可比较。

初始 118 FPS / 9ms、20分钟温升等保留为特定120Hz使用场景的体验目标，**不再作为单台手机决定算法优劣的主闸门**。不同刷新率使用各自帧预算；温升、电池、亮度、充电与初始状态是设备实验条件和补充证据，不用它们单独决定算法排名。

## 当前阶段的解释边界

- Apple M5 Pro 独立数学 compute：验证公式、数据布局、固定输入下的成本及扩展性。
- macOS 原生真实 USDZ/SceneKit：验证台呢实际纹理过滤、法线、材质组合和冻结/运动画质；原生Metal校准通过后，M5 Pro/M4用同冻结包比较完整台呢材质的GPU、CPU和显式目标资源。隔离场景没有完整生产球房、球反射和SwiftUI页面，不能把此层净收益外推整页。
- iOS Simulator 的生产场景：验证真实 App 场景接线、资产、相机和完整渲染程序。GPU timestamp/allocatedSize不作性能或内存排名：本轮出现像素数4倍而GPU span近乎不变、allocatedSize为0的现象，且[Apple明确说明Simulator的性能测量限制](https://developer.apple.com/documentation/metal/developing-metal-apps-that-run-in-simulator)。同步render调用及指定CB等待的墙钟仅作该宿主流程观察，不升格为真实GPU/整页结论。
- 原生 iPad-on-Mac 的生产固定场景：r9已真实运行完整App测试宿主、GPU校准和完整球房/真实球材质的同输入对照。允许报告本Mac固定场景GPU/CPU编码与同步等待，不代表SwiftUI页面、实际呈现或移动设备；两臂共用R probe，首编与guard probe生成成本另验。
- 完整 SwiftUI 页面：验证应用调度、交互/计算与渲染叠加成本。
- 不同实体设备：补充实际呈现和持续运行证据，不能替代上面的可复现因果对照。

当前用户表示手机暂不方便，继续其余验证；不因此停止数学、画质、完整场景及规模矩阵工作，也不把未测真机写成通过。

“通用标准”指相同输入、清楚的成本范围、跨规模/跨硬件可复现，**不等于不用真实硬件测量**。没有可用手机时，使用Mac原生Metal/SceneKit直接硬件验证数学与材质计算；模拟器仍承担生产接线和功能验证。不同证据层级不相互代替。
