## 1. 目标与成功定义

### 1.1 产品目标

保持用户目前看到的效果：

- 球缘圆滑、球号清晰，球杆与教学线条清楚。
- 球与台面、库边、袋口之间的空间关系可信。
- 阴影方向、半影、重叠和进袋过渡稳定。
- 相机运动时，高光与反射正确变化。
- 球位、旋转、球号、相机和教学标注同步。
- 长时间训练中的实际呈现节奏、输入响应和温感可接受。

### 1.2 工程目标

减少不必要的重复工作，同时考虑：

- 当前完整页面的 CPU 更新/提交、GPU 工作和等待。
- 真实屏幕呈现间隔与输入到可见响应。
- 静球观察、持续瞄准、真实击球和多视图的实际成本。
- 冷启动、可交互时间、GPU 资源、进程内存与生命周期。
- 持续能耗与温升，而非只有短时峰值。

### 1.3 不能预设的结论

- 稳定 120 FPS 与低温升是待验证目标，不是必然可兼得的前提。
- SceneKit 不是已证明的主要瓶颈；Metal 本身不是提速保证。
- 64 通道不是已证明的最佳表示。
- 更少通道、算式、三角形或包体，不自动等于更低整页成本。
- 使用新的近似算法，不自动等于保持现有画质。
- 该方案追求较高潜在上限，但没有证据承诺全 App 提速倍数。

## 2. 必须保留的约束

1. **保留物理与真实时间。**不修改求解精度、碰撞行为、轨迹、训练判定；不重复显示 60 Hz 球态来伪装 120 Hz 真实运动。
2. **保留当前画质合同。**原生输出尺寸、4×MSAA、HDR/曝光/色调映射、法线与粗糙度响应保持可比较；改变这些参数只能作为明确标识的诊断或独立画质档位。
3. **保留当前 R 基线和可切换后端。**实验初期通过显式开关进入，默认生产行为保持可回退；无有效候选数据时用当前球态直接求值。
4. **球体与球影同帧一致。**不允许旧影场与新球位混用，不允许以隔帧影子更新偷换要求。
5. **保持相机和交互。**不借优化恢复被否决的相机行为，也不改变瞄准、拖球、过渡、球杆和教学标注含义。
6. **相同输入比较。**同球态、同相机、同实际输出尺寸、同 MSAA、同曝光和同材质配置。
7. **计算总成本。**计入生成、采样、剩余着色、回退、同步、额外 pass、CPU 与资源管理。
8. **不制造额外后台负担。**A/B 对照时不要让两套主渲染后端同时持续运行。静止停绘、无窗口/后台暂停和退出释放必须保持。
9. **有界资源。**缓存、纹理、预热和异步任务必须有所有权、版本和释放规则。
10. **区分严格等价与视觉等价。**代数重排、空间插值、量化、低秩拟合和滤波不是同一种误差；未经实际画质验证，不写“无损”。

## 4. 推荐架构：三个决策分别验证

以下三件事应独立作出判断：

1. **依赖分层是否成立。**
2. **使用什么光照/遮挡表示。**
3. **需要多少 Metal 与宿主控制权。**

### 4.1 四层依赖可以保留

| 层 | 主要内容 | 何时变化 |
| --- | --- | --- |
| 静态照明资源 | 固定房间、灯几何、反射资源、无影照明和基底/LUT | 对应配置改变 |
| 空间遮挡/照明 | 球态对接收面的联合遮挡或照明系数 | 球遮挡状态、灯几何、接收面或表示规则改变 |
| 视角材质 | 法线、粗糙度、视线、纹理及空间数据组合 | 当前有效可见帧 |
| 投影与合成 | 几何覆盖、相机、深度、MSAA、HDR、UI 合成 | 当前视图可见内容改变 |

它是依赖图，不要求每帧固定执行四个 pass，也不要求先建立庞大状态框架。

### 4.2 SceneKit 与 Metal 的职责

| 能力 | 建议承担方 | 边界 |
| --- | --- | --- |
| 已有模型、场景、相机和动画 | 初期保留 SceneKit | 不顺带更换物理或改写全部资源系统 |
| 动态空间数据生成 | Metal Compute | 精度、通道、更新区域和布局由算法决定 |
| 台呢光照消费 | 现有 modifier 或必要时局部 SCNProgram | SCNProgram 接管该对象 vertex/fragment，需补齐有用效果 |
| 外部帧时序与 present | 需要时采用 SCNRenderer + MTKView | 不等于能删除/合并 SceneKit 内部全部 pass |
| 其他成熟材质 | 初期保持现有实现 | R、房间和其他材质不随台呢实验无依据重写 |
| 全部原生 Metal 绘制 | 后续基于剩余瓶颈决定 | 控制范围最大，不等于已经证明收益最大 |

MTLTexture 可以作为 SceneKit 材质内容；具体数组纹理、atlas 和自定义参数绑定仍需原型验证。使用同一兼容 Metal device 及明确的资源生命周期，避免逐帧 GPU→CPU→GPU 搬运。

SCNProgram 不会自动消除整个场景的 HDR、MSAA、后处理或其他材质成本。SCNRenderer 接受 command buffer/pass descriptor，也不意味着内部编码完全由我们控制。

## 5. 高上限主候选：低维光照表示

### 5.1 要减少的是计算，不只是存储

当前逐方向贡献可以概括为：

~~~text
L(x, n, v, r, B) = Σ_j W_j(x, n, v, r) · V_j(x, B)
~~~

目标候选：

~~~text
C_k(x, B) = Σ_j b_kj(x) · V_j(x, B)
L(x, n, v, r, B) ≈ Σ_k a_k(x, n, v, r) · C_k(x, B)
~~~

其中：

- x：接收点；B：球遮挡状态。
- n/v/r：当前法线、视线、粗糙度。
- j：现有离散灯方向；k：压缩后的基底。
- C 随球态更新；a 必须能以较低成本根据当前材质/视角求值。
- K 应显著小于参考方向数量；每灯 K=2/4/8 等只作候选测试，不预定足够。
- b 可能随空间位置变化，其静态存储、插值和生成开销也必须计入。
- 以上为研究表达，不是已经验证的生产公式。

**禁止的“假成功”：**

- 只把 64 分量压成 K 分量，却在消费端重新展开并做全部方向 BRDF。
- 为求 a_k 先计算全部 W_j，再执行投影，导致主要成本没有消失。
- 只报告离线 SVD 压缩率/平均 PSNR，不实现并测量廉价消费路径。
- 拟合范围缩小后，仍宣称覆盖全部产品视角和材质。

每个候选必须交付：生成方式、廉价消费方式、精确/近似边界、失效判定、回退方式和完整成本。

### 5.2 漫反射方向矩：可验证的条件分解

若每灯采样权重能写成 a_j(x)·max(n·l_j,0)，且所有相关灯方向都位于当前法线上半球，则：

~~~text
M_V(x) = Σ_j a_j(x) · V_j(x) · l_j(x)
D_V(x,n) = n · M_V(x)
D_final = D_analytic(x,n) · (n·M_V)/(n·M_0)
~~~

需核实真实 shader 的权重、clamp、归一化、epsilon 和法线依赖。灯方向跨越法线地平线或存在其他非线性项时，不得宣称该分解严格成立。

两灯按两张 RGBA16F 存储，256×128 时约 0.5 MiB，但这不证明性能收益。若高光仍逐方向重算 visibility，可能完全没有移走主要遮挡成本。

### 5.3 高光必须独立证明

- 平均 visibility × 无影高光，通常不等于逐方向加权高光。
- 多个球的平均阴影相乘，通常不等于联合方向遮挡后再积分。
- GGX 的低粗糙度、掠射角、细法线和阴影交叠是重点反例。
- 可探索适合实际台呢范围的低秩/基底响应或解析积分加局部修正。
- LTC 简化无影面积灯积分，不自动解决方向相关遮挡；它也是需验收的近似。
- 低频球谐动态遮挡有研究基础，但不能直接套用到所有矩形灯、近景和高光。
- 对不能准确表示的区域或状态，可局部提高精度或回退；若大量回退使收益消失，否决该候选。
- 球面的 R 已有专门预过滤，本阶段不把台呢的低维表示强行套到所有球材质。

### 5.4 离线验证要求

- 使用实际 shader 权重与允许的产品参数范围，不用另一套方便测试的近似替代参考。
- 按完整球局、运动轨迹和相机路径留出验证集；避免相邻像素随机拆分造成泄漏。
- 覆盖近景、低位、法线扰动、粗糙度边界、密集球架、散台、影子交叠、贴库、袋口与进袋过渡。
- 分别报告漫反射、高光、线性输出和最终显示输出误差。
- 同时报均值、高分位和最坏区域；球脚/半影/高光应单独统计，不能被大面积平坦背景稀释。
- 检查动态稳定性：闪烁、阴影滞后、边缘爬动、亮度跳变。
- 说明基底、系数精度、参数范围、静态资源大小与预计运行时求值方式。
- 离线通过只允许进入 GPU 原型，不等于整页性能或画质验收通过。

## 6. 保守对照：64 通道空间可见度场

### 6.1 合理性与边界

它保存当前两盏灯合计 64 个近档样本的 visibility，保留方向信息；它主要移走球遮挡，不会自动移走 64 方向材质积分。

可以先做冻结球态的消费对照，验证最有利状态下的空间精度和读取成本；不要为了这个对照先完成整套每帧宿主迁移。

### 6.2 资源与精度

| 字段 | 单份基础数据 | 双份 | 三份 |
| --- | ---: | ---: | ---: |
| 256×128×64 FP16 | 4 MiB | 8 MiB | 12 MiB |
| 512×256×64 FP16 | 16 MiB | 32 MiB | 48 MiB |

- 约 2.54×1.27 m 台面上，256×128 格距约 10 mm；不能预设近景足够。
- 最终软影平滑，不代表每个方向的 visibility 边界也同样平滑。
- 64 个 FP16 值每位置为 128 字节；典型四通道布局需多次采样，不是一次 texture sample。
- 逻辑读取量不等于实际 DRAM 带宽，应看真实纹理访问、缓存、占用和时间。
- 对比空间插值与 FP16 量化误差；不要把几何运算也随意改成低精度。
- 软化 visibility 不能直接当作 64 个布尔位压缩。
- 灯样本索引是离散通道，不能沿通道轴做普通空间插值。
- 使用 atlas 时防止通道间过滤串色；纹理布局和采样方式需单独验证。

### 6.3 必须保留的语义

- 原近档 64 与远档 8 的选择条件；不得随意把 64 平均为 8。
- 支持域边界、灯样本足迹和过滤方式。
- 多球联合可见度。
- 只覆盖几何确认合法的平面接收面。
- 袋口、折面、库顶、不同高度和无效映射必须直接回退。
- 插值邻域也必须合法；不能只检查中心 texel。
- 回退比例按实际可见片元/工作量统计，不只按台面面积。
- 脏区包含旧/新影响范围及过滤邻域；重叠区联合重算。
- 失效区域恢复正确的无挡值或明确标为无效，不能残留旧影。

核实过滤中是否有 fwidth、ddx/ddy、屏幕足迹或其他相机依赖。物理遮挡不随相机变化，不保证已有过滤结果或缓存精度需求也完全相机无关。

## 7. 低风险补充路线与回退策略

### 7.1 静球缓存、动球直接求值

这是可独立交付的过渡路线：

- 球遮挡状态稳定且存在持续观察需求时，生成不可变空间结果。
- 生成结束且版本仍匹配，才安装使用。
- 球态变化立即采用当前快照的直接求值，不能继续消费旧场。
- 缓存未完成、生成失败或精度不足，使用直接路径。
- 完全静止继续停绘，不为了缓存本身增加无用更新。
- 缓存/直接路径切换需要验证无可见亮度或阴影跳变。

它主要改善静球观察，不能替代持续运动阶段验证。

### 7.2 空间候选球表

若实测支持域/候选构造占比值得处理，可按台面分块生成保守候选球集合：

- 缓存“可能影响这里的球”，片元仍用当前公式。
- 每格每灯一个 uint32 时，256×128 两灯基础数据约 256 KiB。
- mask 使用整数读取，不做线性插值。
- 片元仍精确判断候选与近远档，不能整格一律改为近档。
- 超过容量的球仍正确处理。
- 它是加速结构，不是空间阴影结果复用，不得冒充 64 场已完成。

### 7.3 接触 AO

无限尾部只否定随意截成小圆斑，不否定全域标量缓存或低频全域加近场修正。256×128 R16F 基础容量约 64 KiB，但仍须验证近球精度与总收益。历史消融收益较小，不应自动升级为主方向。

## 8. 状态更新合同

| 状态/变化 | 空间光照/遮挡 | 视角着色与投影 |
| --- | --- | --- |
| 球中心/高度/有效性不变，只有相机移动 | 物理结果可复用；精度需求可能变化 | 必须按当前视角更新 |
| 球只自转 | 理想球形遮挡不变 | 球号、纹理、姿态变化 |
| 相机固定，球移动 | 更新影响区域或直接求值 | 球及其影响的画面变化 |
| 球和相机同时移动 | 与当前球态同版本 | 每视图按当前相机更新 |
| 全部静止 | 不无故生成 | 保持按需停绘 |
| 增加第二视图 | 同世界状态可共享 | 各视图独立判断是否需要绘制 |
| 灯几何/样本布置变化 | 失效 | 更新 |
| 仅灯强度/颜色变化 | 纯几何 visibility 原则上可复用 | 权重变化；照明系数场是否失效取决于其含义 |
| 仅材质颜色/粗糙度变化 | 几何 visibility 原则上可复用 | 重建参数变化；若系数已混入材质则需失效 |
| 接收面或映射变化 | 失效 | 更新 |

球杆、教学节点、透明过渡、UI 和布局有独立依赖，不可仅靠球心是否变化决定整页活动。

## 9. 同帧调度与资源生命周期

### 9.1 目标顺序

~~~text
确定本帧时间
  → 推进 SceneKit 动作/动画/约束一次
  → 冻结最终 presentation 的不可变球态快照
  → Metal 生成或复用同版本空间数据
  → 主视图及其他需要更新的视图消费该版本
  → present
  → 所有 GPU 消费者完成后才允许复用相关资源
~~~

### 9.2 版本内容

至少明确：

- 球遮挡状态版本：中心、高度、半径、显隐、有效遮挡权重等。
- 灯几何、采样布局及过滤约定版本。
- 接收面几何、坐标映射和有效区版本。
- 表示格式、分辨率、基底/LUT 与算法版本。
- 已混入结果的材质或光照参数版本。

不要把所有 UI/相机变化都粗暴并入一个全局 dirty 标志；也不要遗漏实际影响结果的配置。

### 9.3 API 与同步注意事项

- SCNRenderer 的 render(atTime:viewport:commandBuffer:passDescriptor:) 会更新 presentation 后再绘制。
- 若先使用 update(atTime:)，应核实后续采用不再推进时间的绘制路径，记录 customAction、约束与回调次数。
- 当前更新位于 didApplyAnimations，并不自动证明已有一帧滞后；需检查约束、父节点变换和实际时序。
- 多视图共享同一快照，不在每个视图中重复推进同一套球动作。
- 传入同一 command buffer 不是万能正确性证明；资源 hazard、跨队列依赖及在途缓冲需明确。
- 不用每帧 CPU waitUntilCompleted() 作为常规同步方式。
- 不能随意结束 SceneKit 当前 encoder 来插入 compute。
- 双/三缓冲只解决生命周期，不允许用旧版本影子换取流水线顺畅。
- GPU 结果留在纹理/缓冲中，不为调度方便逐帧读回 CPU。
- 退出、切样式、后台、内存警告后，过期异步结果不得安装。
- 取消 CPU 任务不等于已提交 GPU 工作结束；资源释放必须尊重所有消费者。
- 跨帧缓存需要持久化存储；tile memory 仅优化适合留在单帧/单 pass 内的临时数据，不等于缓存零显存。

## 10. 分阶段实施与具体交付

阶段用于形成可比较结果，不是新增审批流程。满足前提后自主继续；失败则调整或结束该候选，不反复询问是否继续常规工作。

### P0：核实当前实现与建立最小基线

**实施：**

1. 读取适用 AGENTS.md，记录 HEAD、工作区差异和相关资源身份，不覆盖已有工作。
2. 跟踪正式每日/训练页面，确认实际 profile、R 安装/回退、最终 shader、视图尺寸和 AA/HDR。
3. 核实台呢采样、过滤、材质组合、接收面范围和当前球态更新时点。
4. 为几个代表状态建立可复现脚本、录制或固定输入。
5. 有设备时采集最短足以定位的整页 trace 与代表 GPU capture；无设备时准备采集入口和说明，继续代码与离线工作。

**交付：**

- 当前事实、与报告差异、复现配置。
- 最终生成 shader 与配置记录。
- 能区分候选筛选、遮挡、剩余 BRDF、其他 pass、CPU/合成的最小证据；不要求先全面扫全仓。

### P1：建立参考入口与验证低维表示

**实施：**

1. 从真实最终 shader 复用或提取参考计算，防止另写一个数学上不同的“参考”。
2. 输出方向 visibility、漫反射、高光、线性结果及同一显示变换后的结果。
3. 验证一个有明确廉价消费方式的低维候选。
4. 如有必要，制作冻结球态的 64 通道消费对照，分离空间插值与表示压缩的问题。
5. 建立留出球局/相机路径和高风险画质场景。

**交付：**

- 可运行的参考和候选代码、固定输入与复现命令。
- 系数生成/消费方式及复杂度、资产和内存估算。
- 最坏场景与连续片段，而不只平均误差。
- 继续低维路线、调整表示或明确否决的结论。

**门槛：**离线画质与廉价消费逻辑成立，才继续扩大该表示的 GPU 工程；失败不意味着暂停所有工作，可转最有依据的保守路线。

### P2：最小 GPU 候选与受控宿主

选择能获得第一份有效证据的最小范围。冻结场消费不依赖整套新宿主；动态同帧生成确有需要时再接受控宿主。

可使用的对照标识：

| 标识 | 配置 | 回答的问题 |
| --- | --- | --- |
| A | 当前 SCNView + 当前 R/台呢算法 | 正式基线 |
| B | SCNRenderer + MTKView + 原算法 | 宿主改造是否等价及其自身成本 |
| C | B 或适用的最小宿主 + 64 通道场 | 空间复用净收益及精度 |
| D | B 或适用的最小宿主 + 低维系数/专用材质 | 进一步压缩积分是否划算 |

C 是按需要保留的对照，不要求一次实现四个完整生产后端。

**实施：**

- 新宿主首先用旧算法校验输出、实际尺寸、4×MSAA、HDR/曝光、动画推进、交互与停绘。
- 初期 shader modifier 可以消费所需结果时不强制更换；确需完整材质控制时使用局部 SCNProgram。
- SCNProgram 先准确保留有效材质贡献，再评价剩余成本，避免直接删 PBR 导致变暗。
- 对真实动态球态，实现生成/消费版本匹配和直接回退。
- 测生成、读取、剩余着色、回退和同步的完整成本。

**交付：**

- 候选开关和明确默认值。
- 代表场景画质、版本一致性与 GPU/CPU 成本对照。
- 实际资源占用、更新 texel/区域、候选球数量、近远档和回退工作量。
- 保留或否决结论。

### P3：完整页面、多视图与生命周期

**实施：**

- 接入每日清台/代表性正式教学页，而不止独立宿主。
- 保留真实瞄准预测、回放、球杆、相机过渡、标注和 HUD。
- 区分实时俯视与图片覆盖分支，验证共享版本和独立失效。
- 清理确实无效的 HUD/视图刷新，但不降低可见交互更新频率。
- 主视图 120 与 HUD 自己的频率分别报告。
- 处理样式切换、退出/重进、后台和内存压力。
- 性能对照时只运行需要的后端，不让另一套后台持续绘制。

### P4：持续、资源与可发布条件验收

按照第 12 节完成持续与生命周期验证。通过之前，不将实验路径的短测结果称为生产达标。

如果设备、工具或条件不可用，保留可运行候选及详细复现方式，明确未验项，不用模拟器替代真机热结论。

### 后续：是否继续全 Metal 绘制

只有当混合方案后，SceneKit 剩余场景处理、提交或内部 pass 仍是实测关键限制，才扩大绘制职责迁移。给出要消除的具体工作、预期收益机制及新增维护范围；不以“全原生一定更快”为依据。

## 11. 画质与时序测试矩阵

| 场景 | 检查重点 |
| --- | --- |
| 静球，全桌转镜头 | 空间结果不随相机无故重建；高光正确变化 |
| 静球，低位/近距离 | 格距、阴影边界、掠射高光、细法线响应 |
| 固定相机，单球真实运动 | 影子与球同帧、旧影清除、纹理/球号姿态 |

| 密集球架 | 多球遮挡组合、候选数量和更新成本 |
| 散台 | 支持域范围、局部更新有效性 |
| 两球影子交叠 | 方向相关性、联合遮挡，避免灰度相乘错误 |
| 贴库/袋口/非平面区域 | 有效区、插值邻域、回退接缝 |
| 进袋高度/透明度/显隐变化 | 状态版本、权重过渡、无残影 |

画质资料应含相同输入下的基线、候选、差异图和连续片段。整体平均误差不能覆盖高风险局部失败。

## 12. 测量口径与原有待验收目标

### 12.1 指标分开报告

至少区分：

1. 用户请求帧率。
2. display link 回调。
3. SceneKit render 回调。
4. GPU 命令跨度、encoder/stage 成本和等待。
5. 实际屏幕呈现间隔。
6. 输入到可见响应。

不对 GPU 命令跨度取倒数当 FPS，不把并行 CPU/GPU 项简单相加，不把消融差值拼成精确占比。

GPU 捕获用于定位；持续验证需看完整页面和实际呈现。使用清晰标签/阶段标记，并保留测试配置与时间范围。

### 12.2 每个候选至少记录

- 源码状态、资源、设备/系统、构建优化和最终配置。
- 实际像素尺寸、MSAA、HDR/曝光与后端。
- 球态/场版本、生成次数、更新范围、回退比例。
- CPU 更新/提交、GPU 生成/消费及完整帧相关工作。
- 实际呈现间隔分布、长帧和连续失约。
- GPU 资源大小、进程内存、冷启动与首次可交互。
- 热状态、运行顺序、初始条件及充电情况。
- 当轮画质缺陷和已知限制。

### 12.3 沿用原方案目标，不能当成已有成绩

在支持 120 Hz、用户选择 120、测试起始条件允许的设备上，对有效活动区间评估：

| 类别 | 原方案的待验门槛/约束 |
| --- | --- |
| 实际呈现 | 平均至少 118 FPS；间隔 P95≤9 ms；超过 12.5 ms 比例≤1%；另报 P99、最长帧和连续失约 |
| 内部余量 | GPU P95≤6 ms、P99≤7.5 ms；CPU 更新提交 P95≤3 ms；先明确采样定义，不拿任意命令跨度套门槛，不相加推 FPS |
| 持续 | 20 分钟代表性训练；末 5 分钟动态仍满足；未充电、条件可比；无明显烫手感，不进入 Serious/Critical |
| 资源 | 新增资产≤8 MiB；新增 GPU 纹理/目标≤16 MiB；暖机进程内存增量≤32 MiB 且≤基线 10% |
| 冷路径 | 进入可交互 P95 增量≤100 ms |
| 生命周期 | 进入退出 20 次；稳定后末 5 次无阶梯增长；缓存持有与泄漏分别判定 |

- 原门槛需要当前版本重新验证；若表示需要突破预算，明确报告取舍，不能静默改标准。
- 先做同为 60 FPS 的能耗/温升比较，再验证 120，避免帧数变化混淆节省。
- A/B 顺序交错，恢复可比初始热条件；相同 Nominal 标签不代表相同内部温度。
- 固定环境、亮度、机壳与可控后台条件，记录无法控制的因素。
- 压力脚本与包含思考停顿的实际训练脚本分别报告。
- 正常空闲停绘不计为活动帧率失败；因自身负载热保护降到 60，则是对应持续 120 目标未通过，不能从结果中剔除。
- 出现严重发热时停止当轮测试，保存已取得的数据并记录失败；不为凑满 20 分钟继续施加负载，也不以降帧后的结果冒充原持续目标通过。
- 回调很密、重复旧画面、降低球态/阴影频率或帧插值，不能代替真实有效运动帧验收。
- 温感评价保留可比记录；有条件记录客观温度/能耗，不编造未测瓦数或温度。
- 未完成真机长测，结论只能是候选或短测结果。

## 13. 明确的继续与停止条件

以下条件按阶段适用，不是 P1/P2 必须一次满足的前置门槛：离线候选进入 GPU 原型，检查数学/画质可行性与廉价消费方式；GPU 原型进入完整页面，检查局部净收益、时序与接入风险；候选转为正式默认，才要求完整页面持续表现、资源和生命周期全部验收。接入完整页面是取得整页证据的一部分，不能反过来要求先取得整页证据才允许接入。

### 支持继续扩大当前候选

- 画质与时序在产品允许范围内通过。
- 最有利状态和代表性真实使用均有超过测量波动的净收益。
- 动球阶段生成和同步成本可接受。
- 多视图确实共享一次空间结果。
- 同帧版本正确，回退不会产生可见切换。
- 内存、准备时间和生命周期满足约束。
- 完整页面持续结果改善，而不只独立宿主或单 kernel 改善。

### 应停止扩大当前候选

- 静球转镜头这一最有利状态都没有稳定净收益。
- 所需秩接近原方向数，或廉价消费方式无法成立。
- 可接受画质需要更高空间精度/大量回退，导致总成本不优。
- 球脚、贴库、低位高光等关键位置持续失败。
- compute、纹理读取、同步或新增 pass 抵消节省。
- 动态球与影场版本无法可靠匹配。
- 合格配置突破资源/冷启动/持续预算。
- 实测主要瓶颈在其他系统，该候选对目标没有足够贡献。

“停止”指不继续扩大失败路线：保存代码、数据和反证，回到直接路径或已定义的更小候选。不要为了维护方案而缩小测试范围、放宽画质或隐藏回退。


## 17. 一手资料与适用边界

以下资料支持技术原理和 API 能力，不证明本项目已有收益。实现时核对当前 SDK、设备支持和实际捕获结果。

### Apple 官方

1. [SCNProgram](https://developer.apple.com/documentation/scenekit/scnprogram)：替换指定材质/几何的 shader。
2. [SCNShadable](https://developer.apple.com/documentation/scenekit/scnshadable)：program 与 shader modifier 的区别。
3. [SCNMaterialProperty.contents](https://developer.apple.com/documentation/scenekit/scnmaterialproperty/contents)：MTLTexture 等材质输入。
4. [SCNRenderer](https://developer.apple.com/documentation/scenekit/scnrenderer)：嵌入 Metal 工作流、update 和绘制入口。
5. [带时间的 render 接口](https://developer.apple.com/documentation/scenekit/scnrenderer/render%28attime%3Aviewport%3Acommandbuffer%3Apassdescriptor%3A%29)：会按时间更新 presentation 后绘制。
6. [Apple GPU 与 TBDR](https://developer.apple.com/documentation/metal/tailor-your-apps-for-apple-gpus-and-tile-based-deferred-rendering)：tile memory、imageblocks、tile shaders 和带宽。
7. [Optimizing GPU performance](https://developer.apple.com/documentation/xcode/optimizing-gpu-performance)：并行时间轴、计数器与 shader 定位。
8. [Understanding Metal Performance HUD metrics](https://developer.apple.com/documentation/xcode/understanding-metal-performance-hud-metrics)：GPU time、on-glass frame interval、present delay 等定义。
9. [MTLDrawable.addPresentedHandler](https://developer.apple.com/documentation/metal/mtldrawable/addpresentedhandler%28_%3A%29)：实际呈现时间。
10. [MPSImage](https://developer.apple.com/documentation/metalperformanceshaders/mpsimage)：多通道数据按纹理切片组织；引用存储原理，不要求引入 MPS。
11. [Optimize Metal Performance for Apple silicon Macs](https://developer.apple.com/videos/play/wwdc2020/10632/)：pass/附件存取、MSAA、寄存器等；应用到目标设备时仍需实测。

### 原始研究

12. [Decoupled Sampling for Graphics Pipelines](https://people.csail.mit.edu/jrk/decoupledsampling/)：几何覆盖采样与着色采样解耦；不能直接套用其场景收益。
13. [Combining Analytic Direct Illumination and Stochastic Shadows](https://eheitzresearch.wordpress.com/705-2/)：无影照明与照明加权阴影的分解，区别于平均灰度 visibility。
14. [Real-Time Polygonal-Light Shading with Linearly Transformed Cosines](https://eheitzresearch.wordpress.com/415-2/)：LTC 的近似与面积灯积分；不自动解决球遮挡。
15. [Real-Time Soft Shadows in Dynamic Scenes Using Spherical Harmonic Exponentiation](https://www.microsoft.com/en-us/research/publication/real-time-soft-shadows-in-dynamic-scenes-using-spherical-harmonic-exponentiation-2/)：低频光源下的动态球体遮挡表示；不保证适合全部高光和近景。
16. [Clustered Principal Components for Precomputed Radiance Transfer](https://www.microsoft.com/en-us/research/publication/clustered-principal-components-precomputed-radiance-transfer/)：低维传输表示与计算顺序；本项目需独立验证其适用范围。
