2026-09-21。用户授权开始实现，保持画质、物理精度与活动帧率。当前角色 Orchestrator / SwiftUI Developer / Test Engineer。使用 principled-engineering，先验证根因、再改变生产行为；手机不参与本轮负载。

## 已确认的根因与首项修复

AngleSceneView 已使静止 SCNView 停止播放，但 CADisplayLink 仍按静止策略约30Hz运行。每次做活动检查、场景树动作遍历、FPS/视口与标签检查。它不是静止GPU重绘，而是残留的CPU轮询，不能拿它解释所有击球发热。

Coordinator 现在在显式静止且动作/过渡/阻尼结束时暂停 display link；手势、内容活动、视口改变仍同步唤醒。FrameDelegate 对休眠期间的真实 SceneKit 重绘通知做线程安全合并，主线程重新检查活动、更新视口与标签，故直接启动SCNAction无需依赖SwiftUI发布。nil活动状态的旧调用方保留原连续更新语义。活动FPS、采样、MSAA、着色、物理不变；停止/销毁清通知与display link。静止HUD在状态切换时更新，避免为刷新FPS维持定时器。

新增测试确认：休眠窗口回调不增长；可见球动画、无几何节点动画都能从休眠完成；视图改尺寸能更新cameraRig；显式播放同步唤醒。已有阻尼、动作、FPS不自激活和帧率政策继续回归。同一模拟器夹具旧路径1.016秒31次回调，新路径1秒0次；这只证明消除该轮询，不是整机CPU下降100%或温升已解决。

证据：build/daily-event-driven-20260921/。candidate-full.log为首次测试编译失败（Swift选择async runAction重载，已显式completionHandler修正）；candidate2-full.log 1测试通过；regression26-full.log 4测试0失败18.968秒；regression17-full.log 5测试0失败23.403秒。最终页面/复验结果见后续追加。

## GPU复用方案的关键修正

MobileTableRendering 接触遮蔽按 inverseDistance³ 衰减，没有有限支持域。移动球即使离某像素很远也会改变该像素的数学结果。因此不能缓存完整背景，仅重画球或可见阴影附近；也不能把事后逐像素diff当作生产失效判据（获得diff本身已需要完整绘制）。

600×1000、MSAA4、固定真实散球盘面、单球平移0.02m的iOS17诊断：2D改变2799像素/0.4665%，但总包围矩形占9.3%；3D改变215像素/0.0358%，分布跨43个32px块，总包围矩形占33.8177%。未变化姿态重复渲染差异0。该样本仅支持“存在时空冗余且影响不只在球附近”，不代表全场景覆盖率或GPU节省比例，不替代真实运动/相机/原生分辨率评估。

可实施的下一原型应缓存着色中间结果，而不是最终背景：

1. 将球位置依赖的全台面接触遮蔽保留为每帧计算，不人为截断远场贡献。
2. 分离昂贵的光源积分E/S、动态直接球影和球体反射。相机/灯光/台面材质不变时，验证静态积分是否可以复用；S含视角依赖，相机变化必须使它失效。
3. 阴影支持域内保留原候选顺序、8×4采样及合并规则；域外原2×2采样路径不能随意换成8×4，两者输出并非必然一致。球旧/新位置、升降、入袋、重叠和投影滤波影响都须纳入。
4. 原生分辨率、MSAA样本位置、法线纹理、深度/遮挡、线性色彩空间须保持。新增纹理读写/存储和额外pass有真实成本，不能仅看算术量。1206×2622的RGBA16Float单缓冲约24.13MiB；两份约48.25MiB，尚未计深度与MSAA。必须先验证缓存带宽不会抵消收益。
5. 第一原型只做固定相机台呢积分缓存，保留完整旧路径逐帧对照；运动相机先回到原路径。证明画面、GPU时间、内存及切换连续性后，才讨论接入生产SCNView或渲染宿主变更。当前未改渲染架构，不新增依赖。

球体64次反射积分暂保留；此前常量表+几何缓存组合已经真机否决，不能重新包装为已完成优化。预过滤反射属于需要单独画质验收的替代算法，不在严格等价原型中混入。
