# P15 拍照建球形（Photo → Ball Formation）

> 从用户拍的球桌照片（任意角度）提取所有球的号码与位置，落到归一化台面系，
> 复用走位/思路/出片管线。**非 DL 方案 + 人工确认一等公民**（用户决策，2026-06-16）。
> 入口：角度 Tab →「工具」→「拍照建球形」。

---

## 背景与决策（讨论纪要）

用户与 AI 多轮澄清后拍板：
- 本质 = **单目图像 → 球桌状态重建**，拆三个**正交**子问题：A 透视矫正（几何）/ B 球检测 / C 号码识别。
- **DL 评估结论**：几何用解析法（homography 闭式解），感知（检测/识别）才用 DL；但 DL 成本在数据，且号码背对相机是信息论不可知 → **先做非 DL 版**验证产品命题，DL 留作后续在「检测」一环增量替换。
- **非 DL 天花板**：可做到「好用的辅助录入工具」（位置八九不离十 + 号码靠中八固定配色给候选），做不到「无人值守全自动」。因此**人工确认（改位置/改号/增删球）是产品一等公民**，既是非 DL 的安全网，也是未来 DL 的训练数据回收入口。
- **布局参考走位编排台**（黑底 / 顶部提示 / 主区 / 底部球库）。

---

## 坐标契约（ADR-P15-01，钉死）

| 系 | 定义 |
|----|------|
| 图像系 | 像素，原点左上，y 向下 |
| **图像归一化 uv** | ∈[0,1]×[0,1]，占图比例，与显示尺寸无关（四角、球标记都存这个） |
| **归一化台面系** | `CanvasPoint` x∈[0,1] 左→右、y∈[0,0.5] 上→下，俯视 2:1（= `table-geometry.md` 真源） |

- 桥梁 = 单应 `Homography`（图像 uv → 台面系），由台面四角 4 点对应闭式解（Heckbert square→quad，`H = sq2quad(dest)·sq2quad(src)⁻¹`，无 SVD）。
- 四角顺序固定：**左上 / 右上 / 右下 / 左下**（对应单位方块 (0,0),(1,0),(1,1),(0,1)）。
- ⚠️ **已知物理误差源**：H 只对台面平面精确，球心高出台面 28.575mm，斜拍有视差 → 调用方用「球底接触点」过 H，**禁止事后加经验 offset 凑**（阶段 2 视差补偿再细化）。

## 阶段划分

### 阶段 1 — 几何竖切（零感知）✅ 本次
拍照 → 手动拖 4 角标定 → 解 H → 在照片上手动点标每颗球+选号（经 H 映射）→
2D 真台人工确认（拖动/改号/增删）→ 产出 `BoardSnapshot` → 送编排台。
**目的**：先证明「斜拍矫正」几何链路成立 + 立起「确认页 + 接入编排台」最有价值的一段，无任何检测/识别风险。

### 阶段 2 — 自动球检测（⏳ 后续）
`BallDetector`：自适应台呢色模型 → 非台呢斑块连通域 → 圆度/面积过滤 → 接触点。
号码仍颜色候选 + 人工确认。

### 阶段 3 — 号码归类 + 可选 OCR（⏳ 后续）
`BallClassifier`：母球/黑8/全色半色（白占比）/色系→候选号码（自适应、防跨球房偏色）+ Vision 文字识别兜底 + 冲突消解（号码唯一，不硬塞）。

## ADR-P15-01 — 拍照建球形采用「非 DL 几何 + 人工确认」分阶段方案

- **状态**：已采纳（2026-06-16）
- **背景**：需从任意角度球桌照片提取球号+位置。
- **决策**：
  1. 几何（透视矫正）用解析单应闭式解，**不用 DL**；感知（检测/识别）后续才上 DL，且优先「球检测」一环。
  2. 阶段 1 先做**零感知**几何竖切 + 人工确认，验证产品与几何命题；阶段 2/3 增量替换手动步骤。
  3. **人工确认是一等公民**（改位/改号/增删），作为非 DL 安全网 + DL 数据回收口。
  4. 输出统一为现有 `BoardSnapshot`，识别模块只产出它 → 走位/思路/出片管线零改动复用（跨模块边界经 `BoardSnapshot` 收口）。
- **后果**：低成本、低风险落地辅助录入工具；DL 不是银弹，留在感知零件位置按需引入。
- **坐标契约**：见上「坐标契约」节（图像 uv → 归一化台面系，球底接触点过 H，禁经验 offset）。
