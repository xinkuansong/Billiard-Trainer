## 2. 已核实事实和待验证项

### 已核实事实

- `SceneAimingView` 和 `AimPointSceneTrainingView` 都以 `TableEntryRenderObserver`、`entryRendered` 和 `DailyTableOrientation` 控制手机 2D 入口。
- `AngleSceneView` 存在合并相机临时 2D 同步路径和非合并相机静态快照路径。
- 静态临时 2D 快照的复用判断包括激活次数、视图尺寸、可读区域和缩放比例。
- `topDownContentRevision` 会从页面传入 `AngleSceneView`，但当前静态快照复用条件没有直接使用该修订号。
- `BTTeachingTablePage` 和 `FreePlayView` 也复用了同类全屏球桌入口。
- 袋口点选当前包含 SceneKit 直接命中、投影中心回退、投影球体尺度命中区和前景栏边判断。
- `BatchAuthoringView` 也使用临时 2D 入口结构，但需要确认是否属于用户可达页面。

### 待验证项

- Q01 是否由静态快照没有跟随球位、轨迹或球影状态失效造成。
- Q02 是否由首次竖屏渲染、横屏请求、窗口尺寸和 SceneKit 尺寸之间的时序竞态造成。
- Q03 是否由透明 SceneKit 背景或宿主页面背景在入口阶段暴露造成。
- Q04 是否由标记尺寸、倾斜投影、栏边深度判断和相邻袋口选择共同造成。
- Q04 的扩展区域建议采用当前画面投影后的圆形或椭圆形触控区，半径以当前显示球直径为参照并通过数值草稿校准。
- Q05 中每个页面是否实际走同一导航入口，以及不同页面是否有自己的背景或相机例外。

### 批次 D · 袋口命中和反馈统一

#### 范围

1. 动手前读取并遵循 `geometry-spatial-reasoning` 技能，钉死 SceneKit X–Z 水平面、投影屏幕坐标和袋口位置真源。
2. 将袋口命中解析抽成共享逻辑，复用当前视角投影后的袋口中心和可见开口。
3. 在每个袋口中心建立透明的屏幕空间圆形或椭圆形命中区，让上方、下方和左右一定范围内的点击都能命中同一袋口。这个区域只负责触控，不新增可见球体，不改变物理袋口或进球判定。
4. 触控区尺寸以当前页面可见球的屏幕直径为参照，设置最小可点尺寸和最大扩展上限，并通过数值草稿和投影示意确认六个袋口在不同视角下的覆盖范围。
5. 对角袋、中袋和不同倾斜视角使用当前投影结果，不直接把世界坐标中的球形半径当作屏幕半径。
6. 保留栏边和真实遮挡判断。点击落在前景栏边时不穿透到被遮挡袋口。
7. 对相邻袋口设置最近点、区域重叠检测和歧义处理。命中多个候选时采用可解释的最近候选规则，无法区分时不提交错误袋口。
8. 保留无障碍自定义操作，检查选中或按下反馈。
9. 覆盖标准视角、倾斜视角、靠近栏边、靠近球体、2D、3D 和临时 2D。

#### 依赖

批次 A 完成袋口命中路径和误选情况记录。动手前完成几何技能读取和坐标验证。

#### 完成标准

- 六个袋口在目标倾斜视角下，点击袋口中心、上方、下方和左右有效区域都能稳定点选。
- 每个袋口的透明触控区以当前显示球直径为参照，尺寸经过数值草稿和投影示意验证。
- 触控区不跨入相邻袋口的有效区域。
- 靠近栏边时不因深度判断全部失效，真正被前景栏边遮挡的袋口不会被穿透选中。
- 共享壳层页面和专用页面使用同一套命中规则。
- `-pocketSelection.probe` 定向证据与无障碍操作检查通过。
- 提供标准视角和倾斜视角的修复后截图或录屏。

### 2026-11-21 角度练习 3D 入口追加修订

### 2026-11-21 临时 2D 管道透底追加修订

用户复验后指出，管道残影仍能看到真实 3D 内容。渲染路径确认临时 2D 使用透明图片或透明 SceneKit 叠层叠在仍运行的透视场景上。管道填充本身保留 20% 教学透明度时，叠层透明像素会把底下的 3D 球和阴影露出来。

修订 `AngleSceneView.Coordinator` 的两条临时 2D 路径。静态快照 `UIImageView` 和合并式 SceneKit 叠层统一设置不透明黑色底。管道仍可在该底色和临时 2D 球桌图上保持半透明效果，不再与真实 3D 场景混合。该修订只影响临时 2D 叠层，不改变 3D 正常视图的管道样式。
