## 2. 已核实事实和待验证项

### 已核实事实

- `SceneAimingView` 和 `AimPointSceneTrainingView` 都以 `TableEntryRenderObserver`、`entryRendered` 和 `DailyTableOrientation` 控制手机 2D 入口。
- `AngleSceneView` 存在合并相机临时 2D 同步路径和非合并相机静态快照路径。
- 静态临时 2D 快照的复用判断包括激活次数、视图尺寸、可读区域和缩放比例。
- `topDownContentRevision` 会从页面传入 `AngleSceneView`，但当前静态快照复用条件没有直接使用该修订号。
- `BTTeachingTablePage` 和 `FreePlayView` 也复用了同类全屏球桌入口。
- 袋口点选当前包含 SceneKit 直接命中、投影中心回退、44pt 最近点回退和前景深度判断。
- `BatchAuthoringView` 也使用临时 2D 入口结构，但需要确认是否属于用户可达页面。

### 待验证项

- Q01 是否由静态快照没有跟随球位、轨迹或球影状态失效造成。
- Q02 是否由首次竖屏渲染、横屏请求、窗口尺寸和 SceneKit 尺寸之间的时序竞态造成。
- Q03 是否由透明 SceneKit 背景或宿主页面背景在入口阶段暴露造成。
- Q04 是否由标记尺寸、倾斜投影、栏边深度判断和相邻袋口选择共同造成。
- Q05 中每个页面是否实际走同一导航入口，以及不同页面是否有自己的背景或相机例外。

## 6. 分批执行方案

### 批次 A · 入口页面盘点、复现和诊断基线

#### 范围

1. 复现 Q01、Q02、Q03、Q04 的用户路径。
2. 逐页确认 Q05 的页面范围。
3. 对手机 2D、手机 3D、iPad 横屏和 iPad 竖屏建立入口基线。
4. 覆盖冷启动、热启动、返回后再次进入、浅色环境和深色环境。
5. 记录 `entryRendered`、`tableFrameReady`、窗口方向、窗口尺寸、SceneKit 尺寸、首个完整画面和背景层状态。

#### 依赖

无。

#### 完成标准

- 生成一份页面矩阵，标记每页使用的入口路径。
- 每个可复现问题至少保留一段短录屏或一组关键截图。
- 记录同一页面正常和异常的状态差异。
- 完成一次定向构建或测试，结果写入本方案的执行记录。
- Q02 的正常 3D 基线和 2D 异常表现分别记录，不能合并为同一验收条件。

### 批次 B · 临时 2D 快照与同步修复

#### 范围

1. 审计 `AngleSceneView.Coordinator.updateTemporaryTopDownOverlay()` 的静态快照生命周期。
2. 让球位、球影、轨迹、瞄准线和教学标记变化触发快照失效或同步。
3. 复用现有 `topDownContentRevision`，避免建立平行状态源。
4. 移动球体时清理旧快照或更新现有覆盖层。
5. 检查所有走非合并相机临时 2D 路径的页面。

#### 依赖

批次 A 已确认静态快照路径和复现步骤。

#### 完成标准

- 连续拖动 5 号球时没有旧球影、旧球位或旧轨迹。
- 移动其他球、释放、取消、重新进入和 2D/3D 往返均没有残留。
- 至少覆盖一个专用练习页、一个共享球桌页和 `FreePlayView`。
- 相关 XCTest 或 XCUITest 完成，新增测试写明覆盖的状态变化。
- 提供修复前后截图或录屏。

### 批次 C · 2D/3D 入口时序和背景修复

#### 范围

1. 统一 `SceneAimingView`、`AimPointSceneTrainingView`、`BTTeachingTablePage` 和 `FreePlayView` 的入口状态协议。
2. 将手机 2D 首次可见时机绑定到目标方向已生效、窗口尺寸稳定和 SceneKit 视图完成最终布局。
3. 在方向切换和首次绘制期间保持稳定的不透明背景。
4. 审计 `backgroundColor: .clear`、全窗口 `GeometryReader`、`opacity` 和宿主页面背景的组合。
5. 保留正常 3D 基线中的短暂转屏过渡，不把该过渡改成静态等待或固定延时。
6. 检查同一共享壳层下的其他页面是否出现相同白色、半屏或错误方向。

#### 依赖

批次 A 已确认具体异常发生在导航过渡、方向请求、首次绘制或背景层中的哪一段。

#### 完成标准

- 角度练习 2D 进入后直接收敛到正确横屏桌面布局。
- 瞄准点练习进入过程中没有应用拥有的白色背景闪现或残留。
- 正常 3D 页面的短暂转屏过渡仍能完成并进入完整 3D。
- 冷启动、返回后再次进入和热启动均通过。
- iPhone 横屏、iPad 横屏和 iPad 竖屏符合球桌页面统一规范。
- 完成角度 2D、瞄准点 2D、正常 3D 的对比录屏。

### 批次 D · 袋口命中和反馈统一

#### 范围

1. 动手前读取并遵循 `geometry-spatial-reasoning` 技能。
2. 将袋口命中解析抽成共享逻辑，复用投影后的袋口位置。
3. 在当前视角的可见袋口区域建立有限扩展的触控区域。
4. 保留栏边和真实遮挡判断。
5. 对相邻袋口设置最近点和歧义处理。
6. 保留无障碍自定义操作，检查选中或按下反馈。
7. 覆盖标准视角、倾斜视角、靠近栏边、靠近球体、2D、3D 和临时 2D。

#### 依赖

批次 A 完成袋口命中路径和误选情况记录。动手前完成几何技能读取和坐标验证。

#### 完成标准

- 六个袋口在目标倾斜视角下均可稳定点选。
- 靠近栏边时不因深度判断全部失效。
- 相邻袋口之间没有明显误选。
- 共享壳层页面和专用页面使用同一套命中规则。
- `-pocketSelection.probe` 定向证据与无障碍操作检查通过。
- 提供标准视角和倾斜视角的修复后截图或录屏。

### 批次 E · 跨页面回归和交付记录

#### 范围

1. 执行 Q05 页面矩阵。
2. 回归所有纳入范围的专用页面、共享球桌页面、`FreePlayView` 和用户可达的作者页。
3. 覆盖 iPhone 横屏、iPad 横屏、iPad 竖屏、冷启动、热启动、返回再次进入、浅色、深色、临时 2D 拖球和六袋口点选。
4. 将每个 Q 编号对应到改动文件、测试、截图、录屏和剩余风险。
5. 更新 `tasks/PROGRESS.md` 和本文件的执行记录。

#### 依赖

批次 B、C、D 全部完成。

#### 完成标准

- 完成定向构建和与问题匹配的测试。
- 每个受影响页面都有通过、未复现或阻塞状态。
- 未纳入页面写明排除理由。
- 证据文件保存到对应任务目录。
- Q01–Q05 均有最终状态，不能只报告共享修复已完成。
