# App 音量提高 · 2026-10-30

> 当前为文末 r2：目标 +6 dB，背景音乐/进袋按峰值余量限制。下方首轮 +3 dB 记录保留为历史。两轮均未安装到 iPhone。

## 用户确认与范围

用户最初报告蓝牙下击球无声，后实听确认音效仍在，只是被同一 iPhone 上网易云音乐掩盖。因此没有以“蓝牙路由/混播中断已证实”为由修改音频会话。用户要求提高 App 实际音量，并明确选择“App 全部声音一起提高，包括背景音乐和操作提示音”。

实现：11 个包内 CAF/WAV 统一 +3 dB（线性幅度 ×1.4125375），覆盖击球、碰球、碰库、袋口、进袋、瞄准/力度操作、背景音乐及休息倒计时/结束提示。通过提高资源 PCM 幅度实现，不改偏好默认值、音色选择、力度曲线、各类相对音量、音频会话或 UI。rail/railStop 的原零输出保持；静音保活不加声。没有改 Documents 的显式试听覆盖，若启用覆盖，包内对应样本仍会被它替代。训练提醒通知使用 iOS 的 `.default` 系统提示音，音量由系统管理，不属于本次 App 音频资源。

## 修改

- `QiuJi/Resources/Audio/` 下 11 个音频及两份 CREDITS；旧 SHA/来源保留为历史，本次新 SHA 另表登记。
- `QiuJiTests/ShotAudioTests.swift` 的操作样本峰值合同随 +3 dB 更新为 0.35–0.36（原峰值 0.25 → 0.353149）。其余时长、淡入淡出、音色差异和播放规则断言不变。
- 原件、原/新 SHA、加工程序、结果及参考试听位于 `output/app-audio-gain-20261030/`。

## 验证与边界

1. Apple AVFoundation 原生编译/运行通过：11 资源全量解码，逐样本核对 3 dB（误差 <0.002 dB）、量化误差 ≤1 个 16 bit 单位；帧数/采样率/声道/编码/16 bit 保持。音乐仍为 2,646,000 帧 / 60 秒。最大资源峰值 0.847473，全部样本无削波。两操作声的时长、首尾零值、新峰值区间也通过。
2. 最终原生运行证据：`output/local-test-runs/3ac1a4151b044463b62c5dcfce046103/evidence/command.log`；受管临时构建已自动回收。资源结果：`output/app-audio-gain-20261030/validation.json`。
3. 离线参考混音原/新版均无削波，峰值 0.895251 / 0.913916；12 个同步强碰球的现有峰值保护计算保持 0.85。读取生产力度曲线和核对当前峰值公式，结果在 `mix-validation.json`；这不是整 App 播放测试。
4. 探索性极端压力模型把独立 AVAudioPlayer 背景音乐、12 个同步强碰球与操作提示直接相加，原版/新版均可能超过满幅（1.050981 / 1.133884）。首轮断言因此失败；保留该结果，改为明确报告跨播放器算术上界，未据此宣称 iOS 实际混音无削波或新增限幅。实际系统混音/任意同时发声/外部网易云及蓝牙耳机听感仍需真机复验。
5. Swift 测试文件语法检查通过；未执行完整 XCTest、App 构建、模拟器或真机安装。原生资产验证不能代替这些结果。
6. `make -f scripts/Makefile verify-gate` 退出 0，通过记录为 `output/app-audio-gain-20261030/gate.log`；本轮文件 `git diff --check` 通过。

首次 FFmpeg 的 ALAC 重编码试验发现解码/封装帧数发生变化，未写入生产资源；改用 Apple 原生读写保持音乐准确帧数。首次 Apple 原生编码默认变成 32 bit ALAC，亦未晋级；最终显式保留 16 bit，再核验后才写入生产。
