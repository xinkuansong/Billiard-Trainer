# 每日清台性能优化 — 2026-09-21

状态：首轮优化已实现并通过定向回归；尚未在用户手机安装新版或验证降温效果。

## 证据与判断

真机基线见 [设备报告](DAILY-CLEARANCE-DEVICE-PERFORMANCE-20260921.md)。iPhone 16 Pro 的 2D 操作窗口 CPU 单核百分比均值 25.09%、样本峰 161.46%，footprint 峰 1.73 GiB；系统 Serious、用户确认明显烫手。3D 主动操作对照未完成，不据此比较两模式发热高低。GPU Fragment 最长 16 ms 是编码通道区间，不能当整帧耗时、利用率或功耗。

代码核查找到两项可直接处理的问题：

1. `PositionPlayViewModel` 原来仅通过 generation 丢弃旧结果，已失效的翻袋全搜索仍继续消耗 CPU。
2. `AngleSceneView` 原来在 Serious 热状态仍允许 60 FPS；默认即为 60 FPS，因此严重发热时没有进一步降频。

其他核查：模型克隆的材质需隔离，但几何源和贴图仍共享；不能仅因 clone 就认定重复占用所有纹理。既有模拟器 10 次场景生命周期测量未见场景残留；静止场景不持续绘制，但保留 30 Hz 活动检测，涉及 SCNActions、相机阻尼及唤醒，尚未贸然暂停。约 1.7 GiB 真机峰值的资源归因仍未解决。

## 已实现

- 每次预测持有线程安全取消标记。新意图、清空/失效、VM 销毁会取消旧任务。
- 翻袋的加塞档、库序并行任务、粗扫、精修评分和终验之间检查取消。取消后返回空目录，旧 generation 仍不得上屏。已经进入的单次物理模拟会完成，不强制中断引擎。
- 新一次去抖会清除更早的补跑标记，避免旧补跑抢先越过最新拖动的 0.5 秒等待。
- Serious / Critical 时上限 30 FPS；离开严重热状态后保持 30 秒恢复等待。正常温度仍遵循用户帧率偏好，低电量仍沿用 60 FPS 上限。
- 共用预测/场景入口受益，包含每日清台 2D/3D 及其他使用相同入口的页面。

本轮没有改变资产、shader、抗锯齿、像素分辨率或物理规则。限制帧率会降低高温时的运动流畅度；每秒最多帧数减少不等于 GPU 功耗按同样比例下降。

## 耗时对照

同一生产翻袋搜索盘面、默认三档加塞，模拟器 iPhone 17 Pro / iOS 26.3，Debug 构建覆盖 `SWIFT_OPTIMIZATION_LEVEL=-O`（不是 Release 或手机实测）。5 轮墙钟时间：

| 条件 | 中位耗时 |
|---|---:|
| 不传取消标记，完整计算 | 61.100 ms |
| 传未取消标记，完整计算 | 61.355 ms |
| 发起后 5 ms 请求作废 | 5.978 ms |

完整计算的库序和加塞结果一致。作废任务全部返回空目录，占用时间相对完整计算约减少 90.2%。这仅证明旧任务能提前释放计算资源，不代表 App 总 CPU 或发热下降 90%。正常任务中位额外耗时约 0.25 ms，样本较小，不作统计显著性结论。
