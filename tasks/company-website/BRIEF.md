## 访问者与网站目标

| 访问者 | 来到官网想解决的问题 | 网站应给出的答案与下一步 |
| --- | --- | --- |
| 希望提升的台球爱好者 | 我在瞄准、走位或训练安排上遇到的问题，能在这里找到帮助吗？ | 用真实产品画面和通俗解释介绍产品价值，进入 CuePhys 产品页 |
| 已了解或正在使用 CuePhys 的人 | 是否上线、在哪里下载、怎样使用、出了问题联系谁？ | 清楚展示当前状态，提供帮助与联系；正式上线后接入真实商店链接 |
| 了解公司或寻求合作的人 | 这是谁做的，公司具体做什么，怎样联系？ | 公司介绍、实际产品与作品、有效联系渠道；仅展示真实开展的业务 |

产品受众参考[产品愿景与定位](../../docs/01-产品愿景与定位.md)：主要面向希望突破瓶颈的台球爱好者。网站介绍突出物理模拟、球形推演与求解、专项交互练习，并用可视化球理和实台工具连接理解与应用；训练安排与记录作为辅助能力。真实击球仍需要球台练习。旧定位文档中的远期设想与历史功能不能直接作为首发能力宣传。

首版成功的判断：访问者无需猜测就能说清公司与产品关系，找到一个与自己有关的训练场景，阅读产品介绍，并找到有效联系方式。上线后再结合实际反馈决定是否增加统计，不预设访问量或转化率承诺。

## 公司与产品的表达

首页同时出现公司身份和 CuePhys，内容顺序建议为：公司正在做什么 → CuePhys 简介与真实产品画面 → 认识公司或联系支持。具体候选正文见[文案草稿](首版栏目与文案草稿.md)。

公司介绍候选句：

> 无锡有球科技有限公司围绕台球开发软件与数字内容，通过可观察的模拟、可操作的工具和清楚的讲解，帮助球友理解球路、尝试不同选择，把思考带到真实球桌。

产品介绍候选句：

> CuePhys 是我们正在开发的台球训练 App，将物理模拟、球形推演与求解、专项交互练习和可视化球理结合起来。从瞄准与杆法，到连续走位、翻袋、解球和防守，动手尝试不同选择，观察结果，理解每一杆背后的思路。

导航和页脚都能到达公司介绍；公司页写出法定名称、所在地和实际业务。详细地址、公开电话或个人背景是否展示，在内容审稿时确定。证件照片、身份证信息、签名、密钥和内部备案材料不进入网站源码或构建产物。

## 已有视频的使用方案

用户于 2026-11-11 明确视频仅在 CuePhys 页面占一小部分，不设独立栏目；也不接受将其用途预设为功能或训练方法演示。用户表示“我也没太想好，只是觉得它可以放一下”。因此先在产品页预留小块位置，暂以真实片名、封面与播放器呈现，具体数量、介绍和摆放随选片及本地页面效果决定。此前首页代表视频、3 至 6 条与视频列表／详情页的提议不再作为首版范围。

先从[视频台账](../../docs/视频台账.md)与[待发布清单](../../output/待发布视频/清单.md)选稿。下列为台账初筛线索，尚未完成本轮逐片播放与官网选稿验收：

| 候选 | 台账所记状态 | 建议用途与待核点 |
| --- | --- | --- |
| V014 短台和中长台反角球 | 10 月 23 日 r6 视频及封面 r1 已认可、已归集 | 瞄准主题代表候选；核最终版本、现行品牌和小屏标注可读性 |
| V009 第一人称角度瞄准 | 45cm r9 已确认 | 从球友视角展示瞄准；核最终文件与对应封面 |
| V003 至 V005 分离角图谱 | 角度、速度、距离篇有成片；发布与认可状态分别记录 | 系列内容候选；核各版说明、适用条件及旧品牌残留，不将三条一概标为可发布 |
| V024、V025 斯诺克四视角 | 粉球中袋已归集，黑球角袋明确认可 | 可作为公司教学作品候选；来源含斯诺克项目，不据此宣称 CuePhys 首版提供该模式 |

V026 目前是关键帧，V027 至 V029 是后续选题，不进入首版成片清单。历史成片认可与官网发布是不同状态；官网实际采用的版本、封面、网页地址和发布时间在发布时单列登记。

每条入选视频记录标题、稳定网址标识、主题、说明、时长、画幅、原片路径与版本、网页副本、封面、字幕或文字讲解、来源及公开使用依据。涉及真人、第三方素材、音乐或配音时核对应使用范围。缺封面或声音存在问题时单列补齐，不覆盖原片。

播放方案建议：封面点击播放，保留暂停、进度和全屏控制；首屏不自动播放有声视频，不同时下载整页视频。竖版保持原画幅，小屏需要能看清字幕与关键标注。无声教学配文字说明，有语音的内容核字幕；仅靠视觉呈现的关键变化补观看要点。网页优化副本与母版分开，不能为压缩而丢失教学细节。

优先评估现有服务器托管少量网页副本；先核实际码率、文件大小、服务器带宽和 App API 的资源占用，再决定是否足够。新增对象存储或 CDN 涉及成本和配置时另行选型，不自动购买。社交平台已发布链接核实后可作为补充入口，不让平台登录成为理解核心内容的前提。播放器和加载策略参考 [MDN video](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/video) 与 [视频延迟加载](https://web.dev/articles/lazy-loading-video)。

## 实现与长期维护

建议以静态内容为主，优先评估 Astro；本地开发和构建后，将产物部署现有服务器。它支持组织 Markdown 内容和本地构建，适合产品介绍、视频说明和后续文章；框架版本与目录在开发阶段固定。[Astro 内容管理](https://docs.astro.build/en/guides/content-collections/) · [本地构建](https://docs.astro.build/en/guides/deploy/)

Sites 使用本地开发流程，Impeccable 负责设计与复核，网页检查参考 [Vercel 规范](https://vercel.com/design/guidelines)。当前无需安装新技能；自有服务器部署仍须依据实际服务配置另写步骤。

内容按页面、产品、视频分别维护，共用公司名、联系方式、上线状态和导航配置。首版中文路径保持稳定；英文版未来上线时使用独立语言路径并维护对应关系，不显示空语言切换。App 的 `/support`、`/privacy`、`/terms` 保持统一入口，部署前核后端路由，避免静态站覆盖已有 API 或绕过法律页发布条件。

公司邮箱开通后测试外部来信和回复。网站源文件与发布产物建立版本记录，部署有回滚办法；把域名、证书、邮箱及服务故障的查看方式纳入维护说明。沿用现有备份体系前核是否覆盖官网文件与配置，不假定数据库备份已经包含网站。

## 验收条件

以下为后续交付条件，当前均不代表已经完成网站验收。

| 范围 | 通过条件 |
| --- | --- |
| 内容 | 公司与产品关系清楚；每个功能、视频和联系方式有依据；无草稿占位、虚假评价、旧名称误导或不可用下载按钮 |
| 页面与操作 | 每个导航、正文链接和联系入口有效；真实 404 页面；手机、平板、桌面布局正常；至少检查 360、390、768、1440 CSS 像素及长文本 |
| 可访问性 | 键盘可操作、焦点可见、图片有合适替代文本、文字放大不丢内容；减少动态效果设置生效，视频有必要文字替代 |
| 视频 | 入选作品完整播放；封面、字幕和版本一致；移动端内联播放、全屏、拖动进度和失败提示实测；未点击时不拉取整段视频 |
| 性能与兼容 | 记录实际加载与布局结果；在 Safari、Chrome 和常用手机浏览器核主流程；视频播放期间验证 API 健康，性能瓶颈先解决再发布 |
| 搜索与分享 | 页面标题和描述明确，网址稳定，站点地图与抓取规则一致，分享标题、封面和链接正确；不承诺收录时间或排名 |
| 公开部署 | 网站备案及适用展示要求落实；匿名 HTTPS 访问、证书、域名、邮件收发与回滚通过；现有 App 服务和备份正常 |
| 用户验收 | 用户查看公司表达、视觉、产品介绍与入选视频后确认；技术通过、内容认可和正式发布分别记录 |

无障碍在制作过程中检查，参考 [W3C 规划说明](https://www.w3.org/WAI/planning-and-managing/)；性能参考 [Web Vitals](https://web.dev/articles/vitals)，本地实验结果与上线后的真实用户数据分开记录。搜索基础参考 [Google 指南](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)。
