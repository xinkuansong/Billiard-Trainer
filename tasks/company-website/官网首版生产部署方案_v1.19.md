| 2 | 盘点现场并暂存正式包，准备服务器配置和恢复点 | 中，一台现服 | 现场只读盘点可与 1 并行，传包依赖 1 |

### 第一批　固定可以复现的上线版本

1. 在官网独立 Git 仓库逐项审查已跟踪和未跟踪改动，将首版需要的代码、文案、素材、构建检查及本地审阅依赖纳入发布提交。截图审查包、构建目录、凭据和证件留在发布源之外。
2. 将该提交同步至现有私有 GitHub 仓库。从该提交干净检出，依次执行 `npm run release:status`、`npm run build:release`、`npm run check:release` 和 `npm test`。核对应提交的 GitHub 两个检查任务；预览与正式模式分别验证。
3. 为 `dist-release/` 制作逐文件 SHA-256 清单，将清单保存在站点根目录之外。记录完整 40 位提交号、构建时间、测试结果、文件数和哈希。

**批次通过条件**　干净检出能复建五个公开页面和 404，自动化通过，站点地图恰含五个地址。备案链接、联系邮箱正确，发布包内没有 App 法律草稿、审阅页或原始资料。

### 第二批　准备现服与恢复点

1. 记录上海实例当前 IP、端口占用、虚拟主机、软件版本、磁盘、系统时间；核对后端 health、PM2、数据库监听及备份定时任务。导出本域 DNS 和本实例防火墙规则，记下相关记录原值与 TTL，受限保存快照。若已有主机或端口发生变化，先适配配置。
2. 准备 Nginx、证书工具及官网独立目录。安装时控制默认站点的启用时机。核已安装轮转规则、全局配置是否重复、日志目录权限及每日任务；复用现有调度。
3. 上传正式产物至 `/var/www/youbilliards/releases/<完整提交号>/`，远端核对**文件集合与各文件哈希**，用 Web 服务用户检查可读权限。安装仓库内的版本切换工具，先运行 `--dry-run` 并记录 previous、target。保存变更前 Nginx 配置和官网 current 链接的原始状态。

**批次通过条件**　远端产物与第一批一致，拟切换路径正确；既有后端和备份基线正常。恢复记录能区分首次上线前原本不存在的资源和已经承担其他业务的资源。

### 第三批　启用域名与 HTTPS

1. 本方案默认采用 HTTP-01。先启用只服务 ACME 验证文件的临时虚拟主机，限定根域和 www，其他请求不得返回官网、默认欢迎页或 App 后端。检查 `nginx -t` 并从本机带 Host 验证，再开放必要的公网 80 端口。
2. 按快照在 DNSPod 将根域和 www 指向现服。若已有冲突记录，先确认其用途；保留 MX、SPF 等邮件记录及其他业务记录。IPv6 仅在端到端验证通过后接入。核权威服务器和外部解析，并从公网读取两个域名的临时验证文件。遇到传播延迟先核 TTL 与权威应答。
3. 用 Certbot 签发同时覆盖根域和 www 的证书，核对 SAN、完整链和有效期。若 HTTP 验证无法实施，可用 DNS-01；只创建所需挑战 TXT，验证结束后按记录标识清理。续期须能重复执行选定的验证方式。
4. 核对正式虚拟主机证书路径，通过原子切换工具将 current 指向已验包。启用正式配置，`nginx -t` 成功后重载，开放必要的 443；验证主域 HTTPS、HTTP 到 HTTPS、www 到主域。安装证书续期重载钩子，检查调度，执行续期演练并验证钩子。记录首次成功公网访问的北京时间。

**批次通过条件**　外网匿名访问正式域名成功；两个主机名的 TLS 均通过信任校验；跳转保留路径和查询串且无循环，陌生 Host 无法取到官网。后端 health 和邮件 DNS 与部署前基线一致。

### 第四批　验收与交接

| 验收对象 | 验证方法及通过标准 |
| --- | --- |
| 页面与搜索入口 | 外部网络逐一 GET 五页，均为 200；随机不存在路径、两个 App 法律路径和本地审阅入口均为 404。核 robots、五条 sitemap、canonical、备案编号及链接。 |
| 电脑与手机 | 桌面 1440 宽与 iPhone 17 Pro Max 尺寸各跑一轮；优先增加手机蜂窝网络访问。点击首页导航、产品四栏、专项分组图文切换、原图查看、返回、邮箱链接和隐私页目录。检查加载、横向溢出、遮挡、CSP 和混合内容；各留实际截图并标明设备或模拟视口。发现问题修复后复验受影响页面及另一端。 |
| 日志与业务 | 用无敏感信息的测试请求读回站点访问日志，核路径、状态以及查询串、UA、Referer 未进入访问日志。再核原后端 health、备份任务及 MX/SPF；错误日志按独立的故障上下文规则检查。 |
| 运维交接 | 私有记录写入提交号、哈希清单、上线时间、DNS 变更记录、证书有效期、续期演练、回退目标及双端证据。按真实开通日期核对并登记后续公安联网备案适用事项。 |
| 次日轮转 | 第一个实际轮转周期后核定时任务结果、归档文件及权限，确认后续请求写入新文件。若首日只登记状态，按下一次真实轮转补验；线上首日验收与该项分别记录。 |

### 故障处理与回退

- **DNS 或签证失败**：保持站点内容未开放，查看权威解析、挑战路径及证书错误。需要撤回时，只恢复本轮改动的记录和端口规则，并复核邮件解析。DNS 缓存可能在 TTL 内继续指向现服。
- **校验失败或切换后异常**：停止扩大变更。已有可用前版时，将 current 原子切回该提交并复验。首次上线没有前版时，停用本次官网虚拟主机，恢复原有 Nginx 配置或原先未监听状态，按快照恢复这次新增的解析及开放规则。保留失败版本和诊断证据。
- **既有业务受影响**：优先恢复部署前后端与邮箱的可用状态；处置只涉及本次官网变更，随后从外部网络重验网站状态、邮件解析与原后端健康检查。修复后的每一版重新走哈希验证和相关双端复验。
