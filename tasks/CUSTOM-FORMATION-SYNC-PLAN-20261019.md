# 自定义球形账号同步方案

状态：代码已实现；2026-10-19 本地定向测试与双模拟器验收、生产事务转换及接口验收通过，见 [部署记录](CUSTOM-FORMATION-DEPLOY-20261019.md)。后续[生产双模拟器7阶段](CUSTOM-FORMATION-PRODUCTION-SIMS-20261019.md)通过；未发布新版App、未做真机双设备验收。界面基线沿用自定义球形 v1.5。

自定义球形属于用户创建的数据，应随球迹账号同步。推荐采用“先保存本机，再后台同步”：旧手机上传成功后，新手机登录同一账号并开启云同步，即可恢复模板并继续编辑、练习。没有网络也能保存和练习；未上传的数据不能承诺在卸载或丢失手机后恢复。

## 用户使用方式

| 场景 | 预期行为 |
| --- | --- |
| 游客创建模板 | 保存在本机游客空间，不上传 |
| 登录并开启云同步 | 同步当前账号模板；游客模板仍须另行确认合并 |
| 保存、重命名、复制模板 | 本机保存成功即可继续使用，后台排队上传 |
| 换手机 | 同一账号在新设备开启云同步后，下载已同步模板 |
| 离线修改 | 保留修改，联网且 App 有执行机会时重试 |
| 删除模板 | 本机立即隐藏，联网后同步删除，旧设备重连不能把它恢复出来 |
| 关闭云同步 | 停止后续上传、下载；保留本机内容、待同步操作及已有云端副本 |
| 切换账号 | 切换到对应账号的模板库，不混用另一个账号或游客数据 |

云同步沿用现有“本设备、当前账号”的明确选择，与登录状态和 Pro 权益分开。新手机不会继承旧手机的开启选择。关闭前已发送的写请求可能已在服务器生效，开关不承担删除云端数据的功能。

## 同步内容

| 保存到账号 | 留在当前设备或当前操作中 |
| --- | --- |
| 模板 UUID、名称、内容版本 | 当前选中哪个模板 |
| 目标球实例身份、球号、母球和全部球位 | 相机、视图、控件布局偏好 |
| 辅助直线、顶点和共用端点关系 | 临时测距线、测角线及测量读数 |
| 每条线关联的球和保存后的排列顺序 | 撤销重做、排序循环的临时原始顺序 |
| 服务端版本、修改和删除状态 | 未明确保存的编辑草稿、练习过程球位和击球状态 |

一份模板作为完整内容同步，不拆开合并球位、线或球的关联。每颗重复球保留独立身份，不能按球号合并。球库数量角标由模板重新计算。保持最多 **25 颗目标球，另 1 颗母球**，不另加模板数量的产品限制。

练习时进球、取回球和重新摆放只改变当次练习。只有用户明确保存模板，才产生模板修改及同步操作。

## 界面调整

复用现有设置页云同步开关、同步状态和重试入口，将范围文案扩展为“训练记录、角度成绩和自定义球形”。游客合并说明也明确包含自定义球形，避免用户不知道哪些数据会进入账号。

模板列表用现有辅助文字与提示样式展示状态：

- 未开启同步或游客：“已保存到本机”。
- 有待上传操作：“已保存到本机，待同步”。
- 当前版本收到服务端确认：“已同步”。
- 上传失败：“同步未完成，本机模板已保留”，复用重试入口。
- 冲突产生副本：“其他设备也修改了此球形，已保留两个版本”。

编辑球桌两侧不增加同步按钮，不弹出阻断摆球的同步提示。设置页汇总必须包含模板的失败和待同步状态，不能出现训练记录成功便显示全部同步完成的情况。

正在编辑或练习的球桌保持当前快照。后台更新只刷新模板库，不突然替换桌面；编辑保存时检查打开时的版本，按下文冲突规则处理。远端删除正在编辑的模板后，保存当前修改应明确保存为新副本。

## 实施前代码基础和缺口（历史基线）

本方案以以下现有消费端为实施入口：

- `QiuJi/Features/CustomFormationPractice/CustomFormationLibrary.swift`：每个 owner 一份 JSON，当前 archive version 为 1，原子写入模板及本机选择；尚无上传记录和删除标记。
- `CustomFormationSession.swift`：模板内容、编辑过程和当次练习状态分离，应保持这一边界。
- `QiuJi/Data/Services/AccountDataCoordinator.swift`：已有账号隔离、游客合并确认、先上传后恢复、异步身份及同步选择检查。
- `AuthState.swift`、`BackendSyncService.swift`：已有同步开关、身份及 REST API 通路，可复用。
- `SyncRestoreService.swift`：现有训练恢复以“本机不存在才插入”为主，不能直接用于模板更新；`SyncPendingItem.swift` 也没有模板类型。
- `OwnerTransferService.swift`：现有 SwiftData 归属迁移不包含模板 JSON；`backend/src/services/accountDeletion.js` 尚未包含模板清理。

因此，这不是给现有队列加一个枚举即可完成的改动。需要补齐模板存储事务、双向版本检查、删除记录和账号生命周期接入。本文不改变训练记录原有合并算法，也不将架构文档里的通用更新时间描述视为已经实现的模板同步能力。

## 本地保存与同步结构

第一版保留现有 JSON 存储，新增模板仓库协议和 `CustomFormationSyncService`。由现有账号编排器调度，复用网络、鉴权、同意检查和状态出口。无需引入第三方依赖，也不为本功能迁移整个 SwiftData 数据库。

将 archive 升级为 version 2，除模板和本机选择外，保存每条模板的服务端版本、本机修改代次、待同步操作、删除标记及拉取游标。**内容修改和待同步操作在同一次原子文件写入中提交**；不能先保存 JSON，再单独写 SwiftData 队列，留下崩溃后永远漏传的窗口。

同一 owner 的读取、修改、迁移和同步回写统一经过一个串行仓库。界面不能持有旧的整份 archive 并覆盖后台已经写入的新数据。文件解析失败时保留原文件，禁止用空库覆盖。

每次上传使用不可变内容快照和持久化 operationId。成功应答只确认实际发送的本机代次；发送过程中用户再次保存，后续修改仍保留待同步。发送前可合并尚未发送的连续修改；已发送但结果未知的操作必须按原 operationId 重试确认，不能擅自取消后假定云端不存在。

登录后开启同步、保存模板、进入前台、网络恢复以及用户主动重试可触发同步，进行中触发合并处理，失败退避重试。不开持续轮询，不承诺 App 被系统终止后立即同步。

## 服务端接口和一致性

增加账号私有的模板集合及接口，名称作为实现建议：

| 接口 | 契约 |
| --- | --- |
| `GET /custom-formations?after=0[&through=N]` | 首次完整恢复，之后获取变更；分页包含删除标记，返回服务端生成的后续游标 |
| `PUT /custom-formations/:clientId` | 提交完整模板、内容 schemaVersion、baseRevision、operationId；创建要求原记录不存在，更新要求版本相符 |
| `DELETE /custom-formations/:clientId` | 携带 baseRevision 与 operationId；写入带版本的删除标记 |

服务端从 JWT 确定账号，唯一键为 `(userId, clientId)`。请求中的 owner 字段不能决定访问权限。服务端修改版本为权威，客户端时间仅用于显示，不用手机时间判断谁覆盖谁。

成功写入、版本变化和可被拉取的变更必须可靠提交，不能出现写入成功但变更流漏掉的情况。分页必须有稳定边界和确定顺序；首批接口实现时明确存储原子性方案，并用并发分页测试证明无遗漏。若方案依赖 MongoDB 事务，先核实部署支持，不能仅在代码中假设存在副本集。

同一 operationId 重试返回原结果；同一 operationId 携带不同内容应拒绝。先识别已经执行过的操作，再判断版本冲突，以处理服务端成功但客户端没收到应答的情况。

删除记录第一版持续保留，账号注销时一并清理。未来若清理旧删除记录，必须同时引入游标过期与全量校准机制，禁止直接设置过期时间让旧设备重新上传已删模板。客户端也不能仅凭一次列表缺项判断删除。

客户端完整校验并原子应用一页后才推进游标。未知版本、无效几何或写盘失败不能静默跳过并越过游标；保留原本机数据、报告同步未完成。后端未支持接口时也保留本机待同步状态，不冒充成功。

客户端和后端都校验名称、实例唯一性、球位范围、母球和目标球数量、线端点与球关联。允许重复球号。名称长度、载荷字节数及工具数据的技术保护上限在接口契约阶段统一确定，并在用户提交前说明，不默默截断。

## 多设备修改规则

服务端通过版本比较拒绝过期写入。几何内容不做逐字段拼接；冲突副本有新的模板 ID，保留原球形内容，并命名为“原名称 冲突副本”。

| 情况 | 处理 |
| --- | --- |
| 本机无修改，云端有新版本 | 更新本机模板库 |
| 本机有修改，云端版本没变 | 上传本机版本 |
| 两台设备修改同一模板 | 原 ID 保留当前云端版本；本机修改另存副本并同步，用户可自行保留或删除 |
| 云端删除，本机无修改 | 移除本机模板 |
| 云端删除，本机有未同步修改 | 原 ID 保持删除；本机修改保存为新副本，提示原因 |
| 本机删除，但云端出现更新版本 | 不自动删除远端新内容；恢复显示该版本并提示“其他设备已更新，如需删除请再次操作” |
| 双方都删除 | 幂等完成，不生成副本 |

内容相同的重复应答不制造冲突副本。冲突处理及副本 ID 映射需持久化，崩溃重试也只能产生一份副本。版本冲突单独处理，不能当作普通网络失败无限重传，也不能丢弃本机修改。

## 旧模板和账号生命周期

**旧版升级。** 先校验并备份 v1 文件，再原子升级为 v2，保留模板 UUID、名称、球实例、球位和线关系。迁移可重复执行；只有成功落盘才切换版本。当前账号的旧模板成为待同步创建项，遵守当前同步开关；游客模板不自动上传。旧版超过 25 颗目标球的模板继续保留本地原数据，提示减少至上限后保存并同步，不自动删球，也不因一条超限阻断其他合法模板上传。

**游客合并。** 现有“是否有游客数据”的判断纳入模板；用户确认后才转入当前账号。同 ID 同内容可去重，同 ID 不同内容另存副本。两份 owner JSON 与 SwiftData 不是同一事务，需要持久化迁移进度和 ID 映射：先可靠写入目标并核验，再清理来源；失败可续做，不重复复制。所有涉及的数据域迁移完成前，不显示“全部合并成功”，也不绕过现有同意门禁上传。

**退出或换号。** 保留各 owner 文件和待同步内容，取消当前调度。请求携带期望账号上下文，取凭证、发送前及每次 await 后均校验账号、操作代次和同步选择；旧请求不能借用新账号 token，也不能清掉新修改。退出后显示游客模板，账号模板不会自动成为游客数据。

**注销账号。** 服务端删除模板、删除标记和幂等操作记录。按现有注销后本机数据转游客的产品约定，将模板一并可靠转入游客空间，并清除旧账号待同步操作和游标；迁移失败进入现有补偿恢复流程。服务端删除过程要可重试，注销中的账号应阻止新写入，避免删除与上传并发留下孤立数据。

## 实施步骤和验收

| 阶段 | 交付 | 必须通过的验证 |
| --- | --- | --- |
| 1 数据契约与后端 | DTO、版本和幂等规则、私有 CRUD、删除标记、分页、注销清理 | 账号隔离；重复请求；版本冲突；并发分页无遗漏；注销与写入并发 |
| 2 本机存储与迁移 | v2 archive、串行仓库、同文件待同步操作、v1 备份升级 | 写盘失败不丢数据；重启可重试；旧文件损坏保留；重复球和线关联不变；旧超限数据不截断 |
| 3 同步和账号接入 | 上传拉取、冲突副本、游客合并、开关与身份隔离、状态反馈 | 上传中再次保存；应答丢失；连续保存后删除；换号和关闭开关；迁移中退出重启；正在编辑时远端变化 |
| 4 双设备验收 | 同一测试账号连接实际测试后端，两台模拟器执行完整流程 | A 新建后 B 恢复；双向编辑；离线重连；删除不复活；冲突副本只生成一次；名称、重复球数、线连接及顺序一致 |

实施时按仓库要求执行构建、定向 Swift/Jest 测试及相关门禁。模拟器使用生命周期登记与借用流程。已有单机 UI 测试继续覆盖 25 目标球另 1 母球、直线连接、等距排列、排序及测量，确认同步接入没有改变摆球体验。

发布先提供向后兼容的后端接口，再发布客户端。只有连接实际服务完成双设备验证，才能宣称换机同步可用；模拟 API 单测、构建通过或本机文件恢复都不能替代这项证据。回退时保留 v2 文件与待同步内容，不把旧备份覆盖到新版修改上。

本期交付保存模板的账号同步。模板分享、公开市场、实时协作、历史版本浏览和练习中途跨设备接续不在本期范围。


## 2026-10-19 实施记录

本机新增 CustomFormationStore / CustomFormationSyncService；archive v2 同文件原子待同步操作，MainActor 串行修改，每次事务重新读取文件。v1 原件保存在同目录 `.v1-backup`，错误文件不覆盖。JSON 跨 owner 迁移先写目标，凭来源ID和内容摘要记录回执，再清来源；中断后再次编辑也不会被旧回执丢弃。

现有账号编排接入模板同步、游客合并、注销补偿、网络恢复及退避重试。每个写请求绑定预期 JWT subject，401重试仍检查，避免旧请求用新账号凭证。模板列表新增辅助状态和冲突说明；设置及合并文案包含自定义球形，编辑两侧不增加控件。
