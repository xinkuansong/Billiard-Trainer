# 通用设置覆盖与页面独立记忆 · 实施方案

日期：2026-10-17。状态：**2026-10-17 用户批准实施；P1–P4 已接入 App，P5 定向模拟器回归通过，用户体验复阅及未覆盖矩阵待收。**

本轮范围：核查相关球桌、训练和回放页面的显示/操作偏好、现有存储及覆盖关系。账号、订阅、数据同步和提醒保留原职责。后续用户授权补齐 Figma，已更新为 r5；本轮随后已授权 App 实施。以下新增交互以 r5 和用户本轮授权为准。

## 1. 已确认的规则与玩法边界

1. 通用设置修改某一项，统一覆盖所有支持该项的页面，包含之前已单独设置的页面。
2. 页面内调整只影响本页，离开再进、重启 App 后保留；之后仍可被下一次通用操作覆盖。
3. 按设置项覆盖，不清空球形、比分、计划、训练记录或其他设置。页面修改不反向改变通用设置显示的值。
4. 通用值表示最近一次统一选择；不要把它描述为所有页面的实时共同状态。没有“卡片自定义管理”、跟随三选项或永久豁免。
5. 真正同时提供 2D/3D 切换的页面，未有历史选择时初始 2D。已有单页选择需迁移保留。固定 2D/3D 训练入口不改变题型。
6. “临时换玩法”留在每日清台球桌菜单，属于对局操作；不进入通用设置、不参与偏好覆盖。现有换玩法会重新开始相应玩法，已有击球时的确认仍需保留。

**默认玩法保留在通用设置（用户最新确认）**：它与用户主玩偏好相关，继续作为第五组；撤回此前移至开局入口的建议。当前 `SettingsView.dailyClearanceSection` 明确只影响下一个新局，进行中的清台保持原玩法；`UserPreferences` 会结合个人资料推断初始玩法。r5 保留这一边界，主动选择保存新默认，不反向改写个人资料。它不等于临时换玩法，也不进入按页面再次覆盖的项目列表；已有球局不能被覆盖重建。

## 2. 现状发现

| 发现 | 影响及处理方向 |
|---|---|
| 当前没有统一的默认视图偏好；多数页面使用内存中的 cameraMode，FreePlay 首次进入会设为 2D | 需要建立独立、持久化的页面视图选择，并接入初始化流程 |
| 蛇彩已有 `snakePractice.view3D` | 保留该历史选择；不能统一迁移成 2D |
| 网格、瞄准特写、轨迹档位大量直接读写 `UserPreferences.shared` | 现有单页开关会影响别处，不能仅增加存储键就宣称实现单页记忆 |
| 每日清台、自由击球、蛇彩、分离角与走位、编排及多个教学页已有局部透明度/3D 隐藏记忆 | 迁移原值，不重置；后续全局同项覆盖仍须能生效 |
| 翻袋解球与颗星解球共用 `bankKick.*`；自由走位与动作试打共用 `composer.*` | 按用户可识别的功能入口拆开，旧共享值分别复制为初始值 |
| 两种角度训练及两种瞄准点场景训练按固定 2D/3D 路由进入，成绩/配置也按路由区分 | 不列入默认视图覆盖；网格等通用辅助仍可按能力接入 |
| 特写注释写默认开启，但实际初始化是 `false` | 以运行代码为现状证据；本次不得照草图示例偷偷改变默认值 |

## 3. 哪些设置需要怎样保存

### A. 通用统一覆盖，同时允许页面单独记忆

| 设置项 | 范围与记忆粒度 | 约束 |
|---|---|---|
| 默认视图 2D/3D | 下表 16 个建议的用户功能作用域；各页独立 | 记逻辑视图，不记横竖屏、相机矩阵或临时俯视 |
| 台面网格 | 所有确实使用该辅助网格的页面；固定题型页也可以支持 | 页面内开关只改本页；预览页目前没有局部入口，可仅接受统一值 |
| 瞄准特写 | 已有特写能力的击球/规划页、瞄准点场景训练 | 开启是允许显示，仍遵守拖动、选球、计算结果可用等触发条件 |
| 打点盘透明度 | 有可调打点盘的页面 | 保存 0…1；滑动结束提交统一设置，避免拖动中反复广播 |
| 轨迹显示 | 提供通用轨迹档位的练习/规划页 | 保留“轨迹·全 / 轨迹·双 / 瞄准线”，3D 的隐藏单独定义，不能用一项抹掉教学图谱专用线 |
| 分离角辅助线 | 支持相应碰撞轨迹辅助的页面 | 建议补页面入口；这是可选辅助，不是分离角图谱的教学内容开关 |
| 运杆演示 | 具有相应击球动画的页面 | 建议补页面入口；不改变物理、击球结果、次数与比分；导出视频使用独立配置 |

**轨迹的具体建议**：把“轨迹档位”和“3D 隐藏辅助”作为两个内部字段。通用选择一个可见档位时，覆盖相关页面档位，并解除这些页面的 3D 隐藏，使“统一显示”确实可见；通用关闭 3D 辅助只作用于 3D，不抹去页面的 2D 档位。界面文案应明确“3D 轨迹显示”，不能让用户误以为 2D 也关闭。该联动需在草图补足后实施。

### B. 保持全局，不额外制造每页副本

| 设置 | 处理 |
|---|---|
| 外观（浅色/深色/跟随系统）、渲染帧率 | 继续全 App 偏好；页面无独立副本 |
| 背景音乐、击球音效 | 继续全局控制，不按功能卡片保存 |
| 球房风格、球桌风格、台呢颜色、球贴纸、球杆外观 | 继续统一外观；本轮不新增各页器材自定义 |
| 显示颗星参考点 | 当前作为球桌外观设置，先保持全局；和叠加网格区分 |
| 训练提醒、权限、账号安全、订阅、同步与数据管理 | 按原业务保存，不受“统一球桌设置”影响 |

全局是作用范围，不代表全部都要挤进同一个设置页面。数据、安全、帮助入口沿既有信息架构另行组织。

### C. 页面独有偏好，独立记忆但不受不相关通用项覆盖

| 页面/选项 | 当前状态与建议 |
|---|---|
| 角度与瞄准：瞄准线、进球线、3D 假想球、瞄准管道、进球管道 | ViewModel 已有持久化，保留；与通用预测轨迹档位语义不同，不强行映射 |
| 四个固定视图场景训练：自由练习、切角范围、母球距离、进球距离、袋口类型 | `SceneTrainingConfiguration` 已按 route 保存，保留；通用修改视图/网格不得重置训练题目条件 |
| 蛇彩：球数、顺序模式 | 已有本地保存，保留；随机生成的具体球号排列和当前成绩是训练状态 |
| 思路训练：允许左右塞、仅基础走位（≤1库） | 目前为 ViewModel 状态；建议补本页持久化，不放进通用设置 |
| 自由/进袋瞄准模式 | 对可自由操作的练习页，可作为后续本页偏好；本期不一刀切保存。动作试打的序列、任务要求和临时自由模式优先，不得被上次选择破坏 |

### D. 当前操作、内容状态，不作为本轮偏好覆盖

- 临时换玩法、开球、重新摆球、清空桌面、恢复默认球形、重新练习、清空计划、结束练习：均为操作，保留必要确认。
- 母球/目标球/袋口选择、力度、杆法打点、球形、规划步骤、求解方案、播放进度、比分：留在现有会话或草稿恢复机制中，不混入通用偏好。
- 分离角图谱/加塞吃库图谱的八档显示选择：本轮继续作为当前对比操作，保持进入时八档全显；不受通用轨迹简化影响。
- 临时顶视、相机转场、示范镜头、首/第三人称镜头姿态、横竖屏适配：不写回 2D/3D 用户偏好。镜头类型若以后单独产品化，再定义独立项。
- 实验物理模型、调试渲染和内容生产参数：不进入面向用户的通用设置，也不能由视图切换修改。

## 5. 设置入口与交互建议

通用设置继续单页直接展开，顺序建议为：

1. **练习显示**：默认视图 → 台面网格 → 瞄准特写 → 打点盘透明度 → 轨迹显示（3D 隐藏范围需明示）。
2. **击球辅助**：分离角辅助线 → 运杆演示。
3. **应用显示与声音**：外观 → 帧率 → 背景音乐 → 击球音效。
4. **球桌与器材**：球房 → 球桌 → 台呢 → 球贴纸 → 球杆 → 颗星参考点。

5. **默认玩法**：与主玩偏好相关，仅影响新局，保持进行中的球局与临时玩法。

保留五组，不增加卡片管理。球桌内沿原“显示 → 击球设置 → 本功能操作”顺序，复用原有菜单、图标与控件，不为这次存储改造重做视觉规范。

页首短说明建议：“这里修改的项目会统一应用到相关页面。各页面仍可单独调整并记住。”页面设置说明：“仅调整当前页面；通用设置再次修改此项时会统一更新。”

**再次应用同值（r5 草图）**：视图再次点选当前 2D/3D 也执行统一覆盖；轨迹菜单同理。页首说明后增加“再次应用某项…”动作入口，列出网格、特写、透明度、轨迹档位、3D显示、分离角辅助、运杆的当前通用值。打开列表不应用；点击一项执行并关闭，取消不改变任何设置。一次只应用选中项，不先关再开，不堆叠每行主按钮，不提供全项重置或逐页管理。动作后给出明确轻提示。轨迹档位重应用按约定同时开启相关页3D轨迹，属于该组明确联动。

## 6. 实现方案（已授权）

### 6.1 一处管理作用域、保存和通知

- 建立稳定的页面标识及能力清单：可切视图、网格、特写、打点盘、通用轨迹、分离角辅助、运杆。关闭页面、尚未进入的页面也有明确默认行为。
- 通过一个偏好服务维护“通用基准 + 页面单项值”。页面操作只写页面值；通用操作原子地更新该项基准并清除对应范围所有页面的该项值，随后通知已打开的页面。
- 清除后有效值自然等于新通用值；以后页面可重新写入自己的值。内部存储的局部值不是用户可选择的永久覆盖权；下一次统一操作仍会清除它。
- 同值应用也是操作，不能被 `oldValue == newValue` 提前返回吞掉。不要靠墙上时钟比较先后。每次操作有明确来源，初始化/读回/转场不触发保存。
- 第一版延续本机持久化边界，不擅自引入云同步或账号隔离。若要跨设备同步，需要独立定义冲突规则。

### 6.2 贯通真正的消费端

必须同时处理入口、ViewModel 和渲染器，不能仅改开关：

- `FreePlayView`、`PositionPlayComposerView`：接收作用域；替换各分支硬编码与全局写入；区分正常模式/试打/蛇彩。
- `BTTeachingTablePage`、`SolverStageChrome`：传入作用域与有效值；翻袋和颗星不再共享本地设置。
- `DrillSceneView`：由详情/记录调用方传身份；设置首帧之前恢复视图，避免先显示 2D 再跳 3D。
- `AngleSceneView`：网格现在会在创建及更新时读全局值，需显式注入；否则上层页面值会被它覆盖。
- `BTAimCloseupHUD`、`BTShotPageChrome` 等辅助组件：统一使用当前页有效值，保留可用性判断。
- `TrajectoryRenderer` 及 PositionPlay/BankShot/Diamond 等 ViewModel：移除业务页面中绕过上下文的全局档位读取；保留内容显式轨迹配置。分离角辅助同样不能继续隐式串页。
- `CueStroke`：实时击球传入有效运杆偏好；导出已有显式参数须保留，不让本地显示偏好改写导出结果。

视图只持久化 2D/3D 意图；`topDown2D` 和 `topDown2DRotated` 根据布局映射，同属 2D。横竖屏、临时俯视、示范镜头和自动回放不会写回。统一变更到达播放中的页面时先保存，在不会打断本杆的安全时点应用画面；不重新建局或重新求解业务状态。

### 6.3 一次性迁移

- 旧全局网格、特写、轨迹、分离角辅助、运杆作为初始通用值；保留原实际默认值。
- 迁移 `snakePractice.view3D`；其他没有历史视图选择的作用域初始为 2D。
- 迁移 `dailyClearance`、`freePlay`、`shotSimulation`、`snakePractice`、`composer`、`silu`、`planthree`、`snooker` 的透明度与 3D 隐藏；精确键名以原代码为准。
- `bankKick.spinTransparency / hides3DAssists` 分别复制到翻袋和颗星；`composer.*` 复制到自由走位和动作试打。之后独立变化。
- 专用训练配置和角度与瞄准五项偏好保留原值。首次迁移不算一次用户统一操作，不抹掉旧局部偏好。
- 迁移版本只执行一次；重启不得把旧键重新灌回，尤其不能复活已被通用操作覆盖的值。非法枚举/透明度值回退到合法默认。验证完成前保留旧键用于回退，避免无关删除。
- 默认玩法保留通用入口，保留已有首选值、个人资料推断与现有对局草稿；两者不能混写，不参与覆盖已有球局。
