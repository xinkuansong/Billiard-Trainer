# 第一人称：画面观察与瞄准条改向

## 用户裁定与范围

用户要求分析第一人称，并制作进袋／自由模式样片；随后明确第一、第三人称共用同一输入语义：

- 滑动球桌画面只观察，保持当前杆向和进袋／自由模式。
- 滚动瞄准条代表用户手动修改瞄准方向，进入自由模式，相机跟随新杆向。
- 回到原角度不自动恢复进袋模式。

第一人称画面滑动由用户选择“保持杆向，只转头观察”。观察时不强制球杆居中；沿杆瞄准及瞄准条调整时保持居中。第三人称按其既有观察轨迹移动，相机跟杆样片现改用“滚动瞄准条”标注。用户认可上一版第三人称整体观感，但本轮仍只做离线视频，不改App。决定另记`docs/00-讨论记录.md`。

## 状态

✅ 六组（3球位×2输入）726姿态已渲染，8段独立视频与4份流程／并排视频已完成；投影、杆网格净距、球心可见性、视频完整解码及SHA核验通过。最终编码关键帧已目视。7份监测生产源码哈希未变，App未改；第一人称观感待用户验收。

## 第一人称候选机位

沿用前轮Blender场景、三种母球位置、固定红球和黄球、材质与灯光。米制XY水平／Z向上，台呢Z=-0.042、R=0.028575。相机焦距38mm，视窗16:10。

当前App `CameraRig.dailyPlayerPose` 的第一人称入口采用沿杆0.90m、杆线上方0.13m作为起点，还会经过原生取景和遮挡处理。本候选借用沿杆0.90m的尺度，独立选择杆线上方0.18m以留出看球余量；不是当前App第一人称的逐像素复刻。

```
eye.xy = cue.xy - aim.xy * (0.90 * cos(cueElevation))
eye.z  = cue.z + 0.90 * sin(cueElevation) + 0.18
```

沿杆状态母球中心位于视窗横向50%、距顶部70%；相机无滚转，固定镜头。近长库／短库／角袋沿用前轮能覆盖±30°杆向的固定杆仰角15.5°／15.25°／10.25°，本轮再次对真实桌网格核净距；两种输入使用同一初态。

站位约在母球后方0.87–0.89m，实际眼高由上述公式派生，不将固定台面高度硬套到不同抬杆角。母球画面更大，球杆后半段自然位于相机后方，不强求整根杆入镜。

## 两种输入

**滑动画面**：左右各8°，眼点和杆的世界变换保持不动，仅绕竖直轴改变视线方向。第一人称母球横向约36%–64%，纵向约70%–70.7%，允许球杆离开中线；不改瞄准方向，也不切模式。

**滚动瞄准条**：左右各30°，与前轮第三人称同一角度序列和时序。新杆向与相机站位共用角度；原锚点解算保持母球50%／70%。初始为进袋模式，首个非零输入即切自由；返回初始方向后仍为自由模式。

每段12秒：1秒初态 → 2秒左向 → 0.5秒停留 → 2秒回正 → 1秒停留 → 2秒右向 → 0.5秒停留 → 2秒回正 → 1秒停留。左右共121独立姿态，返回复用原帧。输入说明栏区分画面拖动示意与瞄准条刻度，俯视小图展示杆向；小图不是物理预测线。

**连续流程**：进袋模式滑屏观察12秒 → 瞄准条操作进入自由12秒 → 自由模式滑屏观察12秒，合计36秒。最后一段复用同样的转头画面，但模式保持自由，展示输入语义与当前模式独立。

初始杆向仍为母球→红球的镜头演示轴，进袋标签表达本段假设的输入状态；没有指定袋口解算或真实进袋动作。球始终静止，原台面细线保留，不把它当新杆向的预测轨迹。

## 验证

- 数值：球心投影在视窗内、沿杆锚点50%／70%、正交姿态、固定焦距、桌外眼点；转头眼点／杆向固定；首帧两输入相同。
- Blender：实际相机forward/up和四个世界点的投影；瞄准条模式检查相机前方杆节点中心X=50%，杆后半段在近裁面之后时自然不纳入可见轴线检查；转头模式逐帧检查球杆世界变换完全不变。
- 六组全部121姿态，母球和红球中心射线均首先命中对应球，中心无杆头／桌沿遮挡。此处不是整球轮廓、所有球形或所有抬杆的可见性证明。
- 每段杆仰角固定，包络净距检查覆盖全部采样杆向；这是离线示意杆，不是生产回杆／出杆或人体可达性验收。
- 生产源码仅做前后哈希，未构建或运行App；原生触控、HUD、松手惯性、模式往返记忆、全角度转头未验。
