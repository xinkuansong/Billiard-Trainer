# 2026-11-01 磁盘清理

用户要求清理再次不足的本机磁盘空间。本轮采用闲置缓存删除、历史日志无损归档、历史快照 APFS 写时复制去重；没有删除代码、原始素材、研究数据、测试结果 Data 或模拟器。

## 实测结果

- 清理前精确基线：1,748,922,368 字节可用（约 1.75 GB / 1.63 GiB；最初 df 四舍五入显示 1.7 GiB）。
- 最终复核：8,026,423,296 字节可用（约 8.03 GB / 7.48 GiB）。
- 本轮观察到净增加 6,277,500,928 字节（约 6.28 GB / 5.85 GiB）。期间其他任务仍可能读写，此值是磁盘可用空间变化，不能等同各目录 du 之和。
- 空间仍较紧。大体量历史素材、验收、研究和待复验现场继续保留，没有因目录大就整体删除。

## 已执行与验证

1. 删除无打开文件占用的 Codex Sparkle 更新暂存目录 `~/Library/Caches/com.openai.codex/org.sparkle-project.Sparkle/Installation/OwkSUHnUP`，目录分配量约 1.89 GB；未动已安装应用。
2. 删除无进程参数引用、无打开文件占用的 8 个 `~/.npm/_npx/` 临时工具缓存目录，分配量约 818 MB；以后使用相关工具时会重新下载。
3. 8 份历史 `CoreSimulator.log`，共 35,196,247,476 字节，压为同目录 `.gz` 共 2,335,239,721 字节。每份在移除原件之前完整解压，核对长度与 SHA-256 一致，并复核 inode/mtime/大小及文件占用。数据存在 APFS 共享块，逻辑缩小约 32.86 GB 不代表释放同等物理空间。
4. 在 7 个明确列出的历史源快照中，先按内容 SHA-256 和属性匹配，再用 APFS clone 合并重复存储块。8,005 个副本保持原路径、内容、模式、属主、mtime 和属性；每个新副本使用独立 inode，临时样本已验证写时复制隔离，未使用硬链接。替换前完整校验内容、元数据和原件身份，再原子替换。最终检查替换 inode、大小和 mtime 全部符合记录。
5. 第二批遇到 macOS 未原样复制属性时，在替换前拒绝；29 个原件完整保留，临时副本移除。其余候选按相同检查完成；无剩余待替换文件。

所有操作清单及机器可读结果位于 `output/disk-cleanup-20261101/`，最终 `final-summary.json` 的 `verification_errors=[]`。本轮未改 App 实现，未执行 App 构建或功能测试。
