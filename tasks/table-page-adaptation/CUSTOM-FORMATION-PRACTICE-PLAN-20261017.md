## v1.3 多线与测量基础（数量与样式以v1.4为准）

- 编辑仍使用标准球桌、来源球栏、BTHUDCompactAction、BTTextActionButton、BTReadout；固定俯视、不击球；重复球与无产品球数上限保持。
- 左侧直线／量距离／量角度，底部撤销／重做。工具互斥。
- 画线：依次点两端，完成后继续画下一条；再次点直线或右侧完成退出。已有端点可作为新起点或终点，连接处共用节点。拒绝零长度和重复连线。
- 只画两端点与直线，无中间预览圆环；端点限制在可摆球台面范围，近水平／垂直吸附并采用宽一些的脱离带。
- 球由用户逐颗添加；当前选中线时点球栏加入该线，拖入时靠近线吸附。单球中点、两球及以上占两端并均分；拖离解除关联。画线不自行生成球，也不收编附近旧球。
- 共用端点已有球时，相连线复用该颗球，避免重叠复制。某分支仅剩该共用球时，球保留在连接点；独立单球仍居中。
- 拖选中线的端点优先于覆盖端点的球，连接处带动相连线及各自的等距球。越界钳制、重叠或过短拒绝本次位移，保持最近有效局面；一次拖动一次撤销。
- 右侧当前线：球数／球距 cm／线长 cm；两距离保留一位小数，少于两球球距为—。选球删球、选线删线；底部保存。取消数量、方向输入和批量应用。
- 测距：两点；测角：三点，第二点为顶点，0–180°。支持球心／端点吸附和测量点拖动，右侧实时读数；测角一位小数。测量不移动球，只保留当前组，完成或换工具清除。
- 设置：网格、自动吸附、恢复全桌、清除全部辅助线、清空目标球。删线不删球。
- 辅助线随模板保存、复制与编辑恢复，兼容无辅助线的旧模板；练习只载入球形，不带辅助线或测量。

## 以下为旧详细提案与首版背景

## 1. 功能定位与范围

在「练」分类的蛇彩后增加「自定义球形」入口。用户选择自己保存的球形，进入熟悉的球桌自由练习；也可以新建球形，借助编排工具精确摆球后保存。

用户已明确：

- 入口与设置过程参考蛇彩，支持新建模板、选择已有模板。
- 常规击球、把球打进即可；没有指定击球顺序、犯规、失败或达标规则。
- 练习中可以把球拿回来，用户自由处理球形。
- 新建模板允许重复球号。
- 引入编排台适合摆球的工具，至少包含直线工具。
- 上一版 Figma 完全不符合，改为依据现有页面写详细方案。

本方案建议：名称暂用「自定义球形」，一张模板对应一个起始球形；首版提供模板管理、重复球、精确摆球、自由练习四个完整闭环。不加入多球形课程、录杆教学、训练评分或模板市场。以下未被用户逐项确认的细节均为建议，不视为已批准开发。

## 3. 页面流程

```text
练 → 自定义球形 → 训练设置
                    ├─ 选择模板 → 开始练习 → 自由练习球桌
                    ├─ 新建模板 → 摆球编辑 → 保存 → 返回设置并选中
                    └─ 模板更多 → 编辑 / 复制 / 重命名 / 删除

自由练习球桌 → 训练设置 → 选择模板 → 开始新练习
             → 摆球工具 → 调整当前桌面 → 继续击球
             → 将当前球形另存为模板
```

首版不增加中间详情页。保存模板后先回设置页，让用户看到保存结果并沿统一的“开始练习”入口进入；不在保存后自动开练。

## 4. 训练设置页：沿用蛇彩原生列表

### 4.1 页面组成

导航栏：左侧「返回」，标题「训练设置」，右侧「开始练习」。从练习中打开时，左侧为「取消」，右侧为「开始新练习」。

正文建议只有两个分节：

1. **练习模板**：逐行列出已保存模板。每行显示名称、目标球数量和选中勾选；点击整行选择，不立即开始。球数从模板读取，不另设球数选择器。首版不放大封面、球桌缩略图和重复说明。
2. **模板管理**：一行「＋ 新建模板」。已有模板的行尾更多菜单提供编辑、复制、重命名、删除；删除需确认。

无模板时显示简短空状态「还没有球形模板」和新建入口，开始按钮禁用。已有模板默认选中上次选择；找不到原选择时清空选择，由用户重新选，不静默换模板开始。

不沿用蛇彩的球数/击球顺序/最近成功失败记录，因为本模式的球数属于球形内容，且没有规则成绩。无需另外增加“自由规则”“允许拿球”等开关，这些就是模式本身的能力。

### 4.2 管理细节

- 新建：进入只有一颗母球的空台草稿；名称可在首次保存时填写，建议默认「未命名球形」。
- 编辑：打开模板副本，保存后才更新原模板；取消退出保留原文件。
- 复制：立即生成独立模板，名称附「副本」，随后可编辑；复制的新球实例 ID 重新生成。
- 重命名：只改名称，不改球位及选择状态；空白名称不允许保存。
- 删除：只删除指定模板；取消不变。删除当前选中模板后取消选择。
- 排序：首版按最近修改在前；开始练习不改变编辑排序。模板多时继续使用原生列表滚动，搜索/分类后续再评估。

## 5. 新建与编辑：现有球桌上的摆球工作模式

### 5.1 布局约束

使用现有球桌、房间背景、材质、字体、HUD、顶部球库和左右控制列。手机进入球桌后横屏；iPad 支持横竖及可用窗口变化。内部编排台“只验个人 iPad 竖屏”的特例不外推到面向用户的新功能。

| 区域 | 编辑时建议安排 |
|---|---|
| 左上 | 返回＋「新建模板」或「编辑模板」；长模板名放菜单/命名框，避免挤压球库和桌面 |
| 顶部中央 | 1–15 号来源球库，使用现有球图、胶囊和拖放视觉；目标球可以反复拖出 |
| 右上 | 系统状态＋现有更多菜单；新增模板保存/命名操作 |
| 左侧上部 | 编排台同类工具入口，包含「摆球」「直线」；不带落区/过点/反解等工具 |
| 左侧中下部 | 保留方向尺；摆球时在既有辅助操作区域提供选中球和四向微调。手机低高度下次要动作进入工具菜单，不加宽控制列 |
| 右侧 | 现有打点盘、杆速尺、击球按钮；击球用于试打当前草稿，不改成另一种大按钮 |
| 台内 | 只在直线取点、放球冲突等必要时显示现有提示/确认控件；无常驻教程面板 |

保存入口确定为「更多 → 保存模板」，编辑旧模板时另有「另存为新模板」。与内部编排的保存能力同源组织，但保存到用户模板仓库。首版不在球桌底部加宽按钮，不为“保存”改变击球按钮含义。

### 5.2 添加、移动与重复球

- 从顶部来源球库拖出 1 号球，放置一次产生一个实例；再次拖出 1 号球，再增加一个实例。来源图标保持可用。
- 在编辑态点击来源球图标，建议进入“待放置该球”的状态；点台面确认落点，取消则不创建。不能点击一次就悄悄叠在已有同号球上。
- 台面已有球可拖动、点选后微调；拖回顶部球库或执行「移除选中球」从草稿删除该实例。
- 默认一颗母球，目标球外观可重复。母球仍是唯一击球主体；多母球不是当前需求，首版不引入。
- 每个同号球有独立选中高亮。辅助名称可显示「1 号球 · 第 2 颗」，不把球面号码改成 1A/1B。
- 复用现有真实球模型拖放预览、手指避让和落点约束。球不能重叠、落在库体里或台外；放不下时保留原状态并说明原因。

这里的“允许重复”指多颗相同号码的球，不等于让多个对象共用一个位置键。摆球合法性是确保模拟可运行的边界，不是训练判罚。

### 5.3 精确摆球工具

| 工具 | 首版行为 | 与现有编排的关系 |
|---|---|---|
| 自由摆球 | 拖动、选择、移除单个实例 | 复用手势和摆放约束，身份改为实例 |
| 四向微调 | 点选球后按屏幕上/下/左/右移动，每步 0.5 mm；支持既有长按重复 | 复用编排微调和屏幕方向映射，不按世界轴硬写方向 |
| 直线 | 选起点→确认→选终点→确认；白线、端点十字、近轴向吸附 | 抽出 `BatchGuideLine`，保留两步交互 |
| 线上等距 | 将靠近线段内部的目标球均分；拖入/拖离直线后重新计算参与球 | 复用现有沿线排序及分布方式；不自动移动线外球 |
| 清除线 | 清掉辅助线和吸附关系，保持已经排好的球位 | 复用现有清线语义 |
| 台面网格 | 显示现有 4×8 参考网格 | 只是参考线；本方案不把它描述成现有“网格吸附” |
| 母球换位 | 进入换位后点击目标球，交换两个球的位置，保持身份和号码 | 抽出编排台点换能力；完成一次后退出换位态 |
| 清空目标球 | 确认后移除草稿目标球，保留母球 | 新页面语义，避免清空后无法找到母球入口 |

直线的新增边界：当前宿主把所有在桌键交给 `BatchGuideLine`，母球也可能参与；本功能建议明确只对目标球生效，避免摆一排球时把母球吸过去。两端点不放球，沿线位置决定排列顺序，不按号码排序。线太短导致间距不足或会碰到线外球时，预览提示并拒绝此次整体排布，不能只移动一半参与球。

直线、母球换位、选球微调互斥；换工具前退出当前取点状态。进入击球时清除临时辅助线，已摆球位保留。工具首版不包含任意数量直线、圆形阵列、镜像、坐标输入或多选组合；以后可基于实际使用补充。

### 5.4 试打与保存，避免把打散后的球形误存成模板

编辑器需要保留“摆球草稿”和“试打桌面”两份状态：

1. 编辑态点「击球」前保存草稿快照，进入试打；后续可连续试打、重打和回放。
2. 试打时工具入口提供「返回摆球」，恢复试打前草稿。台内用一次短提示说明，不持续占据桌面。
3. 试打期间隐藏/禁用通常的「保存模板」，提供「采用当前球形继续编辑」；用户明确采用后，当前桌面才成为新的摆球草稿。
4. 保存时校验名称、唯一母球、至少一颗目标球、位置有效及实例唯一。保存成功才返回设置并选中模板；写入失败保留草稿供重试。
5. 编辑有未保存变化时退出，使用现有确认容器提供继续编辑、保存并退出、放弃修改。没有变化直接返回。

## 6. 练习球桌：自由击球、自由拿回

### 6.1 进入及布局

开始时从所选模板创建一份独立练习快照。球位与外观按模板恢复，显示/瞄准设置按本页偏好。标题使用简短「自定义球形」，当前模板全名可在更多菜单中查看。

基本布局完全沿用蛇彩：顶部实例球库；左上「重新开始」；左方向尺、重打/回放；右打点盘、杆速尺、击球；右上更多。去掉蛇彩的“下一目标锁定”、首杆自由球限制与判定提示。

练习中所有静止的球都能直接拖动。需要精确调整时使用「更多 → 摆球工具」进入与模板编辑相同的摆球状态，作用对象是当前练习副本；完成后回到通常练习控制。新增/移除目标球也在该状态完成，避免普通练习时误把球库当无限补球源。

### 6.2 顶部球库与拿回球

编辑页顶部是“球的来源”；练习页顶部是“这次练习的球实例”。两者视觉沿用同一组件，交互含义必须显式区分。

- 练习顶部显示当次所有目标球实例，顺序固定，即使号码相同也占独立槽位；落袋后仅对应槽变暗，不压缩、不重新排序。
- 点亮槽位可定位/选中台上的那颗球；从变暗槽拖到台面，把对应实例拿回来，不额外生成一颗。
- 为轻点操作提供替代：点击变暗槽进入待放置态，再点台面放回；可取消。首次触发时短提示「点按球桌放回」。
- 槽位的可访问名称包含号码、同号序号和在桌/已收起状态。不能让两颗 1 号球共用选中态或进袋态。
- 从台面拖回球库表示暂时收起该实例，仍可拿回；与编辑态“从草稿删除”区分。永久移除当次球需在摆球工具中执行。
- 新增实例排在末尾；移除实例只在明确编辑动作后改变槽位。大球数容量通过球库自身滚动/分页解决，保持球径、台面与双尺空间，不通过缩小球桌容纳无限槽位。
- 母球延续现有球库不占母球槽的布局。母球落袋后按共享复位路径回台，并允许继续任意摆位；摆球工具另有「放回母球」作明确入口。复位落点被占时进入待放置，不能重叠或凭空消失。

首版精确新放球和直线取点建议使用 2D/临时俯视；3D可拖动现有球，并沿共享入口进入临时俯视拿回球，完成后返回原观察。临时俯视禁止击球，避免放球与出杆手势冲突。

### 6.3 没有判定规则的具体含义

- 可任选目标、袋口、击球顺序和杆法；碰到其他球、空杆、母球落袋都不判失败。
- 进袋瞄准和自由瞄准是辅助方式，仍可切换，不承担规则判断。
- 一杆结束等待真实停稳，保留自然停点。没有“失误选择”“通关结果”“再来一局”强制流程。
- 目标球全部不在桌面时保持原页和球库可操作。用户可以拿回任何球、增球、重摆或退出。最多短提示「台面已清空」，不显示成功/清台成绩；手动收球也不会被记成清台成功。
- 不接入全局训练记录、胜负、命中率、连续成功、计时任务或排行榜。模板列表的球数是内容属性，不是训练成绩。
- 当前预测未就绪、无母球、球仍在运动或回放中，击球按钮按真实能力禁用；这些是运行状态，不是惩罚规则。

### 6.4 四种恢复操作不能混用

| 操作 | 恢复对象 | 对模板的影响 |
|---|---|---|
| 拿回球 | 一颗被打进/收起的实例，由用户选择新落点 | 无 |
| 重打 | 最近一杆开始前的全部球位、姿态和击球参数 | 无 |
| 回放 | 最近一杆的运动；结束返回观看前的练习现场 | 无，不二次进袋或扣球 |
| 重新开始 | 当次开练时的模板快照，恢复全部目标球及母球，清掉当次临时增删 | 无；有现场变化时确认 |

手动拿回/增删/移球后，旧一杆的重打、回放会与新桌面冲突；首版建议使两者失效，下一杆形成新历史。这样不会在拿回一颗球后按“重打”又丢掉刚做的调整。完整编辑撤销栈不混进“重打”。

### 6.5 修改后保存、切换和离开

- 「将当前球形另存为模板」从当前在桌实例创建新模板；已落袋/收起的球不混进新球形。没有目标球时禁用。名称确认后保存，当前练习继续。
- 练习中不直接覆盖原模板。要更新原模板，从设置中的编辑入口处理，避免一场练习悄悄破坏原摆法。
- 「训练设置」打开时保留当前现场；取消准确回到原现场。点击开始新练习才切换，必要时确认替换现场。
- 普通退出直接结束此次自由练习，不产生失败记录。模板编辑的脏数据确认不套在每次练习退出上。
- 前后台切换取消正在进行的拖放/取点/调参，按共享播放生命周期处理；不重建球形。首版只保证当前会话保留，不承诺进程被杀后恢复整次练习。

## 7. 菜单、相机与偏好完整映射

公共菜单顺序沿用当前 `FreePlayView.dailyMenuItems`：显示 → 击球设置 → 本页操作。下表每个适用项均需接到实际场景/VM，不能只放一个开关。

| 能力 | 练习 / 编辑试打 | 摆球状态与作用域 |
|---|---|---|
| 2D / 3D | 保留，切换不重置球形 | 编辑默认从适合摆球的2D进入；临时俯视期间不再嵌套切换 |
| 全局 / 第三 / 第一人称 / 临时俯视 | 复用现有相机与观察恢复 | 取点、拖放与相机手势明确互斥；无母球时禁用依赖母球的沿杆观察 |
| 打点盘及透明度 | 保留四向、回中、收起和实际透明度效果 | 取点/模态打开时互斥；关闭不透点 |
| 台面网格 4×8 | 保留 | 实际场景开关；与直线辅助工具分开 |
| 瞄准特写 | 保留现有触发时机与避让 | 仅有有效瞄准且真实输入时出现，不因摆球常驻 |
| 瞄准模式：进袋 / 自由 | 保留 | 无可用目标时不调用无效进袋求解；不锁定最低球号 |
| 轨迹：瞄准线 / 双线 / 全部，3D关闭 | 保留 | 新球位/身份变更使旧预测失效；更新显示和求解绑定 |
| 分离角辅助线 / 运杆演示 | 保留现有能力 | 保持当前参数和开关的真实接线，不另建第二套 |
| 重新开始、重打、回放 | 按§6语义 | 运动/回放/临时俯视按共享约束禁用冲突操作 |
| 模板保存/改名/清空/摆球工具 | 页面专属 | 只作用草稿或练习副本，保存失败不能离页 |
| 开球、定组、玩法切换、规则裁决 | 不适用 | 自定义模板已经提供起始球形，无对局规则 |
| 蛇彩顺序/失败/最近成绩 | 不适用 | 模式无规则成绩，不能旁路写入蛇彩记录 |
| 编排录杆、选杆重录、批量导出、反解 | 不适用 | 首版保存静态球形，不生产教学序列 |

建议新建 `customFormationPractice`、`customFormationEditor` 两个偏好作用域。显示偏好不写进球形模板；页面内调整记住本页，通用设置再次应用后按现有机制统一更新。最后选择模板 ID 单独保存，不挤进显示偏好。

当前 `TablePreferencesStore.swift` 是工作区进行中的共享改造；实施前核其最终 API 和测试，不回退成旧的零散 UserDefaults，也不顺手改其他页面的默认值。

## 8. 数据与技术拆分

### 8.1 三层数据隔离

| 数据 | 必要内容 | 何时改变 |
|---|---|---|
| 已保存模板 | 模板ID、名称、版本、创建/修改时间、球实例及初始位置 | 新建、编辑保存、复制、改名、删除 |
| 编辑草稿 | 来源模板ID/版本、独立可变球形、是否已修改、试打前快照 | 编辑操作；保存成功才提交 |
| 练习会话 | 开练基准快照、当前球实例、在桌/收起状态、最近一杆快照与参数 | 击球、拿回、摆球、重开；不写回模板 |

每颗球至少有 `instanceID`、`appearance`（母球或1–15号外观）、位置；会话快照另保留恢复所需姿态。实例 ID 在本次练习内稳定，不能用当前数组下标或显示号码生成临时身份。

建议模板首版本地保存，使用独立 repository 和带 schemaVersion 的原子写入文件；显示偏好仍走偏好仓库。按现有 owner/游客机制划分存储归属，登录或切换账号不能意外混入另一人的模板。具体 owner 适配在实现前核当前数据层；本轮不增加云端接口或宣传同步能力。

不把用户模板写进 `Resources/Drills` 或内部 `content/position_play/sequences`。这两处承担官方内容与出片资产，生命周期和数据契约不同。

### 8.2 重复球的关键改造

当前 `BoardSnapshot.onTable` 是 `[String: CanvasPoint]`，且 `offTableKeys` 从固定 `PositionPlayBall.allKeys` 推导；`AngleTrainingScene.allBallNodes`、选球、求解参数、落袋与回放也按这些键串联。不能仅把 `[_1, _1, _1]` 传进去。

建议引入实例目录：稳定运行时 key → 外观 key。物理与交互只用实例身份，贴图与球面数字只用外观。既有页面由兼容适配器继续得到一号一球的原有键，不迁移全部官方内容。

必须贯通核对：实例创建/释放 → 节点克隆与材质 → 拖球命中 → 目标选择/轨迹求解 → 多球物理输入 → 进袋事件 → 顶部状态 → 快照/重打/回放。不同实例不得共享可变节点或互相影响选中材质。重复外观与单球数上限分开处理。

**首版球数建议**：先以“最多15颗目标球＋1颗母球、号码任意重复”为可控容量目标；这是提案，不是用户已确认的上限。必须在实现前确认是否需要超过15颗，并据此核动态实例与球库容量、物理性能。数据模型不把15写成身份数量上限，不能为了省改造偷偷禁止重复球。

### 8.3 推荐模块与接入点

| 模块 / 位置 | 责任 |
|---|---|
| `Features/CustomFormationPractice`（拟新增） | 设置、模板管理、编辑/练习协调器、自由模式状态 |
| `AngleHomeView` 的入口枚举与路由 | 同类卡片、新入口、返回；会员策略待定，不因蛇彩是Pro而自动复制 |
| `FreePlayView` 与 `PositionPlayEditorConfiguration` | 复用共享页壳，按能力注入球库模式、拖放权限、左上动作和业务菜单 |
| 独立模板 repository（拟新增） | 持久化、版本、owner隔离、原子写入和失败恢复 |
| `PositionPlayModels` / `PositionPlayViewModel` | 兼容旧键的实例目录、动态球集、完整快照与预测失效 |
| `AngleTrainingScene` / 物理与回放适配层 | 实例节点、外观映射、事件身份、资源释放 |
| 从 `BatchAuthoringView` 抽出的共享摆球工具 | 直线、微调、母球换位；移出仅模拟器编译保护的用户所需部分 |
| `BTBallPalette…` 组件族 | 支持来源球与实例球两种语义，保持现有样式/拖放规范 |
| `TablePreferencesStore` | 新页面作用域和场景接线，不复制旧偏好实现 |

不要把新功能包装成 `snakeConfiguration`，也不要为了复用球桌实例化蛇彩规则控制器。推荐小范围增加页面能力配置，控制规则、可拖球、球库来源、动作回调；不趁此重写所有球桌宿主。

几何继续通过现有投影及 `AngleSceneCalculator` 转换；世界系为 X–Z 台面、Y 向上，单位米；界面手势使用实测视口 point。微调按真实投影确定屏幕方向。此方案不新增坐标换算、袋口尺寸或物理参数；实施工具时再做数值与原图验证。

## 9. 分批实施与验收

依赖顺序：先定重复球容量及兼容边界，再贯通实例，再落编辑/练习页面。共享文件当前存在其他任务未提交修改，实施时须核差异并保留，不能用旧快照覆盖。

| 批次 | 交付内容 | 通过依据 |
|---|---|---|
| A · 实例与存储 | 同号球独立身份、模板草稿/会话隔离、本地保存读取 | 三颗同号球保存重载不合并；复制/删除隔离；保存失败不丢草稿；旧模板/旧球集兼容 |
| B · 原生入口与编辑 | 设置列表、新建/编辑/复制、球库重复添加、拖放、微调/直线/换位、试打返回 | 实际入口走完创建保存；球位精确；无工具遮挡或误触；试打不污染草稿 |
| C · 自由练习 | 任意击球、拿回、增删摆球、母球回台、重打/回放/重开/另存 | 多颗同号球分别进袋/返回；全过程无规则弹窗与成绩写入；重开恢复当次基准 |
| D · 适配与回归 | 手机/小屏、iPad横竖及窗口、2D/3D、菜单/偏好、旧页面回归 | 原生整页和交互证据；共享消费者无回归；待真机项单列 |

关键验收场景：

1. 无模板→新建→放3颗1号球和2颗8号球→直线排列其中一组→另组位置不变→保存→退出重进仍准确。
2. 只打进三颗1号球中的一颗→顶部仅一个槽变暗→拿回该实例→另外两颗身份/位置/状态不变。
3. 任意顺序击球、碰其他球、空杆、母球落袋→没有失败/犯规/强制重开；停稳后可以继续处理。
4. 全部球打进→仍能拿回→再次击球；手动全部收起不形成清台成绩。
5. 重打恢复位置、球姿态、参数；回放不二次改球库；手动改台后旧历史失效，下一杆正常建立历史。
6. 重新开始准确恢复开练基准；练习另存只存当前在桌球，原模板不变。
7. 直线取消不动球；短线、交叉障碍、边界、同号顺序均验证；微调四方向在手机横屏/iPad横竖跟屏幕方向一致。
8. 编辑试打一杆或多杆→返回摆球仍是原草稿；采用试打结果后才保存新球位；写入失败不弹回列表。
9. 2D/3D/临时俯视切换、前后台、旋转不丢实例；忙碌期间冲突动作禁用，预测过期不被误用。
10. 本页偏好独立保存，通用设置重新应用有效；模板选择不改变其他练习；蛇彩原规则/记录及公开自由走位原流程保持。

原生视觉检查以蛇彩球桌和编排工具实际组件为对照：桌面占比、上下球库关系、双尺对齐、主动作位置、完整六袋、菜单末项可达、直线取点不遮挡、最大普通字号与主要辅助字号、长模板名和容量溢出。不可用简化球桌图证明符合现有设计。

公共契约参考 `CORE-TEMPLATE-C56` 的 DC01–06/11–13/18–27 适用部分；每批以当前规范与最新用户决定核对具体能力，不继承每日规则/结果。球桌完整只适用于2D/全局观察；3D沿杆视角按可读性判断。

实施后运行与改动相称的模型/物理适配/交互回归、构建及仓库门禁；涉及模拟器先走生命周期登记。实际命令、有效测试数量、原图、设备/系统/窗口与源身份随批次记录。本文未运行新功能测试，也没有声称原生首版或真机验证已完成。
