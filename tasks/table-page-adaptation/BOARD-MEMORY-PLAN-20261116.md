# 七页球形记忆实施方案

本文件是本轮需求真源。日期为 2026-11-16，版本 v1.0，状态为全部完成。用户已于 2026-11-16 授权连续完成全部子任务；前轮使用 issue-collection 技能写方案，执行技能采用仓库的 `issue-collection-restructure`。排期入口为 B1，每批完成实现与验收后再交付下一批。

## 1. 需求回显

- 用户发现分离角与走位退出后缺少球形记忆，要求同时分析同类页面，并同意七页一起补齐。
- 七页为分离角与走位、走位求解、打一走二想三、角度与瞄准、进球容错角、翻袋、颗星解球。
- 每页恢复最近一次稳定球形，以及该页已有的目标、袋口、模式和已调输入。走位求解保存画好的约束，打一走二想三保存球序、逐球袋口及规划步骤，进球容错角保存每颗球选择的袋口。
- 拍照导入优先使用新盘面。提供恢复默认球形操作。
- 验收覆盖摆球后退出重进、击球停稳后恢复、重启 App、2D/3D 切换和手选球袋保留。

方案经用户确认后实施。以下为本轮行为合同，导入归属、求解重建和中断恢复按此执行；实际完成状态见第7节及结果记录。

## 2. 现状与实际依赖

| 页面或组件 | 现状 | 实施影响 |
|---|---|---|
| 分离角与走位 | 正式导航进入 `PositionPlayComposerView`，新实例载入默认球形或 `initialBoard` | 存档接入必须走正式 composer 宿主，覆盖首页与理论文章路由 |
| 走位求解、打一走二想三 | `setupScene()` 建默认球形，随后 `onSetup` 应用导入；约束和上一杆快照在内存中 | 导入、存档、默认三者的选择必须在初始化时统一决定，避免先恢复再被 `onSetup` 覆盖 |
| 角度与瞄准、进球容错角 | 共享 `BTTeachingTablePage`，模型初始化摆默认球；容错页 `pocketsByBall` 为内存字典 | 可共享生命周期接线，各页明确保存自己的字段 |
| 翻袋、颗星解球 | 共享 `SolverStageChrome`，现有 `captureBoard/applyBoard` 支持球位和姿态 | 翻袋快照另含目标身份，颗星快照使用 `__cue/__target`，需要显式序列化和球号映射 |
| `PositionPlayViewModel.TrainingInput` | 可编码方向、模式和参数；`restoreTrainingInput` 固定 `manual: true` | 新存档需要记录自动／手选来源，避免自动推荐恢复后被永久锁成手选；既有消费者做兼容回归 |
| `SolveConstraintDraft` / `SolveShotSnapshot` | 前者保留区域、落点、过点语义，后者包含解集、预测和内存状态；均非现成持久化模型 | 为用户输入建立可编码表示，恢复时从输入重建计算结果 |
| `TrainingCheckpointStore` | 支持 owner 隔离及原子写入，但以考核项目 `TrainingProject` 为键 | 复用其隔离与原子写入做法，按七页身份建立独立草稿命名空间 |
| `CustomFormationProgressStore` | 已有模板进度校验和输入恢复；无目标球时返回无可续练记录 | 自由摆球需要保存合法空桌、仅母球状态，读取判定按自由页面语义实现 |

每日清台、多球走位、自定义球形作为已有恢复能力的回归消费者。蛇彩沿既有训练会话合同。动作试打和模板编辑使用各自入口合同。

## 3. 已确认行为

### 3.1 进入页面与隔离

1. 有显式导入球形时，应用本次导入；普通进入时读取本页、当前用户的最近有效草稿；首次使用时显示现行默认球形。
2. 每页使用独立身份，同页的 2D、3D 和临时俯视共用业务草稿。游客与账号按现有 owner 规则隔离，切换 owner 时结束旧写入订阅，再读取新 owner。
3. 导入成功后将该盘面作为该页当前工作盘面，后续编辑及停稳保存为该页最近草稿；再次从首页进入可继续这副导入盘面。显式保存成自定义球形继续作为独立操作。
4. 显示偏好沿用既有设置存储。打开菜单、切视角、旋转和更改窗口尺寸均继续使用当前业务状态。

### 3.2 保存时机与稳定性

| 事件 | 处理合同 |
|---|---|
| 加球、撤球、拖球松手 | 提交完整盘面，再保存一次稳定草稿 |
| 手选球／袋、修改输入、约束绘制完成 | 保存输入与选择来源，连续输入合并写入，离页前补齐最后一次提交 |
| 普通出杆前、开球前 | 先保存可恢复的出杆前状态；开球待发状态保存其玩法和阶段 |
| 普通击球／开球停稳交接 | 保存正式业务交接后的终局与下一杆选择 |
| 回放开始、回放中途、回放结束 | 保存并保留回放前的工作盘面，结束后回到该盘面 |
| 切后台、退出 | 先按各页现有生命周期收敛拖动／播放，再提交有效快照；序列号隔离迟到求解和防抖回调 |
| 杀进程后重进 | 恢复最后成功提交的完整状态；击球中断按出杆前快照恢复；完成交接则恢复停稳盘面 |
| 恢复默认球形 | 取消本页旧任务，恢复现行默认球形及与其关联的初始选择、约束和输入，并立即持久化；显示偏好继续沿本页设置 |
| 清空桌面／撤到只剩母球 | 按本页现有清桌行为保存实际结果，重进读取该状态 |

保存应具备版本、owner、页面身份和有效性校验，并以原子写入替换当前完整草稿。恢复过程中抑制默认盘面及半恢复状态写回。损坏／不兼容存档保留原件，在现有提示层提供原因和明确的恢复默认操作；写入失败保留上一份成功记录。重试成功后解除错误状态。

同页出现多个活实例时，采用明确的会话所有权或修订校验，防止旧实例离页回调覆盖新盘面。文件数量和保留策略在 B1 定义，使用“每页最近草稿”这一产品范围。

### 3.3 每页字段

| 页面 | 需要恢复的用户状态 | 恢复后的计算 |
|---|---|---|
| 分离角与走位 | 在桌球／球位、目标球／袋口、自动或手选来源、进袋偏好与实际模式、自由方向、杆速／打点，开球待发时的玩法和阶段 | 一次恢复完成后重算轨迹；自动态继续全桌 v9 比较，手选态保留有效球袋 |
| 走位求解 | 盘面、目标／袋、落区形状与边界或落点／过点、容差／过点速度、求解选项、已调输入 | 恢复约束图形，再按现有自动求解规则重算；求解完成后才建立可击球状态 |
| 打一走二想三 | 盘面、①②③球角色、第一／第二袋、当前规划步骤及完成状态、现有约束及已调输入 | 从已选输入重建角色、袋口标记和推荐区域，保留未完成步骤，按现行条件求解 |
| 角度与瞄准 | 盘面、当前目标、选袋 | 重算切角、瞄准与辅助图形 |
| 进球容错角 | 盘面、当前目标、每颗在桌球的袋口映射，含未选袋状态 | 恢复当前球读数，切球时读取对应袋口；撤球按现行规则处理其映射 |
| 翻袋 | 目标身份、母球／目标／障碍球及姿态、袋口、求解／自由模式、库数筛选、自由方向和杆速／打点 | 沿真实球号恢复，再按当前模式重建求解或自由预览 |
| 颗星解球 | 母球／目标／障碍球及姿态、求解／自由模式、库数筛选、自由方向和杆速／打点 | 用本页目标身份和现有求解合同重建预览 |

求解缓存、上一杆和回放具有独立的运行时依赖。本轮把持久化范围定为当前盘面及可编辑输入，重进后由现行算法重建有效解。微调参数仅在恢复得到匹配的有效路线后应用；失效参数须有明确回退，不能显示旧解却击出新路线。会话内重打／回放仍用原有真实快照。若后续要求跨启动回放上一杆，单独定义轨迹、版本和存储量合同。

### B1 完成标准

- 正式首页路由完成摆球、手选、退出、重进、重启 App 的恢复链，拍照盘面压过旧草稿且后续可续练。

- 验证空桌／仅母球、恢复默认、稳定停球、普通击球中断、开球待发及开球停稳、回放中断。

### B2 完成标准

- 两页分别恢复真实修改过的盘面和手选内容；走位求解逐种覆盖区域、落点、过点，形状与语义一致。
- 打一走二想三覆盖完整规划和至少两种未完成步骤，角色／袋口标记与可操作步骤一致；撤销后重进不复活已撤内容。
- 拍照交接、重启、求解中离页、播放中断都有明确后置状态；迟到求解不得回写另一副球形。
- 恢复后至少执行一次真实求解与击球，核对实际参数和球袋；相关上一杆快照回归通过。
- 构建、定向单测、两页原生恢复流程通过，并保存恢复前后截图。

### B3 完成标准

- 两页真实改球位、增撤障碍球、改模式和库数后退出／重启恢复；翻袋另覆盖更换目标球号和袋口。
- 球位与姿态用实际保存对象核对，`__cue/__target` 与真实球号映射一致。
- 自由模式方向、力度、打点恢复后可实际击球；求解模式恢复后产生当前盘面的有效结果。
- 中断与回放恢复符合稳定盘面规则；构建、定向功能测试、两页原生恢复流程和前后截图通过。

### B4 完成标准

- 角度与瞄准恢复多球、当前球与袋口，读数与球位一致。
- 进球容错角至少三颗球分别设置不同袋口，退出重启后逐球切换核对；覆盖未选袋和撤球再添球。
- 七页各自写入可区分的球形，顺次退出重进核对页面隔离；验证共享 owner 切换后的归属。
- 每页至少有一次完整退出重进及杀进程重启用例；整体覆盖 iPhone 与 iPad、2D/3D、iPad 旋转，生命周期较复杂的三页及两个共享宿主各有代表设备覆盖。
- 归档每页功能结果、原生截图、失败与复验、设备和源码版本。真机体验另列实际验证状态。
