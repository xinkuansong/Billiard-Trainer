# 手动选球／选袋反馈与 iPad 多球设置复验

2026-10-27 开始，跨日至 10-28。FL-215；上轮合同为 [规划上一步与球库标记](PLANNING-PREVIOUS-AND-PALETTE-20261027.md)。用户授权修复并验证，不改动作库静态图。

## 根因与处理

多球规划第二／第三球及球库已有角色只改业务游标，没有调用原有 TableBallPulse；持续角色袋只更新材质，没有显式触感事件。P05选袋和三球下一袋同样遗漏。普通当前目标球原本有脉冲，但震动依赖自动推荐袋，无法可靠表达选球本身。

- 多球第二、第三球及球库角色定位接入共享 `confirmBallSelection(key:)`，成功的当前球选择由 PositionPlayViewModel 统一触发。复用原 1.7 倍、0.18 秒放大／0.24 秒复原；不改变物理球位，不改变球库尺寸。
- 普通选球的自动配袋视觉保留，取消同一操作的重复配袋触感；一次手动选择只确认一次。
- 角色袋采用 `confirmRolePocketSelection(at:)`，只确认选袋事件，不覆盖天蓝／金黄的持久颜色和同袋双色。三球在保存成功后反馈，非法索引、缺前提和不可编辑阶段不反馈。
- P05已有角色的球库点击补定位反馈；思路、角度交互、分离角图谱、加塞图谱的手动目标选择补原有脉冲，已有选袋确认保留；防守页合法选球补脉冲和确认。
- 两球／准度／分离角等固定题库球不增加手选权限；三球只补已有下一袋能力。球形提取的编辑选中／取消选中保持其独立编辑语义，未改静态资产或导出链。

## iPad 验证范围

原中断用例原样重跑，测试体 68.642 秒通过，未增加等待或跳过断言；尾部 Xcode 独立诊断子进程等待，核所属后仅中断该诊断，xcodebuild 最终零退出。此次未复现原用例中的 60 秒动画通知等待，没有为此修改产品生命周期。

最终扩展用例继续覆盖规划→自主：取消保留原计划，开始切换；自主→规划：取消保留球位及状态，开始生成规划并手动选袋。2D、3D及iPad横竖屏分别记录实际结果。首次新增诊断输出漏字段导致UI取证失败，保留原失败并补字段重跑，不放宽断言。

最终验证与原图见 [报告](../ui-reviews/UR-20261028-selection-feedback.md)。原始证据在 `output/selection-feedback-20261027/`。真机触感、系统VoiceOver实操和全App回归不由本轮模拟器替代。
