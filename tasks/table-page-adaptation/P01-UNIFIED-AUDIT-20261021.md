## 2. 需补齐的整改项

### R01 · P1 · 不可击球时缺少可见原因

- **条款**：TP13、TP24、TP35。
- **已确认代码事实**：`PositionPlayViewModel.recompute/apply`会将缺少输入、预测不可行、模拟未完成等原因写入`statusText`并关闭`isFeasible`。本页击球按钮因此禁用，但现行`dailyFeedbackOverlay`没有P01不可执行原因分支；`simulationReadout`只显示切角/厚薄。旧`BTSolverNavStatus`位于被隐藏的导航栏，且静止P01的`navigationStatusText`本身返回nil。仅击球点击后专门转发`CueStrikeAccess.unavailableMessage`不能覆盖按钮已经禁用的情形。
- **影响**：出现相应状态时，用户只看到灰色击球键或空读数，无法知道该调整什么。此项是提示接线缺口，具体真实失败球形尚需运行复现。
- **建议整改**：在现有不占布局行的提示位置呈现当前阻断原因；计算中、播放中、相机切换与真正不可行分开，不显示陈旧结果。恢复可用后清除；不恢复已被精简的成功播报或常驻模式说明。
- **验收**：通过真实输入分别进入缺必要目标/参数、不可行预测及恢复状态；说明与禁用原因一致，旧异步返回不覆盖新提示；正常可出杆不多一行，不把自由模式合法空杆当作错误。
- **依据**：S02的1225、1467、1992、2194、2226行附近；S03的1709、1985、2068行附近。

### R02 · P2 · 球库拖放提交没有使用松手事件的位置

- **条款**：TP06、TP18。
- **已确认代码事实**：`simulationPaletteDrag.onChanged`调用`BTPalettePlacement.sample(value.location)`；`onEnded { value in ... }`没有读取`value.location`，直接提交`projector.palettePreview?.requestedWorld`，即上一次变化事件的结果。共享采样器本身能够从当前触点做合法位置约束。
- **影响**：最后变化事件与松手事件不同、尤其从有效区移出后松手时，提交可能沿用旧合法位置；反向进入有效区也可能丢掉本次放球。是否在具体设备手势中出现、频率多少，本轮未实测。
- **建议整改**：松手时使用同一投影/约束链重新采样末触点，再决定提交或取消；结束/取消清除旧预览。保留52pt防遮挡、两目标上限、母球规则，不另写坐标偏移补丁。
- **验收**：台内→台外、台外→台内、快速末段、边界/重叠/满额、旋转或切模式取消；核实际落点与最终合法预览一致，取消不放球。涉及共享宿主时补编辑页调用方回归。
- **依据**：S02的247–276行，S04的409–442行。

### R03 · P2 · 旧测试入口与菜单行为未随现行页面收敛
