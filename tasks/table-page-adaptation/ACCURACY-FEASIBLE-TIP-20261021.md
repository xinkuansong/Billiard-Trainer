# 准度出题：可行打点接入（2026-10-21）

用户反馈：2D准度母球靠右下角袋，题目固定左塞，击球被“当前方向受库边或球遮挡”拦住。原因是出题只按九打点配额分配，未与正式CueStrikeAccess可行域衔接。球形可入库不等于任意指定打点都能出杆。

## 用户确认规则

1. 开启高低杆／左右塞：与对应允许轴向取交集，在可行打点内随机。未开启的轴保持0。
2. 两项都关闭：优先中杆；中杆不可行时左右保持0，向上搜索最低可行高杆并留数值余量，显示“高杆（避让）”。
3. 无可行打点时先在同组合更换球形；候选耗尽或256次未命中时，本轮暂排除该组合并在所选条件内重校准，页面明确提示比例受限。不会放宽用户条件。球形库、入库物理筛选与抽题目标权重不改。
4. 可行性按正式有效入袋点的假想球方向判断。本题打点选定即固定；用户调方向后按当前方向检查，不动态改指定打点。

## 实现

`AccuracyTipSelector`复用正式CueStrikeAccess、30°抬杆上限、当前球杆模型／样式的实测轮廓及页面台面／球心高度；不修改现有库边避让几何，也不绕过击球守卫。

连续随机先在允许轴／圆盘拒绝采样（128次上限）；狭小区域补33×33或33点离散候选并随机选取。默认抬高先扫描64层，再在首个可行区间二分18次；数值余量0.00035R，复验后才采用。搜索有限，未命中不等同连续空间无解。

TrainingGridBank增加可选accepting入口：抽中组合后同组合无放回替换，每次抽中组合最多尝试256个候选；耗尽或未命中后本轮暂排该组合，保留目标权重并对剩余支持重新校准，提示“部分组合未找到允许的可用打点，本轮已在所选条件内重新分配比例。”全部不可用则明确失败。普通角度／瞄准出题不传此过滤，原抽题行为保持。准度不再使用旧4题中杆／16题其他打点配额。

`AccuracyTip`保存精确x/y及避让标志；题目与冻结尝试新增可选exactTip，旧九分类保留用于总结和旧记录读取。variantID包含精确坐标位模式。击球、打点盘、回放均消费精确值；旧尝试按旧坐标读回，不改历史成绩；旧版未出杆题目提示重新开始。SwiftData实体未变，载荷向后兼容。

## 验证状态

已通过：iPhone SE / iOS 26.3，7项定向测试0失败（r5：8c75cec0eeea4abdb71678dcefaa71a5）。包含4种开关×20个种子共80轮1600题、同组合换题／整组合暂排重校准／全部不可用失败、精确打点冻结及旧记录解码。

实际题库中抽取四边库／六袋口共10例，5例中杆、5例高杆避让；全部通过正式AngleTrainingScene.permitsCueStrike。导出原生可行域网格及精确打点后渲染10张核对图，已检查靠角袋高杆及靠短库中杆图。验证图：`output/accuracy-feasible-tip-20261021/可行打点验证.html`。这是出杆可行性验证，不是这些球形的进球解验证。
