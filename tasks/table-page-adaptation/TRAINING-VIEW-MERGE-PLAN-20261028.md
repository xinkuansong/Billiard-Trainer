# 练习页面 2D 与 3D 合并方案

日期：2026-10-28 · 版本：1.1 · 状态：方向已确认，方案已整理，代码未实施。

用户原话：“可以，按这个方向，先把需要合并的页面梳理一下，出一个完整方案，2D和3D共用题目额度，自由训练保留Pro，先不要改代码。”

本方案将七组成对入口合并为七个训练项目，在同一题目内切换视图。免费用户可用两个视图，同一项目共用每日额度；不限题的自由训练模式继续需要 Pro。**本轮只产出方案和规格记录；下文批次、接口和测试均是待实施工作。** 用户确认的是上述方向，本文补充的迁移和交互细节是拟采用方案，不伪称已逐项获验收。

2026-10-28追加决定：“所有的20题的都换成15题吧。”本方案内原20题的六项免费日额度和普通模式每轮题数统一改为15题；多球仍3题，不限题自由训练仍Pro。以下源码现状中的20题仅为迁移基线，不是目标值。

活动入口为本文；逐项适用性见[检查表](TRAINING-VIEW-MERGE-CHECKLIST-20261028.md)。通用视觉与交互依[球桌统一规范](../../docs/design/table-pages/球桌页面统一规范.md)，每日参考的当前状态只查[每日 CURRENT](../daily-adaptive/CURRENT.md)。

## 1. 页面清单与边界

直接核对 `AngleHomeView` 目录、`MainTabView` 正式目的地、七组页面消费者及额度服务。当前有 **14 个路由入口、7 组业务页面**，多数已经复用同一个 Swift View，但用固定视图参数创建不同业务身份。减少的是七个重复入口，不是删除七套独立引擎。

|编号|现有正式入口及路由|所在分区|合并后名称|免费额度|业务与迁移重点|
|---|---|---|---|---|---|
|M1|2D角度 `sceneAiming2D`／3D角度 `sceneAiming3D`|练习 Tab → 练|角度练习|15题/天|数字作答、角度误差、辅助标记；提交前后切换不揭题或再记分|
|M2|2D瞄准点 `aimPointScene2D`／3D瞄准点 `aimPointScene3D`|练习 Tab → 练|瞄准点练习|15题/天|调方向、毫米误差、圆形结果特写、验证击球；答案和验证动作分离|
|M3|2D准度 `accuracy2D`／3D准度 `accuracy3D`|练习 Tab → 练|准度练习|15题/天|固定题目球位/袋口，击球轴权限，首杆成绩，重打不覆盖首杆|
|M4|2D分离角 `separationPractice2D`／3D分离角 `separationPractice3D`|练习 Tab → 打|分离角练习|15题/天|目标轨迹、杆速/打点、首答和重试统计、测量工具；不改评分|
|M5|2D两球走位 `twoBallPractice2D`／3D两球走位 `twoBallPractice3D`|练习 Tab → 打|两球走位|15题/天|轨迹走位／自由走位两种题型保留，同题多路线与下一球袋口保留|
|M6|2D三球走位 `threeBallPractice2D`／3D三球走位 `threeBallPractice3D`|练习 Tab → 打|三球走位|15题/天|同题两杆，首杆后承接真实球形与已选袋口；整题只扣一次|
|M7|2D多球走位 `multiBallPractice`／3D多球走位 `multiBallPractice3D`|练习 Tab → 打|多球走位|3个新球形/天|顺序／中八、不同球数、规划／自主和两个视图共用额度；完整清台才是一道题|

以上额度是**各项目独立、项目内两视图共用**，不是所有七项合起来15题，也不是2D15题加3D15题。M5两种题型共用两球额度，不再拆出“自由走位额度”。M6当前源码已有独立20题额度，目标随本轮统一调整为15题。

### 保留的独立项目

|项目|处理与理由|
|---|---|
|角度预测 `geometricQuiz`、瞄准点训练 `aimPointTraining`|保留。分别是独立预测/拖假想球题型，不是场景页的另一个视图；原共享额度不并入M1/M2|
|每日清台|只作切换交互参照；保留每天1局及现有计局规则|
|蛇彩练习|没有成对入口，保留原Pro与规则|
|自由击球、自定义球形、分离角与走位|独立自由击球/编辑/实验工具，保持现有权限；不能按名称中的“自由”统一加锁|
|自由走位推演、思路训练、打一走二想三、防守、翻袋/颗星、图谱、教学与编排|不属七组成对练习入口，本轮不合并、不改权限和分区|

名称建议采用表中短名；M2卡片副标题明确“球桌场景中调方向，比较瞄准误差”，与原“瞄准点训练／拖假想球看毫米差”区分。保留当前「练／打」归属及相对顺序，在原一对入口的首个位置显示合并卡片；不借本轮重排整个练习 Tab。

## 2. 权益和题量合同

### 2.1 用户看到的规则

- 2D／3D均开放，菜单视图项不挂PRO锁；首页合并卡片不再因为有3D能力整卡加锁。
- M1–M6普通模式每轮改为15题，M7每轮仍3题；实际可开始题数受当日剩余额度约束。Pro取消**每日上限**，普通模式每轮同样按15题收尾，多球仍按3题。
- 各项目设置中的“不限题自由训练”保留锁形PRO。两球的“自由走位”是题型，可以在免费15题模式使用；它不等于不限题的自由训练。
- 训练设置显示“今日剩余 X 题，2D与3D共用”；训练球桌不新增常驻余额行，沿现有精简信息布局。
- 额度耗尽时允许进入设置、查看结果以及使用本题已允许的观察/重打/回放能力；开始新题、新球形或重新开始新轮次时进入既有会员流程。未开始的预取题不能绕过额度。
- 最后一题保留完整结果。M1/M2公布答案后仍不新增同题重答；“不重复扣题”不意味着所有页面都获得重打按钮。
- 会员权益文案建议：“专项练习不限每日题量，支持不限题自由训练。”删除七项对应的“解锁3D训练”，补齐三球；其他Pro权益、价格、登录和恢复购买流程保持。

例：准度当天2D完成6题、3D完成4题，剩5题；某题从2D切3D再切回只算一次。角度项目余额不受这10道准度题影响。

### 2.2 一道题何时计次

保持各业务既有计次时点，消除对视图的条件判断，不一律改成“打开球桌就扣题”。

|页面|计次事件|同题不另扣的事件|
|---|---|---|
|M1/M2|首次有效答案被接受，答案与稳定扣题凭证同时形成；结果保存重试复用该凭证|切视图、辅助状态更新、答案查看、M2验证击球及其失败重试|
|M3|本题首杆有效结果成功保存|同题重打、已存在回放、跨视图查看与保存重试|
|M4|本题首个完整试打/提交结果成功保存|同题调整和重试、测量工具、观察|
|M5|沿现有题目消耗状态：本题首次结果或业务明确的跳过成功保存|同题新轨迹、两种视图、重试；新路线不生成新题扣题身份|
|M6|本题首杆结果成功保存，包括合法完成的失败结果|第二杆、首/第二杆重打、切视图、两杆均分结算|
|M7|新球形成功成为当前可用题目时|当前球形同题重开、各杆击打、规划选择、切视图|

题库空、生成失败、非法输入、缺少必要选袋或模拟未完成不计次。M3–M6保存失败保留结果等待重试，不把失败当新题，也不在未保存时放行换题。M1/M2现为先计次后异步保存，实施需补可恢复的待保存答案与幂等凭证，不能用简单回退次数放开重复作答。

正常提交后答错、未进球或规则判负属于已完成的作答结果，仍按表中事件计一次；只有技术失败或尚未形成有效作答不计。M6首杆合法完成但失误为0分，也不免扣。

计次唯一键使用“项目＋本次题目实例ID”，不使用视图、当前尝试ID或纯题库ID。抽到同一题库球形但属于下一道新题时有新实例ID；同题重打沿用原实例ID。一次题目的首次消费时间固定，跨午夜恢复已消费题不扣新一天；未消费题在当天实际提交时扣当天额度。日期边界沿现有本机自然日口径，不增加账号/服务端配额。

### 2.3 持久化与权益变化

- 复用七个现有额度桶和当日计数，兼容名称含`2D`的旧存储键；逻辑名称可以中性化，第一阶段不为去掉字样清零或复制计数。旧ledger与计数的并集去重，不把旧计数再次累加。
- 20→15迁移不清零已用题数：当天已用12题则剩3题，已用15题或更多则剩0题；已获准的当前题仍可完成，随后按新上限拦截新题。旧20题轮次保留全部已存成绩，达到15题后不再追加新题；不删除历史第16–20题，新轮次统一15题。
- 先写可恢复业务事实/扣题凭证，再以幂等操作兑现计数；恢复时补账。M1/M2待保存队列和M7新球形激活需有持久凭证，避免崩溃后丢题却已扣次数，或重复恢复再扣。额度账本与草稿分开，删草稿不退款。
- Pro新作答不消耗免费余额；升级前已消费的免费额度保留，升级/恢复购买不重置，降级后仍按当日真实余额。迁移时保留旧版本已记的计数，不追溯重算历史Pro使用。
- 非Pro在两个窗口/两个页面实例并发申请最后一个名额时，通过同一串行额度服务处理；尚在进行的题目持有临时名额预留，取消未作答题释放，重复回调不另扣。预留不对用户显示为“已完成题数”。需要原子持久保证和崩溃回收证明，不能只在按钮上检查一次余额。
- 权益在击球中变化，允许本杆完成、保存和展示。普通模式继续当前已获准题；Pro自由训练在安全杆末保存并提示升级或结束，停止启动下一杆/新题。取消购买保留球形、结果、输入和设置草稿，不自动出杆。
- 购买成功后恢复用户原先的“开始/下一题”意图；从自由训练选项升级只选中该模式，不自动开始。权益尚在检查、失败和取消分别沿现有流程，不把未解析等同于已购。

## 3. 合并后的页面与切换

### 3.1 入口流程

`练习目录 → 合并项目 → 统一训练设置/可恢复训练 → 同一球桌 → 三点菜单 → 显示 → 视图 2D / 3D`

设置页沿现有正式导航：iPhone完整竖屏设置，球桌横屏；iPad支持横竖及窗口恢复。取消返回原题和原设置；确认开始才产生新轮次。新入口的首选视图按：恢复草稿视图 → 项目上次选择 → 通用默认 → 2D初值。旧3D直达路由作为兼容别名时，以3D打开同一项目；不得开出另一份会话或重新加Pro锁。

视图分段复用每日菜单样式，普通选档后保持菜单。2D/3D切换不新增确认弹窗、不自动下一题、不改变玩法、不重置操作计时。现有3D内的临时俯视保留其短时观察语义，与正式2D模式明确分开；它不覆盖正式偏好或2D操作布局。

### 3.2 状态转换规则

|当前状态|视图切换|必须保留/禁止事项|
|---|---|---|
|准备作答、调参、两杆之间、已结算结果|允许|题目实例、球形、杆序、方向/打点/杆速、袋口、规划草稿、成绩、额度凭证不变|
|数字输入弹层、打点拖动、球/袋拖动|先正常结束或取消当前输入，再切换|不丢已提交输入；不把屏幕坐标直接当新投影世界位置|
|求解/提交/保存事务、出杆/运动、自动验证、现有回放播放中|分段保留可见但禁用，结束后恢复|不取消已承诺杆、不重放运动、不因相机事件再次触发保存；保存失败先恢复/退出安全状态|
|结果静止查看、现有回放停止后|允许|不改首答成绩；公布答案仍保持结果阶段|
|操作布局编辑、需台面操作的测量工具编辑中|先退出该编辑状态|保存/取消按原合同；测量几何用世界坐标重投影，切换不生成新参考|
|后台/恢复/窗口旋转|恢复正式视图与最后有效状态|旧相机转换、旧求解/播放回调不能提交到新页面|

稳定持有同一个ViewModel和场景宿主。相机缓存只存机位，不能把题目/评分复制进CameraRig。2D→3D恢复该题上次合法3D机位；新题使过期聚焦失效。临时俯视结束后回原正式3D，正式切2D后则留2D。

### 3.3 答案和能力边界

- M1角度/M2瞄准点切换前后保留同一作答阶段与辅助使用记录，不新增正确线、正确角、假想球答案或新重答机会。
- M3准度继续按现有合同开放方向、杆速及击球轴；正确线路/预测轨迹继续隐藏。允许的瞄准特写只放大现有信息。
- M4/M5/M6保留各自目标轨迹、题型、固定球/袋、首答统计和重试规则，视图不决定题目难度或评分算法。
- M7保留顺序/中八合法球权、规划/自主、顺延锁袋、重打恢复；切换不能让对方球变可选或重摆整桌。
- 最新测量/几何参考能力以[2026-10-28任务卡](GEOMETRIC-REFERENCE-20261028.md)和真实代码为准；M4–M7不得因旧页面卡写“回放”就重新添加已被替代的入口。M3及其他仍有回放的消费者保留其能力。

完整菜单能力按[检查表§3](TRAINING-VIEW-MERGE-CHECKLIST-20261028.md)接线，不整套复制每日菜单。

## 4. 记录、统计与旧数据迁移

### 4.1 新身份分工

拟将现有固定`is3D`的多重职责拆开：

|概念|唯一职责|
|---|---|
|练习项目身份|导航、额度桶、记录类型和题库入口；七个稳定项目|
|训练模式|普通定题数／不限题自由训练；控制Pro门槛|
|题型/玩法|两球轨迹/自由走位、多球顺序/中八及规划/自主；不由相机决定|
|正式视图|可变2D/3D，控制呈现、相机与输入映射|
|临时观察状态|3D内临时俯视等，不替换正式视图身份|
|会话/题目/尝试身份|分别控制续练、题数和每杆记录；切视图不创建新身份|

不先抽象一个承包七种业务的巨型ViewModel。各现有VM/Controller保留本页状态机，复用视图选择和额度/身份适配能力。无新依赖、无生成器或物理参数变更。若实现需要改SwiftData Schema、跨层接口或同步契约，实施批次先补对应Phase ADR和迁移设计；本方案没有宣告这些结构已改。

### 4.2 成绩与历史

- 新记录保存正式视图、提交前实际观察过的视图集合；临时俯视也计入观察，避免标为纯3D。结果之后再切视图不追改该次作答记录。
- 新会话按统一项目聚合，详情/统计可区分“2D／3D／混合视图”；沿现有辅助与评分版本维度统计。混合视图结果不伪装纯3D，无额外惩罚或系数。
- M1/M2目前历史按`quizType`和时间间隔分组。新记录优先稳定会话ID和统一项目，`quizType`兼容旧读取；测量单位仍分别为度/毫米，不能因为新中性标识丢掉毫米识别。
- 旧记录原始`quizType`、`sourceId`、`is3D`、评分版本和分数不批量重写；只用读取适配映射到统一项目。旧3D记录按“旧3D入口”保留，不臆造其从未使用过临时俯视。
- 不新增历史题目详情浏览权限，不修改60天历史边界或其他会员权益；退出/重新进入同题不另建记录。

### 4.3 草稿与偏好

- M3–M6当前Repository按2D/3D `sourceId`各自查询草稿。合并读取时保留两份旧草稿：默认继续最近更新且兼容的一份，另一份作为可选旧进度保留；显式开始新轮次按现行确认处理，不能直接覆盖第二份。
- M1/M2不能凭相机合并假定已支持完整跨启动恢复。实施补齐本轮视图、会话ID、已接受答案和扣题凭证的持久恢复；不因此增加历史题目重答功能。
- M7当前控制器主要持有运行时球形与进度，新球形激活凭证至少须与可恢复球形快照同写，包含球形ID/初始与当前状态、规则/题号、额度事件。实现前核对FreePlay宿主已有存储，复用适用者，不假定已有完整跨重启续练。
- 显示偏好继续用`TablePreferencesStore`“本页覆盖→通用值→初值”。统一项目增加视图偏好支持；旧2D/3D显示值冲突时，先保留两份备份，首次根据实际恢复/打开的旧视图选取为新项目值，之后显式选择覆盖。不编造旧记录没有的“最后修改时间”。
