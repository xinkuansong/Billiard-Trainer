## 1. 目标、范围及决定来源

用户2026-10-25要求在“打”中增加两球走位练习，主要功能和训练设置参考分离角；提供轨迹走位／自由走位，默认轨迹走位；明确跳过→击球→新轨迹／下一题及重打状态；遵循球桌页面统一规范。随后确认“两种模式都纳入，2D和3D一起做，自由走位先沿用题库的难度指标，越低越好，生成端脚本不要改”。

### 1.1 本轮产品范围

1. 正式入口“2D两球走位”“3D两球走位”，放在练习首页→打，紧接分离角两个入口；保留原分离角、自由击球、自由走位等页面。
2. 每道题固定母球C、第一目标球A、第二目标球B及第一球目标袋；用户只调整打点、杆速，系统对第一杆补偿瞄准。
3. 轨迹走位：每题练习该B位置下的有效推荐路线，每条按母球碰A后的轨迹相似度评分。
4. 自由走位：出杆前固定B的指定袋口；只打第一杆，根据实际停点评价第二杆几何难度；不要求用户执行第二杆。
5. 两种模式共用题库、三球物理、页面组件、恢复与记录基础。2D/3D分别持有场景和轮次，使用同一物理与评分代码。
6. 同期覆盖入口、设置、权益、完整状态、结果、重打/回放、持久化、历史摘要、预取、iPhone/iPad适配及回归。

## 3. 题目、模式、设置与权益

### 3.1 身份

- 内容题目键：结构化`{layoutID, cellID}`，其中layoutID保留原字符串；显示/日志拼接需转义，不依赖按冒号拆解。
- 题库版本键：manifest的schema、contract及索引/资产摘要；相同题目ID跨版本不视为同一内容快照。
- 路线键：`{bankVersion, layoutID, cellID, comboIndex}`。comboIndex只在当前初始球形内有效。
- 每次出题另建questionInstanceID，区分同内容再次抽到；sessionID、ownerKey、正式维度、业务模式分别保存。
- 同一轮不重复内容题目；候选耗尽时明确结束/调整条件，不静默重复、扩角度或增加杆法。

### 3.2 设置表单

同一“练习模式”分组使用两行现有segmented样式：先“轨迹走位／自由走位”，再“20题／自由练习”。模式首次/重置默认轨迹走位，已有个人选择按本页偏好恢复；首次数量20题。与“自由摆球”无关。

|设置|默认及含义|接线和边界|
|---|---|---|
|击球|开；保持分离角播放选择语义|开：提交后揭示实际线1.5秒再正常出杆；关：提交计算并展示结果，不自动播放，仍保存真实完整物理结果|
|中杆参考|关；继承分离角阶段规则|当前路线/自由题首答前显示固定0/0/2.5参考；提交后按开关决定是否保留；无可用参考不伪造、不阻塞有效目标题|
|角度范围|近直球、小角度、中角度（0–50°）|筛选第一球球形，沿现行SceneTrainingConfiguration语义；其他角度仍可选|
|球形条件|距离、袋口类型、库边距离默认随机|全部指第一杆C/A/第一袋口，复用现行TrainingBankStore筛选语义；不直接拿board.angle当正式实测切角|
|出题杆法|允许高低杆、允许左右塞均开|按推荐路线spinX/spinY筛选，禁用轴要求源参数零值；不量化改写路线，不限制用户练习输入|
|开始／重新开始|表单草稿确认|冻结完整配置；取消恢复原轮次/题目/参数，不写入草稿|

两种模式所有设置都有效。自由模式的杆法选项用于筛选“能提供该题指定袋口的推荐解”，不限制用户以其他杆法完成。新页专有模式配置包裹现行公共配置，不能为支持本页破坏旧payload。

补齐“击球关闭”的文案映射：轨迹未修改仍叫“跳过”；已修改/重试就绪叫“提交”，结果仍为“新轨迹／下一题”；辅助键沿分离角叫“重试／击球”。开启击球时使用用户要求的“击球／重打／回放”。关闭只影响呈现，不改变计分、三球模拟和按钮状态逻辑。

### 3.3 权益与计数（沿分离角体系的本页落地规则）

- 2D每天20道球形题，两种走位模式共用本功能独立额度；不占分离角额度，不因切模式获得第二份额度。
- 3D与“自由练习”沿现有Pro门控；“自由走位”本身不是Pro条件，2D的20题内可选择。
- 一道题首次成功持久化“提交或跳过”时计一次消费，幂等键为questionInstanceID；同题其余路线、重打、回放均不再消费。未展示的预取、求解/保存失败不扣题。
- 跳过属于处理题目但不是练习成绩；全题跳过也会推进20题进度并占该题额度，不能用无限跳过绕过日额度。
- 第20题首条轨迹后即使已到日额度，也必须允许完成该题其余路线与重打；额度仅阻止新题。跨日按原消费时间与实例账本恢复。
- 购买取消可退出；预取不触发购买弹层；前台消费和新题交付时重新核权益。真实购买依赖已有账号协议项，不能用本地StoreKit测试宣称真实沙盒通过。

## 4. 题库消费、筛选与切换

### 4.1 关联与校验

每条JSONL是一个初始球形。读取`board.cue/object/pocket/aim`建立C/A/第一袋口，按一个`candidate.position`放置B；`candidate.top5[].comboIndex`仅在同一行`routes`内查找。目标轨迹取`trajectory2mm.points`，不使用candidate数组索引作为cellID，不将所有候选B同时放上桌。

验证schema/contract支持、分片SHA/字节数、ID唯一与引用完整性、有限数值、袋口0…5、打点合法、路线时间非倒退、点格式、mandatoryPointIndices合法。重复ID/断引用/损坏gzip视为内容错误，不能当作正常空候选吞掉。分片SHA首次入缓存前核对，未知schema拒绝并保留错误诊断。

坐标合同：世界X–Z平面，Y向上，长度米；横桌+X向右、+Z向下；轨迹点`[相对首碰秒, X米, Z米]`。渲染Y取实际scene.surfaceY及球半径，不用固定0或把XZ误作XY。评分转换厘米只在P2适配边界进行。袋名用PocketDisplay按实际桌面方向显示，旋转镜头不改变袋ID。geometry以所选manifest快照核对运行时常量。

### 4.2 抽题流水线

1. 读取只读消费索引，按第一杆设置筛选layout，再挑选有有效推荐解的candidate；每轮可复现随机种子写入记录。
2. 保留top5原顺序，按出题杆法和消费者可执行性筛选，不重新搜索或补足五条。
3. 以三球真实重放复核推荐参数、首球进指定袋、母球安全、B未被碰动及轨迹一致性；剔除失败路线并记录诊断。一次题目最多验证其现有五条，缓存结果。
4. 本题有效数N为1…5；N=0换候选，空candidate/空top5属于正常数据边界。准备有取消和明确预算，不无限循环；预算/条件耗尽显示可重试或调整条件的错误。
5. 轨迹模式逐条使用过滤后路线；自由模式取过滤后第一条路线的pocket作为固定第二袋口，记录selectionRouteID。它只用于选题和审计，不把其score充当用户成绩。
6. 轨迹模式随当前路线标注其第二袋口，路线不同可以不同；第一袋口始终不变。自由模式一个题实例只固定一个第二袋口，重打/恢复不重选。

推荐复核先沿保存strikeDirection固定重放，不再次寻优掩盖源偏差；失败不能修改保存参数“修到可用”。用户输入则按其实际参数补偿第一杆方向后，执行完整三球模拟。源2mm线是目标，不能被复核结果静默替换；B2必须先以固定夹具确定“源压缩误差＋数值重放误差”的比较预算并存证，再用于运行时复核，禁止为通过某题放宽。

### 4.3 载入、缓存与分发

- 消费端采用异步分片加载/解压，不将873.82MB JSONL或整个routes库装入主线程内存。
- 建立独立消费索引：题目ID、分片/行定位、第一杆筛选元数据、候选可用性、版本与SHA。允许写独立消费打包工具和产物；只转换索引/封装，不更改源坐标、参数、top5和生成规则。
- 初版采用随包只读压缩资源＋小索引，无新OTA服务或第三方依赖。完整联调包可导入当前已完成全库；若正式包体需裁减，应单独评估，不能默默以小样代替全库。本地output绝对路径不得进入生产运行时代码。
- 有界LRU分片缓存，保留当前题和最多一个预取题；第一版起始上限两个解压分片，内存警告先丢预取/非当前数据。测量后再调整，不能以整库常驻换流畅。
- 预取键含owner/session/config/mode/bankVersion；离页、换模式、重开、换账号取消旧任务。当前题有效路线集合准备完成后冻结，不能练到一半因异步剔除而改变N。
- 新全量只在`state=complete && auditPassed=true`且manifest/index/分片校验成功后成为可选版本；缺任一字段继续用已固定旧版。只在新轮次切版本；不热换当前题。兼容schema适配仅发生在消费端。
- 验证及打包报告放本工作包独立目录，保留所用源SHA、打包后大小、峰值内存与冷/热载入耗时。禁止写入两个生成全量目录及其research脚本目录。

## 5. 两种模式的页面状态合同

### 5.1 共用阶段

`loading → settings → preparingQuestion → aiming → submitting → revealing/playing → result → nextRoute/nextQuestion → summary`，外加`replaying`、`saveFailed`、`contentError`。业务模式与呈现维度是独立枚举，不通过按钮标题反推状态。

- 调打点/力度只改输入和球杆；不显示当前输入碰后预测线，不自动出杆。单任务＋最新意图替换，后台准备不闪“计算中”。
- 点击后冻结inputRevision、题目/路线、方向、物理/评分版本及scene.surfaceY；完整结果保存成功后揭示/播放，不先扣额度。
- 击球开：实际整线已上屏后计1.5秒，再走标准运杆/出杆/三球运动；击球关：不自动播放，直接进入结果展示，可用辅助“击球”播放同一记录。
- preparing/submitting/revealing/playing禁调参、换轨迹、重复提交和布局编辑；离页/后台撤销待执行意图，不在回前台突然自动击球。
- 已保存而动画被中断：恢复结果和真实终态，不重新提交；未保存：恢复输入，需再次显式点击。保存失败只重试同一shotID，不重新模拟/重复计题。
- 回放消费冻结三球帧/事件，停止或结束恢复回放入口现场和相机；不新计分。重打恢复三球before及上一杆输入/视角。

### 5.2 轨迹走位

|触发/状态|击球开时主按钮|结果与后置状态|
|---|---|---|
|进入新轨迹，参数等于默认基线|跳过|默认中杆0/0、杆速2.5m/s；保留实际可出杆守卫，不填答案参数|
|用户改变打点或力度|击球|比较有效输入值，不以手势次数判断；调回基线恢复跳过|
|点击跳过，尚有未处理轨迹|跳过|成功保存当前路线skipped后进入下一条，重置默认输入；无分数、无模拟、无动画|
|点击跳过且为最后一条|下一题／查看总结|保留当前球形，显式进入题目完成状态，不伪造已击球结果|
|一杆完整提交完成，尚有未处理轨迹|新轨迹|当前路线为attempted，不设及格门槛；点击后进入下一条并重置输入|
|当前最后一条提交完成|下一题／查看总结|所有路线attempted或skipped才完成题目；最后一题可先重打，再看总结|
|结果点击重打|击球|保持当前路线、上一杆参数；设置retryOverride，即便等于默认也可以击球|
|回放结束|恢复进入回放前按钮|不修改路线完成状态/首答成绩/跳过数|

默认基线不可出杆时仍可跳过；修改后若当前参数不可执行，给真实原因，不偷偷更改输入/答案。`retryOverride`在换轨迹、换题或重开时清除，重进必须恢复。

单条路线记`unseen/attempted/skipped`；attempted下允许多次重打。离开路线后不增加历史路线选择器；当前路线仍可重打。跳过没有上一杆，不显示可用回放/重打。

### 5.3 自由走位

- 初始主按钮“击球”（击球关为“提交”），默认参数也可直接提交；不采用“未调参即跳过”。
- 题面显示A的进袋任务、B及其指定袋口；没有推荐目标轨迹/答案打点。中杆参考遵守§3.2的显式辅助合同，不由显示设置打开推荐答案。
- 一杆提交后展示实际线、实际停点、第二杆难度及结果原因；主按钮“下一题”，末题“查看总结”。没有“新轨迹”。
- 点击重打恢复同一题、同一B袋口和上杆输入；首答成绩不被重打覆盖。
- 第二杆角度/到B距离仅在结果或重打后的“上杆结果”中展示，不随调参实时预测。临时观察和转屏不重算目标袋口。

## 6. 评分与统计

### 6.1 第一杆共同有效性

必须有完整停稳三球结果、母球首先命中A、A进指定袋、母球未落袋、B未被任何球碰动且未落袋。用实际球ID和球球/捕获事件判定，不拿终点位移小于某阈值冒充未碰B；B被撞后又停回附近也算失败。同刻先碰A/B的歧义按不满足“先A且不碰B”处理。

完整但失败的杆属于正式尝试；数值失败、截断、取消、损坏内容和保存失败属于系统错误，不得当用户失误计分。用户路线吃袋角、吃库次数与推荐不同不额外判失败；生成端过滤只约束推荐题。

### 6.2 轨迹评分

- 使用现行`SeparationTrajectoryScore`，算法版本`arc1cm-rms-p2-t20-potgate-v3`；保持`100 × 2^(-RMS厘米/20)`、1cm弧长采样和顺序约束。
- 源目标线与实际线均截取首次C→A接触至母球停止/捕获；静止碰后线与未碰A区分，保留吃库事件锚点，不把源时间当整杆时间。
- 共同有效性失败记0并附具体原因；新增“碰动第二球”等业务原因由本功能结果包装，不能强改旧评分历史枚举使既有记录失效。
- 每路线首个已保存尝试是正式分数；后续重打只更新本杆分、次数和练习统计。跳过为无分，不是0分。
- 本题首答均分＝本题已尝试路线首答分的算术平均（含失败0）；本轮均分＝有正式分数的各题均分等权平均，避免五路线题权重为单路线题五倍。未完成题在退出总结时纳入已提交部分并标未完成。
- 同时呈现已练路线/已处理路线、跳过路线/整题跳过数；全部跳过时均分为“—”，不显示0或100。没有跨模式排行榜或共同总分。

### 6.3 自由走位难度（用户已确定沿用题库）

保存原值，UI统一标“第二杆难度 · 越低越好”，建议显示三位小数，计算和排序保留原精度；不加“分”、百分号或进球概率。量纲为米制距离系数，解释置于信息说明，不占台面常驻长行。

设C为实际母球停点，B为第二球固定位置，P为指定袋口的**原生成下球点**，R为该题库几何半径：

```
u = normalize(P - B)
G = B - 2R × u
θ = angle(G - C, u)
D = |P - B| / cos(θ)    （0° ≤ θ < 90°，向量有定义）
```

切角必须与生成端一致，不能改用B−C；不是补偿后真实第二杆碰撞切角。P来自manifest的length/width/radius及原生成anchor规则：四角为±(length/2−R)、±(width/2−R)，中袋为(0, ±width/2)。原读取锚点为`pocket_geometry_filter.py: Geometry.anchors/pocket_metrics`，只读参考；在Swift独立消费适配中实现并对拍。不能把运行时effectivePocketAimPoint替入该指标，也不能把生成P拿来假称真实第二杆进袋证明。第一杆瞄准/实际进袋仍按其题目与正式物理合同验证。

- 仅评价指定袋，不能提交后遍历六袋取最小值；推荐top5.score只作测试/审计，不是本次结果。
- 共同有效性失败、球位重叠、退化向量、θ≥90°、非有限值：显示“未完成指定走位”或“无正向直击线路”及原因，difficulty=null；不能保存0、NaN、Infinity或任意巨大惩罚数。
- 25°只筛推荐路线；用户26°或更大但<90°仍计算真实D。难度不含C到B距离、首杆执行成本或第二杆扰动容错，UI不得声称已综合评价。
- 本轮统计：已练题数、首杆有效走位率（有效几何结果题数/正式首答题数）、有效首杆平均难度。失败计入有效率分母、不进入有限难度均值；必须同时显示有效样本数，避免省略失败后均值被误读。
- 重打保留首答结果；显示最新难度及该题尝试数即可，不用后来的最好成绩改写首答。
