# C1 台呢逐帧重复计算：续研执行卡

2026-11-13，基线 `354480b97`。用户新授权：继续台呢优化，重点解决每帧重复计算，每轮记录，非必要不停。这张卡接续活动期 v1 §7 C1；不改写 B3 淘汰结果。生产画质、原采样、球影/AO 同帧、用户帧率、物理均保持。

## 本轮与旧路线的区别

先验证**当前视口、相机、材质不变时的时间复用**。旧 R3/R5/R7 为世界空间场/低秩近似，生成随球态更新；本候选只缓存不依赖球态的 far 光照，在每帧用当前球位重新执行原 near 判定，near 仍走完整现有 shader。缓存不包含 AO、最终色调映射或旧球影。保持两个 Float32 RGB 输出，不插值、不量化、不改变 BRDF。

坐标为生产 SceneKit 世界米：XZ 水平，Y 向上；输入沿用已提取的真实 geometry/normal/roughness，不以平面常法线替换。

## 轮次与门槛

1. **C1-R1 核心可行性**：从已核当前 guard 构建原生 Metal 原型。五组真实像素输入，动态球位、near/far 转换、缓存无效回退；六个实际光照输出逐位相同。A/A 与顺序平衡 A/B；分别记录生成、消费、生成+1/2/8/60 帧的总成本、缓存字节。收益门槛 `max(5%, abs(A/A))`，不把 kernel 收益当整页收益。
2. **C1-R2 真实接入验证**：只有 R1 成立才验证 SceneKit 真实材质可获得/复用完全一致的片元输入、MSAA 边界、缓存读写同步。先最小接入证明，再扩大真实资产。帧缓冲缓存必须有视口/相机/几何/材质/灯光/renderer 身份；变化立即回原 shader，不能显示过期结果。资源按实际全分辨率算，不拿紧凑离线样本数组冒充屏幕缓存。
3. **C1-R3 一消费者成本**：接入成立后计完整渲染、生成、同步、首帧、换外观和进退资源；通过才接生产共享入口。未成立则记录明确反例并尝试有针对性的结构修订，不重跑旧 UI 基准。

## 限制与结束条件

- 首轮只是可缓存性的必要条件。真实 SCNView 的生成、同步、MSAA、内存和输入一致性均不能由 compute 原型代替。
- 两张 RGBA32F 视口纹理为 32 字节/像素，手机高分辨率可能超预算；必须在 R2 前列明资源，必要时转有界局部缓存或另一个视角无关项，不默许低分辨率/半精度。
- 原生工具使用现有本机 Metal，不占用手机；当前手机不方便的约束仍有效。
- 每轮记录工作量、数值、成本、缺口与保留/淘汰决定。只将通过实际材质与总成本的候选写入生产，原 R/guard 回退始终保留。
