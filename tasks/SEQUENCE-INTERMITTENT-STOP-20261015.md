# 同一序列偶发停止 · 2026-10-15

状态：修复、7项核心测试和2项正常界面测试通过，已安装并启动到用户iPhone16Pro，用户真机体验待复验。共享摆球流程改为逐节点动作完成屏障，摆球端点由动画线程提交后才回到主线程计数；详情和试打取消流程同步取消节点动作。序列、物理、瞄准保留，证据在`output/sequence-intermittent-fix-20261015/`。未提交或发布。

用户真机反馈：两库走位、五分点在同一回放中偶发“当前球位无法接续”，重播可能通过，停止杆数不固定。截图为两库走位第7/12杆。以下根因实验为修复前的只读诊断记录。

## 结论与证据边界

已复现当前摆球完成判定所使用的跨线程时序缺陷，足以导致上述现象；尚未取得用户真机该次停止的逐帧日志，不能将所有停止原因归结为这一项。

1. `SequenceSceneTransition.arrange`分别给每球添加0.45秒move/fade，再给root添加独立0.45秒wait。root的完成回调经Task切主线程，不是全桌球动画完成屏障。
2. `finishArrangement`只设置隐藏/透明度，没有保证每颗球已经到达目标坐标。
3. `DrillSceneController.solveStep`随即从节点读取currentBoard。`SequenceReplayResolver.solve`对有录制轨迹的杆要求起点差小于0.0001米；尚未完成的摆球坐标会直接返回nil，界面统一显示“当前球位无法接续”。该拒绝分支目前不记录球名和误差，截图不能独立证明具体分支。
4. 两库走位第2–12杆均有存档换球形，第7杆有新录制轨迹；五分点第2–8杆均有存档换球形，第1、3–8杆有新录制轨迹。因此两者会经过上述路径。

## 修复方向（诊断时方案，现已实施）

- 将“独立计时结束”替换为真正的全桌摆球完成交接；所有应到位节点完成，且该轮播放代次仍有效，才允许读取下一杆起点。
- 明确区分存档要求的换球形与连续击球：前者完成本来就应执行的摆位，后者不能借机把物理结果吸附回存档。
- 不放宽0.1毫米校验，不增加经验延时，不改轨迹或球位来躲过检查。
- 补充接续失败诊断：杆号、球名、预期/实际起点、差值、播放代次和阶段；复测两库走位/五分点反复播放及暂停、继续、切换球形、后台恢复。

前一轮98文件一致性与38轨迹原生读取校验，验证的是数据和解码/轨迹绑定，不覆盖渲染线程摆球与主线程接续的竞争；不能据此宣称真机实时回放无此缺陷。
