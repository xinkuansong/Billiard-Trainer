# 目标球贴库诊断（2026-11-03）

用户确认目标球贴库，并指定 15° 切角、不同力度对照。本轮仅诊断，不改生产物理、瞄准参数、题库或用户已采用的 0.75 默认值。

## 已确认的分层原因

1. 上轮修复解决了半贴库方向漏搜，没有解决大多数完全贴库球；当前正式样本重放仍为 20/150 合法直进。116 次 missed、9 次 scratch、2 次 indirect、23 次准度 success（其中3次二次目标碰球，不计求解器合法直进）。物理目录源码与上轮冻结版无变化，不能归咎于本轮版本漂移。
2. 去掉母球、碰球与瞄准补偿，目标球单独沿库滚向角袋，仍能复现“稍加力就弹出”。因此袋口响应本身足以造成失败，继续扩大瞄准搜索不是唯一解决方向。
3. 当前模型的合法贴库球心 Z=0.606425m；角袋捕获多边形最小 Z=0.6175364256m，深部收集圆最小 Z=0.635m。保持沿库直线时，球心到不了捕获域，必须向袋内偏转至少11.1114mm（只是必要条件）。这不是“库线旁看着经过袋口就算进”；必须联合审查圆弧碰撞和捕获域。
4. 默认裁定为 `planarReference`；局部空间袋口模拟用于呈现，不反馈进球裁定。3D画面不会自动修正平面裁定中偏窄的入袋窗口。不能据此直接宣布平面规则错误，需要接触/支撑与实物参照。

## 用户指定的15°实际击打

固定目标球(0.5,0.6064249873)、母球(−0.1367055178,0.4511335790)，均为XZ米；目标球球面距长库为0。母球到幽灵球0.6m，中杆、无横塞，袋3。程序实测切角14.999997881°，12档只改杆头速度，走正式 `predictForPositionSolve`（2000事件/45s观察预算），全部停稳。

| 杆头速度 m/s | 目标球实际进指定袋 | 正式路线判定 |
|---|---|---|
| 0.6 | 否 | missed |
| 0.8 / 1.0 / 1.2 / 1.4 / 1.6 | 是 | 全部 indirect，求解器不接纳 |
| 1.8 / 2.0 / 2.5 / 3.0 / 4.0 / 6.0 | 否 | missed |

**新定位的同刻事件处理缺口**：0.8–1.6的五档进球，母球碰库与首次碰目标球的记录时间完全相同（差0秒），但事件数组先写cue库事件。`AccuracyShotJudgement.evaluateResolvedSearch`用顺序布尔量`contact`，在该库事件处直接设置`indirect=true`，不检查事件时间。`ShotPredictor.isDirectPot`复用该结果，所以进袋仍被新补搜拒绝。不能把这五档说成“物理打不进”。

同一球形2.5/4/6m/s则记录球球碰撞在前，母球碰库分别晚约0.596/0.171/1.214微秒。表明接触边界还具有事件排序敏感性；这几档仍实际未进，不能认为只修排序就能救回。

解析搜索在`tTarget == tFirst`时先返回球球碰撞分支，而完整模拟记录可能先列库事件。两者在同时接触边界的表达不同，是下一轮必须核对的入口；本轮尚未直接记录这12档解析首事件，不能把代码分支差异当作已实测数值分歧。

12档最终offset均约0.000000125°。说明该球形最终返回的基本仍是几何种子，不能据此声称“补偿已找到当前杆法下最佳入袋线”。

## 单球隔离实验

真实生产 `EventDrivenEngine.simulate`，初始位置 (0.6, R, 0.635−R)，R=0.028575m，朝 +X 进入袋3，纯滚动、无竖轴自旋。下表速度是**目标球起始速度，不是杆头速度**。

| 目标球起速 m/s | 0.75 当前值 | 0.70 对照 | 0.60 诊断对照 |
|---:|---|---|---|
| 0.6 | 进 | 进 | 进 |
| 1.0 | 进 | 进 | 进 |
| 1.4 | 进，3次圆弧碰撞 | 进 | 进 |
| 1.8 | 不进，5次圆弧碰撞 | 进 | 进 |
| 2.4 | 不进 | 不进 | 进 |
| 3.0 | 不进 | 不进 | 进 |

只修改每个独立诊断几何副本的8个角袋圆弧恢复系数，其余模型不变。0.60仅用于识别参数敏感性，绝非建议的新生产值。

进一步固定贴库、无侧旋，扫描出射方向 ±0.5°、步长0.05°（每档21个方向）：1.4m/s时，0.75仅2个方向进袋，0.70为15个；1.8m/s时分别为0和10。0.75收窄该样本入袋窗口的因果关系已被单变量实验验证，但不证明0.70符合真实球桌。

完整单球矩阵：3个恢复系数 ×4个离库间隙（0/1/3/10mm）×6个速度 ×3个目标球竖轴角速度（−20/0/+20 rad/s）×21个方向＝4536次，全部停稳。竖轴角速度是目标球状态，不等同用户打点盘的左右塞。离库间隙实验仍按同一平行方向发射，不是各间隙重新求最优入袋线，不能拿它的进球比例比较球形总体难度。

## 旧测试的合同问题

`PocketBehaviorDiagTests.test_R_railFrozenCornerEntry` 明确断言0.70下0.6–1.8m/s应进、≥2.4m/s应不进；`test_R2_railFrozenEndToEnd`只要求至少一档力度能进。这样的历史合同不能保护“多档正常力度的贴库球可打性”。当前0.75单球1.8m/s失败与旧低中速期望冲突，本轮为同形诊断重放，不冒称运行了原XCTest。

## 修复方向与边界

第一优先级：核对同刻碰库/碰球的真实接触证据与引擎分组，统一解析筛选、完整模拟、直进判题对同时接触的合同；必须保留真正先碰库的反例，不能加任意时间阈值一概放行。第二优先级：核对实际袋角接触点/法线、反弹后路径与捕获入口之间的关系，并建立用户指定的15°力度窗口回归。0.75→0.70是可解释的对照，却不保证完全解决；直接改成0.60或放大捕获域只能抬高部分数值，不能替代校准。近库补搜保留，暂不再增加全模拟搜索预算。

没有真实球桌匹配条件下的球速/轨迹参考，仍不能断言哪一个恢复系数正确、哪些大力球现实中必须进，也不能把有限扫描失败证明为连续方向空间无解。
