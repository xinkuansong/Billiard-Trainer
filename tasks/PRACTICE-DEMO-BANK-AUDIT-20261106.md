## 3. 袋角怎样处理

验收关注**本可干净入袋，参考杆却碰了目标袋角**。先按练习规则判定是否完成原题。对成功进指定袋的参考杆，记录目标球碰袋角的事件，再按下表判断。贴库、半贴库仅是可能需要吃角的例子，适用口径由这道题的实际进袋路线决定。

**用容错角筛选需要微调的杆。** 先用 App 重放原杆。对按原题完成且目标球实际碰到目标袋角的杆，再查进袋末段的直线管道。直接进球取目标球出发时的球心与受击后的实际方向。翻袋取目标球最后一次碰规定主库时的球心及反弹后的实际出射方向，从离库侧判断到指定袋的末段。起点刚发生的规定碰库属于应有事件，后续额外碰库或袋角须计入。若候选改变了最后碰库点，应按候选的新碰库点重新核算。

复用[容错角底层计算](../QiuJi/Core/Scene/AngleSceneCalculator.swift#L1298)给出的连续球心方向区间，以该区间内部方向（优先中线）作微调目标。[教学页](../QiuJi/Core/Scene/PocketToleranceGeometry.swift)显示的两条线是球宽管道的外缘，计算直接读取区间数据。若有多个区间，分别考察。插值、窄窗和临界方向用实际球位重新计算。存在有净空的内部方向且原杆吃角，即列为需要尝试微调；若实测出射方向已在窗内却仍碰角，先复查取点、方向、障碍和真实碰撞事件。几何阶段给出目标球末段可走的方向，验收仍以原球形整杆复演为准。单次查不到正宽窗口仅记为未发现，孤立方向和边界情况保留待核。解球无指定进球袋，沿用原解球规则。

|同一题、同一条教学路线的证据|验收结论|
|---|---|
|原杆完成任务，目标球干净入指定袋|通过。|
|原杆吃了目标袋角；在相同球位、指定袋及原题要求下，App 用玩家可操作的参数能重现至少一杆全程合法、进目标袋不碰袋角的打法|可避免，微调参考杆。即使原杆只轻擦一次也归此类。多个合格干净候选之间优先选容错较好的。|
|按实际入袋方向、球的半径与袋口形状核实，原路线允许的入袋范围都需接触目标袋角；原杆合法并完成原任务|属于这条路线需要的接触，保留合理吃角的示范。附几何依据及 App 轨迹。|
|原杆吃角，有限搜索未找到干净候选，亦缺乏足以判定必然吃角的几何依据|标为待定，保留已测输入范围和轨迹，再扩大搜索或人工复核。|

对翻袋保住规定库数、库段和顺序；K 球保住碰 B 的时机，两球走位和分离角保住原题要求的母球路线。玩家自动瞄准的练习须从正常出杆入口复现候选。中途借其他袋角改线、错袋、犯规及示范无法播放，另按本题规则处理。解球没有指定进球袋，只走解球验收。碰撞次数、擦碰轻重、静态贴库标签仅作诊断信息。

## 5. 全量怎样跑

1. **建立唯一清单。** 从构建产物 Bundle 通过正式解码器展开资源，两球把每个引用连回球位、参数和下一袋。保存原题 ID、可用筛选条件、球位、原输入和路线声明。四个固定库首轮共 **764,443** 个工作项（21,569＋53,928＋11,458＋677,488）。各筛选条件共享同一球形时记录可达性，汇总按稳定键去重。每个执行分片写出预期键集合。
2. **分离角另建分母。** 共享基础库清单含底袋 580,804 和中袋 201,724 个摆位。先用正式筛选条件导出分离角实际可达球形，再与可选的高低杆／侧旋开关组合。每个组合先跑一个预登记种子，按稳定球形 ID 派生；袋型、距离、角度与允许打点各档另设多种子边界样本。成功生成时保留题面原目标线和答案，走保存、恢复和实际示范判定。没有生成答案的组合记录生成预算和原因，另按正常出题入口测能否及时补到下一题。连续随机输入无法穷举，未来每次实际生成的答案须在交题前具备同版复演证据，可复用已验证的预测以控制等待时间。[共享摆位清单](../QiuJi/Resources/training-grid-bank-manifest.json) · [正式抽题与生成入口](../QiuJi/Features/SeparationPractice/SeparationQuestionGenerator.swift#L62)
3. **在 App 内建立基准。** 使用 App 宿主测试，从真实 Bundle 创建指定稳定 ID 的题，复用正式出题准备、球杆模型、物理演进、判题及示范重建函数。批处理仅负责枚举和记账。用正常页面选中的同 ID 对照初始球位、方向、打点、杆速、碰撞顺序、落袋和终态。若另启离线加速程序，先用同快照正负例对拍，最终候选仍须通过正式 App 路径。遇到共用层漂移时重新标识受影响批次。
4. **先量吞吐，再分片。** 每库取含慢例和负例的小片，记录每秒处理数、峰值内存、输出体积和超时率，据此确定并发、单片上限与余量。报告分别估算基线、候选搜索、最终复算时间。按稳定 ID 范围领取任务；成功完成的分片原子写入，恢复时校验资源指纹、批次规则版本和分片摘要。取消、中断、超时均留下缺口，补跑时按键合并。
5. **分类后再改。** 每个原始键只占一个首轮结果：通过、通过但入袋质量待优化、失败、按规则被筛掉、证据不足。另存事件原因和全部次要问题。同一故障跨多题出现时，先用原始记录定位共同原因。对候选同时核玩家可复现、原任务成立、袋口改善和邻域稳定性。保留原始与新结果两列，候选单独出包。删题、换球形、换教学路线、修改判题或全局物理进入独立决策。
6. **独立重放与重跑。** 按最终打包资源重新枚举全部可展示答案，从新进程重新解码并重建。比较原始清单与最终清单的增删及原因，检查重复／孤儿引用、空筛选档、出题耗时和旧存档。内容变更重验受影响的全部引用与最终包；公共物理、瞄准或判题变更使依赖它的库恢复待验。
