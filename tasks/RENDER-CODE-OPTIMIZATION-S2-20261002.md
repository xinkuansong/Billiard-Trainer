# 渲染代码优化 S2 / 模拟器集成交付（2026-10-02）

状态：S0–S2 的本地实现与可自动完成的模拟器检查收尾；S3 按证据不足停止候选，生产 GPU 实验仍关闭。S4 的构建与模拟器集成完成，真机配对性能、用户体验及 iPad 每日清台全屏复验仍未完成。工作分支 `codex/render-code-optimization`，未合并 main。

## 实际保留的改动

1. S1：同一次图解标签布局复用 viewport 的 inset 边界。六组 ABBA 的局部均值改善 1.1～3.4%，平均每次省约 0.0026ms；24 个布局状态旧/新合成 RGBA 零差。只作用于启用图解标签的页面，不能据此宣称每日清台或全 App 加速。详见 [S1](RENDER-CODE-OPTIMIZATION-S1-20261002.md)。
2. S2：修复快速重开时旧球杆动作覆盖新瞄准位置的生命周期竞态（FL-097）。这是正确性修复，没有宣称 CPU/GPU 性能收益。

保护区 `Core/Physics`、`Core/Rack`、`Core/PositionPlay` 和 `Resources` 的 1424 个文件哈希与 S0 一致。固定回放 SHA-256 为 `79182a3666b9c92074cf195165b28b66c2dfae96eeccad20c6f2e139078a0911`，未变。摆球仍为名义缝隙 0.20mm、偏移半径 0.09mm。材质、着色器、灯光、反射、阴影、相机公式、动画曲线、分辨率、MSAA、帧率请求和浮点精度均未调整。Debug 的 -O 是既有配置，未当作新成果。

## FL-097：实际问题、根因与修复

生产 `testImmediateMovingRestartWithLiveRendererKeepsBreakAddress` 首轮失败，而孤立复测偶尔通过。保持原断言，追加三轮、每轮普通杆与开球两种前置动作，总六次快速重开，修复前再次失败：旧普通杆把新开球 pivot/yaw 覆盖为原来的位置和角度。原日志保留在 `standard/unit`、`standard/restart-before-stress`；孤立绿结果未替代红结果。修复前 CueStick/CueStroke 与 b69aa749 基线逐字节一致，该测试未创建图解标签协调器，所以问题并非 S1 引入。

`removeAction` / `removeAllActions` 无法撤回已经进入 SceneKit 渲染线程的 customAction，或已排入 MainActor 的触球、淡出、隐藏回调。只有业务侧取消令牌不足以保护渲染节点。

修复限于 `CueStick.swift` / `CueStroke.swift`：

- 每支球杆保存 UInt64 动作代次；开始新动作、普通瞄准更新或显式隐藏使旧代次失效。
- 用 NSRecursiveLock 将代次检查和节点写入作为同一个同步操作，防止“检查通过后，重开先写新位置，旧动作再覆盖”的窗口。
- 动画中的位置、透明度、隐藏以及延后 MainActor 触球/淡出均检查原代次；外部触球回调不在锁内执行。
- 正常完成本杆淡出只隐藏球杆，不使本杆代次失效，避免 UI 繁忙时吞掉同杆已经排队的有效触球回调。显式取消仍使其失效。
- 原姿态计算、后摆/前送/停留/退杆时间和淡出公式未变，渲染更新未移到异步主线程。

新增测试覆盖有效代次与原姿态路径的精确 transform/PNG 对照、A→B→A、故意留下旧 fade action、新地址后的晚到姿态/隐藏、正常淡出完成与显式取消的区别。实际 SCNView 压力回归保留全部六次新开球姿态断言。同步开销尚未做真机配对测量，不能称为提速。

## 渲染提交检查与停止决定

生产 contact occlusion 有 16 个球槽，但材质引用只有 1 个、唯一材质也是 1 个；不存在多材质重复提交可去重。原有按变化合并提交与不可变 Data 保留，不重新包装为新优化。

新增 production-path 回归检查世界坐标及父节点变换、透明度权重、隐藏/移除/抬高/低于台面、恢复可见后权重，以及旧 Data 快照未被新帧覆盖。变化时按组提交一次，静止时写入为零。六个场景的旧展开参数→现有 packed→旧展开参数图像对照在最终代码下通过。阴影读取 presentation 的路径未改变，没有新增跨帧缓存或延后一帧更新。

S1 已拒绝直接 NSData 构造、2D 相机缓存、排序距离预计算；没有遗留候选或启用开关。当前应用包装层剩余 CPU 成本较小，没有证据支持大幅重构带来整帧收益，按方案停止强行优化。

69 张最终原生 UI PNG 均有 manifest、字节数、SHA-256、IHDR 尺寸，ImageIO 系统解码及缩略图非纯色检查通过。已审九张不重叠联系表及每尺寸三张代表原图；旧联系表因缩略图超出格子而重生成，未修改原图。新开球的球杆指向母球，新杆仍能出杆；图解标签存在，没有发现本批引入的材质或球影异常。有效代次像素对照与 UI 目视分别记录，不能由原生 UI 截图反推前后逐帧零差。

**iPad 每日清台处于 iPadOS 系统窗口模式**：截图显示圆角窗口、系统窗口控件、壁纸和 Dock。窗口内四项 UI 契约通过，角度/击球页另外有占满当前屏幕的原图；不能把每日清台结果写成 iPad 全屏横屏通过。曾尝试通过真实 Simulator UI 核对/最大化，CUA 返回 Mac 已锁屏且无法自动解锁；未操作系统窗口或用 App 参数伪造全屏。保留待复验项，无需因此阻止其余可自动完成的工作。

小屏角度页顶部统计末项截断、教学提示对比度较低可见；本批没有调整统计条或提示布局，S1 的旧/新标签对照相同。这些现象另记视觉待办，不作为本批画面全优声明。手势放大、低机位及袋口观察造成的桌面裁切按实际观察状态判断，未强行改相机。动态字号、Reduce Motion、Split View、真正双外观全页面以及真机触感未覆盖。详见 [视觉审查](ui-reviews/UR-20261002-RenderCodeOptimization.md)。

## GPU：已有录制能说明什么

对之前 S0 的短真机 Metal 录制作离线归属解析：3388 条 App 区间均属 PID 4486，GPU 的 9642 条总记录中 3941 条 Active 记录显式属该 PID。按 channel 单独保留统计，重叠区间不直接相加。录制请求为短窗口，导出区间未裁成统一有效配对窗口，不把区间并集除以“8秒”写成利用率。

该记录来自旧基线，缺少本批当前版本的成组 ABBA、材质/shader 归属与完整呈现帧数据。Fragment/Vertex 活动不能证明某一台呢公式是热点，也不能证明某种 GPU 改写有收益。因此 S3 不改生产 shader，不启用 merge/factor 等既有实验。不从模拟器或短录制推算真机 FPS、温度或功耗。
