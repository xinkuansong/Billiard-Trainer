# 设计决策日志 — P9-01

## 决策 1: 7 功能分组布局采用三段式 Section
- **上下文**: AngleHomeView 从 3 入口扩展到 7 功能 + 1 历史入口，需要合理组织
- **选项**: A) 无分组平铺 B) 按功能类型三段分组（学习/训练/工具）
- **决策**: 采用 B，三段 Section 分组
- **理由**: 7 张卡片平铺过长，三段分组（学习 3 + 训练 3 + 工具 1）信息结构更清晰，用户可快速定位目标功能
- **日期**: 2026-04-14

## 决策 2: FeatureCard 模式完全沿用 P1-05
- **上下文**: 新增 5 张功能卡片需要确定视觉样式
- **决策**: 所有 7 张卡片统一使用 P1-05 确立的 FeatureCard 模式（白卡 16pt 圆角 + 48pt 浅绿底圆形图标 + 标题/副标题 + chevron）
- **理由**: 保持角度模块内部视觉连续性，用户对已有模式有认知惯性
- **日期**: 2026-04-14

## 决策 3: Tab 栏渲染偏差以 P0-01/P1-05 为准
- **上下文**: Stitch 将中央"角度"Tab 渲染为凸起大图标样式
- **决策**: 开发时以 P0-01/P1-05 标准等大 Tab 栏为准，忽略 Stitch 渲染偏差
- **理由**: Tab 栏组件已在 Phase B 确立，Stitch 无法完全复刻已有组件样式
- **日期**: 2026-04-14

## 决策 4: Dark Mode 不单独生成，参考已有设计
- **上下文**: P9-01 原计划 Light + Dark 两帧
- **决策**: 仅保留 Light Mode Stitch 截图，Dark Mode 开发时参考 E-01 ~ E-04 的 Dark Mode 规范和标注文档
- **理由**: Phase E 已建立完整的 Dark Mode Token 表和开发标注，AngleHomeView 结构简单（列表页），SwiftUI 原生 Dark Mode 支持可自动适配
- **日期**: 2026-04-14
