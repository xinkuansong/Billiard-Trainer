# 球桌页面适配

项目专用技能，v1.4。工作方法与当前页面决定分开：本文件管流程，项目方案和页面卡管当前范围、设计、尺寸与状态。

## 入口与真源

在球迹仓库内先遵循 `.agents/skills/cursor-project-adapter/SKILL.md` 的角色路由和状态检查。默认工作包为仓库根目录的 `tasks/table-page-adaptation/PLAN.md`；用户明确指定其他方案时使用该方案。相对路径以仓库根目录解释，不依赖固定用户名。

每次开始或跨会话恢复，读取当前方案、本页卡及最新 `REVIEWS.md`，核实实际源码／工作区和依赖。根据最新用户请求确定本轮是规划、实施、反馈修订还是验收；不能把旧总结中的“下一步”置于用户新指令之上。

本技能不自动执行每日清台独立方案、不把方案创建授权扩大为 App 全量改造，也不要求重复确认已有授权。共用文件或模拟器被其他任务使用时先协调，保留他人工作。

## 设计规范与长会话入口

参考每日清台时，读取 `docs/design/daily-clearance/每日清台设计规范.md` 的总原则、历史覆盖关系及本批相关DC条款，再打开对应原图；其他页面逐项标适用/保留差异/不适用，不照搬每日专属球组或摆球权限。

多批次、新会话或上下文压缩后的恢复按[交接协议](references/session-continuity.md)执行。每日独立适配读取 `tasks/daily-adaptive/CURRENT.md`；其他页沿用现有页面卡交接节及REVIEWS。设计决定、排期、当前进度和原始证据各留在对应真源，不在多个方案复制外部批次状态。

## 根据请求行动

### 制定方案

从实际导航入口、渲染组件和共享控件调用方盘点，标明直接检查、间接待查和实际页面未采集的边界。按击球、规划、答题、阅读／内部编辑分类，写清能力差异和推广顺序。

对齐参考页时，完整读取实际菜单组合与功能入口，逐项列“适用并纳入／保留差异／不适用及理由”，包含状态、禁用条件、偏好作用域和真实渲染接线；不能只比截图外观或只移动按钮。用户明确的位置与收纳要求写入当前页面契约，不再保留被替代选项为待决。

用[模板](references/templates.md)生成最小可执行页面卡：现状证据、目标布局、业务保留、适配策略、代码锚点、依赖、批次、验证和用户待决事项。确定一个下一执行入口，不把初步推测登记成已复现缺陷。

### 实施已授权批次

使用 `.cursor/skills/plan-batch-execution/SKILL.md` 消费批次。SwiftUI、几何／投影和多设备验证分别按项目适配器加载对应技能，不预先加载全部知识。

先保留 source/build/before 身份，再局部实施和验证。已有共用控件优先复用；新共用规则经第二个实际消费者检验后再推广。改共享默认值须重查调用方和受影响回归。保留固定视角训练入口与成绩归属、球数限制、开球能力、重打／回放语义等页面差异。

### 用户反馈迭代

定位用户正在评价的页面、轮次、设备和状态；已有上下文足够就直接落实。语义不清且会改变任务／范围时才澄清，不要求用户填写表格或给像素数。

记录原话、可观察目标、适用范围、处理、证据与状态。单页反馈先作用于单页；推广为同类／全局规则前确认适用性和授权。明确反馈的实现、检查和普通修复连续完成，不每步请求许可。

新轮次交付逐项回应上一轮。已实现、已验证、待用户体验、已认可必须区分；不能因等待超时视为认可，也不能将一句“可以”覆盖用户未看到的设备与状态。

### 组织评审与收口

每轮交付真实原生图／必要录屏或可运行版本，附简明变化和少数具体判断点。方向发生实质变化时先给具体可比较提案；已确认方向不重复征询。静态截图不证明手感，模拟器不证明真机温升。

每轮完成约定目标和相关验证后交付，避免无限自我打磨；新的用户反馈启动下一轮。等待体验时可继续不依赖选择的盘点与检查，但不扩散待决规则。

原始 before/after 与概念／标注图清楚区分；同条件对比记录设备、OS、窗口、字号、球形、模式和源／构建。旧轮次保留，用户认可的体验参考与改动前技术 before 分别保存，禁止自动刷新参考吞掉差异。

## 结束与交接

更新页面卡、评审账本和 `tasks/PROGRESS.md`；只有实际改变产品设计／API 时才按项目规则记 DR／规格，不能把提案写成已上线行为。遇到相关返工按项目规则留痕。

交付注明已完成、未验证、用户待决、依赖状态和唯一下一步。安装、提交、发布分别记录。技能 v1 在首个试点后根据真实摩擦小幅改进，不因单次偏好增设全局硬约束。

## 经验教训

### FL-123 — 参考页适配遗漏设置能力

r01只对照外观、保留底部球库，并未盘点每日完整设置，用户要求返工。后续参考页适配必须交付上述能力对照，检查新增菜单有实际接线、设置分组最终顺序及跨页偏好影响；具体球库位置由当前方案和用户决定，不推广到无球库页面。

Changelog：2026-10-06 / v1.1 / FL-123：补参考页能力与设置对照，保留用户已明确方向。

FL-123 / r03补充：参考图可访问时必须重新打开逐模式对照。用户要求延续原界面时，保留球桌比例、成对控件轴线／尺区、圆盘大小和仅某模式出现的入口；对照图直接使用原图或真实原生页面，不能用任意长宽占位块和混合模式线框代替保真验收。缺失状态（如展开大盘）另查，不能推断已验证。Changelog：2026-10-06 / v1.2。

FL-123 / lab-r02补充：参考页复用须做同窗口原生对照，区分SCNView矩形、实际投影桌框、控件可见形状和命中范围；仅验证自身对称不足以证明与参考一致。布局锚点应从参考的真实计算链复用，记录相同与差异，不用独立常量近似。模式迁移同时核对“用户偏好／当前临时状态／下一杆恢复”，通过真实操作验证生命周期。具体尺寸、间距和恢复规则留在页面卡，勿推广到无关页。Changelog：2026-10-06 / v1.3。

Changelog：2026-10-06 / v1.4：设计DC条款接入批次验收；活动交接、按需恢复与事件检查点见专用协议。不改变页面授权范围。


### FL-132 — Figma粗调按用户实际操作验收

用户要求直接拖角时，必须用普通移动工具实际拖角验证内部视觉一起变化，不能以K/Scale、可编辑W/H或脚本resize代替。保留用户已调的位置和尺寸；修复结构前保存原稿。需要便捷粗调时可采用独立高清图块、保持内容比例，并在精调文件保留完整文字/矢量结构；明确两者编辑范围。转换后检查圆角、遮罩、文字和刻度，不能仅检查节点数。用户提出双文件时，精调不得覆盖粗调版；明确确认后再实施代码。

Changelog：2026-10-06 / FL-132：补真实编辑操作验收与粗调/精调证据边界；具体文件和状态见每日交接。
