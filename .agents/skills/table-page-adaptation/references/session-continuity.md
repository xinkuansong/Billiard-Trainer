# 设计契约、批次执行与长会话恢复

适用于每日清台独立适配及其他球桌页工作包。沿用 plan-batch-execution 的批前核对、实证验收和回写；本协议补充持久状态与最小阅读顺序，不要求创建新聊天或逐步审批。

## 1. 文件职责

|文件|负责什么|不负责什么|
|---|---|---|
|页面设计规范|现行目的、约束、取舍、编号及被覆盖决定|当轮命令和进度流水|
|方案/页面卡|范围、依赖、批次DoD及契约映射|复制整份规范、复制其他工作包动态状态|
|CURRENT或页面卡的当前交接节|本工作包当前轮次、有效证据、未完成项、在途工作、唯一下一动作|重新定义产品规则或自行宣布用户认可|
|评审记录及原始证据|每一轮实际做了什么、源/构建身份、通过/失败/未验、用户裁定|把历史通过自动沿用到新实现|
|PROGRESS|项目级摘要和进入上述文件的链接|积累整段聊天和重复全部交接内容|

一个工作包只维护一个活动交接入口；现有页面卡已有完整交接节时直接补齐，不另造平行CURRENT。每日独立工作包用 `tasks/daily-adaptive/CURRENT.md`。其他工作包引用这个路径获取每日状态，不抄W/R编号。

## 2. 恢复顺序

新会话、压缩后、被中断后、准备开始下一批，均执行：

1. 按项目入口做相关阻塞检查；定位工作包的活动交接入口，核对用户最新指令和当前工作模式（规划/实现/审阅/暂停）。聊天摘要用于找路，不能覆盖当前文件或最新用户要求。
2. 读取当前批次的范围/DoD/依赖，以及设计规范§总原则、历史覆盖关系和本批DC条款。首次接手先扫全篇目录/状态表建立整页结构；不把所有28项全文、全部DR和50张图反复塞入每轮上下文。
3. 打开本批明确关联的用户参考图与当前before；图不可访问时先检查归档位置，不能凭缩略图记忆编造尺寸或悄悄换参考。
4. 核对实际仓库路径、分支/HEAD、相关未提交差异、当前源码锚点和在途命令。证据必须匹配其采集源；源已变则标记受影响证据待重验，不抹去原通过历史，也不全量重跑无关项。
5. 回显一段：本批目标、已确认约束、已完成/尚未完成、下一动作。已有授权继续执行，不把“换会话”当作重新索要同一授权的理由。

若旧摘要、计划表与CURRENT不一致，先用最新明确用户决定、源码和原始证据核实，再修正过期摘要；CURRENT自身也不是免核对的事实。无法证实的结果记未验，不猜测成功或失败。

## 3. 活动交接的最小内容

建议约60–100行；它是可替换的当前快照，详细历史保留在既有报告，不无限追加。

- 更新时间、工作包/方案/规范版本、当前工作模式和本轮授权范围。
- 当前批次与小步骤；DoD勾选及未满足项；唯一下一动作。
- 本批DC条款、参考图、最新有效before/after及其来源，不复制规则正文。
- 实際改动文件/工作区身份；最新验证的命令、退出码、日志/xcresult路径、源指纹与适用范围；未运行直接写未运行。
- 在途任务：命令身份、目录、日志、会话/PID、所属工作包和状态；未知需查询，不重复启动、不误杀其他工作。
- 未闭合问题、已废弃方向与用户待决事项；已确认决定引用其真源。

不把临时会话ID当永久可恢复句柄；恢复后先确认任务是否仍存在。检查点写作按最小相关文件更新，避免覆盖其他会话新内容。

## 4. 何时落盘

在这些事件后及时更新活动交接，而不等聊天结束：用户改变方向或判定返工；形成重要取舍；完成一段实现；发起长构建/测试（先记命令与日志）；收到结果；切换角色/批次；暂停或交付。突发中断可能丢掉最后未记录的一步，因此检查点后留下的产物须核实，不能按旧状态重复执行有副作用的命令。

上下文压缩不会改变批次状态或完成标准。恢复时重复必要的真源核对，不重做已经有匹配证据的工作。若任务仍可安全推进，不因消息长就强制用户换会话；需要转到新会话时先完成可恢复交接，给一句入口指令即可。

## 5. 从规范到验收

批次卡按“DC条款 → 本批具体判断 → 原图/操作/测试证据 → 通过/失败/未验”登记。所有条款须有覆盖批次、明确保留回归或不适用理由；仅填编号不算完成。新发现受影响条款及时补入，不将未预见影响默认为不适用。

视觉要求用同条件原生图核对；状态/命中/物理用对应操作或测试；手感/声震用真机体验。客观缺陷修复不新增审批。用户主观判断确实影响方向时交付可比较结果再询问；未展示设备/状态不外推认可。

用户反馈先更新现行规范或页面决定（标明覆盖何条），再更新受影响批次/验收及CURRENT，最后压缩回写PROGRESS。只让受影响结论失效，保留可复用工程修复和历史证据。
